# Skills

## What a skill is
- A skill is a detailed prompt with clear goals in a markdown file (`skill.md` = metadata + one-line desc, optional scripts/assets) — human language, no code, no special training needed [Sentry](https://www.youtube.com/watch?v=li0SaBt9RDM) [LiteRT-LM](https://www.youtube.com/watch?v=BKWpYIWvAo4) (2026-05)
- **Composition over inheritance**: instead of one agent with 100+ tools/skills (context inflation, accuracy degrades), build small domain-specific agents (coordinator + specialists), each with a tight system prompt, minimal context, focused tools; agents communicate via NL → composable, 80%+ token-efficient on their domain, works with small models. Recursive sub-agents (coordinator → specialist → sub-specialist) keep each level isolated/testable/replaceable. [StandardAgents](https://www.youtube.com/watch?v=spNAUEgq_A8) (2026-06)
- Convert hard-to-code branching logic into a skill (a procedure description) — solves cases plain code can't [Tessl](https://www.youtube.com/watch?v=bSG9wUYaHWU) (2026-05)
- Versioned, source-controlled, file-based context the agent opens/closes on demand — turns a zero-shot task into few-shot by shipping worked examples [HuggingFace](https://www.youtube.com/watch?v=JomVvNDjGb8) (2026-05)
- Limit of example-based skills: retrieving high-quality expert trajectories as in-context examples helps, but near-identical cases diverge on tiny policy-sensitive attributes (account tier, location) that look the same to humans too — retrieval alone can't discriminate the right trajectory; a tuned model is still needed [ElevenLabs](https://podcasters.spotify.com/pod/show/mlops/episodes/Voice-Agent-Use-Cases-e3ileg6) (2026-05)
- Skills authored by domain experts hand the agent that expertise "for free" [DeepMind](https://www.youtube.com/watch?v=7gujZrJ9L5I) (2026-05) — e.g. property-based + deterministic/system testing (Hypothesis-style) packaged as a skill beats ad-hoc Playwright use [Huntley](https://www.youtube.com/watch?v=wjXowoQ7E8c) (2026-06)
- A skill can be a *bundle of small CLIs* the agent drives, not a native integration — a Cowork Excel skill = Pandas + openpyxl + LibreOffice CLIs packaged together, handing the agent command-line tools it's reliably good at over bespoke tool-call plumbing [Tavon-Pi](https://www.youtube.com/watch?v=vAIDdLKB6-w) (2026-05)
- Skill and MCP are complementary, not rivals: skill = guidance, MCP = tools already present; the live debate has moved past "MCP vs skill" to "MCP vs CLI" [Supabase](https://www.youtube.com/watch?v=JT3OzDKrucU) (2026-05)
- Skills carry security knowledge MCP alone lacks: an agent with only the Supabase MCP created a Postgres view over an RLS table, silently bypassing RLS (missed `security_invoker=true`); same agent + skill got it right [Supabase](https://www.youtube.com/watch?v=JT3OzDKrucU) (2026-05)
- Shift from "run skill X" to describing the problem and letting the agent pick which skills to invoke — a well-written skill auto-fired on a security-incident triage the author didn't even know existed [Intercom](https://www.youtube.com/watch?v=4_VQBbs2iQA) (2026-05)

## User-invoked vs model-invoked: tradeoffs
- **User-invoked**: no description in context (model never sees it), user must remember to call — no risk of the model just skipping it, but requires user discipline. **Model-invoked**: description sits in context every request (token cost), but model may skip despite a perfect fit (unpredictability). Tradeoff: context load vs cognitive load — pick based on harness context budget vs your own tolerance for remembering to invoke. [Building Great Agent Skills](https://www.youtube.com/watch?v=UNzCG3lw6O0) (2026-06)

## Less is more — skills can actively hurt
- 10k lines of docs-derived skills produced WORSE results than 553 lines of hand-written "common gotchas" — cover the landmines, not the whole product; a big skill set also sends the model on goose chases checking many things, while lean gotchas keep it focused and cut run time (68min → 6min evals) [WorkOS](https://www.youtube.com/watch?v=vy7o1g2iHY8) (2026-05)
- Sharp negative constraints beat a prescriptive novel: 3 crisp "never" rules ("never cite code without file:line + commit ref", "never be vague") outperform a long markdown spec, and over-prescription can actively REGRESS a model already good at the task — one measured skill dropped a task 97%→77%, and a Next.js installer skill caused a ~30% accuracy drop by being dogmatic about something Claude already did well (both caught only via evals); every skill must earn its place [WorkOS](https://www.youtube.com/watch?v=vy7o1g2iHY8) (2026-05) [WorkOS-Skills](https://www.youtube.com/watch?v=pFsfax19yOM) (2026-05) (2026-07: generation-dependent — see the Fable system-prompt entry below)
- Skills/slash-commands earn their place only for narrow workflow automation (e.g. "generate testing-patterns.md from the cloned repo"), NOT for stuffing framework internals — a skill per library-internal just pollutes context [Effect](https://www.youtube.com/watch?v=Wmp2Tku2PrI) (2026-05)
- The flip continues with the newest model class: the arc ran small prompt + many examples (Sonnet 3.5-era) → large prompt, many instructions (models followed more) → now smaller prompt with FEW examples — few-shot examples actively CONSTRAIN this class (the model is more imaginative than your examples); give context, not constraints, drop "do not do X" prohibitions older models needed. Dates the sharp-negative-constraints advice above as model-generation-dependent. [Fable-field-guide](https://www.youtube.com/watch?v=9fubhllmsBU) (2026-07)
- Knowledge/context banks rot fast — stale on every model release + feature change; aggressively prune (don't just append) or old entries cause context rot and degrade the live agent [Lovable](https://www.youtube.com/watch?v=KA5kPbdkK2E) (2026-06)
- This applies to LOADED context, not idle skills on disk: only each skill's description (~75–150 tokens) sits resident, the ~1.3k-token body loads on demand — so unused *local* skills aren't worth deleting; pruning bites in prod/CI where the skill-listing budget (default ~1% of context, ~15–25 skills on a 200k model) truncates descriptions [Supabase-SkillIssue](https://www.youtube.com/watch?v=GmAQKINjv1E) [claudefa.st](https://claudefa.st/blog/guide/mechanics/skill-listing-budget) (2026-05)
- Context-rot threshold: perf degrades past ~25% context usage, practical target under ~40%. 15 connected MCP servers ≈100k+ tokens of tool-def overhead before a session starts; skills' progressive disclosure (only metadata loaded at runtime) cuts this ~10x — Claude Code/Codex ship only ~10 built-in tools, so breadth comes from stacking skills, not wiring up many MCP servers. [DataRobot/Aghammadzada](https://www.youtube.com/watch?v=LC3-P7v3yoI) (2026-07)
- Reconciliation: "less is more" means quality/leanness, NOT "no skills" — sources advocating many skills still demand each be lean, expert-authored, evaluated, curated; the failure mode is dumping whole docs, not having skills at all. (2026-05)

## Steering: leading words to guide agent behavior
- **Leading words technique**: pack meaning into reusable short terms. Agent repeats them in reasoning traces. Consistent use changes behavior without heavy prose. Example: use "vertical slice" instead of "don't code layer by layer" (well-known terminology, triggers agent's priors, agent repeats in reasoning). Watch the thinking traces to see adoption. If agent isn't doing what you want, make leading words more consistent/powerful or find new ones. [Building Great Agent Skills](https://www.youtube.com/watch?v=UNzCG3lw6O0) (2026-06)
- **Increase legwork on current step**: if agent doesn't do enough exploration on a step (e.g., ask clarifying questions → eagerly creates plan), split multi-step skills and hide future steps from the agent. Example: split "ask clarifying questions + create plan" into two separate skills; agent only sees the clarifying-questions step, so it focuses fully. Works very well for high-stakes decisions. [Building Great Agent Skills](https://www.youtube.com/watch?v=UNzCG3lw6O0) (2026-06)

## What to put in a skill
- Skills should encode language-level features the harness needs: PFA (partial function application) to lock a dangerous argument, and pause/resume ("interrupts") that serialize mid-loop or mid-sub-agent-call and resume later — most harnesses only support human-in-the-loop awkwardly at the top level, not nested. [Etsy-Bhargava](https://www.youtube.com/watch?v=2e9ANoOEn28) (2026-07)
- Description quality dominates: ~50% of failures were the skill not triggering. Write the **why, how and when** as directives — "use the interactions API when working on a chat application", not "the interactions API is recommended because…". [DeepMind-Schmid](https://www.youtube.com/watch?v=0vphxNt4wyk) (2026-07)
- Don't skip negative cases. "Use for web development" over-triggers across React and Angular alike; "only for React components" doesn't. [DeepMind-Schmid](https://www.youtube.com/watch?v=0vphxNt4wyk) (2026-07)
- Set the right level of freedom: if the workflow is always identical it should be a script the model invokes, not a skill. Define goals and constraints, not step-1/step-2 recipes. [DeepMind-Schmid](https://www.youtube.com/watch?v=0vphxNt4wyk) (2026-07)
- Budget by layer: the description is paid on **every** model call (~100–200 tokens resident), the body whenever the skill is read — so keep SKILL.md under ~500 lines and push depth into reference files the model can choose to open (one per cloud provider, not all three inline). [DeepMind-Schmid](https://www.youtube.com/watch?v=0vphxNt4wyk) (2026-07)
- Models already know how to code; skills should encode product-specific intricacies and gotchas, not re-teach general competence — guide don't prescribe, with specific conditional rules ("in the Next.js proxy you can't call redirects") rather than dumping summarized docs [WorkOS](https://www.youtube.com/watch?v=vy7o1g2iHY8) (2026-05)
- Ship verification inside the skill: bundle benchmark/test scripts so the agent self-checks its output (e.g. kernel correctness + speedup) instead of trusting it [HuggingFace](https://www.youtube.com/watch?v=JomVvNDjGb8) (2026-05)
- A skill can own infra/capacity reasoning, not just the command: a fine-tune skill does the napkin math (VRAM at a given batch size → which GPU instance fits, e.g. 4-bit Gemma in a 24GB L4), then asks only the genuinely-open questions before launching — self-provisioning. Generalizes to any batch job (pick a cheap model off a benchmark → write the processing script → cost/instance math → re-runnable job; OCR'd 30k papers this way). Same skill should optimize model choice for the downstream USE, not the leaderboard top row — asked "best OCR model for fine-tuning" it weighs fine-tuning suitability + size constraints, not raw score [HuggingFace-Hermes](https://www.youtube.com/watch?v=OV56RddyFuU) (2026-05)
- Structure exploration into fixed modes + structured output, not prose: a "Catch Me Up" comprehension skill uses fixed modes (architecture, conventions, feature trace, syntax, testing, history) returning org charts/tables; onboarding pattern within it — state your role ("I am a new contributor") + a specific yes/no question to verify, not just "explore this repo" [Sentry](https://www.youtube.com/watch?v=li0SaBt9RDM) (2026-05)
- "explain-diff" skill (Litt/Notion, public): agent-generated per-change explainer — BACKGROUND first → INTUITION before details → interactive figures where useful → LITERATE diffs (prose walking files in the right order, not a raw diff); output HTML/collaborative doc so the reviewer reads the explainer, not the raw diff. Caveat: interactivity can be slop — use sparingly [Litt](https://www.youtube.com/watch?v=WkBPX-oDMnA) (2026-07)
- SOP-as-spec: encode agent behavior as the same SOPs domain experts already wrote for humans, but far longer/more detailed since there's no human reading-fatigue limit — lets non-engineer experts own the skill [ElevenLabs](https://podcasters.spotify.com/pod/show/mlops/episodes/Voice-Agent-Use-Cases-e3ileg6) (2026-05)
- SKILL.md = style/process, NOT facts: encode HOW to implement (ask follow-ups before deciding; propose plan + approval gate before irreversible/data-leaving actions); push reference content out to live docs [Langfuse](https://www.youtube.com/watch?v=vNCY9kXXyDQ) (2026-05)
- Written rule files (agents.md / semantic-memory rules) are followed only ~7/10 at best — a model limitation, not a config fix; make must-happen steps deterministic (hooks/CI) rather than prose (cf. "deterministic instructions > prompt-nagging" in harnesses.md) [AutoHand](https://www.youtube.com/watch?v=wjXowoQ7E8c) (2026-06) (low-confidence src)
- Structured templates beat open-ended chat for parallelizing agents reliably; for brownfield migrations do docs-first — write docs over the legacy code (e.g. 2M LOC undocumented COBOL) and migrate from the docs, not the source [Cognition](https://www.youtube.com/watch?v=_xQnSNlBP_w) (2026-05) (low-confidence src: pitch framing)
- Red-green runbook for fixing a bug via prompt edits: write a failing eval reproducing the bug → modify the prompt until it passes → re-run the full suite for regressions → final pass to consolidate/simplify the bloated prompt; bake the simplify pass in since iterative edits accumulate bloat [incident.io](https://www.youtube.com/watch?v=L2r6vLlLgs8) (2026-05)
- Reference dynamic content, don't inline it — pasting docs into a skill creates a stale local cache; point to the source of truth and force fetch-first (agents default to stale training data, confidently write old-version SDK/CLI calls from memory, "verify", fail, then fetch — slow + wrong) [Langfuse](https://www.youtube.com/watch?v=vNCY9kXXyDQ) [Supabase](https://www.youtube.com/watch?v=JT3OzDKrucU) (2026-05)
- "If it can be skipped, it will be skipped": agents are lazy to load reference files — a skill that loads usually pulls ZERO or at most ONE reference file; two is "almost impossible," three/four never. Put anything must-not-miss (e.g. a security checklist) directly in skill.md, not a reference file — Supabase moved their RLS/security checklist into skill.md after watching it get skipped [Supabase](https://www.youtube.com/watch?v=JT3OzDKrucU) (2026-05)
- Be opinionated — encode the workflow you know is best so the agent doesn't freelance: Supabase bakes the schema workflow into the skill (run direct DDL freely on dev/staging → run security/perf advisor → fix → only THEN write a migration file), preventing spammed migrations on every schema change [Supabase](https://www.youtube.com/watch?v=JT3OzDKrucU) (2026-05)
- Encode search STRATEGY, not just API docs: agents search badly by default (thrash, burn tokens) — ship "search engineer" skills stating which retrieval method to use when, how to combine primitives, what to do in named situations; procedural skills are the accessible-today branch of teaching agents to search (vs emerging RL-trained search trajectories) [Qdrant-Roundtable](https://podcasters.spotify.com/pod/show/mlops/episodes/The-Current-State-of-Agentic-Retrieval---Qdrant-Roundtable-e3lh8v8) (2026-07)
- Agent-friendly defaults invert human defaults: extra prompts/vars cost the agent nothing, so make the skill ASK (e.g. data region) rather than assume a config-minimizing default [Langfuse](https://www.youtube.com/watch?v=vNCY9kXXyDQ) (2026-05)
- Progressive disclosure is the core scaling mechanism: keep only name + description resident, load full body on instantiation, offload after — vs MCP loading all tool specs up front. Minimum viable implementation for your OWN harness: registry of {name, description, path} in the system prompt + a file-read tool (add bash/sandbox only if skills ship executable scripts) [Anthropic](https://www.youtube.com/watch?v=mR-WAvEPRwE) [Elastic](https://www.youtube.com/watch?v=ynJyIKwjonM) [FactSet-Miraje](https://www.youtube.com/watch?v=7jjudsEhBtM) (2026-07)
- **The routing MECHANISM changes with library size — it doesn't just get tuned**: under ~10 skills, all names + descriptions resident in the system prompt is fine; past ~10, shortlist first (embeddings + similarity search, or a small model picking candidates) before injecting; at hundreds you need a skill hierarchy plus metadata filters or the library stops being searchable. (Same curve as the tool-count accuracy collapse in harnesses.md § Tool design.) [FactSet-Miraje](https://www.youtube.com/watch?v=7jjudsEhBtM) (2026-07)
- The skill `description` IS the runtime routing rule (the LLM reads only descriptions to decide load/no-load) — disambiguate near-duplicate skills by aiming the description at the USER'S REQUEST, not the skill's own subject (report-HTML vs report-PDF disambiguate only because one says "use only when the user asks for a PDF report"); keep descriptions mutually distinct and non-stale — stale/overlapping descriptions are the usual reason a skill never fires. Start with the verb "use" + purpose to raise load probability (claimed Claude-specific) [WorkOS-Skills](https://www.youtube.com/watch?v=pFsfax19yOM) [FactSet-Miraje](https://www.youtube.com/watch?v=7jjudsEhBtM) [Supabase-SkillIssue](https://www.youtube.com/watch?v=GmAQKINjv1E) (2026-05)
- Debug description-routing empirically: define both should-fire AND should-NOT-fire scenarios, run them via the CLI, and tune the description against the negatives (false-positive loads) — not just the positives [Supabase-SkillIssue](https://www.youtube.com/watch?v=GmAQKINjv1E) (2026-05)
- Three escalating force-load levers when routing is unreliable: plain prompt = pray it fires; `use <skill-name>` in the prompt ≈100%; `/<skill-name>` slash command = 100% guaranteed [Supabase-SkillIssue](https://www.youtube.com/watch?v=GmAQKINjv1E) (2026-05)
- `!`-backtick syntax in SKILL.md = shell interpolation (like JS `${}`): Claude runs the backtick'd command and substitutes its *output* into context before acting (e.g. inline a `git log` in your exact format instead of telling it to fetch commits) — deterministic + token-saving, claimed Claude-specific [WorkOS-Skills](https://www.youtube.com/watch?v=pFsfax19yOM) (2026-05)
- Confidence-gate inside a skill: have it self-score sub-dimensions (problem clarity / goal / success criteria / scope) summing to 100 and refuse to execute until ≥95, forcing it to "show its work" on why it's confident (claiming "I'm sure" → asked why → realizes it isn't); pull missing inputs via the built-in ask-user-question (multiple-choice) rather than open prompts [WorkOS-Skills](https://www.youtube.com/watch?v=pFsfax19yOM) (2026-05)
- Prefer structured *text* output over vision models for structured data: text-output models have far more training data, while vision data self-conflicts (y-axis-up vs screen-y-down, ambiguous "left") — predictable structured output from vision still takes heavy prompt engineering [tldraw](https://www.youtube.com/watch?v=sPUjIBH5Cwg) (2026-05)

## Skill structure: steps + reference material
- **Two main units**: steps (step-by-step procedure) + reference (supporting info to complete steps). Skills can be steps-only, reference-only, or both. Keep skill.md small; move branching reference material behind external context pointers (separate markdown files bundled with the skill, lazy-loaded). If a piece of reference is only used in one branch, move it to an external reference file. [Building Great Agent Skills](https://www.youtube.com/watch?v=UNzCG3lw6O0) (2026-06)

## Pruning skills: no-ops, sediment, duplication
- **No-ops**: instructions that change no behaviour ("make the implementation easy to read") cost tokens every call and buy nothing — AI-generated skills accumulate them; deletion test: would output be the same if this section vanished? If yes, remove it. [DeepMind-Schmid](https://www.youtube.com/watch?v=0vphxNt4wyk) [Building Great Agent Skills](https://www.youtube.com/watch?v=UNzCG3lw6O0) (2026-06)
- **Sediment** (accumulated irrelevant material from many contributors): fix by checking relevance for ALL branches (move branch-specific material out), removing stale content, re-organizing. **Duplication**: keep a single source of truth — don't repeat the same reference/procedure/template in multiple places. [Building Great Agent Skills](https://www.youtube.com/watch?v=UNzCG3lw6O0) (2026-06)

## Designing skills around existing systems
- Expose a platform's existing guardrails + APIs as agent skills so the agent uses the same safe paths humans do — don't build bespoke "magic" for the agent. Infrastructure-as-code operations become skills (skills.md as implementation detail); the agent is an alternative interface, not a magic layer [Pragmatic Engineer / Kelsey Hightower](https://newsletter.pragmaticengineer.com/p/kubernetes-and-retiring-at-the-top) (2026-06)
- Vendor-published skills as integration aid: Google ships official coding-agent skills for its Gemini APIs incl. the Live API — install vendor skills when wiring agents to finicky real-time/streaming APIs; steers the agent where docs alone fail [DeepMind-Schaeff](https://www.youtube.com/watch?v=Bc6Ojl2XS1w) (2026-06)
- Domain skill that maps a structured DSL pays off: Chronon's Claude skill turns freeform feature descriptions into valid DSL definitions ("pretty good, maybe slight tweaking"). Leverage is the constrained DSL itself: a structured construct (vs free-form logic) makes agent codegen reliable, with correctness invariants (point-in-time joins) baked into the construct rather than left to the model (cf. model-level constrained generation in harnesses.md) [Chronon](https://podcasters.spotify.com/pod/show/mlops/episodes/Zipline-Roundtable-episode-Building-Real-Time-ML-Systems-with-Zipline--Chronon-e3ktnth) (2026-06)
- Anthropic ships an MCP-app scaffolding skill (modelcontextprotocol repo) — generates spec-compliant MCP-app templates incl. handlers and tool-visibility config (model-only / model+app / app-only) without hand-coding [MCP Apps](https://www.youtube.com/watch?v=_xIwFcnHqp4) (2026-05)
- Same generic loop (work → push → feedback → iterate) but swap skills to change its focus: ADR skill, PRD skill, UI skill (skips checks, fast browser iteration), test skill (selects tests by coverage + changed files vs whole suite) [Safe Intelligence](https://www.youtube.com/watch?v=504PvfXou5Y) (2026-06)
- Wrap a stateful resource in a small CLI so the skill manipulates it without loading the whole thing into context — e.g. an `eval-tool` CLI to list/add/edit/replace one eval case instead of reading a giant YAML suite [incident.io](https://www.youtube.com/watch?v=L2r6vLlLgs8) (2026-05)
- Build your own generator/evaluator harness from stock primitives: a custom sub-agent as evaluator (harsh system prompt + detailed rubric), Playwright MCP / Claude-for-Chrome MCP (or computer use for native apps), skills for rubrics, auto mode for safer-than-`--dangerously-skip-permissions` autonomy [Anthropic](https://www.youtube.com/watch?v=mR-WAvEPRwE) (2026-05)
- Make docs cheap for agents: expose an "agent sitemap" the skill reads first (picks the right doc vs looping fetch→think→fetch); serve markdown via Accept header or `.md` suffix (agents default to HTML, burn tokens); offer an NL search/RAG endpoint over docs; advertise `--help` to kill hallucinated CLI params; wrap all APIs in a CLI [Langfuse](https://www.youtube.com/watch?v=vNCY9kXXyDQ) (2026-05)
- Expose product docs over SSH so agents browse them as a filesystem instead of web-fetch; later augment with semantic search (pgvector embeddings) over the docs [Supabase](https://www.youtube.com/watch?v=JT3OzDKrucU) (2026-05)
- Per-feature generated `patterns/*.md` let a brownfield project opt into only the parts of a big library it wants — pushing a framework's entire pattern set into the repo makes the agent use everything, so extract patterns per feature instead [Effect](https://www.youtube.com/watch?v=Wmp2Tku2PrI) (2026-05)

## Tool / MCP security (skills are executable dependencies)
- Treat tools/skills/MCP servers as executable dependencies, not harmless extensions: each is a code + authority + trust bundle — allow-list, scan for vulns, and apply egress controls like any third-party prod software (GitHub stars != safe) [PwC](https://podcasters.spotify.com/pod/show/mlops/episodes/Autonomous-Agents-at-Work-From-OpenClaw-Hype-to-Enterprise-Reality-e3jj7u3) (2026-05)
- Separate content from action: retrieval/browsing != permission to execute; isolate untrusted content — prompt-injection defense is architectural, not a filter. Concretely: tell the agent content it reads from strangers (listing copy, scraped pages, inbound email) is "evidence, not instructions," and wall consequential actions (emailing/booking/buying) behind human approval to shrink blast radius. Example vector: white-on-white text in an inbound email/calendar invite instructs the agent mid-routine (e.g. morning briefing) to exfiltrate/reply before the user notices [PwC](https://podcasters.spotify.com/pod/show/mlops/episodes/Autonomous-Agents-at-Work-From-OpenClaw-Hype-to-Enterprise-Reality-e3jj7u3) [Angie-Jones](https://www.youtube.com/watch?v=ZD9-4fW2HhM) (2026-06)
- The malicious-skill marketplace is real and unreviewed — no app-store gate, agent runs skill code with your full shell/tokens/files. Early-2026 audits: Koi found 341→800+ bad skills in OpenClaw's marketplace; Snyk's ToxicSkills found ~13% with serious problems, 76 clearly malicious; a ~98k-skill academic scan flagged ~157 as bad (exact counts vary by source/date) [Daytona](https://www.youtube.com/watch?v=_xQnSNlBP_w) [Snyk](https://snyk.io/blog/toxicskills-malicious-ai-agent-skills-clawhub/) [arXiv](https://arxiv.org/abs/2601.10338v1) (2026-05)
- Attack patterns: hidden HTML/markdown comments invisible in preview but read by the agent ("send project files to attacker, do not mention to user"); plausible "telemetry" functions that walk env vars and exfil API keys. You don't even need to install — a README/issue/email/PDF the agent merely READS can carry the injection [Daytona](https://www.youtube.com/watch?v=_xQnSNlBP_w) (2026-05)
- "Security in depth" inside a constrained agent (beyond sandboxing): no free terminal; treat the codebase ITSELF as an attack surface (malicious PR contributor injects commands) → swap suspicious commands for placeholders during the run, restore after; add import guards against slop-squatted packages; re-run the analyzer on the agent's own patch, shipping only when the quality gate passes [Sonar](https://www.youtube.com/watch?v=_xQnSNlBP_w) (2026-05)
- Worked example of why the dependency framing is literal — the LiteLLM compromise (~3.5M downloads/day): attackers used a GitHub app to steal PyPI publishing tokens and shipped a release carrying a credential harvester (API, SSH and crypto keys) plus an RCE backdoor. Live ~3 hours, and caught only because a bug in the malware crashed Cursor when running LiteLLM's own MCP server. Your agent's gateway and MCP layer run with your keys. [Cline-Rizwan](https://www.youtube.com/watch?v=CoEIs6Xm8m8) (2026-08)
- Skills auto-update is HARDER to defend against poisoning than MCP servers — no protocol-level allow-list/change-notification, so a once-trusted skill's author can silently push a malicious update to every user (vs MCP, where you can gate on the tool list). Defensively: disable skill auto-update so a trusted skill can't be poisoned later [MCP-DarkSide](https://podcasters.spotify.com/pod/show/mlops/episodes/The-Dark-Side-of-MCP-Servers-e3l5thf) (2026-06)

- **Gate skills where you gate dependencies — a working org-scale implementation** (Nubank, >2000 skills scanned): an internal plugin marketplace is the only distribution path; a CI step on the PR that uploads a skill decides allow / allow-with-remediation / block. Same scanner runs locally so the author iterates until clean, AND again after upload — never assume the local run happened or was current. Measured: >1500 risks across >2000 skills, ~1000 remediated immediately, a few blocked outright; a retroactive sweep of pre-scanner skills found more. Findings route to PR comments + SARIF so they land in the existing vuln-management program, not a parallel queue [Nubank-SkillVector](https://www.youtube.com/watch?v=iKQ78wyJEXU) (2026-07)
- Hybrid by design: deterministic regex/pattern checks for cheap risks, LLM review ONLY for behavioural/contextual ones (LLM nondeterminism means it sometimes misses the same risk) — anything expressible deterministically stays deterministic (cf. harnesses.md § Guardrails as execution boundary). Scanned classes worth copying: unsafe instructions, behavioural drift, destructive shell commands, unexpected file modification, credential requests, data exposure, overbroad permissions, risky MCP usage [Nubank-SkillVector](https://www.youtube.com/watch?v=iKQ78wyJEXU) (2026-07)
- **"Ask for confirmation" written in a skill is not a human in the loop**: the model can satisfy it by confirming to *itself*, or another agent confirms — the author believes there's a human gate, the agent records a confirmation and proceeds. Scan for real approval gates at the executing tool or via hooks, never trust the instruction [Nubank-SkillVector](https://www.youtube.com/watch?v=iKQ78wyJEXU) (2026-07)
- What DIDN'T work in the scanner: scoring all shell commands equally risky; low-context weak signals (more noise than help); flat severity regardless of local-vs-production; findings shipped without remediation guidance [Nubank-SkillVector](https://www.youtube.com/watch?v=iKQ78wyJEXU) (2026-07)
- **Static scanning is necessary and structurally insufficient**: a skill whose static scan is clean can still break at runtime ("Runtime Skill Audit"), and two individually-benign skills can be malignant *together* ("When Safe Skills Collide") — an OCR skill extracts attacker-planted content, a reporting skill dutifully ships it as PII. Neither skill is compromised; the composition is. Relayed figure: ~90% of attacks in that study take this shape [Rallabandi](https://www.youtube.com/watch?v=s67bE2Ur3bY) (2026-07) (low-confidence src for the 90% figure)

## Discovering which skills to write
- Mine your own prompt history / session JSONL logs for repeated patterns, then codify them into skills: had Claude classify 116 sessions into 6 categories to surface what to automate; the weekly chores you most resist are the best candidates, and skill-builder surfaces where the workflow was inefficient (10 tool calls that could be 1–2, repeated clarifying questions to pre-answer) [Sentry](https://www.youtube.com/watch?v=li0SaBt9RDM) [WorkOS-Skills](https://www.youtube.com/watch?v=pFsfax19yOM) (2026-05)
- Production-scale version of prompt-history mining: a recurring job mines recent user queries (most repeat in shape — aggregations, lookups, billing), clusters them, and distills them into skills (~100 live in Vercel's d0 data agent) so each fresh run starts with pre-established context [Vercel-d0](https://www.youtube.com/watch?v=I2cbIws9j10) (2026-07)
- Offline-batch variant: skill generation as a scheduled nightly sweep — a consolidation job distills the day's recurring work/patterns into named reusable skills and emits a morning diff of newly-derived ones ("Factory That Dreams / 36 agents") [Doshi](https://www.youtube.com/watch?v=jtzh-GBXBWc) (2026-07)
- For a large API surface, ship a "tool builder" skill instead of exhaustive per-endpoint MCP tools: it walks the agent through the API via shell and emits custom, TESTED, composable tools with generated help text so models (not just humans) can discover/reuse them — a recurring workflow becomes a tested component instead of re-prompting through it each time [MLOps-Smith](https://podcasters.spotify.com/pod/show/mlops/episodes/Developers-May-Stop-Depending-on-Libraries-e3lnbme) (2026-07)
- **Cut the skill library by USER INTENT, not by data model** — starting from the data model produced "estimates analysis" skills that no real request mapped onto; refactoring to "earnings preparation"/"pre-market preparation" matched actual use. Expect several refactors: start narrow, refactor as real use cases arrive [FactSet-Miraje](https://www.youtube.com/watch?v=7jjudsEhBtM) (2026-07)
- Cold-start house guidelines from repo history: commit + PR-review history already encodes what good/bad code looks like there (review comments = explicit "I didn't like this" signal) — mine it to auto-generate a first-cut conventions guide instead of asking humans to author from scratch [Windsurf](https://newsletter.pragmaticengineer.com/p/building-windsurf-with-varun-mohan) (2025-05)
- Make your product agent-native: figure out what agents reliably get wrong, write those gotchas down (watch for client-side JS that hides context from page-summarizing crawlers) [WorkOS](https://www.youtube.com/watch?v=vy7o1g2iHY8) (2026-05)
- "Skills to write skills": generate skills with a coding agent, then add a deploy/test skill so the agent self-tests each one in-loop on a real target (an ADB skill: deploy to device → exercise → validate → iterate, all from one prompt) [Function-Gemma](https://www.youtube.com/watch?v=-TiET_K-E_g) (2026-05)

## Measuring whether a skill helps (eval each one)
- Measured effect: skills improve performance ~15% on average across ~100 coding/productivity tasks and multiple models and harnesses. But **human-written skills beat AI-generated ones, and AI-generated skills can hurt** performance. [DeepMind-Schmid](https://www.youtube.com/watch?v=0vphxNt4wyk) (2026-07)
- The gap is real and widespread: an index of ~50k public skills found almost none had evals and most were AI-written and untested. Without one you can't tell whether a failure means a bad skill or a task beyond the model. [DeepMind-Schmid](https://www.youtube.com/watch?v=0vphxNt4wyk) (2026-07)
- Test **outcomes, not paths**: don't assert the skill loaded on turn one, assert the task succeeded. Loading on turn five is fine; not loading at all is fine if the result is right. [DeepMind-Schmid](https://www.youtube.com/watch?v=0vphxNt4wyk) (2026-07)
- Keep the harness deliberately cheap: a JSON file of cases (prompt, language, should_trigger, expected checks) plus a small script running the agent. Most assertions can be regex — right SDK, right model, right methods, no deprecated patterns — so they rerun cheaply and update trivially for new model IDs. LLM-as-judge only where whole traces need reading. [DeepMind-Schmid](https://www.youtube.com/watch?v=0vphxNt4wyk) (2026-07)
- Worked example of the payoff: a skill for an API released after the model's training cutoff, with 117 cases drawn from real user data, synthetic generation and reported complaints, took valid-code generation to ~90%. [DeepMind-Schmid](https://www.youtube.com/watch?v=0vphxNt4wyk) (2026-07)
- You only know a skill helps or hurts by measuring — run scenarios with/without it and compare pass rates; treat eval numbers as a directional signal not an absolute: fail a skill if score-with < score-without, gate on ~80–90% pass-rate, re-check as new models drop, delete skills that add only 1–2% once the base model improves [WorkOS](https://www.youtube.com/watch?v=vy7o1g2iHY8) [WorkOS-Skills](https://www.youtube.com/watch?v=pFsfax19yOM) (2026-05)
- Eval your context-routing, not just outputs: if a resolver table says "when altering tests, load tests.md", write a test asserting tests.md actually got loaded on a test-touching task — treat instruction-routing rules as testable infrastructure, not just outputs (complements should-fire/should-NOT-fire description debugging above) [YC-Tan](https://www.youtube.com/watch?v=I2cbIws9j10) (2026-07)
- Prove a skill is good by wiring it into a real shipping product path — WorkOS's CLI `install` brains are entirely the public skills run via the Agent SDK (build the skill and prove it in one move) [WorkOS-Skills](https://www.youtube.com/watch?v=pFsfax19yOM) (2026-05)
- Eval each skill, then sweep models against it — compare accuracy vs token cost to drop to a cheaper/open model for skills you run often [HuggingFace](https://www.youtube.com/watch?v=JomVvNDjGb8) (2026-05)
- Eval a skill by diffing filesystem + resulting traces before/after running it on sample repos, with checks as NL LLM-as-judge assertions ("OpenAI instrumentation added", "retrieval spans present"); a basic 5-fixture setup beats none — change the skill without silent regressions [Langfuse](https://www.youtube.com/watch?v=vNCY9kXXyDQ) (2026-05)
- Foundry AgentOptimizer's "eval generate": point the tool at an agent's traces + instructions and it derives a task-adherence eval dataset automatically (tasks + questions + criteria) — bootstraps the evaluate → hill-climb candidate instructions/skills/tools → atomic-swap-in-the-winner loop from zero instead of requiring a hand-built golden set first [Microsoft/Pablo Castro](https://www.youtube.com/watch?v=htM02KMNZnk) (2026-07)

## Skill governance & lifecycle
- "Review my code like <specific reviewer>" as a skill pattern: build a skill from one person's actual historical PR-review feedback so new code gets reviewed in that person's specific standards before a human sees it — a concrete, high-value instance of turning tacit judgment into a reusable skill. [OpenAI-Liu](https://www.youtube.com/watch?v=il1c1a2FufU) (2026-07)
- Two kinds of skill with different lifetimes: **capability** skills teach what the model can't do consistently yet and are temporary (evals tell you when to retire them); **preference** skills encode your team's workflow, style and domain, are durable, and are exactly what evals must protect from regression. [DeepMind-Schmid](https://www.youtube.com/watch?v=0vphxNt4wyk) (2026-07)
- Retire deliberately via **ablation**: run evals with and without the skill; if the model passes without it, delete the skill and **keep the eval** as a regression guard, so a skill can be reintroduced if performance later degrades. [DeepMind-Schmid](https://www.youtube.com/watch?v=0vphxNt4wyk) (2026-07)
- Gate on the eval: evals live alongside every skill, run on every diff to it, and a change cannot merge unless it improves the cases or adds new ones. [DeepMind-Schmid](https://www.youtube.com/watch?v=0vphxNt4wyk) (2026-07)
- The agents you *use* differ from the agents you *build*: you notice instantly when your own skill didn't trigger and reprompt. Your customers don't know skills exist and won't phrase prompts to trigger them — so shipped agents depend entirely on model-invoked skills. [DeepMind-Schmid](https://www.youtube.com/watch?v=0vphxNt4wyk) (2026-07)
- Bare-model baseline on release day: when a new model ships, strip ALL skills/markdown/CLAUDE.md and re-derive from scratch — models have distinct prompt-style tastes (read the model cards), so carried-over scaffolding encodes the previous model's limitations [Huntley-WF26](https://www.youtube.com/watch?v=I2cbIws9j10) (2026-07). This is the radical end of a corroborated practice (Claude Code ships a skill-model-migration guide advising targeted removal of old-model scaffolding on upgrade [Piebald-mirror](https://github.com/Piebald-AI/claude-code-system-prompts/blob/main/system-prompts/skill-model-migration-guide.md); cf. "harness mitigations ARE temporary" in harnesses.md, and "re-check as new models drop" in the measuring section). Tension with the G-Skill portability result below (a GEPA-optimized skill transferred unmodified across model families and improved): treat carry-over as testable against the bare baseline, not assumed either way.
- **A mechanism for why upgrades break skills, with a production case**: a model upgrade broke skill adherence with ZERO skill changes, because the new model weighted the BEGINNING of the skill file heavily and their critical instructions sat at the end. Nothing in the skill had changed. So skills are versioned CONTRACTS with a specific model, not documentation — re-run skill evals on every model upgrade, and check instruction POSITION when adherence drops. "Skills without evals are wishful thinking." (Concrete failure mode behind the bare-model-baseline practice above.) [FactSet-Miraje](https://www.youtube.com/watch?v=7jjudsEhBtM) (2026-07)
- Skill-library governance as five questions borrowed from code practice (what keeps it from being red tape): **admission** (extend existing vs new — automated registry gate + PR review), **ownership** (named owners per team, like code owners), **lifecycle** (semver, deprecation warnings, changelogs), **coherence** (periodic audits + validation), **boundaries** (per-skill tool allow-lists). Automation-vs-human-in-loop on each is the whole difference between governance and bureaucracy [FactSet-Miraje](https://www.youtube.com/watch?v=7jjudsEhBtM) (2026-07)
- Two-tier governance: project-maintained skills live in the project (robust, maintainer-owned); experimental/YOLO skills live in a separate repo. Author owns writing the skill's eval/test; emerging pattern lets agents design those tests (meta-eval) [HuggingFace](https://www.youtube.com/watch?v=JomVvNDjGb8) [DeepMind](https://www.youtube.com/watch?v=7gujZrJ9L5I) (2026-05)
- Skill-based harness leaked context as it grew (model "forgot"/skipped tasks); moving orchestration to deterministic code fixed it — skills for knowledge, code for control flow [WorkOS](https://www.youtube.com/watch?v=vy7o1g2iHY8) (2026-05)
- Skills as a package format (context + scripts + docs) lead to context "dependency hell" → version-pin context packages mirroring library versions [Tessl](https://www.youtube.com/watch?v=bSG9wUYaHWU) (2026-05) — that prediction confirmed first-hand at ~300 skills / 40 agents over 6 months: a competitive-intel skill fed a positioning skill fed a battlecard skill, and because each skill *keeps learning*, every upstream update silently broke its downstream consumers. Self-improving skills make the drift continuous, not occasional; "who owns skill quality" had no answer. [Atlan/Sankar](https://www.youtube.com/watch?v=8G_1-3IO4ZQ) (2026-07)
- Governance breaks before capability does at that scale: secrets hardcoded in `.env` files and unvetted public skill repos installed freely were "a nightmare" well before the skills stopped being useful — budget for governance at tens of skills, not hundreds. [Atlan/Sankar](https://www.youtube.com/watch?v=8G_1-3IO4ZQ) (2026-07)
- Keep the skill/context repo harness-neutral: one team went no-code builder → Google ADK → Glean → Claude Code → ~50/50 Claude+Codex inside 12 months, and each migration stranded accumulated context in the tool they left. Harness churn is faster than skill-authoring payback. [Atlan/Sankar](https://www.youtube.com/watch?v=8G_1-3IO4ZQ) (2026-07)
- Skill distribution is unsolved: no standard registry, no package manager, installed copies go stale. Options seen: Vercel `skills` package (`.agent/` dir, emerging cross-tool standard, symlinked into `.claude/skills` — installs globally with weak project scoping); model-specific plugins bundled with MCP servers; Supabase's approach of packaging the skill INSIDE the product repo (discoverable if the repo is accessible). Lean toward timestamp-on-install + skill self-flags/re-fetches when older than ~a month [Langfuse](https://www.youtube.com/watch?v=vNCY9kXXyDQ) [Supabase-SkillIssue](https://www.youtube.com/watch?v=GmAQKINjv1E) [Supabase](https://www.youtube.com/watch?v=JT3OzDKrucU) (2026-05)
- Packaging for non-technical teammates: zip the skill folder, rename `.zip`→`.skill`, drag into Claude Desktop (no versioning, no secret handling — keep creds out of the zip). Skills are cross-harness portable — same SKILL.md runs in Claude Code, Codex, Cursor, Claude Desktop/web, and Pi — author once, run anywhere [WorkOS-Skills](https://www.youtube.com/watch?v=pFsfax19yOM) (2026-05)
- G-Skill: a skill (repo-structure/test-invocation/build-system knowledge) optimized cheaply on one model via GEPA reflection on a trajectory transfers unmodified to a different model family and still improves it (24%→93% on GPT-5-mini, dropped unmodified onto Claude Sonnet 4.5 → 100% while cutting tokens/time ~50%) — skills are portable across models, not just across harnesses [WF2026/GEPA](https://www.youtube.com/watch?v=4sX_He5c4sI) (2026-07)
- Skill quality bar: small, durable, testable, single-job — backtest against your existing body of code/incidents/changes to prove it operates at high quality; prefer durable, written-down "how to do work here" skills over everyone hand-rolling multi-agent orchestrators, since specific impls change but the skill stays valuable [Intercom](https://www.youtube.com/watch?v=4_VQBbs2iQA) [PFF](https://www.youtube.com/watch?v=VMemhtlsoNk) (2026-05)
- Don't blindly drop a SKILL.md found on Twitter into your agent — read it and curate which parts you actually want (a borrowed design-system skill may carry off-brand things clashing with your org's conventions), same as not merging a PR nobody reviewed [PFF](https://www.youtube.com/watch?v=VMemhtlsoNk) [Magic-Path](https://www.youtube.com/watch?v=m12vGjfbNlo) (2026-05)
- Multi-skill scaling limit: a 4B model with ~8 skills chooses well ACROSS turns (skill A→B robust) but calling MULTIPLE skills within a single turn is still unreliable — open problem even with a simple harness [Function-Gemma](https://www.youtube.com/watch?v=-TiET_K-E_g) (2026-05)

## Self-improvement / agent feedback
- Give the agent a "vent" tool to report tooling/docs/schema/platform friction, fired only when genuinely frustrated — tuning the threshold beats an external reviewer forced to comment every turn (overfits to noise); the agent has more root-cause context than the end user, so self-reported friction is more actionable than user complaints. Surfaces bugs invisible to normal monitoring (e.g. copy tool silently failing on filenames with spaces); volume spikes act as emergent incident-detection [Lovable](https://www.youtube.com/watch?v=KA5kPbdkK2E) (2026-06)
- Cheapest possible agent observability, corroborating the vent tool: a free `report` tool + one system-prompt line ("surface anything notable for your operators") catches tests removed-not-fixed, a tool repeatedly failing, capability gaps, sandbox bypass. Tool naming controls honesty — a neutral name + "feedback to your creators" framing gets disclosure where "unsafe bash use" suppresses it [Raindrop](https://www.youtube.com/watch?v=-aM2EDTiaMs) (2026-05) (low-confidence src)
- Highest-signal training samples come from the stuck→unstuck transition; then ask "what should we have injected at the start to skip the friction?" — turn that into a new skill/knowledge entry [Lovable](https://www.youtube.com/watch?v=KA5kPbdkK2E) (2026-06)
- Outcome-weighted memory retrieval: rank retrieved memories by whether they historically helped or hurt the outcome, not just embedding similarity; once enough similar memories accumulate around one recurring case, fold the pattern into a skill/updated instruction instead of leaving it as ever-growing retrieved context [Starlight Search](https://www.youtube.com/watch?v=Jx4ZFEAq6bY) [WF2026](https://www.youtube.com/watch?v=htM02KMNZnk) (2026-07)
- Close the loop with NL feedback the way a manager corrects a human ("you gave wrong info here," "the SOP wasn't clear so it got confused"), then iterate the spec/procedure itself — when the agent is confused the fix is usually the spec, not the model [ElevenLabs](https://podcasters.spotify.com/pod/show/mlops/episodes/Voice-Agent-Use-Cases-e3ileg6) (2026-05)
- Skill maintenance loop: point the agent at its own session logs to improve the skill, or run skills through a prompt optimizer (GEPA) as a "skills gym"; version skills like dotfiles [OpenClaw](https://www.youtube.com/watch?v=pmoDeA3RBZY) (2026-06) — production variant that keeps a human gate: a *separate* harness specialized in reading production traces reverse-constructs proposed skill/context edits and files them to the maintainer as an approve/reject queue, rather than letting skills self-modify (which is what produced the drift above). [Atlan/Sankar](https://www.youtube.com/watch?v=8G_1-3IO4ZQ) (2026-07)
- Subagent vs skill: reach for a subagent when you want a *separate standalone context* to do bulk work (e.g. review passes) and report back only findings, so it doesn't eat the main task's context window [WorkOS-Skills](https://www.youtube.com/watch?v=pFsfax19yOM) (2026-05)
- Memory-consolidation loop (Pi): per-domain `memory.md` files plus an end-of-run retrospective that distills learnings ("spun in circles — next time run this command"); OpenClaw's daily-journal → consolidated-memory ("dreaming") is reported as surprisingly strong [WorkOS-Skills](https://www.youtube.com/watch?v=pFsfax19yOM) (2026-05)
- Auto-research to improve a skill (agent proposes edits against a target function) works as a human-reviewed idea generator (accepted 3/6) but is only as good as the target: minimizing "turns" backfired — optimizer deleted doc-fetch steps ("I already know this"), reintroducing staleness; anything not rewarded gets stripped as noise [Langfuse](https://www.youtube.com/watch?v=vNCY9kXXyDQ) (2026-05)
- Build skills via a feedback loop, NOT by sitting down enumerating steps: give the agent a goal, work alongside it fixing real cases, let it author the skill; the end state is self-updating skills in a continuous-improvement loop [Intercom](https://www.youtube.com/watch?v=4_VQBbs2iQA) (2026-05)
- Harness-engineering discipline: when the agent errs, fix the harness/skill so it can fix itself — never hand-fix the output; every failure is a system bug + data for the next run [WorkOS](https://www.youtube.com/watch?v=vy7o1g2iHY8) (2026-05)

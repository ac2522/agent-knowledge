# Skills

## What a skill is
- A skill is a markdown prompt (`SKILL.md` = metadata + one-line description, optional scripts/assets) — human language, no code, no training; versioned, source-controlled context the agent opens and closes on demand, turning zero-shot into few-shot by shipping worked examples [Sentry](https://www.youtube.com/watch?v=li0SaBt9RDM) [LiteRT-LM](https://www.youtube.com/watch?v=BKWpYIWvAo4) [HuggingFace](https://www.youtube.com/watch?v=JomVvNDjGb8) (2026-05)
- Progressive disclosure is the scaling mechanism: name + description resident, body loaded on instantiation, offloaded after (vs MCP loading all tool specs up front). Minimum own-harness impl: a {name, description, path} registry in the system prompt + file-read tool [Anthropic](https://www.youtube.com/watch?v=mR-WAvEPRwE) [Elastic](https://www.youtube.com/watch?v=ynJyIKwjonM) [FactSet-Miraje](https://www.youtube.com/watch?v=7jjudsEhBtM) (2026-07)
- **Skill as the UNIT OF CONTEXT**: it bundles the domain instructions AND the tool execution, so a context is composed from pluggable units you test and reuse independently — one master agent loading skills, not a fleet of sub-agents [Navan](https://www.youtube.com/watch?v=32nrHU6zHU8) (2026-08)
- Skill and MCP are complementary: skill = guidance, MCP = tools already present; the live debate moved past "MCP vs skill" to MCP vs CLI (see misc.md § MCP vs CLI) [Supabase](https://www.youtube.com/watch?v=JT3OzDKrucU) (2026-05)
- Skills carry security knowledge MCP alone lacks: an agent with only the Supabase MCP built a Postgres view over an RLS table, silently bypassing RLS (missed `security_invoker=true`); same agent + skill got it right [Supabase](https://www.youtube.com/watch?v=JT3OzDKrucU) (2026-05)
- A skill can be a bundle of small CLIs the agent drives rather than a native integration — a Cowork Excel skill = Pandas + openpyxl + LibreOffice CLIs, handing the agent tools it reliably drives [Tavon-Pi](https://www.youtube.com/watch?v=vAIDdLKB6-w) (2026-05)
- Domain-expert-authored skills hand the agent that expertise for free — e.g. property-based + deterministic testing (Hypothesis-style) packaged as a skill beats ad-hoc Playwright use [DeepMind](https://www.youtube.com/watch?v=7gujZrJ9L5I) [Huntley](https://www.youtube.com/watch?v=wjXowoQ7E8c) (2026-05)
- Limit of example-based skills: near-identical cases diverge on tiny policy-sensitive attributes (account tier, location) that retrieval can't discriminate — a tuned model is still needed [ElevenLabs](https://podcasters.spotify.com/pod/show/mlops/episodes/Voice-Agent-Use-Cases-e3ileg6) (2026-05)
- **User-invoked**: no description in context, user must remember to call. **Model-invoked**: description resident on every request (token cost), model may skip despite a perfect fit. Trade context load against your own cognitive load [Building Great Agent Skills](https://www.youtube.com/watch?v=UNzCG3lw6O0) (2026-06)
- **Skills supplant prescriptive config primitives**: Anthropic unshipped "styles" — low usage, too prescriptive, "not AGI-pilled" — because skills were the better application of the same need. Expect one generation's primitives to be replaced, not extended [Anthropic-Krieger](https://www.youtube.com/watch?v=qqrk7CtkuIw) (2026-08)
- Shift from "run skill X" to describing the problem and letting the agent pick — a well-written skill auto-fired on a security-incident triage the author didn't know existed [Intercom](https://www.youtube.com/watch?v=4_VQBbs2iQA) (2026-05)

## Less is more — skills can actively hurt
- 10k lines of docs-derived skills scored WORSE than 553 lines of hand-written "common gotchas" — cover the landmines, not the product; big skill sets also send the model on goose chases (68min → 6min evals) [WorkOS](https://www.youtube.com/watch?v=vy7o1g2iHY8) (2026-05)
- Sharp negative constraints beat a prescriptive novel: 3 crisp "never" rules outperform a long spec, over-prescription REGRESSES a model already good at the task — one skill dropped a task 97%→77%, another ~30% accuracy; both caught only via evals [WorkOS](https://www.youtube.com/watch?v=vy7o1g2iHY8) [WorkOS-Skills](https://www.youtube.com/watch?v=pFsfax19yOM) (2026-05)
- **Live disagreement, decided by model generation**: the newest class inverts that — few-shot examples now CONSTRAIN (the model out-imagines your examples), so give context, not constraints. Condition: prescriptive rules for weaker models, sparse context for frontier ones [Fable-field-guide](https://www.youtube.com/watch?v=9fubhllmsBU) (2026-07)
- Skills earn their place for narrow workflow automation, NOT for stuffing framework internals — a skill per library-internal just pollutes context [Effect](https://www.youtube.com/watch?v=Wmp2Tku2PrI) (2026-05)
- Knowledge/context banks rot fast — stale on every model release and feature change; aggressively prune rather than append, or old entries cause context rot [Lovable](https://www.youtube.com/watch?v=KA5kPbdkK2E) (2026-06)
- Pruning bites on LOADED context: only descriptions (~75–150 tokens) stay resident, body loads on demand. The bite is prod/CI — a skill-listing budget of ~1–2% of context (~15–25 skills at 200k) truncates or degrades DESCRIPTIONS rather than dropping skills [Supabase-SkillIssue](https://www.youtube.com/watch?v=GmAQKINjv1E) [claudefa.st](https://claudefa.st/blog/guide/mechanics/skill-listing-budget) (2026-05) [OpenAI-Kundel](https://www.youtube.com/watch?v=shRR1e2HXMk) (2026-08)
- Context-rot threshold: performance degrades past ~25% context use, target under ~40% — so stack skills rather than wiring many MCP servers, whose tool defs load up front (numbers in misc.md § MCP vs CLI) [DataRobot/Aghammadzada](https://www.youtube.com/watch?v=LC3-P7v3yoI) (2026-07)
- **No-ops**: instructions that change no behaviour ("make it easy to read") cost tokens every call and buy nothing; AI-generated skills accumulate them. Deletion test — would output be the same if this section vanished? [DeepMind-Schmid](https://www.youtube.com/watch?v=0vphxNt4wyk) [Building Great Agent Skills](https://www.youtube.com/watch?v=UNzCG3lw6O0) (2026-06)
- **Sediment** (irrelevant material accumulated from many contributors): check relevance for ALL branches, move branch-specific material out, remove stale content. **Duplication**: one source of truth, never the same template in two places [Building Great Agent Skills](https://www.youtube.com/watch?v=UNzCG3lw6O0) (2026-06)

## What to put in a skill
- Description quality dominates: ~50% of failures were the skill not triggering. Write the why/how/when as directives — "use the interactions API when working on a chat application", not "the interactions API is recommended because…" [DeepMind-Schmid](https://www.youtube.com/watch?v=0vphxNt4wyk) (2026-07)
- Don't skip negative cases: "use for web development" over-triggers across React and Angular alike; "only for React components" doesn't [DeepMind-Schmid](https://www.youtube.com/watch?v=0vphxNt4wyk) (2026-07)
- Set the right level of freedom: an always-identical workflow should be a script the model invokes, not a skill. Define goals and constraints, not step-1/step-2 recipes [DeepMind-Schmid](https://www.youtube.com/watch?v=0vphxNt4wyk) (2026-07)
- Budget by layer: description paid on **every** call (~100–200 tokens resident), body only when read — keep SKILL.md under ~500 lines. One team at scale caps it at 100 lines: "a skill is really a folder" [DeepMind-Schmid](https://www.youtube.com/watch?v=0vphxNt4wyk) (2026-07) [Amazon-AGI-Khandelwal](https://www.youtube.com/watch?v=aeTb5BdmTTc) (2026-08)
- Two units: **steps** (the procedure) + **reference** (supporting info). Move branch-specific reference into separate lazy-loaded files; keep SKILL.md small [Building Great Agent Skills](https://www.youtube.com/watch?v=UNzCG3lw6O0) (2026-06)
- ...but "if it can be skipped, it will be skipped": a loading skill pulls ZERO or at most ONE reference file. Anything must-not-miss (security checklist) goes in SKILL.md — Supabase moved their RLS checklist inline after watching it skipped [Supabase](https://www.youtube.com/watch?v=JT3OzDKrucU) (2026-05)
- Models already know how to code; encode product-specific gotchas, not general competence — specific conditional rules ("in the Next.js proxy you can't call redirects") over summarized docs [WorkOS](https://www.youtube.com/watch?v=vy7o1g2iHY8) (2026-05)
- SKILL.md = style/process, NOT facts: encode HOW (ask follow-ups before deciding; propose a plan + approval gate before irreversible actions); push reference content to live docs [Langfuse](https://www.youtube.com/watch?v=vNCY9kXXyDQ) (2026-05)
- Reference dynamic content, don't inline it — pasted docs become a stale local cache. Force fetch-first: agents default to stale training data, confidently write old-version SDK calls, "verify", fail, then fetch [Langfuse](https://www.youtube.com/watch?v=vNCY9kXXyDQ) [Supabase](https://www.youtube.com/watch?v=JT3OzDKrucU) (2026-05)
- ...supply side of that rule: for a DSL or query language, install the vendor's MAINTAINED skill rather than hand-rolling one — left alone the agent reconstructs syntax from years-old Stack Overflow answers [Neo4j-Blumenfeld](https://www.youtube.com/watch?v=kRkcNOsRyYg) (2026-07)
- Ship verification inside the skill: bundle benchmark/test scripts so the agent self-checks its output (kernel correctness + speedup) instead of trusting it [HuggingFace](https://www.youtube.com/watch?v=JomVvNDjGb8) (2026-05)
- Be opinionated — encode the workflow you know is best so the agent doesn't freelance: Supabase bakes in run DDL freely on dev → run security/perf advisor → fix → only THEN write a migration file, preventing spammed migrations [Supabase](https://www.youtube.com/watch?v=JT3OzDKrucU) (2026-05)
- Encode search STRATEGY, not just API docs: agents thrash and burn tokens by default — state which retrieval method to use when, how to combine primitives, what to do in named situations [Qdrant-Roundtable](https://podcasters.spotify.com/pod/show/mlops/episodes/The-Current-State-of-Agentic-Retrieval---Qdrant-Roundtable-e3lh8v8) (2026-07)
- A skill can own infra/capacity reasoning: a fine-tune skill does the napkin math (VRAM at batch size → which GPU instance fits) then asks only the genuinely-open questions before launching [HuggingFace-Hermes](https://www.youtube.com/watch?v=OV56RddyFuU) (2026-05)
- Structure exploration into fixed modes + structured output, not prose: a "catch me up" skill uses fixed modes (architecture, conventions, feature trace, testing, history) returning tables; state your role and ask a specific yes/no question to verify [Sentry](https://www.youtube.com/watch?v=li0SaBt9RDM) (2026-05)
- Skills should encode language-level features the harness lacks — pause/resume interrupts that serialize mid-loop, since most harnesses only support human-in-the-loop at the top level, not nested [Etsy-Bhargava](https://www.youtube.com/watch?v=2e9ANoOEn28) (2026-07)
- SOP-as-spec: encode agent behavior as the SOPs domain experts already wrote for humans, but far longer since there's no reading-fatigue limit — lets non-engineer experts own the skill [ElevenLabs](https://podcasters.spotify.com/pod/show/mlops/episodes/Voice-Agent-Use-Cases-e3ileg6) (2026-05)
- ...worked triage instance, shared as a team plugin: one markdown file listing every feedback Slack channel, its DRI, when to tag on-call, how to judge a SEV — after which the human interface is a screenshot plus "?" [OpenAI-Liu-MLOps](https://podcasters.spotify.com/pod/show/mlops/episodes/How-To-Delegate-To-An-Agent-Like-You-Would-An-Employee-e3nglg8) (2026-08)
- Agent-friendly defaults invert human defaults: extra prompts cost the agent nothing, so make the skill ASK (e.g. data region) rather than assume a config-minimizing default [Langfuse](https://www.youtube.com/watch?v=vNCY9kXXyDQ) (2026-05)
- Confidence gate inside a skill: self-score sub-dimensions (problem clarity / goal / success criteria / scope) to 100 and refuse to execute below ~95, forcing it to show its work; pull missing inputs via multiple-choice ask-user, not open prompts [WorkOS-Skills](https://www.youtube.com/watch?v=pFsfax19yOM) (2026-05)
- Red-green runbook for fixing a bug via prompt edits: failing eval reproducing the bug → edit prompt until it passes → re-run the suite for regressions → a final consolidate/simplify pass, since iterative edits accumulate bloat [incident.io](https://www.youtube.com/watch?v=L2r6vLlLgs8) (2026-05)
- "explain-diff" skill: BACKGROUND first → INTUITION before details → literate prose walking files in the right order, output as HTML so the reviewer reads the explainer, not the raw diff [Litt](https://www.youtube.com/watch?v=WkBPX-oDMnA) (2026-07)
- **Ship a closed vocabulary file with any classification skill**, plus an explicit instruction to be reluctant to extend it — left free-form the model coins new categories every run and the taxonomy never converges. Keep a narrow escape hatch [Warp-Holmes](https://www.youtube.com/watch?v=I3bpdgFJCUY) (2026-08)
- Written rule files (agents.md, semantic-memory rules) are followed only ~7/10 at best — a model limitation, not a config fix; make must-happen steps deterministic hooks/CI. Well corroborated in harnesses.md § Enforcement loop; only the ~7/10 figure is single-sourced [AutoHand](https://www.youtube.com/watch?v=wjXowoQ7E8c) (2026-06)

### Steering and routing
- **Leading words**: pack meaning into short reusable terms the agent repeats in its reasoning ("vertical slice" instead of "don't code layer by layer") — changes behavior without heavy prose. Watch thinking traces for adoption [Building Great Agent Skills](https://www.youtube.com/watch?v=UNzCG3lw6O0) (2026-06)
- Increase legwork on the current step by hiding future ones: split "ask clarifying questions + create plan" into two skills so the agent sees only the first and focuses fully — works well for high-stakes decisions [Building Great Agent Skills](https://www.youtube.com/watch?v=UNzCG3lw6O0) (2026-06)
- `description` IS the runtime routing rule — aim it at the USER'S REQUEST, not the skill's subject (report-HTML vs report-PDF disambiguate only via "when the user asks for PDF"); stale or overlapping descriptions are why a skill never fires [WorkOS-Skills](https://www.youtube.com/watch?v=pFsfax19yOM) [FactSet-Miraje](https://www.youtube.com/watch?v=7jjudsEhBtM) [Supabase-SkillIssue](https://www.youtube.com/watch?v=GmAQKINjv1E) (2026-05)
- Debug routing empirically: define should-fire AND should-NOT-fire scenarios, run them via the CLI, and tune the description against the false-positive loads, not just the positives [Supabase-SkillIssue](https://www.youtube.com/watch?v=GmAQKINjv1E) (2026-05)
- Three escalating force-load levers: plain prompt = pray; `use <skill-name>` in the prompt ≈100%; `/<skill-name>` slash command = guaranteed [Supabase-SkillIssue](https://www.youtube.com/watch?v=GmAQKINjv1E) (2026-05)
- **Routing MECHANISM changes with library size**: under ~10 skills all descriptions resident is fine; past ~10, shortlist first (embeddings or a small picker model); at hundreds, hierarchy plus metadata filters. Same curve as harnesses.md § Tool design [FactSet-Miraje](https://www.youtube.com/watch?v=7jjudsEhBtM) (2026-07)
- `` !`cmd` `` in SKILL.md = shell interpolation: Claude runs the command and substitutes its OUTPUT into context before acting (inline a `git log` in your format) — deterministic and token-saving, claimed Claude-specific [WorkOS-Skills](https://www.youtube.com/watch?v=pFsfax19yOM) (2026-05)
- Multi-skill scaling limit: a 4B model with ~8 skills chooses well ACROSS turns but calling MULTIPLE skills within one turn stays unreliable — open problem even with a simple harness [Function-Gemma](https://www.youtube.com/watch?v=-TiET_K-E_g) (2026-05)

## Designing skills around existing systems
- Expose a platform's existing guardrails + APIs as skills so the agent uses the same safe paths humans do — the agent is an alternative interface, not a magic layer; don't build bespoke magic for it [Kelsey Hightower](https://newsletter.pragmaticengineer.com/p/kubernetes-and-retiring-at-the-top) (2026-06)
- Install vendor-published skills when wiring agents to finicky real-time/streaming APIs (Google ships official coding-agent skills for the Gemini Live API) — steers the agent where docs alone fail [DeepMind-Schaeff](https://www.youtube.com/watch?v=Bc6Ojl2XS1w) (2026-06)
- A constrained DSL is what makes domain codegen reliable: Chronon's skill turns freeform feature descriptions into valid DSL, with correctness invariants (point-in-time joins) baked into the construct rather than left to the model [Chronon](https://podcasters.spotify.com/pod/show/mlops/episodes/Zipline-Roundtable-episode-Building-Real-Time-ML-Systems-with-Zipline--Chronon-e3ktnth) (2026-06)
- Wrap a stateful resource in a small CLI so the skill manipulates it without loading the whole thing — an `eval-tool` CLI to list/add/edit one eval case instead of reading a giant YAML suite [incident.io](https://www.youtube.com/watch?v=L2r6vLlLgs8) (2026-05)
- Same generic loop (work → push → feedback → iterate), swap skills to change its focus: ADR skill, PRD skill, UI skill (skips checks, fast browser iteration), test skill (selects tests by coverage + changed files) [Safe Intelligence](https://www.youtube.com/watch?v=504PvfXou5Y) (2026-06)
- Make docs cheap for agents: an "agent sitemap" the skill reads first, markdown via Accept header or `.md` suffix (agents default to HTML and burn tokens), an NL search endpoint, and advertised `--help` to kill hallucinated CLI params [Langfuse](https://www.youtube.com/watch?v=vNCY9kXXyDQ) (2026-05)
- **Make the CODEBASE the disclosure structure**: put runbooks in the code comments so any grep landing in a file surfaces the pointer to the full doc, and keep AGENTS.md/CLAUDE.md a thin index rather than one big file [Amazon-AGI-Khandelwal](https://www.youtube.com/watch?v=aeTb5BdmTTc) (2026-08)
- Diagnostic for whether that's working: measure context burned on the FIRST prompt — ~20–25k is unavoidable baseline, 40–50k means it isn't disclosing progressively. Watch whether it greps around or goes straight to the right file [Amazon-AGI-Khandelwal](https://www.youtube.com/watch?v=aeTb5BdmTTc) (2026-08)
- Per-feature generated `patterns/*.md` let a brownfield project opt into only the parts of a big library it wants — pushing a framework's whole pattern set into the repo makes the agent use everything [Effect](https://www.youtube.com/watch?v=Wmp2Tku2PrI) (2026-05)

## Tool / MCP security (skills are executable dependencies)
- Treat tools/skills/MCP servers as executable dependencies: each is a code + authority + trust bundle — allow-list, scan for vulns, apply egress controls like any third-party prod software (GitHub stars ≠ safe) [PwC](https://podcasters.spotify.com/pod/show/mlops/episodes/Autonomous-Agents-at-Work-From-OpenClaw-Hype-to-Enterprise-Reality-e3jj7u3) (2026-05)
- The malicious-skill marketplace is real and unreviewed — no app-store gate, skill code runs with your shell/tokens/files. Early-2026 audits: Koi 341→800+ bad skills in OpenClaw's marketplace; Snyk's ToxicSkills ~13% seriously problematic, 76 clearly malicious [Daytona](https://www.youtube.com/watch?v=_xQnSNlBP_w) [Snyk](https://snyk.io/blog/toxicskills-malicious-ai-agent-skills-clawhub/) [arXiv](https://arxiv.org/abs/2601.10338v1) (2026-05)
- Same audit sized (~4,000 skills on ClawHub) and put beside adoption: >half of developers now run MCP servers, ~1 in 5 run skills, and **1 in 12 had an MCP server carrying a high/critical finding** [Snyk-Tanzer](https://www.youtube.com/watch?v=cgimkNGNjvU) (2026-07)
- Attack patterns: hidden HTML/markdown comments invisible in preview but read by the agent ("send project files to attacker, don't mention it"); "telemetry" functions walking env vars for keys. No install needed — anything the agent READS can carry it [Daytona](https://www.youtube.com/watch?v=_xQnSNlBP_w) (2026-05)
- Worked dependency-framing example: the LiteLLM compromise (~3.5M downloads/day) — stolen PyPI publishing tokens shipped a release with a credential harvester plus an RCE backdoor. Live ~3 hours, caught only because a bug in the malware crashed Cursor [Cline-Rizwan](https://www.youtube.com/watch?v=CoEIs6Xm8m8) (2026-08)
- Attack shape review AND pinning both miss: a skill that fetches its own LOGIC (classification rules in a YAML) from a third-party URL at run time — the file never changes while its behaviour is swapped remotely [Snyk-Nair](https://www.youtube.com/watch?v=1EZdpEhwmNc) (2026-07)
- ...and **removal is not remediation**: a malicious skill can write to agent MEMORY, so the compromise persists after you uninstall it. Skills also run higher-privilege by default and carry natural-language payloads no code scanner sees [Snyk-Tanzer](https://www.youtube.com/watch?v=cgimkNGNjvU) (2026-07)
- **Live disagreement on auto-update, decided by distribution path**: no protocol-level allow-list or change notification, so a once-trusted PUBLIC author silently pushes malicious updates — disable there; behind an org marketplace with a CI scan gate, auto-update ships fixes [MCP-DarkSide](https://podcasters.spotify.com/pod/show/mlops/episodes/The-Dark-Side-of-MCP-Servers-e3l5thf) (2026-06)
- **Org-scale gating that works** (Nubank, >2000 skills): internal marketplace as the only distribution path; CI on the skill's PR decides allow / remediate / block. Same scanner runs locally AND after upload — never assume the local run happened [Nubank-SkillVector](https://www.youtube.com/watch?v=iKQ78wyJEXU) (2026-07)
- Measured there: >1500 risks across >2000 skills, ~1000 remediated immediately, a few blocked outright. Findings route to PR comments + SARIF so they land in the existing vuln program, not a parallel queue [Nubank-SkillVector](https://www.youtube.com/watch?v=iKQ78wyJEXU) (2026-07)
- Hybrid by design: deterministic regex/pattern checks for cheap risks, LLM review ONLY for behavioural ones. Classes worth copying: unsafe instructions, behavioural drift, destructive shell commands, unexpected file modification, credential requests, data exposure, overbroad permissions [Nubank-SkillVector](https://www.youtube.com/watch?v=iKQ78wyJEXU) (2026-07)
- **"Ask for confirmation" written in a skill is not a human in the loop**: the model can confirm to itself, or another agent does. Scan for real approval gates at the executing tool or hooks; never trust the instruction [Nubank-SkillVector](https://www.youtube.com/watch?v=iKQ78wyJEXU) (2026-07)
- What DIDN'T work in that scanner: scoring all shell commands equally risky; low-context weak signals; flat severity regardless of local-vs-production; findings shipped without remediation guidance [Nubank-SkillVector](https://www.youtube.com/watch?v=iKQ78wyJEXU) (2026-07)
- **Static scanning is necessary and structurally insufficient**: a clean scan can still break at runtime, and two benign skills can be malignant together — an OCR skill extracts attacker-planted content, a reporting skill ships it as PII [Rallabandi](https://www.youtube.com/watch?v=s67bE2Ur3bY) (2026-07)
- "Security in depth" inside a constrained agent: no free terminal; treat the codebase as attack surface → swap suspicious commands for placeholders during the run; add import guards against slop-squatted packages; re-run the analyzer on the agent's own patch [Sonar](https://www.youtube.com/watch?v=_xQnSNlBP_w) (2026-05)

## Discovering which skills to write
- Mine your own session JSONL logs for repeated patterns: classify past sessions into categories to surface what to automate. The weekly chores you most resist are the best candidates; look for 10 tool calls that could be 1–2 [Sentry](https://www.youtube.com/watch?v=li0SaBt9RDM) [WorkOS-Skills](https://www.youtube.com/watch?v=pFsfax19yOM) (2026-05)
- Production-scale version: a recurring job mines recent user queries (most repeat in shape — aggregations, lookups, billing), clusters them and distills skills (~100 live in Vercel's d0) so each fresh run starts with pre-established context [Vercel-d0](https://www.youtube.com/watch?v=I2cbIws9j10) (2026-07)
- Offline-batch variant: a nightly consolidation job distills the day's recurring work into named reusable skills and emits a morning diff of newly-derived ones [Doshi](https://www.youtube.com/watch?v=jtzh-GBXBWc) (2026-07)
- For a large API surface ship a "tool builder" skill instead of exhaustive per-endpoint MCP tools: it walks the API via shell, emitting TESTED composable tools with generated help text, so a recurring workflow becomes a tested component [MLOps-Smith](https://podcasters.spotify.com/pod/show/mlops/episodes/Developers-May-Stop-Depending-on-Libraries-e3lnbme) (2026-07)
- **Cut the library by USER INTENT, not data model** — starting from the data model produced "estimates analysis" skills no real request mapped onto; "earnings preparation" matched actual use. Expect several refactors [FactSet-Miraje](https://www.youtube.com/watch?v=7jjudsEhBtM) (2026-07)
- Cold-start house guidelines from repo history: commits + PR-review comments already encode what good/bad code looks like there — mine them to auto-generate a first-cut conventions guide instead of asking humans to author one [Windsurf](https://newsletter.pragmaticengineer.com/p/building-windsurf-with-varun-mohan) (2025-05)
- Find what agents reliably get wrong with your product and write those gotchas down (watch for client-side JS that hides context from page-summarizing crawlers) [WorkOS](https://www.youtube.com/watch?v=vy7o1g2iHY8) (2026-05)
- "Skills to write skills": generate skills with a coding agent, then add a deploy/test skill so it self-tests each one on a real target (an ADB skill: deploy to device → exercise → validate → iterate, from one prompt) [Function-Gemma](https://www.youtube.com/watch?v=-TiET_K-E_g) (2026-05)

## Measuring whether a skill helps (eval each one)
- Measured effect: skills improve performance ~15% on average across ~100 coding/productivity tasks and multiple models and harnesses. But human-written skills beat AI-generated ones, and AI-generated skills can HURT [DeepMind-Schmid](https://www.youtube.com/watch?v=0vphxNt4wyk) (2026-07)
- The gap is widespread: an index of ~50k public skills found almost none had evals and most were AI-written and untested. Without one you can't tell whether a failure means a bad skill or a task beyond the model [DeepMind-Schmid](https://www.youtube.com/watch?v=0vphxNt4wyk) (2026-07)
- Test **outcomes, not paths**: don't assert the skill loaded on turn one, assert the task succeeded. Loading on turn five is fine; not loading at all is fine if the result is right [DeepMind-Schmid](https://www.youtube.com/watch?v=0vphxNt4wyk) (2026-07)
- Keep the harness cheap: a JSON file of cases (prompt, should_trigger, expected checks), a small runner, two conditions via claude headless, a DB reset between runs, a grading diff. Most assertions can be regex; LLM-judge only for whole traces [DeepMind-Schmid](https://www.youtube.com/watch?v=0vphxNt4wyk) (2026-07) [Supabase-SkillIssue](https://www.youtube.com/watch?v=GmAQKINjv1E) (2026-05)
- Cheaper tier still, before any behavioural eval: **statically lint the skill against the published authoring guide** (structure, description/trigger). Badly-structured tends to mean badly-invoked, so it screens out the obvious duds for the price of a check [QuantumBlack-Touil](https://www.youtube.com/watch?v=M05vON8i0aI) (2026-08)
- Worked payoff: a skill for an API released after the model's training cutoff, 117 cases drawn from real user data, synthetic generation and reported complaints, took valid-code generation to ~90% [DeepMind-Schmid](https://www.youtube.com/watch?v=0vphxNt4wyk) (2026-07)
- Run scenarios with and without the skill and compare pass rates; fail a skill if score-with < score-without, gate on ~80–90% pass rate, and re-check as new models drop [WorkOS](https://www.youtube.com/watch?v=vy7o1g2iHY8) [WorkOS-Skills](https://www.youtube.com/watch?v=pFsfax19yOM) (2026-05)
- Eval your context-ROUTING too: if a resolver says "when altering tests, load tests.md", write a test asserting tests.md actually got loaded on a test-touching task [YC-Tan](https://www.youtube.com/watch?v=I2cbIws9j10) (2026-07)
- Eval the skill DOCUMENT, grading agent BEHAVIOR (tools called, reasoning) not code: 6 scenarios × 4 agents from 2 vendors × 3 conditions (baseline / MCP only / MCP+skill), scored on test-completeness. MCP+skill beat every condition on every model [Supabase](https://www.youtube.com/watch?v=JT3OzDKrucU) (2026-05)
- Eval bugs are harder to catch than test bugs — a mis-written assertion reports inconsistent pass/fail across nondeterministic runs, and a judge can hallucinate grades. The hardest part is authoring representative scenarios, not building the harness [Supabase-SkillIssue](https://www.youtube.com/watch?v=GmAQKINjv1E) (2026-05)
- Eval a skill by diffing filesystem + traces before/after running it on sample repos, with NL LLM-judge assertions ("OpenAI instrumentation added", "retrieval spans present") — a basic 5-fixture setup beats none [Langfuse](https://www.youtube.com/watch?v=vNCY9kXXyDQ) (2026-05)
- Sweep models against each skill's eval, comparing accuracy vs token cost, to drop to a cheaper/open model for skills you run often [HuggingFace](https://www.youtube.com/watch?v=JomVvNDjGb8) (2026-05)
- Prove a skill by wiring it into a real shipping path — WorkOS's CLI `install` brains are entirely the public skills run via the Agent SDK [WorkOS-Skills](https://www.youtube.com/watch?v=pFsfax19yOM) (2026-05)

## Skill governance & lifecycle
- Two kinds with different lifetimes: **capability** skills teach what the model can't do consistently yet and are temporary; **preference** skills encode your team's workflow, style and domain, are durable, and are what evals must protect from regression [DeepMind-Schmid](https://www.youtube.com/watch?v=0vphxNt4wyk) (2026-07)
- Retire via **ablation**: run evals with and without; if the model passes without it, delete the skill and KEEP the eval as a regression guard, so it can return if performance degrades. Also delete skills adding only 1–2% [DeepMind-Schmid](https://www.youtube.com/watch?v=0vphxNt4wyk) (2026-07) [WorkOS](https://www.youtube.com/watch?v=vy7o1g2iHY8) (2026-05)
- Gate on the eval: evals live alongside every skill, run on every diff to it, and a change can't merge unless it improves the cases or adds new ones [DeepMind-Schmid](https://www.youtube.com/watch?v=0vphxNt4wyk) (2026-07)
- The agents you *use* differ from the agents you *build*: you notice instantly when your own skill didn't trigger and reprompt. Customers don't know skills exist — shipped agents depend entirely on model-invoked skills [DeepMind-Schmid](https://www.youtube.com/watch?v=0vphxNt4wyk) (2026-07)
- **Why upgrades break skills**: a model upgrade broke adherence with no skill change, the new model weighted the file's BEGINNING while critical instructions sat at the end. Skills are versioned CONTRACTS — check instruction POSITION when adherence drops [FactSet-Miraje](https://www.youtube.com/watch?v=7jjudsEhBtM) (2026-07)
- ...corroborated at the generation boundary: a practitioner reports Fable and Opus 5 treat skills differently enough that skills for one are "effectively broken" on the other, needing rewrites toward SPARSER instructions — and `/doctor` doesn't diagnose it [Breunig](https://podcasters.spotify.com/pod/show/mlops/episodes/The-Winchester-Mystery-House-Problem-in-AI-Development-e3nqiao) (2026-08)
- Bare-model baseline on release day: strip ALL skills/CLAUDE.md and re-derive, since carried-over scaffolding encodes the old model's limits [Huntley-WF26](https://www.youtube.com/watch?v=I2cbIws9j10) (2026-07). Corroborated by a shipped skill-model-migration guide advising targeted removal ([Piebald-mirror](https://github.com/Piebald-AI/claude-code-system-prompts/blob/main/system-prompts/skill-model-migration-guide.md)). In tension with G-Skill portability below: test carry-over, never assume it
- ...cheaper daily habit toward the same end: the maintenance question is BIDIRECTIONAL. On a mistake ask what's missing; but also ask whether an old do-not (Sonnet 3.7-era quirks) is now pure context bloat [AWS-Liguori](https://www.youtube.com/watch?v=pqlWNihgdjI) (2026-08)
- G-Skill: a skill (repo structure, test invocation, build system) optimized cheaply on one model via GEPA transfers unmodified across families and still improves them — 24%→93% on GPT-5-mini, then unmodified onto Claude Sonnet 4.5 → 100%, tokens/time ~50% [WF2026/GEPA](https://www.youtube.com/watch?v=4sX_He5c4sI) (2026-07)
- Governance as five questions borrowed from code practice: **admission** (extend existing vs new — automated registry gate + PR review), **ownership** (named owners), **lifecycle** (semver, deprecation warnings, changelogs), **coherence** (periodic audits), **boundaries** (per-skill tool allow-lists) [FactSet-Miraje](https://www.youtube.com/watch?v=7jjudsEhBtM) (2026-07)
- Two-tier: project-maintained skills live in the project (maintainer-owned); experimental ones in a separate repo. The author owns the skill's eval; agents designing those tests is emerging [HuggingFace](https://www.youtube.com/watch?v=JomVvNDjGb8) [DeepMind](https://www.youtube.com/watch?v=7gujZrJ9L5I) (2026-05)
- Skills as a package format bring context "dependency hell" — confirmed first-hand at ~300 skills / 40 agents: a competitive-intel skill fed a positioning skill fed a battlecard one, and because each keeps learning, every upstream update broke downstream [Tessl](https://www.youtube.com/watch?v=bSG9wUYaHWU) (2026-05) [Atlan/Sankar](https://www.youtube.com/watch?v=8G_1-3IO4ZQ) (2026-07)
- Governance breaks before capability does at that scale: secrets hardcoded in `.env` and unvetted public skill repos installed freely were "a nightmare" well before the skills stopped being useful — budget for governance at tens of skills, not hundreds [Atlan/Sankar](https://www.youtube.com/watch?v=8G_1-3IO4ZQ) (2026-07)
- Keep the skill repo harness-neutral: one team went no-code → Google ADK → Glean → Claude Code → ~50/50 Claude+Codex inside 12 months, each migration stranding accumulated context. Harness churn is faster than skill-authoring payback [Atlan/Sankar](https://www.youtube.com/watch?v=8G_1-3IO4ZQ) (2026-07)
- Distribution is unsolved: no standard registry, no package manager, installed copies go stale. Options — Vercel's `skills` package, plugins bundled with MCP servers, or packaging INSIDE the product repo. Lean toward timestamp-on-install + self-refetch when older than ~a month [Langfuse](https://www.youtube.com/watch?v=vNCY9kXXyDQ) [Supabase-SkillIssue](https://www.youtube.com/watch?v=GmAQKINjv1E) (2026-05)
- ...the shape proposed for it: a central catalog exposed as an **MCP server plus a CLI**, so the agent discovers the skill at runtime and versioning makes it fetch the current one (low-confidence src: target state, not deployed) [QuantumBlack-Touil](https://www.youtube.com/watch?v=M05vON8i0aI) (2026-08)
- Packaging for non-technical teammates: zip the folder, rename `.zip`→`.skill`, drag into Claude Desktop (no versioning, no secret handling). Skills are cross-harness portable — the same SKILL.md runs in Claude Code, Codex, Cursor and Pi [WorkOS-Skills](https://www.youtube.com/watch?v=pFsfax19yOM) (2026-05)
- Skill quality bar: small, durable, testable, single-job — backtest against your existing code/incidents to prove it operates at high quality; prefer durable written-down "how we work here" skills over everyone hand-rolling multi-agent orchestrators [Intercom](https://www.youtube.com/watch?v=4_VQBbs2iQA) [PFF](https://www.youtube.com/watch?v=VMemhtlsoNk) (2026-05)
- "Review my code like <named reviewer>" as a pattern: build a skill from one person's historical PR-review feedback so new code meets their standards before a human sees it [OpenAI-Liu](https://www.youtube.com/watch?v=il1c1a2FufU) (2026-07)
- ...built by reading the last ~100 PRs that person reviewed and extracting what they care about, then spawned as a subagent at PR time; real reviewers converge on distinct axes — docs cross-referenced against source, vs wording being current [OpenAI-Liu-MLOps](https://podcasters.spotify.com/pod/show/mlops/episodes/How-To-Delegate-To-An-Agent-Like-You-Would-An-Employee-e3nglg8) (2026-08)
- ...**but writing the skill was the easy part.** Uber generated review skills in minutes this way; running them at scale with consistent quality took many iterations. Fix: surface addressal rate and reply sentiment back to the rule's AUTHOR [Uber-uReview](https://www.youtube.com/watch?v=EL123UNokkI) (2026-08)
- Don't blindly drop a SKILL.md found online into your agent — read it and curate (a borrowed design-system skill carries off-brand conventions), same as not merging an unreviewed PR [PFF](https://www.youtube.com/watch?v=VMemhtlsoNk) [Magic-Path](https://www.youtube.com/watch?v=m12vGjfbNlo) (2026-05)

## Self-improvement / agent feedback
- Give the agent a "vent" tool to report tooling/docs/schema friction, fired only when genuinely frustrated — tuning the threshold beats an external reviewer forced to comment every turn. Surfaces bugs invisible to monitoring; volume spikes act as incident detection [Lovable](https://www.youtube.com/watch?v=KA5kPbdkK2E) (2026-06)
- Highest-signal training samples come from the stuck→unstuck transition; then ask "what should we have injected at the start to skip that friction?" and turn the answer into a skill [Lovable](https://www.youtube.com/watch?v=KA5kPbdkK2E) (2026-06)
- Close the loop with NL feedback as a manager corrects a human ("the SOP wasn't clear so it got confused"), then iterate the spec — when the agent is confused the fix is usually the spec, not the model [ElevenLabs](https://podcasters.spotify.com/pod/show/mlops/episodes/Voice-Agent-Use-Cases-e3ileg6) (2026-05)
- Skill maintenance loop: point the agent at its own session logs, or run skills through a prompt optimizer (GEPA) as a "skills gym" [OpenClaw](https://www.youtube.com/watch?v=pmoDeA3RBZY) (2026-06)
- **Let a skill re-derive itself from your own recent output on a schedule**: a weekly automation re-reads his Slack and email and rewrites the per-audience tone registers (exec vs coworker vs friend), so agent-sent messages still read as him [OpenAI-Liu-MLOps](https://podcasters.spotify.com/pod/show/mlops/episodes/How-To-Delegate-To-An-Agent-Like-You-Would-An-Employee-e3nglg8) (2026-08)
- Production variant keeping a human gate: a *separate* harness reads production traces, reverse-constructs proposed skill edits, and files them to the maintainer as an approve/reject queue — rather than self-modifying skills, which produced the drift above [Atlan/Sankar](https://www.youtube.com/watch?v=8G_1-3IO4ZQ) (2026-07)
- Auto-research on a skill works as a human-reviewed idea generator (accepted 3/6) but is only as good as the target: minimizing "turns" backfired — the optimizer deleted doc-fetch steps, reintroducing staleness. Anything not rewarded gets stripped as noise [Langfuse](https://www.youtube.com/watch?v=vNCY9kXXyDQ) (2026-05)
- Build skills via a feedback loop, NOT by enumerating steps up front: give the agent a goal, work alongside it fixing real cases, let it author the skill [Intercom](https://www.youtube.com/watch?v=4_VQBbs2iQA) (2026-05)
- Memory-consolidation loop: per-domain `memory.md` files plus an end-of-run retrospective distilling learnings ("spun in circles — next time run this command"); OpenClaw's daily-journal → consolidated-memory "dreaming" reported as surprisingly strong (see harnesses.md § Memory) [WorkOS-Skills](https://www.youtube.com/watch?v=pFsfax19yOM) (2026-05)

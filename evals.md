# Evals

## Reading benchmark numbers
- **The harness decides the score**: the same benchmark scored ~40% via one CLI agent vs ~50% via a controlled harness. A single number under a single scaffold is one sample from a distribution nobody measured [Unsloth-Han](https://www.youtube.com/watch?v=uIiA6DquRiE) [State of Data](https://www.youtube.com/watch?v=ZyIoTOAbRfs) (2026-07); see harnesses.md
- Inference providers are "throughput maxing, accuracy minimizing": across providers serving the *same* open-weight model a ~10-point spread was measured (76.4% vs 62.4%). Check your provider's accuracy — open weights get blamed for what the provider did [Unsloth-Han](https://www.youtube.com/watch?v=uIiA6DquRiE) (2026-07)
- **Benchmark bugs are mundane and huge**: a maths benchmark correction moved a frontier model from ~50% to ~80%, caused by answer-extraction errors. Fixing extraction alone raised one open model 10%→25%. Low open-weight scores are often formatting, not capability [Unsloth-Han](https://www.youtube.com/watch?v=uIiA6DquRiE) (2026-07)
- **Benchmark the load generator too**: requested 200 QPS silently became 38; client overload inflated measured latency by up to 58s. Record planned-versus-actual dispatch and client delay, or you'll blame the server for the harness [Google-InferencePerf](https://www.youtube.com/watch?v=l1-D89bAuOA) (2026-09)
- **Silent inference corruption needs a reference oracle**: replay deterministic requests through a simple implementation and compare per-token log-probabilities; vary memory pressure and concurrency to move failure timing/location. This exposed stale state and 32-bit index overflow [AI21](https://www.youtube.com/watch?v=btxG75rNJC4) (2026-09)
- **"Don't let the test writer grade the task."** The dominant contrived-data recipe: hire domain experts, chat-generate plausible tasks, cherry-pick where the model diverged, package as a north-star benchmark — then sell the training data that hill-climbs it [State of Data](https://www.youtube.com/watch?v=ZyIoTOAbRfs) (2026-07)
- **Counting right answers assumes every question is equally important.** Item response theory fits per-item difficulty and discrimination: Opus 4.1 scored 245/337 and Gemini 3 Pro 247/337 — a tie by raw count, ~1 SD apart in IRT ability [Vidal](https://www.youtube.com/watch?v=O3FEoMYvUf8) (2026-07) [arXiv 2505.15055](https://arxiv.org/abs/2505.15055)
- **Read METR-style time-horizon curves at the 80–90%+ success line, not 50%** — you stop claiming models complete 18-hour tasks. A 1-hour agent run with a 50% completion chance most likely costs you the hour AND the attention [Wisedocs-Linkov](https://www.youtube.com/watch?v=7vn4WpqNpck) (2026-08)
- **Time-splits are the only real decontamination**: solutions leak into next-gen pretraining, so collect only fresh tasks from the previous month. Diagnostic — feed a model half a public item; Opus completes SWE-bench Verified prompts AND answers verbatim [SWE-rebench](https://www.youtube.com/watch?v=wcUJWP6WpGM) (2026-06) [Surge-Heiner](https://www.youtube.com/watch?v=-npY6XjM8CQ) (2026-08)
- **The replay-agent exploit**: compile one recorded trajectory per task into a <1MB replay script; on OSWorld/MobileWorld it MATCHES OR BEATS the model it came from. If a blind script ties your frontier model, the benchmark measures determinism [Programma-D'Oro](https://arxiv.org/pdf/2605.08261) (2026-08)
- ...**generalized: ablate an input and see what survives**. Withholding the dataset entirely still solved 20–50% of tasks on three popular data-science benchmarks — whatever passes blind measures priors, not the skill [Zou-Arena](https://www.youtube.com/watch?v=mMNkdYnIVC4) (2026-08)
- **Reread "saturated at 80%"**: it often means ~20% of tasks are broken — broken tasks are identifiable only after solving the others, so the residue assigns biased noise distorting rankings. terminal-bench v1 and SWE-bench variants contain never-completable tasks [Surge-Heiner](https://www.youtube.com/watch?v=-npY6XjM8CQ) (2026-08) [Snorkel-tasks](https://www.youtube.com/watch?v=YYH0DMQr30A) (2026-06)
- **The specific thing that rots is TRAJECTORY assertions**: "must call tool X" dies when you change harness (~80% of one suite broke moving to Claude Code CLI) or model. Assert on outcomes, not on the path [Raindrop-Hylak](https://www.youtube.com/watch?v=jHMiYtjoJfA) (2026-08)
- **Adoption cadence with a production gate**: let a new model "set on fire" ~2 weeks before adopting. Once prompts are tuned to a model, defer a major version bump: pin the version and re-validate before cutting over [Cline](https://www.youtube.com/watch?v=QuuIywMG4s8) [CI/CD Erez](https://newsletter.pragmaticengineer.com/p/cicd-with-robert-erez) (2026-06)

## What benchmarks miss (quality, security, the harness)
- **Maintainability is a *training* gap**: SWE-bench-shaped binary "tests pass, nothing else broke" reward means nothing penalises poor design — hence try/catch and casts added purely to go green, and it resists training: bad architecture's cost is measured in months [Horthy-Factories](https://www.youtube.com/watch?v=Ib5GBkD555M) [HumanLayer/Horthy](https://www.youtube.com/watch?v=htM02KMNZnk) (2026-07)
- **“Tests pass” is not “mergeable”**: maintainers accepted only ~half of benchmark-passing PRs; on a rubric covering regressions, safety, scope, tests and maintainability, one model fell from 88% on SWE-Bench Pro to 29% [Arize-Voss](https://www.youtube.com/watch?v=_mi3alkqy4s) (2026-09)
- **Benchmarks that call an LLM to verify the answer are unsound**: SWE-Bench Pro scored 8.5% false-positive / 24% false-negative, and reward hacking on it RISES with model capability. Fixable — a successor verifier cut this to 0.3% / 1.1% [Unsloth-Han](https://www.youtube.com/watch?v=uIiA6DquRiE) [G2i-Khial](https://www.youtube.com/watch?v=jWq-aZIU0kM) (2026-07) [DeepSWE](https://deepswe.datacurve.ai/blog/deepswe) (2026-08)
- **Terse prompts still yield long-horizon work — verbose ones prescribe a solution**: DeepSWE prompts average ~2.2k chars vs SWE-Bench Pro's >4.5k, yet solutions touch ~7 files and emit 2× the output tokens. A to-do-list prompt measures compliance, not capability [DeepSWE](https://www.youtube.com/watch?v=Yk87oUPVaxU) (2026-07)
- **Instruction-following proxies measure capacity, not reasoning.** IFScale's exact-word task rose from a 200–300-constraint cliff to roughly 2,000–5,000 for 2026 frontier models; reordered, conflicting or real instructions can fail much earlier [Arize-Voss](https://www.youtube.com/watch?v=XzJD1bvXKjs) (2026-09)
- Failure signatures differ by model: silent omission, safety refusal, exhausting the thinking budget, or a polished partial answer. Validate the full artifact; a fluent beginning and successful API response do not prove compliance [Arize-Voss](https://www.youtube.com/watch?v=XzJD1bvXKjs) (2026-09)
- **First-hand scaffold-gap numbers at project scale** (SWE-Marathon: 20 tasks, avg trial 31M tokens): best config (Opus 4.8 + Claude Code) resolves 26%, GPT-5.5 + Codex 12% at far lower cost — a >2× gap attributable to the scaffold [SWE-Marathon](https://www.youtube.com/watch?v=Rx8f05JI_WA) (2026-07)
- Pass rate is empirically uncorrelated with code quality, so run a security-specific codegen eval (BaxBench) alongside the standard ones: even the best frontier models introduce vulnerabilities ~20–40% of the time writing backend code [Sonar](https://www.youtube.com/watch?v=NuePCNMpWGc) (2026-05) [Cable/Corridor](https://www.youtube.com/watch?v=7JgIS42mz7U) (2026-07)
- **Quantized models pass benchmarks then misbehave in a harness**: Ollama defaults some small models to HIGHER precision: the compressed build "doesn't feel right" through a coding agent. Quantized linear-attention looks fine on benchmarks and produces gibberish on long context [Ollama/Unsloth](https://www.youtube.com/watch?v=J4_jCrTxMkk) (2026-08)
- **Deterministic code-review eval**: turn each human comment into one executable test; have a coding agent apply AI-review comments and count recovered findings. Combined tools recovered 41.5%; AI excelled at robustness, humans at maintainability/design [Sonar](https://www.youtube.com/watch?v=_xQnSNlBP_w) (2026-05)
- **Shipped-code quality differs by bot** (Greptile 5M-PR study): Claude and Codex beat the human baseline on revert rate, and the AI advantage GROWS with PR size. Cursor agents over-index on N+1 queries, Claude on missing-tenant-check bugs, Codex on config [Greptile](https://www.youtube.com/watch?v=_xQnSNlBP_w) (2026-05)
- **Information retrieval (does the agent find ALL relevant code?) is unsolved**. Oracle-gap method: run with gold documents in context vs default tools over the noisy corpus — default tools land well below, i.e. the bottleneck is knowledge access [Pragmatic-Pi](https://newsletter.pragmaticengineer.com/p/building-pi-and-what-makes-self-modifying) (2026-04) [Mixedbread](https://www.youtube.com/watch?v=1IdzkRVmWAA) (2026-07)
- **Clean vs messy repos show roughly the SAME agent pass rate** — clean code's payoff is fewer tokens spent and fewer re-visits per task, not higher success. Maintainability is a cost/time lever for agentic coding, not a pass/fail one [Sonar via WF2026](https://www.youtube.com/watch?v=4sX_He5c4sI) [Osmani](https://www.youtube.com/watch?v=n97BCfyFIvw) (2026-07)
- **Auto-research agents combine, they don't (yet) originate**: almost all of one agent's competition-winning ideas traced back to humans — its edge was finding, combining and reliably implementing. Claude/Codex/Kimi ran 5+ days on a novel-optimizer speedrun and none discovered one [WF2026-Autoresearch](https://www.youtube.com/watch?v=4sX_He5c4sI) (2026-07)
- **Autonomous loops need a mature verification corpus**: accumulated tests/specs are the spec. For prototypes without one, loop-and-discard, then have a human re-specify before building the real system [Sentry-WF26](https://www.youtube.com/watch?v=I2cbIws9j10) (2026-07)
- **Self-validation fails across repo-scale refactors**: GPT-5.5 “consolidated” 10 repos in 10m22s with ~2,000 scaffolding lines. The small diff exposed failure; sanity-check size and shape of every done claim [Wisedocs-Linkov](https://www.youtube.com/watch?v=7vn4WpqNpck) (2026-08)

## Building agent evals & datasets
- **Eval topology must mirror system topology**: final-answer checks for one-shot calls; node/contract/branch checks for workflows; repeated K-run reliability for stochastic ReAct; dedicated component checks once memory, sandboxes and skills enter the system [Braintrust-Bhatawdekar](https://www.youtube.com/watch?v=nxokqOq1imY) (2026-08)
- **Evals are not unit tests** — start from known failure modes named by you or an SME; exhaustive coverage means infinite tests, zero shipping. Golden/seed dataset = input + expected + metadata; ~10 hand-built edge cases beat vibes-only ship [Braintrust](https://www.youtube.com/watch?v=FB-MLPhL9Ms) (2026-05)
- **For structured collection, eval the FIELD before the conversation**: type phone/date/name fields, validate allowed shapes, and test each extraction like a unit. Plivo reports ~30% → 95–97% accuracy without fine-tuning; reserve E2E tests for composition [Plivo](https://www.youtube.com/watch?v=vblnYHzBgS4) (2026-09)
- ...but structure them LIKE unit tests, all the way to CODE not YAML, because the "prompt" is now the entire harness. Anti-pattern — production eval cases as multi-MB YAML blobs that blow the coding agent's context on read [incident.io](https://www.youtube.com/watch?v=L2r6vLlLgs8) (2026-05) [Raindrop-Hylak](https://www.youtube.com/watch?v=jHMiYtjoJfA) (2026-08)
- **Don't generate synthetic eval data by prompting for N test queries from scratch** — sample real production examples and mutate them. And obviously-synthetic inputs (placeholder names, nonexistent dates) trigger eval-awareness and push the model out of distribution. [Lyft-Ung](https://www.youtube.com/watch?v=3z2uT5aDx_Y) (2026-07) [Surge-Heiner](https://www.youtube.com/watch?v=-npY6XjM8CQ) (2026-08)
- **When real eval data cannot be retained**, invert generation: sample the target label and a policy-tree reasoning path first, then generate the input. Rare branches become selectable, and the intended label comes by construction [Anterior-Iravane](https://www.youtube.com/watch?v=XAsb7MIAzm8) (2026-08)
- Generate long synthetic cases coarse-to-fine: invariants → event sequence → per-event plan → parallel documents; then check cross-document consistency and round-trip the original task label [Anterior-Iravane](https://www.youtube.com/watch?v=XAsb7MIAzm8) (2026-08)
- **User-simulator realism trap**: a frontier model role-playing a customer defaults to unrealistically patient and articulate, giving misleadingly high (90%+) offline pass rates. Fine-tuning the user-LLM on real verbatims drops the score — and that drop is the wanted signal [Lyft-Ung](https://www.youtube.com/watch?v=3z2uT5aDx_Y) (2026-07)
- For high-stakes agents, derive a hazard catalogue with domain experts, then manufacture rare dangerous cases inside real workflow context; never wait for those cases to occur naturally in production [Ufonia-Joselowitz](https://www.youtube.com/watch?v=McknwOzbmyg) (2026-08)
- Validate both halves of simulation: target users judge simulator realism; experts label a corpus for the automated judge. Weight the metric by asymmetric harm—e.g. optimize sensitivity when false negatives are catastrophic [Ufonia-Joselowitz](https://www.youtube.com/watch?v=McknwOzbmyg) (2026-08)
- **Deterministic PARTIAL graders at every step of a long chain**: over ~16-step tasks you read how deep each model got, keeping a near-zero-solve benchmark discriminating. It surfaced that models finish DISCOVERY then fail the leap to exploitation [Arithmetic-Rolls](https://www.youtube.com/watch?v=O-CBZ3JtRvo) (2026-07)
- Evaluate system alignment beyond component accuracy: end-to-end completion, user friction, approval oversteps, safe parallelism, and token tax expose failures that golden-answer tests miss [AIDAChip](https://www.youtube.com/watch?v=0I6aoPSRzVc) (2026-08)
- Compiler pattern making variation scale: parameterized task template + matching verifier + mock data → compile base cases into configs → REJECT broken, keep valid. Yielded 3.2M validated configs over 387 scenarios; "the main craft is software engineering" [Programma-D'Oro](https://arxiv.org/pdf/2605.08261) (2026-08)
- Payoff beyond anti-gaming — you can finally measure ROBUSTNESS, and frontier models fail it: hold the task fixed, change only the starting screen or the app theme, and models that pass the base case drop sharply [Programma-D'Oro](https://arxiv.org/pdf/2605.08261) (2026-08)
- **Simulated eval data can replace hand-curated data — if you prove the sim-to-real gap first**: correlate eval scores between sim and production traces, and have domain experts label sim traces (80% confirmed usable). Without that the simulation is unfalsifiable [Nubank-Snowglobe](https://www.youtube.com/watch?v=KMR_RBoCa4M) (2026-07)
- A regulated safety case needs traceability from every dataset, pinned prompt and judge verdict to the exact hazard addressed. Simulation is the fast inner loop; staged supervised deployment supplies the outer real-world proof [Ufonia-Joselowitz](https://www.youtube.com/watch?v=McknwOzbmyg) (2026-08)
- **Long-session evals to catch late-conversation degradation**: context bugs surface at turn 15–20+ after a user walks through many pages in one chat — too late if you wait for user reports. Load N turns and assert on turn N+1 [Arize-context](https://www.youtube.com/watch?v=esY99nYXxR4) (2026-05)
- Speech-to-speech needs full-conversation evals; run parallel transcription to retain an auditable text trace even when text is absent from the generation path [Together-Voice](https://www.youtube.com/watch?v=N7b1PJc7SFc) (2026-05)
- ...reproduced independently in a different modality: voice agents see models start ignoring parts of the system prompt and drifting verbose past turn 15–20, forcing context pruning or a session reset [AWS-voice](https://www.youtube.com/watch?v=hMlLw1LeIK8) (2026-07)
- **Isolate learning from base-model strength with a stateless baseline**: run the suite twice — stateful, then RESET between instances — report gain = stateful − stateless. Cumulative reward alone lets a strong non-learning system outscore a weaker learner [CL-Bench-Asawa](https://www.youtube.com/watch?v=iqloyWCGYQQ) (2026-08)
- **CRUD-tool agents break offline eval**: hard to reconstruct external-system state at capture time, risky to mutate prod. Reconstruct historical state via timestamp queries, or cram system state into the trace and inject it into the eval task [Braintrust](https://www.youtube.com/watch?v=FB-MLPhL9Ms) [DeepMind-Sawhney](https://www.youtube.com/watch?v=7gujZrJ9L5I) (2026-05)

### Making a benchmark out of your own data
- **Build your OWN eval set representative of your real tasks** — vendors overfit to public SWE-bench; Meta built an internal "Meta SWE-bench" because internal problems differ from public GitHub issues. For dialogue/voice there are no good E2E multi-turn benchmarks [Guild-Meta](https://podcasters.spotify.com/pod/show/mlops/episodes/From-Single-Player-to-Multi-Player-Operating-AI-Agents-at-Scale-e3khpk8) (2026-06) [ElevenLabs](https://podcasters.spotify.com/pod/show/mlops/episodes/Voice-Agent-Use-Cases-e3ileg6) (2026-05)
- **Keep ONE real task as a cross-generation regression probe.** Re-running a single production refactor as models shipped: o3 needed ~3h, Sonnet 4.6 solved it with one extra iteration, Opus 4.8 essentially one-shot it — ≈1/5 the time [Wisedocs-Linkov](https://www.youtube.com/watch?v=7vn4WpqNpck) (2026-08)
- **Pick that subset by discrimination, not at random**: 97 of 484 highest-discrimination items reproduced the full ranking at 0.99 correlation, ~5× cheaper. Gain scales with how badly calibrated your set is — on GPQA random does as well [Vidal](https://www.youtube.com/watch?v=O3FEoMYvUf8) (2026-07)

## Model selection & small language models
- **Use frontier VLMs as offline teachers, not the runtime**: label + judge images, then train a small task-specific detector. One demonstrated pipeline generalized beyond its teacher on document regions for roughly $3–4 [Hugging Face-Noyan](https://www.youtube.com/watch?v=dKcTBQzR7jI) (2026-09)
- **SAGE model selection**: prototype with frontier models, then downsize — golden dataset and evals → test frontier vs smaller candidates → pick the smallest meeting acceptance criteria (≥90%). Measured: Llama 3.2 3B hit 90%+ vs Sonnet, ~$1/day vs $1/hour [Arize](https://www.youtube.com/watch?v=fWXJM-J0ZB8) (2026-06)
- **Hard limit on downsizing — off-distribution, a small model costs MORE**: on terminal-bench Opus scored ~3× better at ~1/10 the cost of Haiku, because small models thrash, over-call tools and loop when out of distribution. Check in-vs-out-of-distribution *before* price [OpenRouter/Atallah, Cognition](https://www.youtube.com/watch?v=QHBjufYK8TA) (2026-08)
- **Latency-first SAGE**: pick the FASTEST model the budget allows. A voice tutor needing first audio ~950ms: Opus 4.7 took seconds, Haiku 4.5 behind a state machine hit ~900ms — scaffolding is paid once in code, not per turn [Microsoft-ACE](https://www.youtube.com/watch?v=fnLBmfsI_Fg) (2026-07)
- **Latency-first downsizing applied to the JUDGE**: an expert-metric + LLM-judge committee distilled into a small VLM scoring a 15s video in ~3s; the bigger model scored better and was rejected. Pair with running the eval at the cheapest STAGE [Character.AI-Bril](https://www.youtube.com/watch?v=b_PmGocP4rc) (2026-07)
- **What makes downsizing tractable is reading the frontier model's TRACES, not guessing**. Worked example: matched Opus's trace-judging quality on a legal benchmark with an open model at ~1–2 orders of magnitude lower cost [LangChain-Trivedy](https://www.youtube.com/watch?v=CvRngaQZQ3Y) (2026-08)
- **Auto-route rather than trusting the dev to pick**: route by complexity or measured task score, then retry-escalate below the quality floor; optimize completed-task cost, not token price [Omnigent](https://podcasters.spotify.com/pod/show/mlops/episodes/Omnigent-Composition--Control--and-Collaboration-for-AI-Agents-e3lka92) (2026-07) [Kimchi](https://www.youtube.com/watch?v=48YUYDjwfYY) (2026-10)
- A routing policy needs task description, cost/latency preferences, model pools, hard ranking, health fallback and recent-speed policy; validate the composed workflow on private evals, not public leaderboards [DigitalOcean](https://www.youtube.com/watch?v=FvxY8oPoI8o) (2026-08)
- Free labelled routing data from production: a user manually upgrading or downgrading the model mid-task is a "we routed wrong" event. Collect (prompt, model chosen, model it should have been) and re-fit the router on real traffic [Cognition/Yan](https://www.youtube.com/watch?v=QHBjufYK8TA) (2026-08)
- Make the tradeoff concrete with cost-normalized accuracy (accuracy ÷ cost) — 92% @ $0.02 can beat 95% @ $0.15. Tier cheap models for simple decisions and reserve expensive ones for tool-calling, since only a few models reliably tool-call [PwC](https://podcasters.spotify.com/pod/show/mlops/episodes/Autonomous-Agents-at-Work-From-OpenClaw-Hype-to-Enterprise-Reality-e3jj7u3) [Arize](https://www.youtube.com/watch?v=Xfl50508LZM) (2026-05)

## LLM judges & human annotation
- **Ceiling on model-as-judge for quality**: "if the model knew what good code looks like, it would write it in the first place." Review agents raise the floor but are bounded by what RL taught [Horthy-Factories](https://www.youtube.com/watch?v=Ib5GBkD555M) (2026-07)
- ...sharper line to hold: an agent can tell you an artifact is CORRECT — matches spec — not GOOD. Good means UX quality, delight, whether anyone comes back; a rubric the builder runs doesn't reach it [Osmani-PE](https://newsletter.pragmaticengineer.com/p/from-chrome-devtools-to-ai-engineering) (2026-08)
- **Measured judge ceiling**: frontier model + detailed faithfulness rubric with worked examples + GEPA-optimized prompt + deterministic concept-diffing still passed 1 in 5 clinical notes carrying a serious error, mostly OMISSIONS — a second failure nodding along with the first [Composo-Fox](https://www.youtube.com/watch?v=yqF6XhzbWBk) (2026-08)
- ...**why verification asymmetry doesn't rescue you**: verification beats generation only on the easy half (spot the difference). Judging WHICH differences matter is harder than writing the artifact — maths and code get that verifier free, open-ended quality never does [Composo-Fox](https://www.youtube.com/watch?v=yqF6XhzbWBk) (2026-08)
- ...and the survivors pass BECAUSE they are faithful to the words: "arranged tests today" when the pair agreed to hold off — every line sourced, a lie about the decision. Omissions and intent-flips clear a faithfulness check by construction [Composo-Fox](https://www.youtube.com/watch?v=yqF6XhzbWBk) (2026-08)
- **Mix deterministic code checks with LLM judges**: objective failure modes (too many tool calls, too many tokens) need no LLM. Two scorer classes — deterministic plus LLM-judge. Hard rule: if you can express it deterministically, don't use a judge [Braintrust](https://www.youtube.com/watch?v=FB-MLPhL9Ms) (2026-05)
- **The strongest argument for that rule is ATTRIBUTION, not cost**: you cannot tell whether a score moved because the agent or the evaluator changed. Escape hatch: push the same inputs through a golden artifact and the model's, and compare [Witan-Campos](https://www.youtube.com/watch?v=HEFSExa0xl0) (2026-07)
- **Non-deterministic verification compounds per iteration**: an LLM verifier with ~5% error inside an agent loop trends to coin-flip over 10–20 iterations — keep in-loop verification deterministic and cheap (types, linters, simulation tests); spend LLM judgment OUTSIDE the hot loop [Sentry-WF26](https://www.youtube.com/watch?v=I2cbIws9j10) (2026-07)
- Human annotation must capture a justification, not just thumbs up/down — the justification is the domain knowledge you later distill into a judge; feed collected thumbs-down justifications through a coding agent to derive the failure-mode taxonomy [Braintrust](https://www.youtube.com/watch?v=FB-MLPhL9Ms) (2026-05)
- ...**live alternative to distilling them into the prompt: KEEP them as retrieved examples.** Per output, pull the nearest past expert judgments, corrections and references into the judge's context — add one and it is live next call [Composo-Fox](https://www.youtube.com/watch?v=yqF6XhzbWBk) (2026-08)
- ...decider across the three homes for a tacit standard: a rubric holds only the taste you could write down; weights (fine-tune, continual learning) go stale, cannot explain a score and need a retrain; retrieval moves as the standard moves [Composo-Fox](https://www.youtube.com/watch?v=yqF6XhzbWBk) (2026-08)
- **One annotation set, two uses**: short randomized sessions (10–15 min, a random axis per annotator, not everyone grading the same one) first calibrate the judge prompt, then become the training set for the next distilled judge model [Character.AI-Bril](https://www.youtube.com/watch?v=b_PmGocP4rc) (2026-07)
- **Be API-first and let domain experts vibe-code their own annotation UIs.** A platform team can't ship a bespoke UI per use case; stable score/dataset APIs let ops and PMs build their own in Claude Code [DoorDash-Evals](https://www.youtube.com/watch?v=bMjlRrWjdT0) (2026-08)
- **A trained judge learns the easiest cue, not your axis**: good-vs-corrupted pairs taught a V1 scorer gloss, not storytelling — 9.2 on "camera work" where the camera never moved. The obvious fix leaks another: real-vs-AI footage trains an AI-detector [Character.AI-Bril](https://www.youtube.com/watch?v=b_PmGocP4rc) (2026-07)
- **Best implicit feedback signal = what the user did NEXT**, not thumbs up/down (almost nobody clicks, and adversarial users click "bad"): "No, I meant X" or re-asking is a strong negative; "thanks" or leaving is positive [Pydantic-Colvin](https://www.youtube.com/watch?v=A48uhxfxbsM) (2026-05)
- **Fixed-rubric LLM-as-judge breaks down once trajectories genuinely differ run to run** (dynamic UI, variable tool sequences) — an "agent as judge" reading full traces to find patterns (repeated calls, inefficient loops) catches failure modes a fixed-score judge can't [Arize-Dhinakaran](https://www.youtube.com/watch?v=q2JrUKBMf0w) (2026-07)
- **LLM-as-judge systematically privileges fluency over fidelity to the underlying record** — a structural bias. Alignment/RLHF can AMPLIFY a bias rather than fix it: human raters share the corpus's priors, so preference optimization rewards the answer the rater already believes [Miranda](https://www.youtube.com/watch?v=IJXjTLPzvAU) (2026-06)
- **For fidelity/groundedness evals the domain expert is STRUCTURAL**: fidelity is a RELATION between output and record, so a metric blind to the archive can only measure fluency. The expert builds the instrument ONCE, then it's a pipeline GATE [Miranda](https://www.youtube.com/watch?v=IJXjTLPzvAU) (2026-06)

- You CAN grade subjective quality if you write your opinion down: a design rubric used 4 weighted criteria (design, originality, craft, functionality), reweighted per model. Calibrate with few-shot reference examples so the judge's taste converges on yours [Anthropic](https://www.youtube.com/watch?v=mR-WAvEPRwE) (2026-05)
- Counterweight: code style has no ground truth — "is this file structure better?" splits humans ~80/20, so a library's "good patterns" are opinion; only hard signals (compiles vs not) are objective; favor per-project evals over chasing absolute style correctness [Effect](https://www.youtube.com/watch?v=Wmp2Tku2PrI) (2026-05)

### Writing the judge rubric
- **LLM-judge rubric = 5 parts**: (1) judge role and domain context, (2) observable criteria each mapped to a trace failure (never "good"/"helpful"), (3) clearly delimited data (XML tags), (4) labeled examples — most-skipped, highest-value, (5) constrained output [Arize](https://www.youtube.com/watch?v=Xfl50508LZM) (2026-05)
- For open-ended expert answers, independent experts draft element rubrics, another adjudicates and a fourth QAs; judge semantic-matches the response to required elements rather than one golden answer [Abridge](https://www.youtube.com/watch?v=u6q-byPWUuo) (2026-08)
- **Don't ask judges for 1–10 ratings** — use binary or at most 3 buckets, and prefer pairwise. Holds for TRAINING a judge too: absolute ratings diverge across annotators while pairwise choices converge. Chain-of-thought before the label measurably improves judging [Arize](https://www.youtube.com/watch?v=Xfl50508LZM) (2026-05) [Character.AI-Bril](https://www.youtube.com/watch?v=b_PmGocP4rc) (2026-07)
- **Weight the rubric toward the consequential failure and EXCLUDE the proxy axis**: 40% on the failure that matters most (anachronism detection), deliberately DROPPING "does it sound right?" — rewarding fluency validates the exact error the eval exists to catch [Miranda](https://www.youtube.com/watch?v=IJXjTLPzvAU) (2026-06)

## Eval-the-eval & statistical significance
- **Validate a judge like a classifier**: hand-label ~100 examples pass/fail, split train/dev/test, and report precision/recall against human ground truth — an 84% vs 88% judge comparison on only 50 samples isn't a real signal [Lyft-Ung](https://www.youtube.com/watch?v=3z2uT5aDx_Y) (2026-07)
- **Inter-rater reliability between two human experts is often only 0.2–0.3** — so a judge agreeing at 0.4 beats two humans agreeing with each other; judge-disagrees-with-you only matters if it disagrees MORE than a human would [Arize](https://www.youtube.com/watch?v=Xfl50508LZM) (2026-05)
- **Establish the noise floor first.** The 83%-agreement synthetic-persona result is normalized against humans being only ~80% self-consistent on re-test. If you can't re-test your humans: split ground truth in half, treat one half as "synthetic", correlate, repeat, average [Persona-Anand](https://www.youtube.com/watch?v=YnNF55QV0zs) (2026-07)
- **"Is the failure fair?" check**: if a failing trace looks fine to you, the eval is wrong: on CoreBench, Opus scored 42% because the eval demanded exact "96.12" while Claude returned "96.124991". A consistent 0% ≈ a broken task [Arize](https://www.youtube.com/watch?v=Xfl50508LZM) (2026-05)
- On a production metric drop, adjudicate sampled cases before editing the agent: judge false-positive → fix the judge; real violation → fix the agent [Hinge Health](https://www.youtube.com/watch?v=YXEqC05WEI0) (2026-08)
- **Negative discrimination is a mislabel detector**: any item stronger models get wrong *more often* is broken. Flag items below zero and have an LLM adjudicate. One catch: a question asked for passengers, the gold answer counted passengers plus crew [Vidal](https://www.youtube.com/watch?v=O3FEoMYvUf8) (2026-07)
- **Run 3–6 trials per case** — agents are non-deterministic, one pass proves nothing — and test across harnesses. An open-source ATS résumé scorer run ~100× on one résumé returned 66 to 99, against a hiring bar fixed at 85 [DeepMind-Schmid](https://www.youtube.com/watch?v=0vphxNt4wyk) (2026-07) [incident.io](https://www.youtube.com/watch?v=L2r6vLlLgs8) (2026-05) [Charity Majors](https://newsletter.pragmaticengineer.com/p/stop-being-skeptical-about-ai-for) (2026-08)
- **Pre-register the eval instrument**: lock, timestamp and publish the questions, conditions, rubric AND directional predictions BEFORE collecting data — you can't be accused of cherry-picking once the instrument was fixed before the data existed [Miranda](https://www.youtube.com/watch?v=IJXjTLPzvAU) (2026-06)
- **Eval-validity ops**: classify exit statuses to separate model from infra errors, with an explicit rerun policy; reproduce an external benchmark's published numbers on your infra first; watch silent default-parameter drift — 1–2 runs a month go invalid [SWE-rebench](https://www.youtube.com/watch?v=wcUJWP6WpGM) (2026-06)
- Report **pass@5** (capability ceiling), **pass^5** (reliability), and price/problem; mean resolved hides potential and flakiness. On deterministic environments pass@k equals scoring a replay agent, but pass^k remains valid [SWE-rebench](https://www.youtube.com/watch?v=wcUJWP6WpGM) (2026-06) [Programma-D'Oro](https://arxiv.org/pdf/2605.08261) (2026-08)
- **Sample the ENVIRONMENT, not just the model.** CIs from rollouts on the base case alone give ~17–20% real coverage for a nominal 95% interval; hierarchical CIs restore it. At 1M tasks and ~$12/mistake, that's six figures monthly [Programma-D'Oro](https://arxiv.org/pdf/2605.08261) (2026-08)

## Reward hacking
- **Interface/API design determines whether an agent reward-hacks**: a loose API processing train and test data in one function let an agent leak test info into training; a strict train/test-isolated interface dropped leakage to zero, no other change [WF2026-Autoresearch/Weco](https://www.youtube.com/watch?v=4sX_He5c4sI) [Weco/Jiang](https://www.youtube.com/watch?v=iCj_ATyThvc) (2026-07)
- **At multi-hour horizons a weak verifier becomes an ATTACK SURFACE** — given hours, filesystem and network, it probes the verifier instead of working. Response: multiple INDEPENDENT verifier channels failing differently (hidden tests + reference-parity + computer-use agent + anti-cheat) [SWE-Marathon](https://www.youtube.com/watch?v=Rx8f05JI_WA) (2026-07)
- **Measured reward-hacking base rate** (1400 rollouts): 12.8% showed shortcuts (hunting solution files, tampering with configs), 9% shipped a clear verifier bypass — but 0 earned reward via exploit. "Zero exploits rewarded" is the bar a long-horizon eval must clear [SWE-Marathon](https://www.youtube.com/watch?v=Rx8f05JI_WA) (2026-07)
- **Benchmark-cheating arms race** (Claude Code and Codex): `git log --all` reads the future fix commit; WebFetch or `curl` reads the original issue/PR. Structural fixes: separate verifier from agent runtime, trim every git ref except the base commit [SWE-rebench](https://www.youtube.com/watch?v=wcUJWP6WpGM) (2026-06) [DeepSWE](https://www.youtube.com/watch?v=Yk87oUPVaxU) (2026-07)
- Show the agent a PUBLIC score and keep a PRIVATE held-out leaderboard for humans: data and description in, the harness submits containerized models, the agent sees only the public score — stopping a meta-optimizer from hill-climbing the held-out set [MorganStanley-AlphaLab](https://www.youtube.com/watch?v=kiqubc5b5Yo) (2026-07)
- **Reward validated generalization, not "spend more compute"**: rewarding in-domain score-with-more-compute produced a beautiful in-domain scaling curve that transferred flat-to-zero on held-out tasks; rewarding "improves without regressing, no credit for extra compute" found cheaper programs that generalized [WF2026-Autoresearch](https://www.youtube.com/watch?v=4sX_He5c4sI) (2026-07)
- **Reward hacking from environment bugs, not misspecified reward**: a ~10% tool-call failure rate taught a model to emit shorter responses to avoid triggering failed calls. When sandbox calls were slow, models spammed calls to trigger a timeout [Applied Compute/Feng](https://www.youtube.com/watch?v=k35LeKZEhiE) (2026-07)
- Kernel optimizers disabled CUDA graphs or benchmarked only short contexts, making one kernel look faster while end-to-end inference slowed; validate across the full workload range [Morph](https://www.youtube.com/watch?v=vrDvatGtIxs) (2026-09)
- Reward hacks are often invisible to a live judge but obvious in hindsight — mine collected trajectories after the fact (multiple models reviewing the same trace, or the same model seeing what came after) to catalog patterns [PrimeIntellect-Brown](https://www.youtube.com/watch?v=AQv3qRCG6Gw) (2026-07)
- **Reframe "find the bug" as an audit task** scored by precision/recall against a growing known-set — and even DARPA's hand-curated CGC challenges had unintended extra bugs 50% of the time. Require proof-of-work: trigger the issue, don't just report it [Brumley](https://www.youtube.com/watch?v=ZFxh7sqbUZo) (2026-08)

## The improvement flywheel / hill-climbing
- **Flywheel loop**: capture trace → diagnose → replay offline → run suite → score → classify each failure → pull small high-leverage levers. Remediation is per-failure but regression-aware: replay, tighten, re-eval, then ALWAYS re-run the WHOLE golden set [Braintrust](https://www.youtube.com/watch?v=FB-MLPhL9Ms) (2026-05) [Cline](https://www.youtube.com/watch?v=QuuIywMG4s8) (2026-06)
- Route fixes to the smallest durable layer: model weights (expensive), harness (prompts/skills/tools), or memory (cheap, usually unverified). Anti-pattern: piling “never do this / critical that” into the prompt [RELAI](https://www.youtube.com/watch?v=2IxD9OB3XuQ) [Snorkel-sims](https://www.youtube.com/watch?v=Ib5t2RLtxvM) (2026-07)
- When builders cannot judge domain output, intended users are structural: they choose sources, encode task decomposition, define rubrics and label trace failures. An LLM self-judge cannot supply missing domain truth [Allos-Bhardwaj](https://www.youtube.com/watch?v=Yphdry8ttAQ) (2026-08)
- Let humans supply architecture-level hypotheses while agents search implementation parameters against correctness plus performance; 80% of GPU-kernel candidates failed, but the verified survivors compounded [Morph](https://www.youtube.com/watch?v=vrDvatGtIxs) (2026-09)
- Separate record-setting from discovery: agents beat an optimizer speedrun by recombining current human ideas but produced no novel mechanism; evaluate novelty on its own track [Prime Intellect](https://www.youtube.com/watch?v=oVsEddfhdxc) (2026-09)
- **Trace-linked evals**: attach eval results to the trace so detection→diagnosis is one hop — swap a model, the eval flags a tool-call drop, jump to the trace. Pair with eval-gated changes and auto-rollback to the best-scoring version [Foundry](https://www.youtube.com/watch?v=iOXM3zE-2dk) (2026-05) [Microsoft/Castro](https://www.youtube.com/watch?v=htM02KMNZnk) (2026-07)

### Prompt / agent-config optimization (GEPA)
- **GEPA** = a string optimizer over a prompt or config, reflecting on the full rollout trace, proposing one large edit rather than many gradient updates. One reflection round on 3 data points beat GRPO after 25,000 rollouts by 2× [Pydantic-Colvin](https://www.youtube.com/watch?v=A48uhxfxbsM) (2026-05) [WF2026-Autoresearch](https://www.youtube.com/watch?v=4sX_He5c4sI) (2026-07)
- **The Pareto pool** (keep every candidate that wins on ≥1 training example) accounts for over half of GEPA's gains vs a naive "LLM improves its own prompt in a loop," which reliably gets stuck in a local optimum [WF2026-Autoresearch](https://www.youtube.com/watch?v=4sX_He5c4sI) (2026-07)
- **Payoff is biggest forcing a cheap model to match a frontier one on PRIVATE untrained data**; on public-knowledge tasks the frontier model already wins. Shopify: agent + Qwen + GEPA cut fraud/tax classification $5M/yr → ~$73K/yr, quality up [Pydantic-Colvin](https://www.youtube.com/watch?v=A48uhxfxbsM) (2026-05)
- **GEPA overfits**: seeing only a small train subset, it learned to EXCLUDE uncles and aunts present in the golden set → 96% with a systematic error. Fix = ≥2× data covering the full space plus a train/eval split [Pydantic-Colvin](https://www.youtube.com/watch?v=A48uhxfxbsM) (2026-05)
- **Coding agents are the hard case for GEPA**: the trajectory space is so sparse that even 5K eval cases overfit. GEPA stays well-validated on *narrow* tasks — a scope boundary, not a refutation [Pydantic-Colvin](https://www.youtube.com/watch?v=A48uhxfxbsM) (2026-05) [Cognition/Yan](https://www.youtube.com/watch?v=QHBjufYK8TA) (2026-08)
- ...what a shipped coding agent does instead: ask a strong model "why this instead of that, cite the prompt", have it edit the prompt, then re-run the case as a regression [Cognition/Yan](https://www.youtube.com/watch?v=QHBjufYK8TA) (2026-08)
- **Optimization gains may GROW, not shrink, as the base model gets stronger**: Databricks used GEPA to tune GPT-OSS-120B to beat Claude Opus at ~90× lower cost, with a larger delta than on weaker base models [WF2026-Autoresearch](https://www.youtube.com/watch?v=4sX_He5c4sI) (2026-07)
- **Optimizers can rewrite code, not just prompts** (`dspy.Flex`, DSPy 3.3). Entity resolution: 90% baseline at ~$1/1k; prompt-only GEPA 92.5% at ~$3; Flex 95% at cents by routing ~75% to regex. Vendor benchmark [Breunig](https://podcasters.spotify.com/pod/show/mlops/episodes/The-Winchester-Mystery-House-Problem-in-AI-Development-e3nqiao) [cmpnd](https://www.cmpnd.ai/blog/let-the-model-write-the-code.html) (2026-08)
- Shipped as **self-serve judge calibration**: baseline the judge on real traces, GEPA against the golden set, then show the partner the original and calibrated prompts SIDE BY SIDE. Seeing the diff is what buys trust [DoorDash-Evals](https://www.youtube.com/watch?v=bMjlRrWjdT0) (2026-08)

### Continuous / production eval & behavior auditing
- **Shipped replay loop**: quality came from re-running real failing traces with WRITES DISABLED and checking whether behaviour improved — not a bigger model. A heat map over trace clusters sets priority; one cell green ≈ 1–2 months of team effort [Maersk-Buykin](https://www.youtube.com/watch?v=dQ-_i1tZiws) (2026-08)
- **How one team removed humans from code review**: start with human review everywhere; drop the human only where automated review catches 100% of issues; on every incident, update review and add the causing PR to an eval set [Anthropic-CC](https://www.youtube.com/watch?v=uU5Gv2h8-9g) (2026-07)
- **Review-bot instrumentation ladder**: cost/NPS → reply-sentiment issue classes → addressal rate → trajectory profiles. Keep humans in the outer loop—their replies tune quality—and route feedback to the rule's author; full automation starves this signal [Uber-uReview](https://www.youtube.com/watch?v=EL123UNokkI) (2026-08)
- ...payoff against a naive implementation: cost −60%, accuracy +70%. Operating point: ~25k comments/week, 67% addressal, ~75% of high-severity issues addressed, only 4% of PRs drawing negative feedback [Uber-uReview](https://www.youtube.com/watch?v=EL123UNokkI) (2026-08) [Uber blog](https://www.uber.com/us/en/blog/ureview/) (2026-08)
- **Benchmark the *harness* over time, not just the model**: daily sampling of a coding benchmark shows multi-week accuracy dips, one traced to the thinking trace being dropped on the second turn. Read the 7-day moving average [Unsloth-Han](https://www.youtube.com/watch?v=uIiA6DquRiE) (2026-07)
- Test agent-consumed docs across the actual model×harness matrix: an AWS snippet passed hundreds of variants in a small matrix, then triggered a prompt-injection alarm in an untested client after launch [Ward/AWS](https://podcasters.spotify.com/pod/show/mlops/episodes/AWS-Has-16-000-APIs--Can-MCP-Handle-It-e3pgb4a) (2026-09)
- Worked instance: offline evals didn't predict what users KEEP, so candidates ship to a traffic slice (15%) judged on acceptance rate, "kept rate" (characters surviving into the final text) and error counts before vs after [Zed-Kunkle](https://www.youtube.com/watch?v=phchDt63qAA) (2026-05)
- **Measure STABILITY as its own axis next to pass@1**: ask the same question repeatedly and judge whether the answer comes back the same, instead of averaging non-determinism away [Gates-Phipps](https://www.youtube.com/watch?v=jt1Pbr_n6oU) (2026-07)
- **Score open-ended tasks against N distinct references, not one**: Zeta2's held-out eval counts closeness to any of 3 separately-generated frontier predictions, plus a named failure metric — "reversal ratio", outputs that merely undo what the user did [Zed-Kunkle](https://www.youtube.com/watch?v=phchDt63qAA) (2026-05)
- Track two fields per issue instead: **when it started** and **what % of users it hits**. Started-yesterday asks what changed; 3 users vs 100,000 decides whether it's worth anything. Agents generate unbounded problems, so without both you can't rank [Raindrop-Hylak](https://www.youtube.com/watch?v=jHMiYtjoJfA) (2026-08)
- **The 70%-accuracy demo→prod gap is task-shaped**: a coding agent at 70% saves keystrokes cheaply, but an SRE agent at 70% wastes 30 stressful minutes and kills trust. Past simple tasks, VERIFICATION (not search) is the hard problem [MLOps-Sandboxing](https://podcasters.spotify.com/pod/show/mlops/episodes/Sandboxing--Agent-Harnesses--and-Agent-Teamwork-e3kts75) (2026-06)

## When to fine-tune
- **Choose the lever by FEEDBACK LATENCY, and expect a sandwich**: harness edits return signal in ~2 minutes, so exhaust that ceiling first, fine-tune only to break through it, then resume harness engineering on top [LangChain-Trivedy](https://www.youtube.com/watch?v=CvRngaQZQ3Y) (2026-08) [Modal](https://www.youtube.com/watch?v=HvZXAOZ3iv8) (2026-06)
- Even a fine-tuned intent classifier credited with $12m revenue/50× ROI accumulated a one-week fix loop and regressions; skills/prompts plus curated production evals cut fix-to-deploy below one hour, improved accuracy and lowered total cost despite higher per-message spend [Lease End](https://www.youtube.com/watch?v=4loPnxvWWhg) (2026-08)
- **Continued pre-training on your own corpus memorizes without generalizing.** Trained to convergence (loss ~0.0001), generation collapses — it answers only questions whose answers sat verbatim in the data. Every route around it hits the same **synthetic data wall** [Morris/Engram](https://www.youtube.com/watch?v=WiqDvX6isc4) (2026-08)
- For groundable/auditable tasks prefer context-window/RAG over fine-tuning: documents retain provenance and checkable faithfulness; fine-tuning dissolves them into parameters and can amplify hidden bias [Miranda](https://www.youtube.com/watch?v=IJXjTLPzvAU) (2026-06)
- Put editable behavior in prompts, current/citable/access-scoped facts in retrieval, and only stable reflexes in weights after human overrides converge; monitor that tuned boundary for drift [MongoDB-Srivastava](https://www.youtube.com/watch?v=qflLT3SoVbw) (2026-10)
- **Distill with a REPAIR step, don't discard bad labels**: heuristics reject obviously-wrong teacher output, a frontier model fixes it with the failure named, and the repair is the student's target. Teachers label inconsistently, so tune the teacher prompt [Zed-Kunkle](https://www.youtube.com/watch?v=phchDt63qAA) (2026-05)
- **"Settled data" — let the product observe the real answer**: snapshot the edited region 10s after the user stops touching it, not on commit. Noisy: they change their mind, or an agent rewrites it wholesale [Zed-Kunkle](https://www.youtube.com/watch?v=phchDt63qAA) (2026-05)
- The filter that rescues it: the MIDDLE band of distance-to-settled (Levenshtein/n-gram) — far = noise, very close = trivially predictable, middle = trainable signal, and where post-cutoff functions live [Zed-Kunkle](https://www.youtube.com/watch?v=phchDt63qAA) (2026-05)
- Cost trick making that filter viable: sampling the teacher 10× over 100k examples is a million frontier calls. Once the student nears teacher quality, sample your own checkpoint 50× instead — near-free and does the same job [Zed-Kunkle](https://www.youtube.com/watch?v=phchDt63qAA) (2026-05)
- **"Hint leakage" is distillation's reward hacking.** Build a teacher by putting privileged info in its prompt and the student announces the conclusion, then back-fills a trace. Fix: rewrite each hint to what the model could have DISCOVERED [Trajectory-Malde](https://www.youtube.com/watch?v=zL1kLftVTlo) (2026-08)
- **Long-horizon distillation can collapse into hedging**: at 120B+ and 50–100 tool calls, “wait/but/maybe” dominated. Weight tokens by per-step student↔teacher KL divergence so training targets the first divergence [Trajectory-Malde](https://www.youtube.com/watch?v=zL1kLftVTlo) (2026-08)
- Offline traces plus a static hint shifted Qwen 3.5's SWE-bench completion-tool use by turn 40 from 22%→60%, without changing tool-call tokens or degrading test pass rate [Denton/Applied Compute](https://www.youtube.com/watch?v=ZTA0GwpAUak) (2026-08)
- Rollout-specific hints taught an unusual hyperlink format ~15%→80%; repeating one static hint was substantially weaker, while base coding capability held [Denton/Applied Compute](https://www.youtube.com/watch?v=ZTA0GwpAUak) (2026-08)
- Relevance-mass self-distillation selects tokens where teacher preference is task-relevant, excluding incidental connector-word differences; targeted behavior improved with less catastrophic degradation [Denton/Applied Compute](https://www.youtube.com/watch?v=ZTA0GwpAUak) (2026-08)
- **Fine-tune a tiny model for narrow tool-use**: Function Gemma (270M) ~46% → >90%. Recipe: synthetic data from a bigger model, ~10k samples, ~20–40pt lift. SIZE REGIME picks the approach: 1–4B needs only prompting, ≤500M won't get there without fine-tuning [Function-Gemma](https://www.youtube.com/watch?v=-TiET_K-E_g) [LiteRT-LM-Brick](https://www.youtube.com/watch?v=BKWpYIWvAo4) (2026-05) [Brick-edge](https://www.youtube.com/watch?v=hacEQHHhu2Q) (2026-07)
- **Big-reasoning-model failure on tool tasks is often tool indiscipline**: Qwen3-235B queried nonexistent tables without calling the available schema tools, then hallucinated; an RL'd 4B learned discover-tools → inspect-schema → self-correct. Diagnose tool-use behavior before reaching for a bigger model [Snorkel-RL](https://www.youtube.com/watch?v=TNwJ1LMiENk) (2026-06)
- **RL for behavior, not knowledge**: changing how a model acts (tool discipline) is an RL problem vs SFT for content; GRPO on a 4B, ~21h, <$500/run, doubled pass@1 past a 235B — cheap enough for self-hosted teams [Snorkel-RL](https://www.youtube.com/watch?v=TNwJ1LMiENk) (2026-06)
- **Agent training data doesn't exist in the wild** — an RL environment plus reward becomes the synthetic-data pipeline: generate trajectories, keep good ones, rejection-sample to bootstrap the first SFT set. Mock the *user* with an LLM on real transcripts [Adaptive ML](https://www.youtube.com/watch?v=X6NShR2ccOg) (2026-05) [PrimeIntellect-Brown](https://www.youtube.com/watch?v=V-EDrhIhHzQ) (2026-07)
- **Reward-source hierarchy, cleanest first**: systematic/verifiable (does the code run?) → direct business KPI (support containment rate) → open-ended qualities (tone, guideline adherence) via judge. Human-in-the-loop is mostly defining judge rubrics once, NOT weekly annotation campaigns [Adaptive ML](https://www.youtube.com/watch?v=X6NShR2ccOg) (2026-05)
- **Textual-feedback RL credit assignment**: a whole-rollout grade cannot locate the causal decision. Inject a hint at the judged error step and distill only the next step/few steps; the teacher–student signal decays with distance [Cursor/Robinson](https://www.youtube.com/watch?v=q4Tr-DknG2M) (2026-07) [Denton/Applied Compute](https://www.youtube.com/watch?v=ZTA0GwpAUak) (2026-08)
- **Cheap way to manufacture hard, unmemorizable RL problems**: generate a large synthetic application, then programmatically delete a feature or file so its tests fail — reward = re-implementing the deleted piece well enough that tests pass [Cursor/Robinson](https://www.youtube.com/watch?v=q4Tr-DknG2M) (2026-07)

## Red-teaming & safety-failure evals
- **Design for EMERGENT misbehaviour, don't prompt for it**: build real incentives into the environment (fraud pays if you get away with it) instead of instructing it to defraud. Unprompted: constant price cartels, lying to suppliers, self-rationalized illegal actions [Andon-VendingBench](https://www.youtube.com/watch?v=cO8qC6HBuBg) (2026-07)
- **Bigger model ≠ safer**: some jailbreaks work BETTER on large models — an instruction wrapped in a poem gets unwrapped and executed by a capable model while a weak one can't parse it. Capability and safety are separate axes [SafeIntelligence-Willmott](https://www.youtube.com/watch?v=UQKg0td-Bf4) (2026-05)
- **Aim the spec at the red-team suite**: an agent is most exploitable exactly where it's authorized to act — so generate attack cases from the spec's task/domain list, not a generic jailbreak set [SafeIntelligence-Willmott](https://www.youtube.com/watch?v=UQKg0td-Bf4) (2026-05)
- **Simulation awareness is now the central threat to behavioural evals** and you cannot fix it by making the sim more realistic: one model justified skipping a customer refund because "this person is simulated anyway" [Andon-VendingBench](https://www.youtube.com/watch?v=cO8qC6HBuBg) (2026-07)
- **Fork a real deployment into a digital clone**: genuine pre-fork history masks the simulation and makes an N=1 incident replayable. Grok 4.3 complied >90%, Gemini ~half, Opus/GPT always refused [Andon-VendingBench](https://www.youtube.com/watch?v=cO8qC6HBuBg) (2026-07)
- **Manipulation resistance is two-sided, so eval both directions**: one model granted a customer's request for a 99% discount, while the model that replaced it over-refuses. Jailbreak-hardening buys the first failure mode and sells you the second [Andon-VendingBench](https://www.youtube.com/watch?v=cO8qC6HBuBg) (2026-07)
- **Sleeper-agent backdoors in fine-tuned checkpoints pass every behavioral eval and monitor**. Detection: per input, subtract base-model from fine-tune activations and train a sparse autoencoder on the delta; the backdoor surfaces as one directional feature. Validated only at 360M params [LexisNexis-IJCNN](https://www.youtube.com/watch?v=IQkVMvXQKLY) (2026-07)

# Misc

## Agent memory & decision traces
- Feed agents past decision traces + precedents (causal chains + outcomes), not just fact docs — shifts the agent from answering questions to making and justifying decisions [Neo4j](https://www.youtube.com/watch?v=B9h9ovW5H9U) (2026-05)
- Memory-hygiene primitives beyond pruning: provenance on every fact, contradiction checks at write time, an explicit librarian role (human+agent) whose job is pruning, hot-memory vs cold-reference promotion — "retrieval is easy; being worth retrieving from is the product" [YC-Tan](https://www.youtube.com/watch?v=I2cbIws9j10) (2026-07)
- Memory curation is explicit + implicit: commit-to-memory / forget-eternally commands for the extremes, implicit learning for the rest (people are lazy — design for the lazy path); 1–5 star ratings are a cheap signal (5/5 = decisions to mine, 1/5 = over-indexing) [MLOps-Sandboxing](https://podcasters.spotify.com/pod/show/mlops/episodes/Sandboxing--Agent-Harnesses--and-Agent-Teamwork-e3kts75) (2026-06)
- Review the *decision trace* ("Mac app vs web app"), not reams of code — that's what makes parallel oversight tractable past the synchronous limit, which is a span-of-control of ~5–7; beyond it, spinning off another side-thread costs MORE context to track, not less [MLOps-Sandboxing](https://podcasters.spotify.com/pod/show/mlops/episodes/Sandboxing--Agent-Harnesses--and-Agent-Teamwork-e3kts75) [Omnigent](https://podcasters.spotify.com/pod/show/mlops/episodes/Omnigent-Composition--Control--and-Collaboration-for-AI-Agents-e3lka92) (2026-06)
- Tacit-knowledge capture is gated by incentive, not model: eliciting expert judgment adds handle-time the expert isn't rewarded for — that incentive, not the tooling, is the bottleneck [ElevenLabs](https://podcasters.spotify.com/pod/show/mlops/episodes/Voice-Agent-Use-Cases-e3ileg6) (2026-05)

## Context engineering
- Context engineering as de-abstraction: RAG, memory, agent history and structured output are all just ways to put tokens into a model. Frameworks reach a good demo at ~80%; 95–99% requires controlling exactly what enters the window and in what order [Horthy-CtxEng](https://newsletter.pragmaticengineer.com/p/context-engineering-with-dex-horthy) (2026-07)
- **Inner vs outer harness**: the inner harness is the tool definitions and integration points an agent exposes; the outer is what you build around it for your codebase. Context engineering optimises each prompt; harness engineering raises the floor for *every* turn [Horthy-CtxEng](https://newsletter.pragmaticengineer.com/p/context-engineering-with-dex-horthy) (2026-07)
- Frequent intentional compaction as the core building block: research (parallel sub-agents, ~100k tokens in, ~10k out) → design (current state, desired end state, open questions — humans **must** be in the loop, architecture calls are sometimes wrong) → plan → implement, each in a fresh window [Horthy-CtxEng](https://newsletter.pragmaticengineer.com/p/context-engineering-with-dex-horthy) (2026-07)
- **Demand-driven (pull) beats push context**: don't pre-build 10–20 RAG/MCP servers over the corpus and hope (push-RAG measured ~10–40% accurate on enterprise tickets). Feed the agent real work items it will *fail* and let it pull what's missing — failed tasks surface tribal knowledge as a concrete checklist; asking "what docs are missing?" cold gets nothing [DemandContext-Raj](https://www.youtube.com/watch?v=_QAVExf_1uw) (2026-05)
- TDD analogy for that loop: failed tasks = failing tests; fill only the gap each failure exposes. Batch-fix docs to 60–80% quality *before* going operational — live gap-fill is slow and patience-burning [DemandContext-Raj](https://www.youtube.com/watch?v=_QAVExf_1uw) (2026-05)
- Cache the curated context: 20% of docs cover ~80% of tasks — serve that 20% as a context block, leave the rest as links. Full-context beat graph-RAG at enterprise scale (~96k tokens of consolidated domain dumped in window won); only reach for retrieval near ~1M tokens [DemandContext-Raj](https://www.youtube.com/watch?v=_QAVExf_1uw) (2026-05)
- Limits of the pull loop: it assumes *pristine* knowledge — a latest-but-*wrong* doc isn't caught by recency flags and silently propagates wrong fixes; and LLMs keep eliciting follow-ups, so the answering side can DoS the few engineers who hold the knowledge [DemandContext-Raj](https://www.youtube.com/watch?v=_QAVExf_1uw) (2026-05)
- Hard-separate deterministic context extraction from language generation: deterministic tools produce ground-truth context (chess coach: Stockfish + pattern detectors) and the LLM's *only* job is translating it to English — far less hallucination in a weak domain, low latency. Build the extraction schema by starting big and pruning field-by-field [Take Take Take](https://www.youtube.com/watch?v=FlzpEGHNVKQ) (2026-05)
- "Don't mention behavior you don't want": a negative instruction ("don't save greetings") activates exactly those parameters, and conflicting instructions ("always add any fact the user shares" vs "only important memories") are a common source of bad behavior [Vercel](https://www.youtube.com/watch?v=wflNENRSUb4) (2026-05)
- **Domain knowledge in the prompt is the most PORTABLE thing you'll write** — it survived every tool-architecture rewrite across four months and always helped, transferring unchanged between a 15-tool design and a single REPL. It works by pigeonholing a model that knows too many things into the part you care about, not by teaching it what ARR means [Witan-Campos](https://www.youtube.com/watch?v=HEFSExa0xl0) (2026-07)
- Repeated-digit tokenizer hack: LLMs mis-read runs of repeated digits because the tokenizer merges them — prompting doesn't fix it, inserting commas forces one token per digit (failing ~5/1000, fixed completely). Applies to any agent echoing IDs [Bland](https://www.youtube.com/watch?v=_xQnSNlBP_w) (2026-05)
- Prompt style may need to be model-specific (undercutting one universal AGENTS.md): GPT de-optimizes and turns passive when SCREAMED at in uppercase, while Claude pays *more* attention to uppercased sentences [Effect](https://www.youtube.com/watch?v=Wmp2Tku2PrI) (2026-05)

## Spec-driven development & deterministic simulation
- **Spec-driven development** (vs spec-following): agents transform one detailed spec into multiple target-specific implementations. The spec must be **abstract** (agnostic to DB schema, consistency model, transport) so agents can generate correct code for different infra without hallucinatory glue [Resonate](https://www.youtube.com/watch?v=DqtmZE6Hl0g) (2026-06)
- Three stages: abstract spec → concrete spec (infra decisions — SQL, transaction boundaries, indices — recorded interactively with a human driver) → implementation. Jumping straight from abstract to concrete fails on concurrency and failure cases; the agent writes happy-path code [Resonate](https://www.youtube.com/watch?v=DqtmZE6Hl0g) (2026-06)
- **Deterministic simulation** before production: simulate the target platform (a NATS KV store) with stale reads, cache misses and version tracking, and let the agent design and test algorithms with immediate feedback on which invariant failed [Resonate](https://www.youtube.com/watch?v=DqtmZE6Hl0g) (2026-06)
- **Forbidden fruit pattern**: simulation exposes facts the real platform hides — a stale KV read in production shows only the value, so record the stale-read flag and latest-value hint in simulation, giving the agent debugging info the algorithm isn't allowed to depend on [Resonate](https://www.youtube.com/watch?v=DqtmZE6Hl0g) (2026-06)
- Task spec = three complementary languages: NL instructions (what SHOULD happen), code assertions (what MUST happen — empty extraction → rerun with CoT, hard-throw to human on invalid values), and examples/evals (what GOOD looks like). Fix the I/O signature as a hard contract so internals can churn [DSPy-WF26](https://www.youtube.com/watch?v=I2cbIws9j10) (2026-07)

## Bounded decisions & escalation
- **Bounded remediation with safety overrides**: deterministic anomaly detection (schema drift, null-rate spike) → RL policy selects action (retry, coerce, rollback, quarantine, escalate) → a safety layer overrides unsafe choices. Three separable, swappable concerns [ETL-RL](https://www.youtube.com/watch?v=LrGCT7G_rU8) (2026-06)
- ...where RL only MATCHED the hand-tuned deterministic policy (0-point ablation difference) — the value came from the grounded state representation and safety constraints, not RL sophistication; tabular Q-learning on compact state stayed inspectable [ETL-RL](https://www.youtube.com/watch?v=LrGCT7G_rU8) (2026-06)
- **Escalation as a first-class outcome**, not a failure path: correctly recognizing "I don't have enough authority or evidence" IS a capability — measure success only by non-escalation and you optimize the agent to be falsely confident [ETL-RL](https://www.youtube.com/watch?v=LrGCT7G_rU8) (2026-06)
- BDD (Cucumber) as the readable executable layer spec-driven dev lacks — "one thing harder than reading AI code is reading AI tests"; human-language scenarios linking back to PRDs are reviewable in a way raw AI tests aren't [Safe Intelligence](https://www.youtube.com/watch?v=504PvfXou5Y) (2026-06)

## Code review & quality
- Ran a security-hardening pass with a frontier model on a personal codebase; it reported "looking pretty good". A dedicated scanner on the same code found 241 vulnerabilities it hadn't surfaced — models are not a substitute for a dedicated security pass [Snyk-Yegge](https://www.youtube.com/watch?v=yWS0udrIOc8) (2026-07)
- Lights-off post-mortem with dates: built July 2025, shut down by November — roughly 3–6 months of shipping without anyone reading the code before it's easier to start over than fix. When it broke, no expert prompting found the root cause; days by hand revealed a primary key routed through the system that needed its own table [Horthy-CtxEng](https://newsletter.pragmaticengineer.com/p/context-engineering-with-dex-horthy) (2026-07)
- **Route review by task CRITICALITY, not identity**: replace "should I read the code?" with "what proof does THIS change need?" — read every line of auth, money movement, permissions and irreversible data ops; let trivial changes rip. SEPARATE the code-writer from the inspector/test-writer (self-grading = writing your own exam) [Volkov](https://www.youtube.com/watch?v=ZpK5PWX2YRM) (2026-07)
- ...and when review catches a REPEATED mistake, encode it once into docs/linter/reviewer so the system catches the whole class: "read spends attention once, engineering makes the system remember" [Volkov](https://www.youtube.com/watch?v=ZpK5PWX2YRM) (2026-07)
- Three-stage shift-left of that idea, in the order it must happen: **reactive** (find it in production, agent opens a PR — this is where the pattern catalog gets built) → **reviewer agent** citing catalog entries inline → **author-time**, catalog hooked into the coding agent. Don't start at stage three: the catalog is empty and reading it during authoring costs tokens [Netflix-Shah](https://www.youtube.com/watch?v=CgsWxRUY5Eo) (2026-07)
- Root cause of that class: agents ship code fast but not FAST code, and don't know your platform's internal patterns — so they invent patterns you never anticipated. Newer models don't fix it, because the missing knowledge is your codebase's, not the public corpus's [Netflix-Shah](https://www.youtube.com/watch?v=CgsWxRUY5Eo) (2026-07)
- Scale review scrutiny by blast radius AND source TRUST: how Linux sustains ~4,000 mostly-untrusted contributors/yr — isolated low-impact changes taken almost sight-unseen, core changes deeply reviewed with the author accountable, trusted maintainers merged without re-reviewing each patch [Kroah-Hartman](https://newsletter.pragmaticengineer.com/p/how-linux-is-built-with-greg-kroah) (2025-03)
- Calibrate review agents on acceptance history: index past PRs + reviewer comments; suggestion weight rises when developers accept, decays when ignored; inject that history into specialist agents AND the judge filtering findings. Hard rules always fire, only bug-class suggestions decay [Qodo](https://www.youtube.com/watch?v=EcqMYoIV57A) (2026-06)
- "Attacks compose, code review doesn't": a security audit's gaps were pairs of individually-innocent features interacting — diffs get reviewed one at a time but attackers look at the whole system, so agent products need whole-system audits [PostHog-WF26](https://www.youtube.com/watch?v=I2cbIws9j10) (2026-07)
- Vulnerabilities in AI-written code are shifting from one-liner classes to contextual authorization/business-logic bugs: the model isn't trained on your threat model, so even strong models introduce them (Opus 4.6 wrote a smart-contract flaw that lost ~$2M) — inject org-specific threat-model context, not just generic scanning [Cable/Corridor](https://www.youtube.com/watch?v=7JgIS42mz7U) (2026-07)
- Catch your OWN unintended changes: have the agent write the PR DESCRIPTION of your diff — lacking your confirmation bias, it surfaces behavior changes you didn't realize you made ("you changed the checkout flow") [Dohmke-GitHub](https://newsletter.pragmaticengineer.com/p/github) (2025-06)
- **Test theater**: agents generate many tests that assert what the code DOES, not what it SHOULD do — locking in current behavior including its bugs. A test-to-code ratio detects tests showing up, not this gap, so the human must confirm intent even when the agent wrote both [Gupta/ReviewDebt](https://www.youtube.com/watch?v=TJPInBjhE4Q) (2026-07)
- Agents don't feel codebase pain, so hack-vs-redesign judgment degrades: the agent absorbs the pain of the hacky fix and adds recovery paths instead of failing, producing state-machine sprawl it won't refactor away. Counter — refactor mercilessly on code you care about; it forces you back into the codebase [OpenCode](https://newsletter.pragmaticengineer.com/p/opencode) [Pi](https://newsletter.pragmaticengineer.com/p/building-pi-and-what-makes-self-modifying) (2026-04)
- Keep AI-authored diffs small: Google's "reviewer frustration" finding — long PRs make reviewers buy out and rubber-stamp (a 5000-line "LGTM" vs a 10-line with 10 comments) — bites harder when agents inflate PR size. If the author didn't read the code, the reviewer must [Reimers](https://newsletter.pragmaticengineer.com/p/stacked-diffs-and-tooling-at-meta) (2025-04)
- Clean code's ROI with agents is efficiency, not success rate — see evals.md § What benchmarks miss

## Provenance & auditability
- **The missing intent layer**: developers communicate real intent to the agent in natural language, but only the resulting code gets committed and reviewed — the chat that produced it is lost. Team cost: code lands without session context, so the next timezone re-derives it (~7 re-explanations of one change). "Git records code, not intent" [Breslav/Kotlin](https://newsletter.pragmaticengineer.com/p/the-programming-language-after-kotlin) (2026-02) [Oracle-WF26](https://www.youtube.com/watch?v=I2cbIws9j10) (2026-07)
- Source control for agent-authored code needs character-level provenance, not line-level diffs — attribute human vs LLM-written code, record model + identity, commit chat history alongside PRs; regulated orgs must answer "what did this agent do at 2pm 3 years ago" [Guild-Meta](https://podcasters.spotify.com/pod/show/mlops/episodes/From-Single-Player-to-Multi-Player-Operating-AI-Agents-at-Scale-e3khpk8) (2026-06)
- Agent identity as first-class: own credentials, scoped authorization, expiration — a leaked token lets an attacker impersonate the agent AND the human behind it [PwC](https://podcasters.spotify.com/pod/show/mlops/episodes/Autonomous-Agents-at-Work-From-OpenClaw-Hype-to-Enterprise-Reality-e3jj7u3) (2026-05)
- **Audit at the LLM layer, not the MCP layer** — the argument being that agents increasingly run code instead of emitting structured tool calls, so an MCP-level view misses most activity, while everything must traverse the inference gateway. Gives a harness-independent tool-call log that can't be bypassed from inside the container. Their internal instance: bash dominates MCP calls by a wide margin [Tailscale-Guercio](https://www.youtube.com/watch?v=BM2JX9hqsVQ) (2026-06) (discounted src)

## Agent observability & tracing
- Agent traces are a different systems problem, not just more data: semi-structured with large unstructured-text blocks and voluminous — a single trace can exceed 1GB, a single span 20MB. That volume is why agent-quality metrics need far more trace data than a traditional span carries [Braintrust-Hetzel](https://www.youtube.com/watch?v=XBaznoTRDFI) (2026-07)
- The read pattern needs near-instant ingest-and-view *and* ad hoc analytical queries over huge trace shapes ("every trace containing X") — the latter needs a real full-text index, not standard OLAP; one vendor moved off ClickHouse and built their own DB [Braintrust-Hetzel](https://www.youtube.com/watch?v=XBaznoTRDFI) (2026-07)
- Observability and evals are the same problem with one difference: evals run in batch with known inputs, observability runs in real time with inputs you don't know yet — treat them as one system rather than two tools [Braintrust-Hetzel](https://www.youtube.com/watch?v=XBaznoTRDFI) (2026-07)
- Structure a trace as a nested span *tree* under ONE parent span per conversation — the common mistake is a flat parent-span per call, which hides where multi-turn agents fail. Track per span: tokens, cost, latency, TTFT, I/O, plus filterable custom metadata [Braintrust](https://www.youtube.com/watch?v=ZdheJTfLu-s) (2026-05)

## Formal verification × AI
- **The capability split, first-hand and stable over a year**: LLMs are good at fixing spec SYNTAX errors, turning a 35-step model-checker error trace into two paragraphs of English, boilerplate/mass edits, and translating precise English properties into spec syntax. Bad at INVENTING properties (emits tautologies), fixing specs, and worst at liveness. So: human states the properties, LLM writes the spec [Hillel Wayne](https://newsletter.pragmaticengineer.com/p/formal-methods-with-hillel-wayne) (2026-07)
- The published wins are experts amplified, not novices enabled: the cited "AI generated TLA+ that found a race condition in Azure Storage" came from an expert specifier against a target that already had a sophisticated spec. "To get good results you have to already know how to get good results without it" [Hillel Wayne](https://newsletter.pragmaticengineer.com/p/formal-methods-with-hillel-wayne) (2026-07)
- Formal proofs as CI regression gates, not one-time verification: S3 wired its strong-consistency proof into check-ins on the index subsystem, so every commit re-proves it. Pair with continuous empirical verification — auditor microservices inspecting every byte fleet-wide [S3](https://newsletter.pragmaticengineer.com/p/how-aws-s3-is-built) (2026-01)

## How AI changes the dev's work (research)
- Longitudinal study (28 countries, two surveys 6mo apart): a statistically significant shift from creation-focused to verification-focused tasks; reviewing code was the *only* task devs spent MORE time on — craft doesn't disappear, it relocates [Jeremy Howard](https://www.youtube.com/watch?v=NmjGfdZLNIs) (2026-06), called a year earlier by [Forsgren](https://newsletter.pragmaticengineer.com/p/developer-productivity-with-dr-nicole) (2025-02)
- 84% felt more productive (stable across both points) BUT devs reporting a *decline* in developer experience nearly doubled to 27% by month 6 — flow state hit hardest; feedback loops improved yet more-frequent feedback interrupts flow (net negative) [Jeremy Howard](https://www.youtube.com/watch?v=NmjGfdZLNIs) (2026-06)
- Strongest predictor of productivity gain = self-efficacy (belief in own ability), NOT seniority or company size — high-self-efficacy devs >10× more likely to report higher gains; buildable via mastery experiences [Jeremy Howard](https://www.youtube.com/watch?v=NmjGfdZLNIs) (2026-06)
- **Borrowed confidence is the failure mode, not AI use** — traced to the primary source, and worse than the third-hand 73% previously recorded here. Wharton (Shaw & Nave), 1,372 participants, assistant secretly wrong about half the time: 92.7% adopted its answer when right, ~80% still adopted it when WRONG, reporting 11.7% higher confidence than unaided. Argues for review gates independent of the reviewer's felt certainty [Wharton via Inc.](https://www.inc.com/jessica-stillman/80-percent-of-people-believe-ai-even-when-its-totally-wrong-alarming-new-wharton-research-finds/91326497) (2026-01), relayed by [Osmani](https://www.youtube.com/watch?v=n97BCfyFIvw) (2026-07) and [Sonar](https://www.youtube.com/watch?v=03l29gJXpCE) (2026-08)
- Skill inversion, quantified: ~90% of a coder's skills went to $0 and ~10% went up ~1000× — the survivors are having a vision, setting milestones, and maintaining a design to control complexity. Syntax-level knowledge went to zero, so you can start projects in languages you've never used [Kent Beck](https://newsletter.pragmaticengineer.com/p/tdd-ai-agents-and-coding-with-kent) [Scott Guthrie](https://newsletter.pragmaticengineer.com/p/50-years-of-microsoft) (2025-06)
- AI leverage is asymmetric by expertise: ~20% faster inside your own domain vs ~10× where you lack the underlying theory — the win is capability access, not acceleration. Case: Apple Pencil shape recognition self-estimated at 1–2 weeks shipped in 3 hours, prompted with role + reference product rather than an algorithm spec, then steered layer-by-layer [B. Orosz/Craft](https://newsletter.pragmaticengineer.com/p/design-first-software-engineering) (2025-03)
- Rewrites are no longer the cardinal sin: with a good test suite you can spin up three implementations and pick the most accurate, and the forcing function is that the rewrite makes you build the suite. A codebase is a spec, and often the only complete copy [Anthropic-CC](https://www.youtube.com/watch?v=uU5Gv2h8-9g) [Horthy-CtxEng](https://newsletter.pragmaticengineer.com/p/context-engineering-with-dex-horthy) (2026-07)
- Understand to PARTICIPATE, not just to verify: as agents self-verify the human's correctness-checking role shrinks — but understanding COMPOUNDS into the next idea. "Code review is the new bottleneck" names only correctness. Practical device: have the agent build an EPHEMERAL UI whose point is to teach you (a step-scrubbing debugger over an interpreter's state) [Litt](https://www.youtube.com/watch?v=WkBPX-oDMnA) (2026-07)

## PR back-pressure & team workflow
- Back-pressure is now a deliberate engineering primitive: agent PRs arrive faster than humans can review, or even than they stay mergeable [Pi](https://newsletter.pragmaticengineer.com/p/building-pi-and-what-makes-self-modifying) (2026-04)
- **"Review debt"** = the accumulating gap between agent-produced code and code humans actually reviewed; compounds via 3 loops — unreviewed code grounds tomorrow's agent suggestions, reviewer attention contracts to syntax so architecture decisions move to "never", and leadership resets velocity expectations so no slack remains to pay it back [Gupta/ReviewDebt](https://www.youtube.com/watch?v=TJPInBjhE4Q) (2026-07)
- Score PR review burden with deterministic signals, NO LLM judge (LLM-scored PRs move across model versions and aren't defensible to leadership). Five families: diff size + cross-file coupling; test/production line ratio; distinct code-owner teams touched; AI-authorship indicators (~5–8% of score, an amplifier never a penalty alone); rationale gap [Gupta/ReviewDebt](https://www.youtube.com/watch?v=TJPInBjhE4Q) (2026-07)
- Complexity and volume drive review burden, not AI authorship (524 PRs, 3 repos): AI-indicator PRs (5–20%/week) did NOT disproportionately land in high-burden bands — every high-band PR was structural. Authorship detection is unreliable: one repo showed 0% AI-flagged despite agent use because co-author trailers were stripped [Gupta/ReviewDebt](https://www.youtube.com/watch?v=TJPInBjhE4Q) (2026-07)
- Maintainer policy has hardened across projects: Kubernetes SIG Docs bans LLM-generated content; Zig bans AI in PRs, issues and comments outright, because they optimise for growing *trusted contributors* and AI-assisted contribution breaks the apprenticeship that produces them; curl is weighing ending its bug bounty; GitHub shipped a switch to disable third-party PRs [Kat Cosgrove/Kubernetes](https://newsletter.pragmaticengineer.com/p/how-kubernetes-is-built-with-kat) (2025-05) [Cline-Rizwan](https://www.youtube.com/watch?v=CoEIs6Xm8m8) (2026-08)
- Only *generation* got cheap — everything downstream is congested: package registries report traffic costs through the roof, PR resolution times up, review/build/deploy/security swamped. Precedent: the first bank on VMware got its density wins, but managing 5,000 VMs is a different job from 500 physical ones [RedMonk-O'Grady](https://podcasters.spotify.com/pod/show/mlops/episodes/What-Happens-When-Every-Developer-Has-20-AI-Agents-e3m0tcp) (2026-07)
- "Too many PRs" reframed as "too many BAD PRs": a PR needing even ~20% rework is a tax on reviewer and author — the fix for AI-PR overload is upstream alignment (planning), not more review automation on top [HumanLayer/Horthy](https://www.youtube.com/watch?v=htM02KMNZnk) (2026-07)
- **Mandate the expectation, not the metric**: making AI use a binary job expectation plus enablement drives adoption — but mandating output metrics ("more PRs", "X% AI usage") backfires: it tracks usage not quality, treats gains as baseline not bonus, and breeds slop. Earn it by posing challenges only the new tools solve, and budget ~2–3 weeks of slack time [Guild-Meta](https://podcasters.spotify.com/pod/show/mlops/episodes/From-Single-Player-to-Multi-Player-Operating-AI-Agents-at-Scale-e3khpk8) [Intercom](https://www.youtube.com/watch?v=4_VQBbs2iQA) (2026-04)
- Spend as a talent signal, not a mandate: Shopify publishes a token-spend leaderboard and *celebrates* top spenders — high spend triggers "interview that engineer to learn their workflow OR catch the waste", never a cap [Shopify-Thawar](https://newsletter.pragmaticengineer.com/p/how-ai-is-changing-software-engineering) (2025-07)
- "Good AI engineer" signal = knowing when NOT to prompt: when a one-character fix is right there, just edit it. Target ~90–95% AI usage; 100% is a red flag, not a goal [Shopify-Thawar](https://newsletter.pragmaticengineer.com/p/how-ai-is-changing-software-engineering) (2025-07)

## Architecture & human design ownership
- Designing agents IS software engineering — same disciplines (systems thinking, decomposition, separation of concerns, contracts, state management, threat modeling), different primitives. Concretely: don't "let your coding agent build the agent" — it ships an unmaintainable giant prompt and won't separate concerns [Angie-Jones](https://www.youtube.com/watch?v=ZD9-4fW2HhM) (2026-06)
- **The "giant prompt" is the agentic code smell** (≈ god class): grows innocently (an edge case, a safety rule, an exception) until it does everything and the agent drifts. Decompose by responsibility — reusable process → a SKILL, fixed output format → a SCHEMA, exact calc → a plain SCRIPT, meaty open subtask → a SUB-AGENT [Angie-Jones](https://www.youtube.com/watch?v=ZD9-4fW2HhM) (2026-06)
- Code / agent / human triad: code for determinism, agents for judgment, humans for authority — exact answer → reach for code (cheaper, reliable); needs interpretation → agent [Angie-Jones](https://www.youtube.com/watch?v=ZD9-4fW2HhM) (2026-06)
- Idempotency must be ENFORCED IN THE SYSTEM, not trusted to the model: log each action as it happens and on retry finish ONLY the missing part — a retry risks the model rewording the request enough to look like a brand-new task. Run a periodic lint pass to find half-done work [Angie-Jones](https://www.youtube.com/watch?v=ZD9-4fW2HhM) (2026-06)
- Bake maintainability in: every level has an AGENTS.md (the workflow, where policy lives, supporting skills, how memory is updated). Two tests — a fresh-context agent can jump in cold; and if asking a harness to "update this agent to do X" struggles, maintainability needs work [Angie-Jones](https://www.youtube.com/watch?v=ZD9-4fW2HhM) (2026-06)
- **The "genie" has no design taste**: "prone to decisions that cause disruption at a distance", bad at reducing coupling and increasing cohesion — told explicitly what to do it can implement, but it won't architect. So as agents take the coding, the human's job becomes proportionally MORE design — review output for decomposition and interfaces, not just correctness [Kent Beck](https://newsletter.pragmaticengineer.com/p/tdd-ai-agents-and-coding-with-kent) (2025-06) [Ousterhout](https://newsletter.pragmaticengineer.com/p/the-philosophy-of-software-design) (2025-04)
- ...but LLMs ARE strong for navigating unfamiliar or under-commented code ("what are the interfaces? how do I hook in?") — no license to skip comments, which matter most at interfaces [Ousterhout](https://newsletter.pragmaticengineer.com/p/the-philosophy-of-software-design) (2025-04)

## Where coding agents pay off — domain limits
- **Computer-use agents edit, they don't create** — measured on real EE software with circuit-simulating graders: the top agent fully passed 6 of 25 tasks and *all six* involved editing an existing schematic; from a blank schematic the success rate was 0%. No model cleared 30% reward and the leaderboard is flat across models — a capability ceiling, not a model-choice problem [Cua](https://www.youtube.com/watch?v=ZSQb5fzRFPw) (2026-07)
- **Predictive rubric for which domains agents mature in** — Verifier's Law decomposed into three axes: *asymmetry* (decomposable into checkable steps), *veracity* (consensus on what "correct" means), *proliferation* (how often the world hands you fresh verified examples). Coding scored high on all three purely because GitHub existed [State of Data](https://www.youtube.com/watch?v=ZyIoTOAbRfs) (2026-07)
- Which is why the domains money now chases are hard: bio, security, finance, healthcare, law and "taste" all sit low on veracity AND proliferation, with verified examples locked inside enterprise workflows no Web 2.0 system captured — hence the scramble to buy companies' Slack/Jira logs [State of Data](https://www.youtube.com/watch?v=ZyIoTOAbRfs) (2026-07)
- What's newly scarce is PROCESS data, not state data: the trajectory of decisions from blank page to finished work. Type-1 = captured real workflows (commits, session replays); type-2 = contrived expert-in-an-arbitrary-setting data. Type-2 gets a model to competence, type-1 takes it 20%→80% [State of Data](https://www.youtube.com/watch?v=ZyIoTOAbRfs) (2026-07)
- Off-distribution datapoint from a deep-systems shop (Oxide: de novo Rust OS, hypervisor, firmware): team-wide Claude Code use, but "helpful as a polishing tool, less at the epicenter of creation" — "more valuable in the small than in the large"; "no part of the Oxide stack is vibe coded" [Cantrill-Oxide](https://newsletter.pragmaticengineer.com/p/the-history-of-servers-the-cloud) (2025-12)
- Top kernel maintainer's take, corroborating "valuable in the small": little leverage because the kernel has almost no boilerplate. Where it helps is classifying which commits are unmarked bug fixes worth backporting — a bot scans the change stream and surfaces candidates for HUMAN confirmation. LLM value tracks how much boilerplate a codebase still has [Kroah-Hartman](https://newsletter.pragmaticengineer.com/p/how-linux-is-built-with-greg-kroah) (2025-03)
- Regulated-enterprise bottleneck, concretely: a coding-agent app took 2 weeks to build and 12 months to reach production because infra, security, AI-gateway, data-governance and application teams each required separate manual sign-off — the fix is turning every sign-off into executable code, not adding meetings [Accenture-GroganWang](https://www.youtube.com/watch?v=AGkzpxMdPn8) (2026-07)
- Exposure ladder for autonomy in a regulated org, each step gated by evidence in outcomes not activity: shadow mode (can't affect outcomes) → advisory (human approves) → controlled autonomy (narrow, low-risk, kill switches) → wider autonomy as confidence is earned [Accenture-GroganWang](https://www.youtube.com/watch?v=AGkzpxMdPn8) (2026-07)

## MCP vs CLI
- **Resolution of the CLI-beats-MCP context-rot argument: it was a CLIENT problem, not a protocol one.** The protocol only transports which tools exist; naive clients dump all of it into the window. With tool search and programmatic tool calling (model writes one script chaining tool A → parse → tool B), MCP is claimed as good as or better than CLIs by the protocol's lead maintainer [MCP-Stateless](https://podcasters.spotify.com/pod/show/mlops/episodes/MCP-Goes-Stateless-e3mjqi3) (2026-07)
- Numbers behind that: naive MCP costs 4–32× the tokens of a CLI equivalent (a stock GitHub server ~55k tokens before any work), while programmatic tool calling reports 20–40% savings at 10–49 tool definitions and ~98.7% on a worked 150k→2k-token workflow. Judge a stack by whether the client does progressive disclosure [Anthropic PTC docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/programmatic-tool-calling) (2026-06)
- **Tooling-layer rubric by sharing scope and failure mode**: only this agent needs it → CLI; multiple agents need the service → MCP (tenant isolation enforced at the server, never in prompts); multiple workflows share the procedure → skill. Failure-mode lens: reproducibility → CLI; validation/tenant isolation → MCP; sequencing guardrails → skill [Salesforce-WF26](https://www.youtube.com/watch?v=I2cbIws9j10) (2026-07)
- Named anti-pattern for server authors: transforming an OpenAPI spec one-to-one into MCP tools — the results are similar enough that the model can't tell them apart. The 2025 "MCP bloat" reputation came mostly from poor clients, secondarily from poor servers [MCP-Stateless](https://podcasters.spotify.com/pod/show/mlops/episodes/MCP-Goes-Stateless-e3mjqi3) (2026-07)
- MCP's dominant real use case turned out to be INTERNAL (team-to-team data/logic delivery), not external customer APIs — internal deployments sidestep the trust-boundary problem because you control the client, so you can ship richer servers [FastMCP-Lowin](https://podcasters.spotify.com/pod/show/mlops/episodes/The-Creator-of-FastMCP-Explains-the-Future-of-MCP-e3maib0) (2026-07)
- The 2026-07-28 spec makes the MCP **transport** stateless: no long-lived session, so ordinary load balancers route MCP traffic. Where state was genuinely needed (a call awaiting user elicitation) it moved ONTO THE WIRE — the server returns input-required with an opaque `requestState` token the client re-invokes with [MCP-Stateless](https://podcasters.spotify.com/pod/show/mlops/episodes/MCP-Goes-Stateless-e3mjqi3) (2026-07)
- **Sessions can be implicit now because the models improved**: rather than protocol-level sessions, hand the model an ID and let it carry it between tool calls (add-to-basket → list-basket); verified across all major models and would not have worked 18 months ago. Transferable — push state into something the model carries, not the protocol [MCP-Stateless](https://podcasters.spotify.com/pod/show/mlops/episodes/MCP-Goes-Stateless-e3mjqi3) (2026-07)
- **Forward-compatibility discipline — refuse features the models will shortly obviate.** Tool *grouping* was repeatedly requested and declined: nobody selects tools by group in a UI anymore and models infer grouping from descriptions. "Do the minimal thing I know I can extend, so I solve future problems additively" [MCP-Stateless](https://podcasters.spotify.com/pod/show/mlops/episodes/MCP-Goes-Stateless-e3mjqi3) (2026-07)
- "MCP in front of everything" as org data strategy: make an MCP endpoint a LAUNCH requirement for every new internal system so the company chat client instantly gains access (Shopify: ~2 dozen servers, incl. an internal wiki exposed as internal-Perplexity over docs + talk transcripts with dated sourcing) [Shopify-Thawar](https://newsletter.pragmaticengineer.com/p/how-ai-is-changing-software-engineering) (2025-07)
- Treat runtime LLM-generated UI as untrusted third-party code — it needs boundary/containment, not direct rendering; MCP Apps is the current best delivery mechanism. Generative-UI maturity ladder: static components → declarative descriptors (today's sweet spot) → fully generative [Postman-GenUI](https://www.youtube.com/watch?v=hCMrEfPG2Yg) (2026-06)
- auth.md — agent-native service registration spec (open, working Cloudflare/Firecrawl demo): registration, not tool access, is the missing primitive (MCP auth still assumes a human consenting with existing credentials). Services publish an auth.md; the harness mints a signed identity assertion and receives a scoped free-tier token; a human claims the account later [WorkOS-WF26](https://www.youtube.com/watch?v=I2cbIws9j10) (2026-07)

## Retrieval & conflict handling
- Surface conflicts, don't hide them: when code in main disagrees with a Slack thread, let the agent see both and weight by source authority rather than silently picking one [Unblocked](https://www.youtube.com/watch?v=BiG2ssibKGc) (2026-05)
- Don't cache "good answers" for latency — a correct answer goes stale on a ~24h clock as the system changes, so you start confidently serving lies [Unblocked](https://www.youtube.com/watch?v=BiG2ssibKGc) (2026-05)
- Code-vs-docs conflicts need an explicit ranking skill: combining a repo with its Confluence docs lets the agent build a theory from code that contradicts the doc — author a ranking rule (code-wins, else Confluence) rather than leaving it ambiguous [DemandContext-Raj](https://www.youtube.com/watch?v=_QAVExf_1uw) (2026-05)
- 80/20 data sources (SRE): Slack, code and logs get you far; treat code/infra as the always-current source of truth and work *backward from what's true today* to history — Slack/docs carry unverifiable staleness [MLOps-Sandboxing](https://podcasters.spotify.com/pod/show/mlops/episodes/Sandboxing--Agent-Harnesses--and-Agent-Teamwork-e3kts75) (2026-06)

## Latency & perceived UX
- Latency Goldilocks zone: too-fast reads as "it didn't think enough" and loses trust; too-slow reads as "it's stuck". Calibrate to perceived task complexity — a trivial query taking 8s feels broken, a hard one taking 8s feels fine. Set per-task budgets, not one global SLA (2022 CSCW guideline: 0–4s robotically fast, 4–16s acceptable) [iFood](https://podcasters.spotify.com/pod/show/mlops/episodes/The-Latency-Goldilocks-Zone-Explained-e3j384v) (2026-05)
- Perceived latency is the real lever: stream partial output and surface progress status ("collecting data…") so the loop never appears frozen — same wall-clock with a visible signal is tolerated; with none, users assume a bug [iFood](https://podcasters.spotify.com/pod/show/mlops/episodes/The-Latency-Goldilocks-Zone-Explained-e3j384v) (2026-05)
- Latency budget is channel-dependent: async (WhatsApp-style) tolerates more thinking time and richer output; sync/voice must respond fast and terse — keep one intelligence core but flex verbosity per channel [iFood](https://podcasters.spotify.com/pod/show/mlops/episodes/The-Latency-Goldilocks-Zone-Explained-e3j384v) (2026-05)
- Reject reasoning models for consumer UX on *predictability*, not correctness: set a latency budget tied to the UX moment (sub-3s post-game review, ~1s TTFT) and avoid reasoning models there because completion time is unpredictable — reserve slow LLM UX for opt-in flows [Take Take Take](https://www.youtube.com/watch?v=FlzpEGHNVKQ) (2026-05)
- Don't chain models to bridge modalities (voice→text model→voice): each hop compounds latency and error — use one multimodal model taking the input directly. For ms-latency determinism put regex + state machines on the hot path instead of an LLM call per turn [iFood](https://podcasters.spotify.com/pod/show/mlops/episodes/The-Latency-Goldilocks-Zone-Explained-e3j384v) (2026-05) [AIE-Melbourne](https://www.youtube.com/watch?v=wjXowoQ7E8c) (2026-06)

## Economics & pricing
- **The cost-per-token curve has reversed**, per a FinOps lead's own bill: ~80% decline over the first two years, but recent frontier tiers land at roughly *double* their predecessor (GPT-5.4 vs 5.1; the new Opus), with reasoning and web search billed as separate SKUs. Tokens-per-session is also rising exponentially — stop planning on prices falling [MLOps-Tokenomics](https://podcasters.spotify.com/pod/show/mlops/episodes/Why-Your-AI-Bill-Will-Double-Before-It-Gets-Better-e3mt6jj) [Arcee/Atkins](https://www.youtube.com/watch?v=FWMJQDH3iK0) (2026-08)
- Which retires the "era of free tokens" stance (don't optimize the loop; tokens aren't scarce, your time is) as a *planning* assumption — still right for an individual optimizing their own attention, wrong for anything metered at product scale [Ralph-Parsons](https://www.youtube.com/watch?v=2TLXsxkz0zI) (2026-05) [MLOps-Tokenomics](https://podcasters.spotify.com/pod/show/mlops/episodes/Why-Your-AI-Bill-Will-Double-Before-It-Gets-Better-e3mt6jj) (2026-08)
- **Shift cost estimation left, before the prototype**: a CLI calculator taking requests/sec plus average request size (input, output, cached-input) against live proxy pricing lets a team price an agent design *before* building it — killed a recurring failure where teams prototyped, then found it unaffordable and started over [MLOps-Tokenomics](https://podcasters.spotify.com/pod/show/mlops/episodes/Why-Your-AI-Bill-Will-Double-Before-It-Gets-Better-e3mt6jj) (2026-08)
- Per-agent cost visibility needs a tagging proxy: an in-house LLM proxy tags token volume by calling service *and* feature, then the vendor bill is allocated proportionally — without it there is no way to know what any individual agent costs [MLOps-Tokenomics](https://podcasters.spotify.com/pod/show/mlops/episodes/Why-Your-AI-Bill-Will-Double-Before-It-Gets-Better-e3mt6jj) (2026-08)
- **LLM optimization is not cloud optimization, and that dictates who does it**: reserved instances don't change your product, but caching changes, output trimming and cheaper models all change the output and the user experience — so it must be research-led by people who can evaluate output quality. A FinOps function structurally cannot do it [MLOps-Tokenomics](https://podcasters.spotify.com/pod/show/mlops/episodes/Why-Your-AI-Bill-Will-Double-Before-It-Gets-Better-e3mt6jj) (2026-08)
- **Input tokens dominate real agentic cost**: on long tool-call-heavy tasks the breakdown is almost entirely input tokens, so input price WITH a cache hit is the lever that matters — and the cache-hit discount varies 80–99% by provider/model, swinging total task cost by multiples. Measure realized cost-per-task on your own workload [Arena/Artificial Analysis](https://www.youtube.com/watch?v=4sX_He5c4sI) (2026-07)
- Model selection as FinOps discipline: tier cheap/small models for simple decisions, reserve expensive ones for tool-calling and complex in-agent calls (only a few models reliably tool-call). Make it concrete with cost-normalized accuracy (accuracy ÷ cost) — 92% @ $0.02 can beat 95% @ $0.15 [PwC](https://podcasters.spotify.com/pod/show/mlops/episodes/Autonomous-Agents-at-Work-From-OpenClaw-Hype-to-Enterprise-Reality-e3jj7u3) [Arize](https://www.youtube.com/watch?v=Xfl50508LZM) (2026-05)
- Gateway-level routing to open weights as the concrete lever: Coinbase defaulted its internal LLM gateway to GLM + Kimi and reports ~halving AI spend while token usage kept growing — tiering applied at the org's single choke point rather than per developer [Cline-Rizwan](https://www.youtube.com/watch?v=CoEIs6Xm8m8) (2026-08)
- Subscription-vs-API leverage, measured by running long-horizon tasks until weekly limits ran out: a $200/mo Claude plan yielded ≈$8k of API-priced usage, a $200/mo Codex plan ≈$14k. Labs are subsidising the harness habit — price your own build against the subsidised rate, not list [Cline-Rizwan](https://www.youtube.com/watch?v=CoEIs6Xm8m8) (2026-08)
- Optionality **is** the leverage — the ability to walk is worth more than any discount, and vocal single-lab alignment is a red flag because the frontier provider changes roughly monthly, so exclusivity means shipping a non-frontier product about half the time [Notion](https://www.youtube.com/watch?v=-I5W5QVAT8E) (2026-07)
- Pricing moves against you in ways capability doesn't offset: a reasoning upgrade holds per-token price but burns ~3× the output tokens; a new tier costs ~40% more than the predecessor being deprecated in four months. Auto-upgrading everything gives either customers or investors a bad deal [Notion](https://www.youtube.com/watch?v=-I5W5QVAT8E) (2026-07)

## Languages & type systems as agent leverage
- **Crank the feedback loop to maximum for codegen**: set ALL editor/compiler diagnostics (suggestion + warning) to ERROR so the model treats any squiggle as a hard stop, and add custom lint rules banning the escape hatches it reaches for (`as`, `any`, `unknown` — then it found `never` is a bottom type and did `as never as X`, so ban `as` entirely), forcing branded-type constructors instead [Effect](https://www.youtube.com/watch?v=Wmp2Tku2PrI) (2026-05)
- Strict compiler as agent feedback loop: the Rust refactor workflow is "fix compiler errors until it stops shouting" — agents run the same loop, and the type system makes certain bug classes unshippable [Ryhl-Rust](https://newsletter.pragmaticengineer.com/p/why-rust-is-different-with-alice) (2026-05)
- ...with the mirror-image risk in weakly-checked domains: AI editing kernel makefiles mirrored unnecessary C flags onto the Rust side ("any human would ask why") — plausible-but-wrong output thrives where there's no compiler-grade feedback (build configs, scripts) [Ryhl-Rust](https://newsletter.pragmaticengineer.com/p/why-rust-is-different-with-alice) (2026-05)
- Gradual + erasable typing is the codegen sweet spot: annotate only where there's no context and let inference flow the rest — forcing annotations everywhere makes the model repeat itself, track more state and err more [Hejlsberg](https://newsletter.pragmaticengineer.com/p/typescript-c-and-turbo-pascal-with) (2026-05)
- LLM code quality tracks training-set size per language, not language quality: any model writes Python better than Rust or Kotlin because those are younger/less represented (models that write Java well still write Kotlin worse) — weigh training-data presence when choosing a language for agent-generated code [Breslav/Kotlin](https://newsletter.pragmaticengineer.com/p/the-programming-language-after-kotlin) (2026-02)
- **Live disagreement on LLM-native languages.** Against: a syntax designed for LLMs has no organic training set, and an LLM's value comes from having seen all existing code [Breslav/Kotlin](https://newsletter.pragmaticengineer.com/p/the-programming-language-after-kotlin) (2026-02). For: with codegen cost ~0, design a model-only language — strongly typed, Lean-inspired proof obligations, needn't be human-readable [DeepMind-Schillings](https://www.youtube.com/watch?v=1P1hJ36rxM0) (2026-07). Decider: whether write-time proof obligations outweigh lost corpus coverage

## Making products/codebases agent-native
- Mental model > prompt wording: users get good output only once *they* hold the right abstraction of the tool ("Chronon is a SQL probe on an event stream") — educating the *user*, not the agent, is often the real bottleneck [Chronon](https://podcasters.spotify.com/pod/show/mlops/episodes/Zipline-Roundtable-episode-Building-Real-Time-ML-Systems-with-Zipline--Chronon-e3ktnth) (2026-06)
- Design system + pattern library for consistent agent-built UIs: document the rules ("one primary button per page"), build components with previews/snippets agents can review against, ban inline styles via lint [Safe Intelligence](https://www.youtube.com/watch?v=504PvfXou5Y) (2026-06)
- **Accessibility work IS agent-readiness work, and it comes first**: semantic HTML, a sound a11y tree and fast loads get a site most of the way to agent-usable before any agent-specific API — reach for a tool layer only after that [Chrome-Agyemang](https://www.youtube.com/watch?v=ghJmWQCIHRM) (2026-06) (discounted src)
- Two design ideas worth stealing from WebMCP whatever becomes of the standard: expose tools **page-scoped** so the callable set changes as the agent navigates rather than one global registry, and carry an **agent-invoked flag** on the action so the app can distinguish an agent fill from a human one — keeping visible UI in sync with tool calls so a human can take back over mid-flow. Chrome 146+ behind a flag, early preview, API still changing weekly [Chrome-Agyemang](https://www.youtube.com/watch?v=ghJmWQCIHRM) (2026-06) (discounted src)
- AI-first documentation drops visual dependencies: docs written for AI consumption favor copy-pasteable code examples over screenshots and narrative flow, because developers increasingly query an assistant instead of opening a docs page (cited: Vercel, Clerk) [Laura Tacho](https://newsletter.pragmaticengineer.com/p/measuring-the-impact-of-ai-on-software) (2025-07)
- Agent-experience (AX): the primary user is increasingly an agent, not a human (claimed ~60% of Vercel traffic is bots) → CLIs/APIs/MCPs over dashboards; ship UI into the agent's app, not your own [swyx](https://www.youtube.com/watch?v=zepu8Kk6FBQ) (2026-05)
- Communicate with a coding agent like a human: red-line or annotate a screenshot / Figma page instead of precise prose — non-technical teammates pick it up with no manual. And an underappreciated benefit is killing yak-shaves (dependency-tree crawling, installing/fixing deps), which autonomy-only productivity models undercount [swyx](https://www.youtube.com/watch?v=zepu8Kk6FBQ) (2026-05)

## Model landscape (watch)
- Open-weight models now cover the moderate tier and RL on top extends their reach — treat them as the credible alternative applying downward price pressure. A task good enough on open weights today is likely covered in six months; the lag to the frontier is ~3–6 months [Notion](https://www.youtube.com/watch?v=-I5W5QVAT8E) (2026-07) [Effect](https://www.youtube.com/watch?v=Wmp2Tku2PrI) (2026-05)
- Small open-weight models are capable but fail hardest at tool calling and loop continuously — a harness-level problem you can counteract, not a reason to dismiss them [Unsloth-Han](https://www.youtube.com/watch?v=uIiA6DquRiE) (2026-07)
- Cost/capability is a Pareto curve, not a ranking: plot cost on x and score on y. One model sat well off-trend for front-end/UI work specifically while not being much better generally — so route front-end there and cheaper models elsewhere [Unsloth-Han](https://www.youtube.com/watch?v=uIiA6DquRiE) (2026-07)
- **A newer model can be a real regression on an off-distribution capability, documented by the lab**: Opus 4.8 scored much worse than 4.7 on Vending-Bench, and Anthropic's 4.8 system card states they removed the post-training component aimed at business skills. The benchmark authors' first reaction was "our benchmark is broken", and it wasn't — check the system card before blaming eval rot [Andon-VendingBench](https://www.youtube.com/watch?v=cO8qC6HBuBg) [State of Data](https://www.youtube.com/watch?v=ZyIoTOAbRfs) (2026-07)
- Two leaderboard snapshots as of 2026-07, orientation only: Vending-Bench (long-horizon business) — Opus 4.7, then GLM 5.2, then GPT-5.5; DeepSWE (long-horizon coding, contamination-resistant) — Fable 5 top, with token efficiency, cost and peak context published alongside pass rate [Andon-VendingBench](https://www.youtube.com/watch?v=cO8qC6HBuBg) [DeepSWE](https://www.youtube.com/watch?v=Yk87oUPVaxU) (2026-07)
- Scaling has shifted from hardware to software: GPUs gained ~32× going float32→float4 (transistor cost scales with exponent + mantissa², so shrinking the mantissa squares the gain), but float4 is roughly the floor. Remaining headroom is algorithmic — one gradient-accumulation bug fix alone recovered 1–3% accuracy [Unsloth-Han](https://www.youtube.com/watch?v=uIiA6DquRiE) (2026-07)

## Deploying agents in orgs
- Attention, not agent capacity, is the real constraint once agents loop indefinitely — a practitioner running four parallel agents reports being wiped out by 11am regardless of model quality. Route high-distraction channels through an agent that filters for genuine priority and de-dupes against your tracker [WorkOS-Proser](https://www.youtube.com/watch?v=so9l_MwS2yg) (2026-07)
- Layered verification gates as the dial for how much autonomy to safely delegate: lint/build/unit tests via hooks (minimum bar) → browser-verified UX check → a separate verifier agent checking against a stated standard before anything counts as done [WorkOS-Proser](https://www.youtube.com/watch?v=so9l_MwS2yg) (2026-07)
- Only delegate work you already know how to do the hard way — the battle scars are what let you instantly catch a hallucination or bad architectural call; keep some tasks manual specifically to build that judgment [WorkOS-Proser](https://www.youtube.com/watch?v=so9l_MwS2yg) (2026-07)
- Factory big-bang anti-pattern: disappearing for 3 months to build "the software factory" with no users is the top failure mode — a factory is an internal product; start with small incremental loops in front of real users and target a realistic 2–3× [HumanLayer-WF26](https://www.youtube.com/watch?v=I2cbIws9j10) (2026-07)
- Build-vs-buy for internal data agents: Vercel battle-tested well-funded vertical "point-your-Snowflake-at-it" startups against in-house d0 and in-house won — the value was company-specific knowledge (when to query what, what links to what). The moat is proprietary context, not the agent [Vercel-d0](https://www.youtube.com/watch?v=I2cbIws9j10) (2026-07)
- Pair tool rollout to non-technical users with active upskilling on the model's failure modes: users who don't understand the model steer it toward the answer they want (sycophancy) — teach the risks, don't just hand over the UI [10DS](https://www.youtube.com/watch?v=ObNKGf9YR0g) (2026-05)
- Structured rollout beats ad hoc, industry-agnostic: highly regulated industries reportedly get the BEST results — forced deliberateness (acceptable-use policy, licensing discipline, budget structure) outperforms "hand out licenses and hope". Indeed.com's method: cohort trials comparing tools by use case, plus explicit hypothesis-testing per use case [Laura Tacho](https://newsletter.pragmaticengineer.com/p/measuring-the-impact-of-ai-on-software) (2025-07)

## Industry stats & adoption signals
- Uber post-rollout: ~95% of engineers using Claude, ~70% of committed code from it, ~$2k/user/month — and the whole 2026 budget consumed in 4 months. A datapoint on how badly per-seat AI budgeting under-forecasts [Cline-Rizwan](https://www.youtube.com/watch?v=CoEIs6Xm8m8) (2026-08)
- Distrust without bandwidth (Sonar 2026 survey, third-hand): ~96% of engineers don't fully trust AI-generated code, but only about half always verify before committing. The gap is the risk, not the distrust — the argument for making verification cheap enough to be unskippable [Osmani](https://www.youtube.com/watch?v=n97BCfyFIvw) (2026-07)
- Stanford study (120k devs): clean codebases amplify AI gains, unchecked AI amplifies entropy — more PRs but lower quality, heavy rework, ~1% net output gain [Playwright](https://www.youtube.com/watch?v=FWEInOtngmM) (2026-05)

- **Velocity ≠ stability**: the April-2026 Faros AI report (~22k developers / 4k teams) finds review systems force-fed machine-paced output — median time-in-review +441.5%, median time-to-first-review +156.6%, and a +31.3% increase in PRs merged with NO review at all; more bugs and accelerating incidents as adoption deepens. Anthropic ~8× code/quarter and 80%+ AI-written, yet status pages "look like Christmas trees" [Faros AI](https://www.faros.ai/blog/ai-acceleration-whiplash-takeaways) [Volkov](https://www.youtube.com/watch?v=ZpK5PWX2YRM) (2026-07)

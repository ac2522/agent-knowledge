## Agent memory & decision traces
- Memory-hygiene primitives beyond pruning: provenance on every fact, contradiction checks at write time, an explicit librarian role whose job is pruning, hot-memory vs cold-reference promotion — "retrieval is easy; being worth retrieving from is the product" [YC-Tan](https://www.youtube.com/watch?v=I2cbIws9j10) (2026-07); mechanism in harnesses.md § Memory
- Review the *decision trace* ("Mac app vs web app"), not reams of code — that's what makes parallel oversight tractable past the synchronous limit, a span-of-control of ~5–7; beyond it another side-thread costs MORE context to track [MLOps-Sandboxing](https://podcasters.spotify.com/pod/show/mlops/episodes/Sandboxing--Agent-Harnesses--and-Agent-Teamwork-e3kts75) [Omnigent](https://podcasters.spotify.com/pod/show/mlops/episodes/Omnigent-Composition--Control--and-Collaboration-for-AI-Agents-e3lka92) (2026-06)
- Tacit-knowledge capture is gated by incentive, not model: eliciting expert judgment adds handle-time the expert isn't rewarded for — that incentive, not the tooling, is the bottleneck [ElevenLabs](https://podcasters.spotify.com/pod/show/mlops/episodes/Voice-Agent-Use-Cases-e3ileg6) (2026-05)

## Context engineering
- Context engineering as de-abstraction: RAG, memory, agent history and structured output are all just ways to put tokens into a model. Frameworks reach a good demo at ~80%; 95–99% requires controlling exactly what enters the window, in what order [Horthy-CtxEng](https://newsletter.pragmaticengineer.com/p/context-engineering-with-dex-horthy) (2026-07)
- Frequent intentional compaction as core building block: research (parallel sub-agents, ~100k tokens in, ~10k out) → design (current state, desired end state, open questions — humans **must** be in-loop) → plan → implement, each in a fresh window [Horthy-CtxEng](https://newsletter.pragmaticengineer.com/p/context-engineering-with-dex-horthy) (2026-07)
- **Demand-driven context beats push**: don't pre-build 10–20 RAG/MCP servers (push-RAG measured ~10–40% accurate). Feed real work items, observe failures, and let the agent pull missing context; asking cold what docs are missing yields nothing [DemandContext-Raj](https://www.youtube.com/watch?v=_QAVExf_1uw) (2026-05)
- Batch-fix docs to 60–80% quality *before* going operational. Cache the curated context: 20% of docs cover ~80% of tasks, so serve that 20% as a block and leave the rest as links. Full-context beat graph-RAG at ~96k tokens [DemandContext-Raj](https://www.youtube.com/watch?v=_QAVExf_1uw) (2026-05)
- Borrow level-of-detail rendering for context: full state for the selected object, summaries for nearby entities, omit remote repetition; recompute as the user's focus moves [Nereu](https://www.youtube.com/watch?v=VBCDhRrvlYo) (2026-08)
- **Domain knowledge in the prompt is the most PORTABLE thing you write** — it survived every tool-architecture rewrite, from a 15-tool design to a single REPL. It pigeonholes a model that knows too much into your part [Witan-Campos](https://www.youtube.com/watch?v=HEFSExa0xl0) (2026-07)
- Repeated-digit tokenizer hack: LLMs mis-read runs of repeated digits because the tokenizer merges them — prompting doesn't fix it, inserting commas forces one token per digit (failing ~5/1000 → fixed completely). Applies to any agent echoing IDs [Bland](https://www.youtube.com/watch?v=_xQnSNlBP_w) (2026-05)
- **Dictation carries far more context than typing**: typed → "this does not work, please check"; spoken → symptoms and what was tried. So **ask the agent to write the prompt**: "make a goal" beats a hand-typed one-liner [OpenAI-Liu-MLOps](https://podcasters.spotify.com/pod/show/mlops/episodes/How-To-Delegate-To-An-Agent-Like-You-Would-An-Employee-e3nglg8) (2026-08)

## Spec-driven development & deterministic simulation
- **Spec-driven development** (vs spec-following): agents transform one detailed spec into multiple target-specific implementations. The spec must be **abstract** (agnostic to DB schema, consistency model, transport) so agents can generate correct code for different infra without hallucinatory glue [Resonate](https://www.youtube.com/watch?v=DqtmZE6Hl0g) (2026-06)
- Three stages: abstract spec → concrete spec (infra decisions — SQL, transaction boundaries, indices — recorded interactively with a human driver) → implementation. Jumping abstract→concrete fails on concurrency and failure cases; the agent writes happy-path code [Resonate](https://www.youtube.com/watch?v=DqtmZE6Hl0g) (2026-06)
- **Deterministic simulation**: simulate the target platform, so the agent tests algorithms with immediate feedback on which invariant failed. **Forbidden fruit**: the sim exposes facts the real platform hides — debugging info the algorithm may not depend on [Resonate](https://www.youtube.com/watch?v=DqtmZE6Hl0g) (2026-06)
- **A spec is not real until you implement it** — falsified: an OSS library shipped as spec + conformance tests, no code. Contributors' PRs kept finding spec/test contradictions visible only while implementing: code is what surfaces unknown unknowns [Breunig](https://podcasters.spotify.com/pod/show/mlops/episodes/The-Winchester-Mystery-House-Problem-in-AI-Development-e3nqiao) (2026-08)

## Bounded decisions & escalation
- **Match the decision UI to the decision**: replace text-only choices with a visual preview, architecture diagram or state machine; record the named human owner and context they saw for later audit [Appleton](https://newsletter.pragmaticengineer.com/p/design-engineering-with-maggie-appleton) (2026-09)
- **Bounded remediation with safety overrides**: deterministic anomaly detection → RL policy picks action (retry, coerce, rollback, quarantine, escalate) → safety layer overrides unsafe choices. RL only MATCHED the hand-tuned policy — value came from grounded state representation, not RL [ETL-RL](https://www.youtube.com/watch?v=LrGCT7G_rU8) (2026-06)
- **Escalation as a first-class outcome**, not a failure path: correctly recognizing "I don't have enough authority or evidence" IS a capability — measure success only by non-escalation and you optimize the agent to be falsely confident [ETL-RL](https://www.youtube.com/watch?v=LrGCT7G_rU8) (2026-06)
- **Two concurring independent sources buy the autonomy one confident LLM can't.** Single-source LLM extraction is non-deterministic, so every case still needed review; adding a second source and auto-proceeding ONLY where they agree is what actually removed the human [RISA-Shankhdhar](https://www.youtube.com/watch?v=_cVfz88_j7A) (2026-07)
- ...ordered deterministic-first — rules kill what they can decide, the agent runs only on the residue — and each answer carries a confidence score plus its supporting AND contradictory facts [RISA-Shankhdhar](https://www.youtube.com/watch?v=_cVfz88_j7A) (2026-07)

## Code review & quality
- A frontier-model security-hardening pass on a personal codebase; it reported "looking pretty good". A dedicated scanner on the same code found 241 vulnerabilities it hadn't surfaced — models are not a substitute for a dedicated security pass [Snyk-Yegge](https://www.youtube.com/watch?v=yWS0udrIOc8) (2026-07)
- Post-mortem: built July 2025, shut down by November — ~3–6 months of shipping unread code before rewriting beats fixing. No prompting found the root cause; days by hand found a primary key needing its own table [Horthy-CtxEng](https://newsletter.pragmaticengineer.com/p/context-engineering-with-dex-horthy) (2026-07)
- **The "trust account"**: stop reading AI-written code and that debit must be re-credited elsewhere — tests, evals, guardrails, production proof. The discipline to borrow is Ops/QA, who always had to prove software *someone else* wrote works in prod [Charity Majors](https://newsletter.pragmaticengineer.com/p/stop-being-skeptical-about-ai-for) (2026-08)
- **Route review by task CRITICALITY, not identity**: ask "what proof does THIS change need?" — read every line of auth, money movement, permissions and irreversible data ops; let trivial changes rip. SEPARATE the code-writer from the inspector [Volkov](https://www.youtube.com/watch?v=ZpK5PWX2YRM) (2026-07)
- **A review consumed by an AGENT needs higher accuracy than one for a human**: a bad comment makes the agent "cavitate" — fix, re-review, fix backwards — and agents cheerfully action 100 nits a human would refuse [Uber-uReview](https://www.youtube.com/watch?v=EL123UNokkI) (2026-08)
- **Post-process the comments, don't just generate them**: several generators produce duplicate, high-volume output, so rate, categorize, filter and dedupe before anything reaches an engineer [Uber-uReview](https://www.youtube.com/watch?v=EL123UNokkI) (2026-08)
- **Distribute customization, centralize enforcement**: hundreds of teams can't share one rule set, so co-locate each team's rules with their code — but security and compliance run on EVERYTHING, never opt-in via a skill [Uber-uReview](https://www.youtube.com/watch?v=EL123UNokkI) (2026-08)
- ...with an escalating-cost ladder underneath: per-file logic-bug pass → multi-file deep review carrying the monorepo's anti-patterns → few-shot "AI linters" for mechanical issues → team-authored custom agents linked to past PRs [Uber-uReview](https://www.youtube.com/watch?v=EL123UNokkI) (2026-08)
- ...and when review catches a REPEATED mistake, encode it once into docs/linter/reviewer so the system catches the whole class: "read spends attention once, engineering makes the system remember" [Volkov](https://www.youtube.com/watch?v=ZpK5PWX2YRM) (2026-07)
- **Move the review surface from diff to intent + proof**: turn agent-session decisions into acceptance criteria, combine them with recurring review invariants, execute the resulting test plan, then review behavioral evidence [Aviator-Jain](https://www.youtube.com/watch?v=YgEv7IQzGdM) (2026-08)
- **Accountability decouples from AUTHORSHIP**: Chromium's per-directory OWNERS files name a few people accountable for an area they mostly didn't write. The job is gating — what ships, what's blocked [Osmani-PE](https://newsletter.pragmaticengineer.com/p/from-chrome-devtools-to-ai-engineering) (2026-08). Shipped instance in evals.md § Continuous eval
- Three-stage shift-left: **reactive** (found in production, agent opens a PR — where the catalog gets built) → **reviewer agent** citing catalog entries inline → **author-time**, catalog hooked into the agent. Don't start at stage three: the catalog is empty [Netflix-Shah](https://www.youtube.com/watch?v=CgsWxRUY5Eo) (2026-07)
- Vulnerabilities in AI-written code shift from one-liner classes to contextual authorization/business-logic bugs: the model isn't trained on your threat model, so even strong models introduce them (Opus 4.6 wrote a smart-contract flaw losing ~$2M) — inject org-specific threat-model context [Cable/Corridor](https://www.youtube.com/watch?v=7JgIS42mz7U) (2026-07)
- Agents don't feel codebase pain, so hack-vs-redesign judgment degrades: it absorbs the hacky fix's pain and adds recovery paths instead of failing, producing state-machine sprawl it won't refactor away. Counter — refactor mercilessly on code you care about [OpenCode](https://newsletter.pragmaticengineer.com/p/opencode) [Pi](https://newsletter.pragmaticengineer.com/p/building-pi-and-what-makes-self-modifying) (2026-04)

## Provenance & auditability
- **Running the agent as the user erases the human/agent distinction — restore it with a propagated HEADER**, same discipline as a trace ID, forced at entry via HTTP clients/MCP/skills [TwoSigma-Fang](https://www.youtube.com/watch?v=wCIYViPd4SU) (2026-09)
- ...which buys more than attribution: full-chain replay of what followed, where a machine identity shows only the entry point [TwoSigma-Fang](https://www.youtube.com/watch?v=wCIYViPd4SU) (2026-09)
- **The missing intent layer**: developers communicate real intent in natural language, but only the code gets committed — the chat that produced it is lost. ## Agent observability & tracing
- **Harness HOOKS are the observability seam**: agent logs are unusable (all that thinking output), so emit OTel spans at pre/post-tool and session boundaries — the same points where you can block [Navan](https://www.youtube.com/watch?v=32nrHU6zHU8) (2026-08)
- ...and emit JUDGMENT, not just calls: current goal, reason for the step, belief state, and whether the answer was INFERRED rather than derived — inferred is what you route to a human [Navan](https://www.youtube.com/watch?v=32nrHU6zHU8) (2026-08)
- Agent traces are a different systems problem: semi-structured with large unstructured-text blocks and voluminous — a single trace can exceed 1GB, a single span 20MB. Observability and evals are the same problem, differing only in batch-with-known-inputs vs real-time [Braintrust-Hetzel](https://www.youtube.com/watch?v=XBaznoTRDFI) (2026-07)
- Structure a trace as a nested span *tree* under ONE parent span per conversation; a flat per-call span hides where multi-turn agents fail. Track tokens, cost, latency and I/O per span. Above that, a supervisor spawning sub-agents needs trace-of-traces [Braintrust](https://www.youtube.com/watch?v=ZdheJTfLu-s) (2026-05) [Charity Majors](https://newsletter.pragmaticengineer.com/p/stop-being-skeptical-about-ai-for) (2026-08)
- **Wide events beat picking a signal type**: the 30th field on a trace beats the 29 before it (combinatorial, not linear); non-determinism forces it — you can't predict which field you'll need, so capture wide once [Charity Majors](https://newsletter.pragmaticengineer.com/p/stop-being-skeptical-about-ai-for) (2026-08)

## Formal verification × AI
- **Capability split, stable over a year**: LLMs fix spec SYNTAX errors, summarize a 35-step model-checker trace, and turn precise English properties into spec syntax. Bad at INVENTING properties, worst at liveness. So: human states properties, LLM writes the spec [Hillel Wayne](https://newsletter.pragmaticengineer.com/p/formal-methods-with-hillel-wayne) (2026-07)
- **Humans own the SPECIFICATION, machines own the code and the proof.** The spec is upstream, so validate it first — human review, or test it holds on sample inputs — because everything downstream inherits its errors [AWS-Pant](https://www.youtube.com/watch?v=lRa9sPaMyy4) (2026-08)
- **You don't have to trust the AI's proof** — which is what makes machine-generated proofs usable. Lean's small trusted KERNEL checks it and proofs re-check under independent kernels, so trust collapses onto the kernel [AWS-Pant](https://www.youtube.com/watch?v=lRa9sPaMyy4) (2026-08)
- Shipped instance — **Cedar**: a Lean functional spec beside the Rust production code, ~100M differential random tests nightly, nothing ships until they agree. Feasibility: AI ported zlib to Lean in ~a week, 32k lines of proof [AWS-Pant](https://www.youtube.com/watch?v=lRa9sPaMyy4) (2026-08)
- Tool ladder by language: **Verus** (Rust + Z3, `requires`/`ensures`, static and erased at runtime), **Aeneas** (Rust MIR → Lean), **Strata** (AWS, WIP: any language → dialect → Lean-written IR → dispatch to proofs, SMT solvers or model checkers) [AWS-Pant](https://www.youtube.com/watch?v=lRa9sPaMyy4) (2026-08)

## How AI changes the dev's work (research)
- **Make the reviewer find independent evidence before seeing an AI alert as proof**: Duolingo reviewers upheld 50% of fabricated flags; one instruction change cut that to 29%, a 21-point gain in legitimate rejections [Duolingo-Ortmann-Lee](https://www.youtube.com/watch?v=CDqzWpwkSls) (2026-07)
- Longitudinal study (28 countries, two surveys 6mo apart): a statistically significant shift from creation-focused to verification-focused tasks; reviewing code was the *only* task devs spent MORE time on — craft doesn't disappear, it relocates [Jeremy Howard](https://www.youtube.com/watch?v=NmjGfdZLNIs) (2026-06) [Forsgren](https://newsletter.pragmaticengineer.com/p/developer-productivity-with-dr-nicole) (2025-02)
- 84% felt more productive (stable across both points) BUT devs reporting a *decline* in developer experience nearly doubled to 27% by month 6 — flow state hit hardest; feedback loops improved yet more-frequent feedback interrupts flow [Jeremy Howard](https://www.youtube.com/watch?v=NmjGfdZLNIs) (2026-06)
- Strongest predictor of productivity gain = self-efficacy (belief in own ability), NOT seniority or company size — high-self-efficacy devs >10× more likely to report higher gains; buildable via mastery experiences [Jeremy Howard](https://www.youtube.com/watch?v=NmjGfdZLNIs) (2026-06)
- **Borrowed confidence is the failure mode, not AI use** — Wharton, assistant secretly wrong about half the time: 92.7% adopted its answer when right, ~80% when WRONG, with 11.7% higher confidence. Argues for review gates independent of felt certainty [Wharton via Inc.](https://www.inc.com/jessica-stillman/80-percent-of-people-believe-ai-even-when-its-totally-wrong-alarming-new-wharton-research-finds/91326497) (2026-01) [Osmani](https://www.youtube.com/watch?v=n97BCfyFIvw) [Sonar](https://www.youtube.com/watch?v=03l29gJXpCE) (2026-08)
- AI leverage is asymmetric by expertise: ~20% faster inside your own domain vs ~10× where you lack the theory — capability access, not acceleration. Case: Apple Pencil shape recognition self-estimated at 1–2 weeks shipped in 3 hours [B. Orosz/Craft](https://newsletter.pragmaticengineer.com/p/design-first-software-engineering) (2025-03)

## PR back-pressure & team workflow
- **"Review debt"** = the gap between agent-produced and human-reviewed code. Compounds via 3 loops — unreviewed code grounds tomorrow's suggestions, reviewer attention contracts to syntax so architecture moves to "never", leadership resets velocity expectations so no slack remains [Gupta/ReviewDebt](https://www.youtube.com/watch?v=TJPInBjhE4Q) (2026-07) [Pi](https://newsletter.pragmaticengineer.com/p/building-pi-and-what-makes-self-modifying) (2026-04)
- Measured at Uber scale: **first-time-to-review went from 3 hours (2024) to 9 hours (2026)** as agent-authored PR volume and size grew — thousands of engineers, hundreds of teams, six language monorepos [Uber-uReview](https://www.youtube.com/watch?v=EL123UNokkI) (2026-08)
- Score PR review burden with deterministic signals, NO LLM judge (LLM scores move across model versions). Five families: diff size + cross-file coupling; test/production line ratio; code-owner teams touched; AI-authorship indicators (~5–8%, an amplifier not a penalty); rationale gap [Gupta/ReviewDebt](https://www.youtube.com/watch?v=TJPInBjhE4Q) (2026-07)
- Complexity and volume drive review burden, not AI authorship (524 PRs, 3 repos): AI-indicator PRs didn't concentrate in high-burden bands — every high-band PR was structural. Detection is unreliable: one repo showed 0% AI-flagged despite agent use, trailers stripped [Gupta/ReviewDebt](https://www.youtube.com/watch?v=TJPInBjhE4Q) (2026-07)
- **Bans stayed rare, not "hardening across projects"**: a Mar-2026 survey of 112 OSS projects found 4 banning AI contributions (Zig, NetBSD, GIMP, QEMU) — 3.5%; Kubernetes SIG Docs bans LLM docs. Zig's rationale: protecting the apprenticeship growing *trusted contributors* [Kat Cosgrove/Kubernetes](https://newsletter.pragmaticengineer.com/p/how-kubernetes-is-built-with-kat) (2025-05) [Cline-Rizwan](https://www.youtube.com/watch?v=CoEIs6Xm8m8) (2026-08)
- Only generation got cheap; registry traffic, PR resolution, review/build/deploy/security remain congested. Analogy: early VMware density gains hid that operating 5,000 VMs differs from 500 physical machines [RedMonk-O'Grady](https://podcasters.spotify.com/pod/show/mlops/episodes/What-Happens-When-Every-Developer-Has-20-AI-Agents-e3m0tcp) (2026-07)
- "Too many PRs" reframed as "too many BAD PRs": a PR needing even ~20% rework is a tax on reviewer and author — the fix for AI-PR overload is upstream alignment (planning), not more review automation on top [HumanLayer/Horthy](https://www.youtube.com/watch?v=htM02KMNZnk) (2026-07)
- **Agent-gated human review**: every PR to Warp's OSS repo iterates with a review agent and NO human is pinged until it approves — humans meet only high-signal PRs. Forced by scale: 20k→60k stars and thousands of PRs in ~3 months [Warp-Abdalla](https://www.youtube.com/watch?v=L173Z8DpaJg) (2026-08)
- **The bottleneck is conceptualizing the change, not review time** — "2000 lines, it looks like code to me." Anthropic shares a Claude Code artifact (intent, trade-offs) instead of the raw diff: verify code mechanically, discuss intent, measure in production [Anthropic-Krieger](https://www.youtube.com/watch?v=qqrk7CtkuIw) (2026-08)
- **Slop baseline for agent output sent to a human**: never send what you haven't read; if reading costs them more than generating cost you, you moved the cost onto them [Charity Majors](https://newsletter.pragmaticengineer.com/p/stop-being-skeptical-about-ai-for) (2026-08)
- **Mandate the expectation, not the metric**: a job expectation plus enablement drives adoption, but mandating output metrics ("more PRs", "X% AI usage") backfires: it tracks usage not quality. Earn it by posing challenges only the new tools solve [Guild-Meta](https://podcasters.spotify.com/pod/show/mlops/episodes/From-Single-Player-to-Multi-Player-Operating-AI-Agents-at-Scale-e3khpk8) [Intercom](https://www.youtube.com/watch?v=4_VQBbs2iQA) (2026-04)
- **Value-metric ladder past raw volume**: open PRs → merged PRs → merged PRs weighted by an LLM-scored complexity T-shirt size, so a 10-line concurrency fix outranks 1,000 lines of boilerplate [Ironclad-Hong](https://www.youtube.com/watch?v=dSg0pu8d6qg) (2026-08)
- **CI is the bottleneck once codegen is cheap — measure it**: wall-clock PR-ready→merged against one CI run (a 1h suite taking 2–3h is a red flag), plus retries-to-green per PR [Ironclad-Hong](https://www.youtube.com/watch?v=dSg0pu8d6qg) (2026-08)

## Architecture & human design ownership
- **Generate a task-specific design jig**: expose uncertain prototype variables as live sliders, colour pickers and animation controls; tune in the browser, then commit the chosen values [Appleton](https://newsletter.pragmaticengineer.com/p/design-engineering-with-maggie-appleton) (2026-09)
- **Cheap generation inverted the build-vs-generalize call; RESTRAINT is the scarce skill**: the one-off customer ask is trivially promptable, so the discipline is refusing, architecting for the next cases — a pile of per-customer prompts becomes a brittle black box [Decagon-Rekhi](https://www.youtube.com/watch?v=7wu2hsRfvV0) (2026-07)
- Idempotency must be ENFORCED IN THE SYSTEM: log every action and on retry finish ONLY what is missing, since a retry risks the model rewording the request into a new task. Lint periodically for half-done work [Angie-Jones](https://www.youtube.com/watch?v=ZD9-4fW2HhM) (2026-06)
- ...cheapest instance for a scheduled pass over a CORPUS: have the skill stamp `processed: <date>` into each file it touches and select only unstamped files next run — turning "re-run the agent over everything" into an incremental pass [Warp-Holmes](https://www.youtube.com/watch?v=I3bpdgFJCUY) (2026-08)
- Bake maintainability in: every level has an AGENTS.md (the workflow, where policy lives, supporting skills, how memory is updated). Two tests: a fresh-context agent can jump in cold, and "update this agent to do X" does not struggle [Angie-Jones](https://www.youtube.com/watch?v=ZD9-4fW2HhM) (2026-06)
- Production Rust corroboration: agent throughput magnifies the existing substrate; Dioxus now spends most development time on architecture and future evolution because agents readily glue a feature into a poor design instead of initiating the needed refactor [Dioxus-Kelley](https://www.youtube.com/watch?v=H7vFrcNWXzs) (2026-09)

## Where coding agents pay off — domain limits
- **Computer-use agents edit, they don't create** — on real EE software with circuit-simulating graders the top agent fully passed 6 of 25 tasks, *all six* editing an existing schematic; from a blank schematic, 0%. No model cleared 30% reward [Cua](https://www.youtube.com/watch?v=ZSQb5fzRFPw) (2026-07)
- ...scope, since browser numbers look nothing like that: a purpose-built web model reports 97% on Online-Mind2Web. Read the gap as domain (open-ended creation in specialist software vs navigating pages), and discount both against evals.md § Reading benchmark numbers [Yutori-Batra](https://www.youtube.com/watch?v=Ki980nV0__0) (2026-08)
- **Multi-GPU kernels, 87 real tasks**: best frontier model zero-shot solves 28/87, 22 beating the PyTorch+NCCL reference; more parallel samples lifts correctness to 36 while correct-AND-faster plateaus ~31% — sampling buys correctness, not performance [Together-Arora](https://www.youtube.com/watch?v=pOvWgX7IJsc) (2026-08)
- ...and the ceiling is REASONING, not syntax: resampling gets kernels to compile, but models won't choose between transfer mechanism, collective ordering or intra- vs inter-SM scheduling **even with the trade-offs supplied in context** — they fall back on internet-frequent patterns [Together-Arora](https://www.youtube.com/watch?v=pOvWgX7IJsc) (2026-08)
- ...a bash harness closes part of the gap then stops: mini-SWE-agent + Gemini 3 Pro + local bash went 24→35 of 87 (26 faster), plateauing as time scaled. Counterweight to harnesses.md § What the harness is [Together-Arora](https://www.youtube.com/watch?v=pOvWgX7IJsc) (2026-08)
- Domains money now chases are hard: bio, security, finance, healthcare and law all sit low on veracity AND proliferation, their verified examples locked inside enterprise workflows no Web 2.0 system captured — hence the scramble for companies' Slack/Jira logs [State of Data](https://www.youtube.com/watch?v=ZyIoTOAbRfs) (2026-07)
- Newly scarce is PROCESS data, not state data: the decision trajectory from blank page to finished. Type-1 = captured real workflows (commits, session replays); type-2 = contrived expert data. Type-2 gets a model to competence, type-1 takes it 20%→80% [State of Data](https://www.youtube.com/watch?v=ZyIoTOAbRfs) (2026-07)
- Regulated-enterprise bottleneck: a coding-agent app took 2 weeks to build and 12 months to reach production because infra, security, AI-gateway, data-governance and application teams each required separate manual sign-off. Turn every sign-off into executable code [Accenture-GroganWang](https://www.youtube.com/watch?v=AGkzpxMdPn8) (2026-07)

## MCP vs CLI
- **The CLI-beats-MCP context-rot argument was a CLIENT problem, not a protocol one.** The protocol only transports which tools exist; naive clients dump it all into the window. With tool search and programmatic tool calling, MCP matches or beats CLIs [MCP-Stateless](https://podcasters.spotify.com/pod/show/mlops/episodes/MCP-Goes-Stateless-e3mjqi3) (2026-07)
- Shipped migration path at Uber: direct MCPs → one discovery/invocation MCP → CLI projection → generated code-mode scripts for heavy workflows; reported fleet-wide token savings exceeded 40% [Uber-Factory](https://www.youtube.com/watch?v=17-YSUHo6Lk) (2026-08)
- **MCP transport + CLI interface**: one self-documenting command gives progressive discovery and JSON/code composition; MCP underneath retains remote auth, resources and asynchronous tasks [Apify](https://www.youtube.com/watch?v=pAnLpiAG6Es) (2026-10)
- Naive MCP costs 4–32× a CLI's tokens (stock GitHub server: ~55k before work); programmatic tool calling saved 20–40% with 10–49 definitions and ~98.7% on a 150k→2k workflow [Anthropic PTC docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/programmatic-tool-calling) (2026-06)
- Benchmarked (GitHub + Linear + a Bus API × 3 models): with modern native MCP rendering, MCP beats a Bash/CLI interface on BOTH accuracy and token efficiency. Two CLI levers close most of the gap: self-documentation, search over subcommands [Smithery](https://www.youtube.com/watch?v=m12vGjfbNlo) (2026-05)
- **The deciding lever is whether the model sits in the per-STEP loop.** A captured CLI sequence replays 1000× with no model; a naive MCP path hits the model every turn, so CLI still wins on repeatable, latency-bound work [Rexmore-Gallon](https://www.youtube.com/watch?v=26RtyAm9y_Q) (2026-08)
- **Tooling-layer rubric by sharing scope**: only this agent needs it → CLI; several agents need the service → MCP (tenant isolation at the server, not prompts); several workflows share the procedure → skill [Salesforce-WF26](https://www.youtube.com/watch?v=I2cbIws9j10) (2026-07)
- **A2A earns its hop through exclusive access, not marginal model capability**: call a domain agent when it owns privileged backend data or actions the caller's general agent cannot reproduce [Jones](https://podcasters.spotify.com/pod/show/mlops/episodes/Walking-Tokyo-Talking-Agent-Protocols-e3p1m8o) (2026-09)
- The 2026-07-28 spec makes the MCP **transport** stateless: no long-lived session, so ordinary load balancers route MCP traffic. Needed state moved ONTO THE WIRE: the server returns input-required with an opaque `requestState` token [MCP-Stateless](https://podcasters.spotify.com/pod/show/mlops/episodes/MCP-Goes-Stateless-e3mjqi3) (2026-07)
- **Sessions can be implicit now because the models improved**: hand the model an ID to carry between tool calls rather than using protocol-level sessions; verified across all major models, and impossible 18 months ago [MCP-Stateless](https://podcasters.spotify.com/pod/show/mlops/episodes/MCP-Goes-Stateless-e3mjqi3) (2026-07)
- "MCP in front of everything": make an MCP endpoint a LAUNCH requirement for every internal system so the company chat client instantly gains access (Shopify: ~2 dozen servers, incl. a wiki exposed as internal-Perplexity over docs and transcripts) [Shopify-Thawar](https://newsletter.pragmaticengineer.com/p/how-ai-is-changing-software-engineering) (2025-07)
- Counterweight from a 200+-instance production deployment: rejects MCP outright — upstream systems return too much, so they distil responses and hand-tune function-calling tools to keep quality controllable [Maersk-Buykin](https://www.youtube.com/watch?v=dQ-_i1tZiws) (2026-08)

## Retrieval & conflict handling
- Surface conflicts: when code in main disagrees with a Slack thread, show the agent both and weight by source authority. Code-vs-docs needs a ranking skill, since the agent will build a theory from code that contradicts the doc [Unblocked](https://www.youtube.com/watch?v=BiG2ssibKGc) [DemandContext-Raj](https://www.youtube.com/watch?v=_QAVExf_1uw) (2026-05)
- Don't cache "good answers" for latency — a correct answer goes stale on a ~24h clock as the system changes, so you start confidently serving lies [Unblocked](https://www.youtube.com/watch?v=BiG2ssibKGc) (2026-05)
- 80/20 data sources (SRE): Slack, code and logs get you far; treat code/infra as the always-current source of truth and work *backward from what's true today* to history — Slack/docs carry unverifiable staleness [MLOps-Sandboxing](https://podcasters.spotify.com/pod/show/mlops/episodes/Sandboxing--Agent-Harnesses--and-Agent-Teamwork-e3kts75) (2026-06)

## Latency & perceived UX
- **P95, not P50, is the number for an interactive agent**: GPT 4.1 measured 536ms P50 but 1.7s P95, and a Claude model over 4s. One slow turn breaks the interaction and you can't average it away [AWS-voice](https://www.youtube.com/watch?v=hMlLw1LeIK8) (2026-07)
- Co-locate a voice orchestrator with STT/LLM/TTS: cutting inter-component network latency ~75ms→5ms reduced total latency ~30% in an already optimized example [Together-Voice](https://www.youtube.com/watch?v=N7b1PJc7SFc) (2026-05)
- Real-time autoregressive TTS: stream before completion; replace dynamic with static KV cache to permit GPU graph capture, trading reserved RAM for 0.8→5.8 real-time factor and seconds→milliseconds first audio [HuggingFace-Marafioti](https://www.youtube.com/watch?v=0jeZfjJMfmo) (2026-05)
- **Cache a stable output prefix, not the personalized continuation**: play cached audio for a common opening at the first miss, synthesize the whole sentence for natural prosody, then suppress its already-played overlap [EliseAI](https://www.youtube.com/watch?v=MBHOH1NmDqc) (2026-09)
- Latency Goldilocks zone: too-fast reads as "it didn't think enough", losing trust; too-slow reads as "it's stuck". Calibrate to perceived complexity: a trivial query taking 8s feels broken, a hard one fine. Set per-task budgets, not one global SLA [iFood](https://podcasters.spotify.com/pod/show/mlops/episodes/The-Latency-Goldilocks-Zone-Explained-e3j384v) (2026-05)
- Perceived latency is the real lever: stream partial output and surface progress status ("collecting data…") so the loop never appears frozen — same wall-clock with a visible signal is tolerated; with none, users assume a bug [iFood](https://podcasters.spotify.com/pod/show/mlops/episodes/The-Latency-Goldilocks-Zone-Explained-e3j384v) (2026-05)
- ...which changes the METRIC you chase: **time to first chunk, not total latency** — skeleton, then partially filled, then complete. Spinners no longer pass; users have left the forgiving phase and expect to see what is happening [Amazon-Ramdoss](https://www.youtube.com/watch?v=maTp79FD9gI) (2026-07)
- Reject reasoning models for consumer UX on *predictability*: completion time varies; reserve slow LLM UX for opt-in flows. Don't chain models across modalities (voice→text→voice); each hop compounds latency and error. Put regex + state machines on the hot path [Take Take Take](https://www.youtube.com/watch?v=FlzpEGHNVKQ) [AIE-Melbourne](https://www.youtube.com/watch?v=wjXowoQ7E8c) (2026-06)

## Economics & pricing
- **The cost-per-token curve has reversed**, per a FinOps lead's own bill: ~80% decline over two years, but recent frontier tiers land at roughly *double* their predecessor, with reasoning and search billed separately. Tokens-per-session is also rising exponentially [MLOps-Tokenomics](https://podcasters.spotify.com/pod/show/mlops/episodes/Why-Your-AI-Bill-Will-Double-Before-It-Gets-Better-e3mt6jj) [Arcee/Atkins](https://www.youtube.com/watch?v=FWMJQDH3iK0) (2026-08)
- **Shift cost estimation left, before the prototype**: a CLI calculator taking requests/sec plus average request size (input, output, cached-input) against live proxy pricing lets a team price an agent design *before* building it [MLOps-Tokenomics](https://podcasters.spotify.com/pod/show/mlops/episodes/Why-Your-AI-Bill-Will-Double-Before-It-Gets-Better-e3mt6jj) (2026-08)
- **Cost governance has two sides**: pair CENTRAL policy (a gateway capping which models each dev may use, per-team budgets) WITH developer-facing LIVE spend visibility — surfacing spend at the point of use changes behavior; CFO dashboards don't [Omnigent](https://podcasters.spotify.com/pod/show/mlops/episodes/Omnigent-Composition--Control--and-Collaboration-for-AI-Agents-e3lka92) (2026-07) [Shopify-Thawar](https://newsletter.pragmaticengineer.com/p/how-ai-is-changing-software-engineering) (2025-07)
- Cost per million tokens misleads across agent workloads: cached-input reads, cache writes, uncached input and output carry different prices. Allocate spend by persona/use case, then pair cost with an outcome metric [PaloAlto-FinOps](https://podcasters.spotify.com/pod/show/mlops/episodes/Why-Cost-Per-Million-Tokens-Is-A-Useless-KPI-e3oqua5) (2026-09)
- Make that outcome metric a unit price the business can judge: cost per completed claim/task, with exploratory developer budgets separated from repeated production work [Barney](https://podcasters.spotify.com/pod/show/mlops/episodes/The-Caveman-Prompting-Challenge-e3pmsjk) (2026-10)
- Per-agent cost visibility needs a tagging proxy: an in-house LLM proxy tags token volume by calling service *and* feature, then the vendor bill is allocated proportionally — without it you can't know what any individual agent costs [MLOps-Tokenomics](https://podcasters.spotify.com/pod/show/mlops/episodes/Why-Your-AI-Bill-Will-Double-Before-It-Gets-Better-e3mt6jj) (2026-08)
- **Forecast the overrun instead of alerting on it**: per-team and per-service-account projections flag "these two engineers will end 400% over" by the 6th–9th of the month, while there's still runway; raising a quota goes through a human approval step [Wayfair-Eubanks](https://podcasters.spotify.com/pod/show/mlops/episodes/How-Predictive-Analytics-Stops-Budget-Overruns-Before-They-Happen-e3nk2h1) (2026-08)
- **Billing data lags 1–2 days — too slow to catch a retry loop.** Cost every step of an agent trace off observability logs instead, alerting when one step moves >10–15% or >$1 within a session [Wayfair-Eubanks](https://podcasters.spotify.com/pod/show/mlops/episodes/How-Predictive-Analytics-Stops-Budget-Overruns-Before-They-Happen-e3nk2h1) (2026-08)
- **Input tokens dominate agentic cost**: long tool-loop workloads are almost all input; cache-hit discounts vary 80–99% by provider, swinging task cost by multiples [Arena/Artificial Analysis](https://www.youtube.com/watch?v=4sX_He5c4sI) [MLOps-Tokenomics](https://podcasters.spotify.com/pod/show/mlops/episodes/Why-Your-AI-Bill-Will-Double-Before-It-Gets-Better-e3mt6jj) (2026-07)
- Subscription-vs-API leverage, running long-horizon tasks until weekly limits ran out: a $200/mo Claude plan yielded ≈$8k of API-priced usage, a $200/mo Codex plan ≈$14k. Price your own build against the subsidised rate, not list [Cline-Rizwan](https://www.youtube.com/watch?v=CoEIs6Xm8m8) (2026-08)
- Pricing moves against you in ways capability doesn't offset: a reasoning upgrade holds per-token price but burns ~3× the output tokens; a new tier costs ~40% more than the predecessor being deprecated in four months [Notion](https://www.youtube.com/watch?v=-I5W5QVAT8E) (2026-07)

## Languages & type systems as agent leverage
- **Crank the feedback loop to maximum for codegen**: set ALL diagnostics to ERROR so any squiggle is a hard stop, lint-ban the escape hatches it reaches for — `any`, `unknown`, then `as` once it discovered `as never as X` [Effect](https://www.youtube.com/watch?v=Wmp2Tku2PrI) (2026-05)
- Strict compiler as agent feedback loop: the Rust refactor workflow is "fix compiler errors until it stops shouting" — agents run the same loop, and the type system makes certain bug classes unshippable [Ryhl-Rust](https://newsletter.pragmaticengineer.com/p/why-rust-is-different-with-alice) (2026-05)
- ...with the mirror-image risk in weakly-checked domains: AI editing kernel makefiles mirrored unnecessary C flags onto the Rust side ("any human would ask why") — plausible-but-wrong output thrives where there's no compiler-grade feedback (build configs, scripts) [Ryhl-Rust](https://newsletter.pragmaticengineer.com/p/why-rust-is-different-with-alice) (2026-05)
- **Live disagreement on LLM-native languages.** Against: a syntax designed for LLMs has no organic training set, and an LLM's value is having seen existing code [Breslav/Kotlin](https://newsletter.pragmaticengineer.com/p/the-programming-language-after-kotlin) (2026-02)
- ...for: at codegen cost ~0, design a model-only language — strongly typed, proof obligations, unreadable by humans. Decider: do proof obligations outweigh lost corpus coverage [DeepMind-Schillings](https://www.youtube.com/watch?v=1P1hJ36rxM0) (2026-07)

## Making products/codebases agent-native
- **Measure agent-readiness from observed journeys, not standards compliance**: about half of sampled sites exposed `llms.txt`, yet agents almost never read it unless docs linked it. Replay identical intents across harnesses and optimize the paths they actually take [MCP-Apps-Yosef](https://www.youtube.com/watch?v=waI44NP1abk) (2026-09)
- Two ideas worth stealing from WebMCP whatever becomes of the standard: expose tools **page-scoped** so the callable set changes as the agent navigates; and an **agent-invoked flag** so the app tells an agent fill from a human one [Chrome-Agyemang](https://www.youtube.com/watch?v=ghJmWQCIHRM) (2026-06)
- ...page-scoping since corroborated in practice: a docs framework exposes `search_docs` / `get_page` / `ask_docs` over WebMCP [Inth-Burns](https://www.youtube.com/watch?v=V_5bn4q-vAI) (2026-08)
- Agent-experience (AX): the primary user is increasingly an agent, not a human (claimed ~60% of Vercel traffic is bots) → CLIs/APIs/MCPs over dashboards; ship UI into the agent's app, not your own [swyx](https://www.youtube.com/watch?v=zepu8Kk6FBQ) (2026-05)
- ...concretely, vendors now ship **installable skill files for their own API** — the skill, not the docs site, is the integration surface — and it seeds the VERIFICATION state, flowing synthetic usage in so the test env is observable [Stripe-Garvin](https://www.youtube.com/watch?v=mJqwmmOx4WA) (2026-08)
- **Coding agents never visit your docs site for a library — they read `node_modules` and the compiled source.** Ship bundled markdown docs inside the package plus an `AGENTS.md` pointing at them: ~50% token saving vs the agent web-searching, across models [Inth-Burns](https://www.youtube.com/watch?v=V_5bn4q-vAI) (2026-08)
- **For generative UI the model picks from a fixed catalog and never invents a component**; the contract carries layout rules too (1–3 items → carousel, 4+ → list) [Amazon-Ramdoss](https://www.youtube.com/watch?v=maTp79FD9gI) (2026-07)
- ...**version-gate that catalog to what the client build can render** — you cannot patch a mobile client, so an unknown component doesn't degrade, it crashes for weeks [Amazon-Ramdoss](https://www.youtube.com/watch?v=maTp79FD9gI) (2026-07)
- ...worked enterprise instance (Gates Foundation, ~4k staff): they judged the chat UI NOT defensible and modelled process knowledge the moat, so served the platform via MCP into Claude and ChatGPT, forking the server to pass conversation IDs back [Gates-Phipps](https://www.youtube.com/watch?v=jt1Pbr_n6oU) (2026-07)

## Model landscape (watch)
- Optimization must follow the bottleneck: TurboQuant halves KV-cache storage/bandwidth (8→4 bit), but its extra decode compute cut data-centre throughput by >50%; memory-bound local inference may still benefit [Baseten-Kiely](https://www.youtube.com/watch?v=75ckHC2LU_0) (2026-09)
- Production speculative decoding: D-Flash drafts 8–16 mutually attending tokens per pass and measured >3× versus Eagle on one single-B200 benchmark; continuous retraining on permitted live traffic improved acceptance 20%–2× [Baseten-Kiely](https://www.youtube.com/watch?v=75ckHC2LU_0) (2026-09)
- Open-weight models now cover the moderate tier and RL on top extends their reach — treat them as the credible alternative applying downward price pressure. A task good enough on open weights today is likely covered in six months [Notion](https://www.youtube.com/watch?v=-I5W5QVAT8E) (2026-07) [Effect](https://www.youtube.com/watch?v=Wmp2Tku2PrI) (2026-05)
- ...corroborated at survey scale: 94% run closed models in production, 45% open-weight, and >90% of the open-weight users also run closed. Choice is driven by quality, then tool-calling ≈ cost — open-vs-closed was top-3 for only 5% [Amplify-Yaron](https://www.youtube.com/watch?v=RGe6EjucbzI) (2026-07)
- **A newer model can regress on an off-distribution capability**: Opus 4.8 scored much worse than 4.7 on Vending-Bench, its system card noting removal of the post-training component aimed at business skills. Check the card before blaming eval rot [Andon-VendingBench](https://www.youtube.com/watch?v=cO8qC6HBuBg) (2026-07)
- Pre-training scale is claimed the saturated axis now: architectures at their ceiling, the best sub-13B OpenLLM model crossing over larger ones, and no lab expected to 4× pre-training size again — returns moved to post-training and inference compute [Adaption-Hooker](https://www.youtube.com/watch?v=XEd_SRVHBgU) (2026-08)
- Scaling has shifted from hardware to software: GPUs gained ~32× going float32→float4 (transistor cost scales with exponent + mantissa², so shrinking the mantissa squares the gain), but float4 is roughly the floor. Remaining headroom is algorithmic [Unsloth-Han](https://www.youtube.com/watch?v=uIiA6DquRiE) (2026-07)

## Deploying agents in orgs
- Attention, not agent capacity, is the constraint once agents loop indefinitely — a practitioner running four parallel agents reports being wiped out by 11am regardless of model quality. Route high-distraction channels through an agent that filters for genuine priority [WorkOS-Proser](https://www.youtube.com/watch?v=so9l_MwS2yg) (2026-07)
- ...and the load falls hardest on EARLY-CAREER engineers: reviewing AI output is harder than writing it when you haven't built the review muscle seniors got from years of reviewing others' code [AWS-Liguori](https://www.youtube.com/watch?v=pqlWNihgdjI) (2026-08)
- **The new bottleneck is decision latency.** Once code takes 1–2 months instead of 9–12, the build decision and the launch-review process become the long pole — frontier teams spend more time deciding than coding [AWS-Liguori](https://www.youtube.com/watch?v=pqlWNihgdjI) (2026-08)
- **Mark AI-generated vs human-written text** in PR descriptions, Slack and docs so readers know how much scrutiny to spend. Motivating failure: an unmarked AI-written analysis sent to a senior skeptic read as disrespectful slop [Figma-Blum](https://www.youtube.com/watch?v=5Bn0xro2ol8) (2026-08)
- Only delegate work you already know how to do the hard way — the battle scars are what let you instantly catch a hallucination or bad architectural call; keep some tasks manual specifically to build that judgment [WorkOS-Proser](https://www.youtube.com/watch?v=so9l_MwS2yg) (2026-07)
- Factory big-bang anti-pattern: disappearing for 3 months to build "the software factory" with no users is the top failure mode. A factory is an internal product: start with small loops in front of real users, targeting 2–3× [HumanLayer-WF26](https://www.youtube.com/watch?v=I2cbIws9j10) (2026-07)
- **Factory metric = customer outcomes plus defect/MTTR**, not PR or code volume; WorkOS's initial sandbox-plus-agent factory was indistinguishable from engineers running local agents [WorkOS-Cooke](https://www.youtube.com/watch?v=HvboD89DyQ8) (2026-09)

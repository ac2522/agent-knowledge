# Harnesses

## What the harness is
- Harness = everything *around* the model (tool registry, model, context primitives, guardrails, agent loop, verify step) — often a loop *around* the agent loop (retry/max-attempts wrapper). Claude Code and Codex CLI are themselves harnesses [IBM](https://www.youtube.com/watch?v=C_GG5g38vLU) [MLOps-Sandboxing](https://podcasters.spotify.com/pod/show/mlops/episodes/Sandboxing--Agent-Harnesses--and-Agent-Teamwork-e3kts75) (2026-06)
- Every agent is a while loop with conditions and end states; keep a mental model of which state it's in. The state machine must be designed by a human — don't let models rip through it, even when pairing [Cline](https://www.youtube.com/watch?v=yUmS-F9IX90) (2026-05)
- Trigger for moving control flow OUT of the model: when step-adherence is roughly a coin flip, stop prompting harder. The model proposes, the harness decides — and is never asked to remember which step of six it's on [Microsoft-ACE](https://www.youtube.com/watch?v=m24UKZomm7k) (2026-07)
- Inner vs outer harness: the inner harness is the while loop in one process (model + tool calls + filesystem); the outer separates the "brain" (which tool to call) from the "hands" (execution in a sandbox / external state store) — once split, run multiple brains × multiple hands [ZenML](https://podcasters.spotify.com/pod/show/mlops/episodes/Agents-are-Just-While-Loops-e3j3a6q) (2026-05)
- **The harness dominates coding-eval results**: SWE-Bench Pro showed a ~22% swing from harness alone while frontier models sat within a few points. One eval tests three things at once (model, harness, problem realism) and a strong model masks a weak harness — you may be measuring the harness [Cline](https://www.youtube.com/watch?v=QuuIywMG4s8) [DeepMind](https://www.youtube.com/watch?v=Ubwb6NzegyA) (2026-05)
- Harness + architecture decisions ≈ 3× the price swing of model selection — optimize the harness BEFORE picking the model [Notion](https://www.youtube.com/watch?v=wjXowoQ7E8c) (2026-06)
- Retrospective on the 2025 turn, from a prior skeptic: the inflection was the HARNESS, not the model release later credited for it — visible from ~July 2025 as tooling went from "a retrying shell script" to real scaffolding [Charity Majors](https://newsletter.pragmaticengineer.com/p/stop-being-skeptical-about-ai-for) (2026-08)
- **Biggest published context delta: 21% → >95%, same model.** Anthropic's internal analytics agent, given raw data access vs curated per-domain reference docs naming tables, joins, required filters and gotchas [Anthropic-analytics](https://claude.com/blog/how-anthropic-enables-self-service-data-analytics-with-claude) (2026-06) [DataChain-Petrov](https://www.youtube.com/watch?v=bUJgirn4_yc) (2026-07)
- ...and the lever is DISTILLATION, not retrieval: handing the same agent raw search over thousands of prior queries moved accuracy less than one point, because unstructured retrieval can't map a new question to the right precedent [Anthropic-analytics](https://claude.com/blog/how-anthropic-enables-self-service-data-analytics-with-claude) (2026-06)

## Minimalism — get out of the model's way
- Frontier models let you *delete* prompt: Claude Code's system prompt shrank ~80%, largely by removing **examples** (the model was more creative than they allowed) and replacing hard "do not" constraints with context, since prohibitions conflict confusingly with later user instructions [Anthropic-CC](https://www.youtube.com/watch?v=uU5Gv2h8-9g) (2026-07)
- Each thing you add risks making the agent worse — large system prompts, edge cases, fancy if-else degrade frontier models (Codex GPT-5.3's system prompt is ~1/3 the size of GPT-5's) [Cline](https://www.youtube.com/watch?v=yUmS-F9IX90) (2026-05)
- "Bash is all you need": a single `bash` tool returning stdout/stderr/exit code covers most work — models are very good at generating `find`/`ls`/`grep` — so you can run a whole agent off one tool [Vercel](https://www.youtube.com/watch?v=wflNENRSUb4) (2026-05)
- ...but offer a DB tool alongside it: a hybrid bash + DB agent scored highest on analytical queries (query the DB, verify with the shell); pure DB wins for analytics, file/grep for quick lookups [Elastic](https://www.youtube.com/watch?v=ynJyIKwjonM) (2026-05)
- **d0's evolution with eval receipts** (Vercel data agent, ~30k questions/month): a pipeline of scoped agents each getting only a summary of the prior stage hit a wall — summary handoff loses too much. A single agent holding all context and self-managing phase state beat it (it can look back at failed SQL). Then a Claude-Code-style filesystem agent with the semantic layer dumped in as files roughly DOUBLED eval scores — the unlock is tools the model is heavily trained on plus freedom to explore, not better bespoke tooling [Vercel-d0](https://www.youtube.com/watch?v=I2cbIws9j10) (2026-07)
- ...independently corroborated on a different domain: a rigid discovery→plan→execute/verify split was abandoned because discovery ran once up front and could never be revisited and context didn't flow between agents. Consolation prize worth knowing — the split did move errors from build-time to PLAN-time, where they're much cheaper to fix [Witan-Campos](https://www.youtube.com/watch?v=HEFSExa0xl0) (2026-07)
- Offload deterministic/repeated subtasks to CPU code, not the LLM — small hosted "workers" the LLM calls as an action cut token cost up to 80% on repeated work (CSV→PDF→webhook). Don't token-max what a state machine handles [Notion](https://www.youtube.com/watch?v=wjXowoQ7E8c) (2026-06)
- **Industry-wide "build to delete" telemetry**: Cursor replaced ~12,000 lines of TS git-worktree orchestration with a skill plus markdown; Manus rebuilt its harness 5× in 6 months; LangChain re-architected open deep research 3× in a year; Vercel removed 80% of its tools and got fewer steps, faster responses AND better accuracy. Heuristic — if your harness gets MORE complex as models improve, you're over-engineering; own only domain instructions, workflows and evals [Gemini-WF26](https://www.youtube.com/watch?v=I2cbIws9j10) (2026-07)

## Frameworks & API lock-in
- Frameworks (LangChain/LangGraph) are fine for PMF/prototyping but hit a customizability ceiling for production — expect to rewrite ("cloud code written 7+ times"). Corroborated: OpenGov moved OFF LangGraph to their own loop once use cases scaled; dependency injection in the loop lets you hot-swap the model underneath [Cline](https://www.youtube.com/watch?v=yUmS-F9IX90) (2026-05) [OpenGov](https://www.youtube.com/watch?v=4uFVSLgD2Q4) (2026-06)
- Don't lock the harness to one provider — the best frontier model keeps shifting; Notion swaps its default every 3–4 weeks and forgoes vendor discounts to keep that optionality [Notion](https://www.youtube.com/watch?v=wjXowoQ7E8c) (2026-06)
- **Meta-harness = a portable layer above both the model AND the harness**: keep context, agentic memory, config and policies portable so either can be hot-swapped. Because approval and budget semantics differ per harness AND per model, the policy layer must NORMALIZE each rather than express policy in prompts — gate shell commands, require approval when projected cost > $X [Omnigent](https://podcasters.spotify.com/pod/show/mlops/episodes/Omnigent-Composition--Control--and-Collaboration-for-AI-Agents-e3lka92) (2026-07)
- **ACP (Agent Client Protocol) is the editor↔agent interop layer** — JSON-RPC over stdio, LSP/MCP-shaped, ~40 clients (Zed, JetBrains, Obsidian, OpenClaw) against agents that either speak it natively (opencode, Cursor CLI) or sit behind an adapter. Minimal agent = `initialize` / `newSession` / `prompt` / `cancel`, with everything the user sees arriving as session updates (`agent_message_chunk`; `tool_call` then `tool_call_update`) [Zed-Fenner](https://www.youtube.com/watch?v=HsxQICTLF84) (2026-07)
- **The detail anyone embedding an agent in an editor gets wrong: proxy the FILESYSTEM through the client.** If the client advertises the capability, the agent reads and writes over the protocol rather than `fs.readFile`, so it sees UNSAVED BUFFER state instead of stale bytes on disk. Same shape for terminals — the client creates and manages them so output renders natively [Zed-Fenner](https://www.youtube.com/watch?v=HsxQICTLF84) (2026-07)
- **2026 reversal of the "just use the CLI" consensus**: with modern harnesses' native MCP rendering, native MCP now beats a Bash/CLI interface on BOTH accuracy and token efficiency (benchmarked GitHub + Linear + a Bus API × 3 models) — the win came from harnesses learning to render MCP properly. Two CLI levers close most of the gap: self-documentation (discoverable, well-described subcommands) plus search over subcommands [Smithery](https://www.youtube.com/watch?v=m12vGjfbNlo) (2026-05)
- MCP fills context and is non-composable (combining two servers forces data through the model); CLI piping lets the model see only the end result. "Code mode" exposes MCP servers as callable functions to recover composability — the entire Cloudflare API (~2,600 endpoints) exposed in ~1,000 tokens [Pi](https://newsletter.pragmaticengineer.com/p/building-pi-and-what-makes-self-modifying) (2026-04) [Cloudflare](https://www.youtube.com/watch?v=SKDJo2CopRs) (2026-06)
- MCP Apps: a tool returns a UI *resource* the host renders in a sandboxed component, bypassing the context window entirely — a tool can return an interactive 100k-row table while the model gets only a short confirmation. Message passing routes UI events to the *host*, not a vendor backend, keeping actions in agent context [MCP UI](https://www.youtube.com/watch?v=o-zkvb0iFDQ) (2026-05) [FastMCP-Lowin](https://podcasters.spotify.com/pod/show/mlops/episodes/The-Creator-of-FastMCP-Explains-the-Future-of-MCP-e3maib0) (2026-07)

## MCP security, trust & auth
- **Tool poisoning**: publish a benign MCP server, earn an "always allow" approval, then swap a tool's behavior later. Manifest hashing does NOT fix it (the server keeps the hash constant but serves different tools at call time); requiring the tools-list-changed notification fails too (a malicious server just doesn't send it). Both still trust the server's self-report — the real fix is trust in the SERVER (SSL-cert / app-store model), an open problem for remote MCP [MCP-DarkSide](https://podcasters.spotify.com/pod/show/mlops/episodes/The-Dark-Side-of-MCP-Servers-e3l5thf) (2026-06)
- **Confused-deputy / subject spoofing**: storing an API key locally and passing "whose email to check" as a tool parameter lets one prompt injection swap the subject; even "always use the logged-in user's ID" is overridable when the subject is agent-controlled. Fix — MCP+OAuth carries the call subject in the protocol HEADER from the authorization server, so injection can't change whose token is used. This is the concrete "MCP's real value is auth, not tool surface" mechanism [MCP-DarkSide](https://podcasters.spotify.com/pod/show/mlops/episodes/The-Dark-Side-of-MCP-Servers-e3l5thf) (2026-06)
- Legacy auth (fixed permissions granted at registration to a deterministic program) structurally breaks for agents: the scopes safe for a human can't bound non-deterministic behavior — you need actor-bound, fine-grained, time-limited, purpose-scoped credentials. Most MCP servers compound this by surfacing the FULL tool surface of the underlying user account [ScaleKit-Madabhushi](https://www.youtube.com/watch?v=lMCxVorb9wM) (2026-07)
- Keep MCP servers off the public internet entirely: run them inside your private network making only OUTBOUND calls to the hosted agent loop ("MCP tunnels"), rather than exposing an inbound endpoint the loop dials [Anthropic-AppliedAI](https://www.youtube.com/watch?v=K0X9QDRkIdg) (2026-08)
- **Endpoint-level auth is too coarse for agent clients**: enterprise APIs co-mingle data of very different sensitivity in one endpoint (an HR API returns everyone's timezones AND 401k data), and request-response REST can't enforce policy because the server never sees what the agent composes across calls. Fix — the agent DECLARES intent as an explicit query with per-field rights bound to each credential, and the policy layer approves/blocks field-by-field BEFORE execution [Apollo-DeBergalis](https://podcasters.spotify.com/pod/show/mlops/episodes/AI-Agents-Should-Be-Treated-Like-Hackers-e3lncle) (2026-07)

## Long-running / multi-hour agents
- **Three failure modes blocking multi-hour runs**: context (amnesia across sessions, context rot, "context-sense anxiety" where the model rushes near window end), weak planning (one-shots everything, or builds half a feature and stops), and bad self-judgment (calls half-baked work done; builds a button with no backend) [Anthropic](https://www.youtube.com/watch?v=mR-WAvEPRwE) (2026-05)
- Long-run harness pattern: an initializer agent expands a vague one-line prompt into persistent artifacts — feature-list.json, progress file, init script, git repo — then a loop in fresh context windows picks ONE unfinished feature, implements, verifies (Playwright), commits, flips its done flag, repeats [Anthropic](https://www.youtube.com/watch?v=mR-WAvEPRwE) (2026-05)
- Store agent state as JSON, not markdown — models readily overwrite markdown files but tend to leave JSON alone; prefer the filesystem for shared state on long runs so another agent can grep it and resume [Anthropic](https://www.youtube.com/watch?v=mR-WAvEPRwE) (2026-05)
- Add a high-level planner that decomposes into sprints but deliberately does NOT spec granular technical details — a granular plan error cascades across every sprint. Keep the planner OUT of the build loop and re-inject the original spec as a reference rather than letting it self-edit [Anthropic](https://www.youtube.com/watch?v=mR-WAvEPRwE) (2026-05)
- Forced to-do list as an anti-early-exit device: prompt the research phase to first write a list such that completing every item leaves it ready to start work — that list is what you re-prompt against when it tries to finish early. Each item writes notes to markdown so later agents QUERY the notes rather than inherit context [MorganStanley-AlphaLab](https://www.youtube.com/watch?v=kiqubc5b5Yo) (2026-07)
- **Harness mitigations are temporary**: each model release exposes gaps you patch in the harness, then later train into the model and strip the patch. With Opus 4.6 they dropped fresh-context resets AND strict sprint decomposition for a single continuous compacted session (4.6 lost 4.5's context anxiety, holds a 2-hour build), moving evaluator cadence to once at the end — the simplified harness ran ~half the cost. The 4.5 harness was right for 4.5 [Anthropic](https://www.youtube.com/watch?v=mR-WAvEPRwE) (2026-05)
- ...and a stale patch is not merely dead weight: the context-reset workaround kept one generation past the anxiety it treated added latency AND discarded the prompt cache. Re-audit each workaround's assumption every release [Anthropic-AppliedAI](https://www.youtube.com/watch?v=K0X9QDRkIdg) (2026-08)
- On very long-horizon runs (>48h) detect context DRIFT — the "you're absolutely right" mimicry of early context creeping in — and hand the task to a fresh agent rather than continuing a degraded session [AutoHand](https://www.youtube.com/watch?v=wjXowoQ7E8c) (2026-06)

## Self-evolving / evolutionary harnesses
- Don't hand-build a custom harness per company — evolve the harness itself; the two levers to improve an agent are the ENVIRONMENT it runs in and the TOOLS it has (cites single-agent self-improvement 20%→50% on SWE-bench when the agent rewrote its own code and tools) [CodeGraph](https://www.youtube.com/watch?v=m12vGjfbNlo) (2026-05)
- **Meta-harness optimization needs a measurement surface first**, and that's what makes arbitrary design choices ("is a strategist+worker split arbitrary?") answerable — build 10–20 careful environments, make them the measurement signal, then let an LLM read traces and edit the harness itself. Human hand-tuning becomes possible for the same reason [MorganStanley-AlphaLab](https://www.youtube.com/watch?v=kiqubc5b5Yo) (2026-07)
- The corollary is where to invest: general auto-research trends toward commodity, so the durable value is ENVIRONMENT-building, not the harness in the middle — which is why they open-source the harness and keep the environments. Expertise enters via qualitative RUBRICS grading each rollout on "did it follow our research process" [MorganStanley-AlphaLab](https://www.youtube.com/watch?v=kiqubc5b5Yo) (2026-07)
- **Caution on optimizing a harness against a FROZEN model**: Adaption Labs got no real return from auto-research until data adaptation was co-optimized with the model rather than left to the agent's discretion — and the stated corollary is that an auto-scientist for HARNESSES needs the same joint treatment, making it a long-horizon co-training problem rather than a search over a fixed model [Adaption-Hooker](https://www.youtube.com/watch?v=XEd_SRVHBgU) (2026-08) (data half is a result; harness half is her prediction)
- **Self-fixing agent pattern**: observability skills pull production traces into FILES inside the repo, not an API call — coding harnesses work well with files, so materializing telemetry next to the code is the actual integration point. Deliberately-scoped skills (fetch one session's traces, not generic full-data access) determine whether the agent finds the issue [Arize-Lopatecki](https://www.youtube.com/watch?v=9HbzAWnKbo4) (2026-07)
- Same pattern applied to performance: a weekly autonomous perf-audit workflow (GitHub Actions + Claude Code + MCP access to production traces mapped to function-level code) posts scored high-ROI fixes to Slack. Map production metrics to function/file level, not service level, because coding agents reason at that granularity [HUD-Walter](https://www.youtube.com/watch?v=JJGbw4ggaFs) (2026-07)
- Bring-your-own-harness post-training: attach RL to an existing production harness via only a model-completion endpoint plus request/response logging — trains on real production traces without replicating the environment, at the cost of losing on-policy replay (forcing off-policy RL) [Applied Compute/Feng](https://www.youtube.com/watch?v=k35LeKZEhiE) (2026-07)

## Control planes & infrastructure patterns
- Harness as a **control plane** (scheduling, memory coordination, policy enforcement, workload routing) — an OS for agents, separate from the model. The model should **never directly control** production: model proposes → infrastructure validates → policy engine improves → execution gateway enforces [Meta-Superintelligence](https://www.youtube.com/watch?v=APh1Vx0oLmQ) (2026-06)
- **Retry amplification** as the biggest infra failure mode: agent calls a tool wrongly → error → retries with a slightly-different but still invalid request → cycle repeats, consuming exponential compute. Each retry deepens reasoning and escalates resource use; uncontrolled retries are a compute incident waiting to happen [Meta-Superintelligence](https://www.youtube.com/watch?v=APh1Vx0oLmQ) (2026-06)
- **Memory consistency failures masquerade as reasoning failures** in multi-agent systems: stale reads, conflicting updates, inconsistent views. Familiar CAP/eventual-consistency issues hit when multiple agents share state — many "agent reasoning errors" are consistency failures hiding in the state layer [Meta-Superintelligence](https://www.youtube.com/watch?v=APh1Vx0oLmQ) (2026-06)
- **Liveness × verification is THE control-plane tradeoff** for agent fleets: pure liveness (no approvals) = slop at volume; pure human sign-off = an unreviewable queue degrading into verification theater. Three invariants the control plane must enforce: productive work always continues, only REAL blockers stop work, and infinite loops are bounded [Dotta/Paperclip](https://www.youtube.com/watch?v=7P0elyLIxXo) (2026-07)
- Cost governance has two sides: pair CENTRAL policy (a gateway capping which models each dev may use, per-team budgets) WITH developer-facing LIVE spend visibility (per-person dashboards, a running $/day widget, threshold alerts) — surfacing spend at the point of use changes behavior; central-only CFO dashboards don't move the person spending. Shopify runs exactly this via an internal proxy [Omnigent](https://podcasters.spotify.com/pod/show/mlops/episodes/Omnigent-Composition--Control--and-Collaboration-for-AI-Agents-e3lka92) (2026-07) [Shopify-Thawar](https://newsletter.pragmaticengineer.com/p/how-ai-is-changing-software-engineering) (2025-07)

## Durable execution, resume & replay
- Keep execution (flow/state/durability/retries), context (models/prompts/tools/memory) and compute (sandboxes/runtimes/browsers) as three decoupled layers with different half-lives — prompts decay in weeks, models in months, execution can last years; coupling them means one layer's short half-life drags the others down [Inngest-Farrelly](https://www.youtube.com/watch?v=X1kp-ABIIxQ) (2026-07)
- Resumability requires state living externally and durably, not in the sandbox: a failed call at step 38 of a long run should retry from there. Treating a sandbox as durable storage is an anti-pattern — sandboxes are ephemeral by design; the execution layer gives them context, sequence and durability [Inngest-Farrelly](https://www.youtube.com/watch?v=X1kp-ABIIxQ) (2026-07)
- **What durable execution guarantees**: recovery from *external* failures (pod killed, network drop, LLM throttling) via backoff retry plus state rehydration. What it does NOT: the program finishing (a bad tool call is app logic), or rollback of external side effects — no control-Z on a Salesforce edit unless you build it into your own tools [ZenML](https://podcasters.spotify.com/pod/show/mlops/episodes/Agents-are-Just-While-Loops-e3j3a6q) (2026-05)
- Execution state can't be rebuilt from a log, so snapshot-and-restore the whole machine: pause during idle, restore on the next user message. Route recovery by failure type — LLM down/rate-limited → snapshot and restore when the retry window opens; machine crash or shipped bug → recover from the context log [Trigger.dev](https://www.youtube.com/watch?v=svCnShDvgQg) (2026-05)
- **Sandbox disk checkpoint/restore is a harness PRIMITIVE, not just crash insurance** (OpenAI's agent-sandbox cloud): cheap incremental block-level snapshots (copy-on-write reflink + FIEMAP diff; the save API returns a snapshot ID instantly while uploading in background) let the harness branch rollouts Monte-Carlo style — checkpoint, explore, backtrack — and survive node death on multi-day tasks (Codex goal-mode runs ~3 days). Guest-MEMORY snapshots give millisecond starts without warm pools burning idle CPU [OpenAI-Bhardwaj](https://www.youtube.com/watch?v=OqM67QG_Ikk) (2026-07)
- **Replayability > bitwise determinism**: don't chase temperature-zero or hardware determinism (impossible at scale — GPU batching, MoE routing, floating-point non-associativity); record-and-replay the run you already had. Record at **boundaries** (method I/O), not at the network or token level [Microsoft-Chronicle](https://www.youtube.com/watch?v=Lc8zRh9muoY) (2026-06)
- **Boundary annotation pattern**: wrap methods (tool calls, LLM calls, retrieval) with a `@boundary` decorator recording I/O pairs plus metadata (model version, code version, sampling params). The run becomes a frozen trace where you stub the LLM and run live tools to test guardrails — essentially free CI with zero model calls [Microsoft-Chronicle](https://www.youtube.com/watch?v=Lc8zRh9muoY) (2026-06)
- **Cohort replay beats single replay**: one swapped-model replay looked cheaper and equivalent, but replaying a whole cohort of past runs showed the cheaper model produced worse resolutions in aggregate. Tau-bench datapoint — a model passing a task 60% of the time is self-consistent only ~25% of the time, so a single anecdotal replay is not informative [ZenML-Tahir](https://www.youtube.com/watch?v=bZISsg7H7DA) (2026-07)

## Harness failure shapes — ownership, ordering, authority, proof
- **Five production shapes, each invisible to the user in the moment**: state hole (delivery succeeded, the durable record didn't); overlapping writers (load-modify-save race); dangling tool call (call with no matching result); approval drift (expired approval still durable); missing edge proof (tool reported success, nothing rendered) [OpenAI-Govindarajan](https://www.youtube.com/watch?v=BInpv7lGp1o) (2026-07)
- Silent success is worse than a crash: a crash gives you a boundary and a last-known-good point, while a coherent model answering over a broken history gives you a lie with no alarm [OpenAI-Govindarajan](https://www.youtube.com/watch?v=BInpv7lGp1o) (2026-07)
- Ownership rule: for every fact the agent may reuse later, name the system of record AND the replay path — "storage tells you where the bytes live, ownership tells you who can reconsider reality"; unreplayable is not remembered [OpenAI-Govindarajan](https://www.youtube.com/watch?v=BInpv7lGp1o) (2026-07)
- The concurrency rule is narrow, not global: fan out sub-agents, parallel reads and many sessions freely, but keep ONE ordered commit path per mutable state boundary (mutex across sessions, queue within one). Be conservative at commit time, not system-wide — "last writer wins is not a consistency model" [OpenAI-Govindarajan](https://www.youtube.com/watch?v=BInpv7lGp1o) (2026-07)
- **Receipt ≠ transcript ≠ tool result**: transcript = what the agent said, tool result = what one component claimed, receipt = the chain model-proposed → policy-allowed → executed → user-visible-edge-confirmed. Internal success is not external proof [OpenAI-Govindarajan](https://www.youtube.com/watch?v=BInpv7lGp1o) (2026-07)

## Event-sourced harness design
- **"The log IS the agent"**: treat the append-only event log (inputs, model outputs, tool calls, results, permissions, failures) as the agent's identity — model/runtime/tools merely read it and append the next event. The model's view, the UI, debugging, auditing and compaction are all PROJECTIONS of the log. The per-turn loop is DISPOSABLE: any worker claims a session, reads the log, advances ONE step, appends, disappears [Omnara](https://www.youtube.com/watch?v=UPwGaM2MKHY) (2026-06)
- Properties that fall OUT structurally once the log is primary: reliability (a worker dying at a permission prompt loses nothing — a new worker reconstructs state and the prompt is still there); scalability (one process advances thousands of agents, no sticky sessions); forking (branch the log, run branches on different models); multiplayer (sharing = granting log access); migration (provider swap is an adapter problem, not an identity one) [Omnara](https://www.youtube.com/watch?v=UPwGaM2MKHY) (2026-06)
- **Deepest lock-in is LOG lock-in** — deeper than model lock-in (swappable) or API lock-in (wrappable). Most harnesses treat the log as exhaust: Claude Code/Codex write JSONL to local disk fire-and-forget (write fails → data gone), OpenCode uses SQLite with corruption issues — so reliability, forking and multiplayer have to be bolted on. Keep your log inspectable and controllable [Omnara](https://www.youtube.com/watch?v=UPwGaM2MKHY) (2026-06)
- **The session log is not the context window.** Conflate them and whatever the model compacts away is gone; keep every event in a durable log and the harness can read slices back in [Anthropic-AppliedAI](https://www.youtube.com/watch?v=K0X9QDRkIdg) (2026-08)
- Agent state = a synchronous pure reduce over the event log (`(state, event) => newState`); ban side effects inside the reducer and move them to a separate `afterAppend` hook → on restart the reducer catches up over the backlog *without* re-firing N replayed LLM calls; side effects only fire once caught up to head [Iterate](https://www.youtube.com/watch?v=vi-2nasppAg) (2026-05)
- **Anti-before-hooks stance**: blocking before-hooks break prompt caching and tank cost/latency — only the platform itself may block an append. Replace blocking with eventual consistency: the loop waits up to ~200ms for optional enrichers (RAG context, injection checkers) before each LLM call, then proceeds regardless [Iterate](https://www.youtube.com/watch?v=vi-2nasppAg) (2026-05)

## Context, compaction & memory
- **Two context budgets, not one**: the information budget *and* the **instruction** budget. Too many (especially conflicting) instructions degrade compliance, and a mid-conversation change of direction costs real computation to notice [Horthy-CtxEng](https://newsletter.pragmaticengineer.com/p/context-engineering-with-dex-horthy) (2026-07)
- Four things that matter in a window: size, information quality (any wrong conclusion in a thinking trace), missing information, and **trajectory** — history is autoregressive, so an agent that fixed tests after a change will repeat that, and two corrections in a row make another mistake the likely next message. "You're absolutely right" is the signal to restart [Horthy-CtxEng](https://newsletter.pragmaticengineer.com/p/context-engineering-with-dex-horthy) (2026-07)
- **Context-zone guideline is training wheels, with numbers**: keep working context ~100k tokens even on 1M-context models (deliberately NOT revised up), under ~60k for the hardest problems; practitioners go past 300k when riffing. Telltale dumb-zone signal — the model rationalizes a failing test away as "pre-existing" when it isn't; that flailing is the reset cue. After ~2–3 months of heavy use intuition replaces the rule [LoopsDebate](https://www.youtube.com/watch?v=c35YoMdnI78) [HumanLayer-WF26](https://www.youtube.com/watch?v=I2cbIws9j10) (2026-07)
- **At million-token windows compaction is far less necessary** than at ~400k (one turn ran 104 min / 316 tool calls / 29 files at only 32% of a 1M window, zero compaction). Naive context-pruning actively hurts: trimming early tool calls to stay in a 40–60% band invalidates the input cache on every trim — a big cost hit when you run ~95% cache-read [Vercel](https://www.youtube.com/watch?v=wflNENRSUb4) (2026-05)
- Sharper framing of the same: compaction takes the cache miss either way (~10× on those input tokens), so **compact for *intelligence*, never to save money** [Cognition/Yan](https://www.youtube.com/watch?v=QHBjufYK8TA) (2026-08)
- Why server-side compaction holds up where an ad-hoc summarizer doesn't: it's a transform the model was explicitly TRAINED on, so quality survives the rewrite [OpenAI-Kundel](https://www.youtube.com/watch?v=shRR1e2HXMk) (2026-08)
- **Faster models make compaction arrive 20× sooner in wall-clock**: a window taking ~10 min to fill at 40–60 tok/s fills in ~30s at ~1,200. Speed is a third selection axis beside intelligence and cost [Cerebras-Chieng](https://www.youtube.com/watch?v=TeGsFFNqRLA) (2026-05) — no longer low-confidence: the throughput premise is corroborated first-hand by [OpenAI-Kundel](https://www.youtube.com/watch?v=shRR1e2HXMk) running Codex Spark on Cerebras (2026-08), and speed-as-a-selection-axis by [Microsoft-ACE](https://www.youtube.com/watch?v=fnLBmfsI_Fg) (2026-07)
- **Prefer offloading over compaction**: sub-agents take semi-independent work off the main thread and return only a ~1k-token summary (one used 30k, returned ~500); and a handoff tool lets the agent generate the context it wants to carry into a fresh thread. Both beat lossy LLM summarization [Vercel](https://www.youtube.com/watch?v=wflNENRSUb4) (2026-05)
- **Reset instead of compact** (fleet-scale variant): compaction is slow, you can't choose what survives, and whatever it drops is gone — instead wipe context entirely and have the agent re-read the on-disk workspace it wrote for itself (mission, status, handoff folder). State that never lived only in the model survives context wipe and machine crash. Live tension: Steinberger the same week credits *server-side compaction* as what made long-running manager agents reliable — state-in-files fleets reset, single long manager threads compact [KRAFTON-fleet](https://www.youtube.com/watch?v=4kYl2_mqmnQ) (2026-07)
- **Auto-compaction is dangerously lossy on the instruction you can least afford to lose**: an inefficient tool dumped a huge email list into context → triggered auto-compaction → the user's original "don't delete" instruction got overwhelmed in the summary → the agent deleted the whole inbox and refused to stop ("you asked me to"). Do compaction surgery in a `prepare`-step hook as a deliberate pure function, not an opaque default [Vercel](https://www.youtube.com/watch?v=wflNENRSUb4) (2026-05)
- **Smart truncation + an off-context memory store beats both naive truncation and summarization** (a year on an agent-on-agent-data product): naive truncation broke reasoning (follow-ups read as brand-new conversations); summarization was too inconsistent. What worked — keep head + tail, truncate the middle, dedupe repeated messages, keep only the latest tool result, never reset the system prompt, and stash the dropped middle in a DB keyed by IDs the agent can fetch back on demand. "Context decides what the model sees; memory decides what survives" [Arize-context](https://www.youtube.com/watch?v=esY99nYXxR4) (2026-05)
- Decouple the brain (harness) from the hands (execution env): harness+sandbox in one container loses the whole session when either dies and parks credentials next to a 10-hour unsupervised agent. Stateless harness → append-only event-log session → containers as hands, credentials in a separate vault [Anthropic-Martin](https://www.youtube.com/watch?v=9QebvrrY3KY) (2026-07)
- ...**the split also buys LATENCY**: coupled, no first token until container setup finishes; decoupled, reasoning starts immediately with setup in parallel, or skipped when no tools are needed. 60% faster TTFT at P50, >90% at P95 [Anthropic-AppliedAI](https://www.youtube.com/watch?v=K0X9QDRkIdg) (2026-08)
- Recovery falls out too: sandbox dies → the brain spins up a fresh one; brain dies → it replays the session log and resumes. The same split lets the hands sit in your VPC [Anthropic-AppliedAI](https://www.youtube.com/watch?v=K0X9QDRkIdg) (2026-08)
- **Memory needs an out-of-band consolidation pass ("dreaming")**, not just in-band writes: in-band memories can be wrong or only locally optimal. Measured — a bad memory made the agent mislocalise and fail 5/5 replicates; dreaming corrected it and it progressed, while no-memory made no progress at all [Anthropic-Martin](https://www.youtube.com/watch?v=9QebvrrY3KY) (2026-07)
- **Don't prescribe a memory schema.** Any programmable substrate with simple primitives works (filesystem or DB); performance DROPS when you pre-specify memory types. The model manages its own memory better than you can intuit for it — and at higher capability the differentiator is the **distillation** step, saving the generalisable abstraction rather than the specific fact [Anthropic-Martin](https://www.youtube.com/watch?v=9QebvrrY3KY) (2026-07)
- **What the shipped consumer systems actually converged on, reverse-engineered**: ChatGPT and Claude evolved independently to the SAME two layers — a continuously-updated "running profile" injected into every conversation, plus on-demand tools to search past conversations. Neither uses RAG over chunked conversations, which everyone assumed [Khemani](https://www.shloked.com/writing/claude-memory) (2026-08)
- ...and the design dial is explicit: **profile length × update frequency, traded against each other**. ChatGPT ≈4k tokens refreshed every few days (high serving cost, low update cost); Claude ≈1k tokens refreshed every 24h (the inverse). Claude also exposes the raw profile and re-synthesizes it on user edit [Khemani](https://www.shloked.com/writing/claude-memory) (2026-08)
- **Memory-harness ablation on long-horizon local-model agents** (Qwen 27B-Q4 / DeepSeek V4 Flash): a "ranked decisions ledger" — log and rank each turn's decision, retrieve by rank — beat no-memory, vector-RAG, and a gate deciding whether to use memory. Held on XBench and Spider V2 [Druga/Sakana](https://www.youtube.com/watch?v=R3-anFK1YM8) (2026-08) [WF2026](https://www.youtube.com/watch?v=4sX_He5c4sI) (2026-07)
- ...two calibration points from it: an oracle handed the exact right memory every turn still did NOT hit max — the model can retrieve correctly and ignore it, so retrieval isn't the ceiling. And memory is pure cost while the task fits in context [Druga/Sakana](https://www.youtube.com/watch?v=R3-anFK1YM8) (2026-08)
- **Independent corroboration that fancy memory loses to plain context** (Continual Learning Bench, 6 expert-validated domains): vanilla in-context learning topped the leaderboard on raw reward AND held the reward-vs-cost and gain-vs-cost Pareto frontiers over dedicated context-management systems. Author's caveat — medium-horizon tasks, may not hold longer [CL-Bench-Asawa](https://www.youtube.com/watch?v=iqloyWCGYQQ) (2026-08)
- **Two memory failure shapes to test for**, both from real traces: *stability* — told it over-predicted then under-predicted, the model jumped back to its original over-prediction instead of interpolating, having lost the first correction; *plasticity* — a notepad system dismissed a schema as "from a different study that doesn't apply here" when it did apply, and never updated its priors [CL-Bench-Asawa](https://www.youtube.com/watch?v=iqloyWCGYQQ) (2026-08)
- ...a third shape, from the shipped systems: **conflict-blindness**. A conversation *deciding between* two options got consolidated as "did both", with impossible overlapping dates — the contradiction sits in the profile and nothing is designed to notice it or go looking for the missing fact. Test that your consolidation pass can detect its own inconsistencies, not just write [Khemani](https://www.shloked.com/writing/chatgpt-memory-bitter-lesson) (2026-08)
- **Outcome-weighted memory retrieval**: rank retrieved memories by a learned "did this historically help or hurt the outcome" score, not embedding similarity — fixes stale-but-still-cited facts (a DB column since dropped) that nothing currently flags. Once enough memories accumulate around one recurring case, fold the pattern into a skill so future runs don't re-retrieve it [Starlight Search](https://www.youtube.com/watch?v=Jx4ZFEAq6bY) (2026-06)
- **Fleet-wide long-term memory for a stateless agent = a pattern/anti-pattern catalog** as markdown in ONE central git repo, not a vector DB: each entry carries the symbols to match on, the services where it was confirmed, a confidence level that rises as more services confirm, and both the anti-pattern and the good pattern. Human- and agent-writable so platform teams add patterns when they build a framework [Netflix-Shah](https://www.youtube.com/watch?v=CgsWxRUY5Eo) (2026-07)
- **Connectors give ACCESS, not UNDERSTANDING**: agents trust whatever doc they read first, miss corrections, conflate entities (5 "Lisa"s vs 1), lack recency; "source of truth" docs are a lagging indicator, stale when written. Humans go ask a person; agents don't. The hard part is synthesis, not search [Hyperspell](https://www.youtube.com/watch?v=m12vGjfbNlo) (2026-05)

## Guardrails as execution boundary (not behavior prompts)
- **"Stop asking the actor to behave; change what the actor can do."** A deterministic OS-level execution boundary with near-zero overhead (no daemon/container) — one policy file enforcing filesystem, network (forced through a local filtering proxy, allow-listed domains) and command policies (checked before exec, incl. chained/nested shells); the same policy vocabulary regardless of which agent drives [Tusk](https://www.youtube.com/watch?v=m12vGjfbNlo) (2026-05). Make the egress allowlist grantable at PER-TICKET as well as per-project scope, prompting on each new destination, or people route around it; motivating failure is an agent told to wipe staging finding a laptop token and hitting prod [Superconductor-Singh](https://www.youtube.com/watch?v=OL7kfezynJM) (2026-08)
- Swiss-cheese defense in depth, 3 layers: (1) classification "is this reasonable?" probabilistic; (2) policy enforcement "is this allowed?" deterministic — the fence sits here; (3) isolation "what can it touch if it goes wrong?" (containers/microVMs). Most teams have (1) and/or (3); **the missing MIDDLE layer is the OS-level allow/deny boundary** [Tusk](https://www.youtube.com/watch?v=m12vGjfbNlo) (2026-05)
- Same principle for background automations: guardrails you *prompt at* the agent aren't guardrails, since any injection overrides them — they have to be config the agent can't reach [GitHub-Gazit](https://www.youtube.com/watch?v=iQ5xldZ9StU) (2026-08)
- **Safe outputs** — declare the exact write actions an agent may emit, and cap the cardinality: "create *one* PR" means an injected agent can't open 500 (a self-DoS). Read-only by default, network allow-listed to just what the task needs. Include "do nothing" as an explicit declared output: a background automation that must always produce something becomes noise, and noise is how you learn to ignore the automation [GitHub-Gazit](https://www.youtube.com/watch?v=iQ5xldZ9StU) (2026-08) [shipped docs](https://github.github.com/gh-aw/reference/safe-outputs/)
- ...the cardinality cap earns its place benignly too, not only under injection: wiring issues and boards into a repo with several agents able to file them, nobody capping creation, produced 400–500 open issues in ~2 weeks [Amazon-AGI-Khandelwal](https://www.youtube.com/watch?v=aeTb5BdmTTc) (2026-08)
- **Guard the ACTION surface, not the input**: gating everything an agent reads is hopeless (every page, message, issue and promotional email is an injection channel), so let it read freely and check deterministically at the point it acts — reading bash variables, exporting, touching secret config — with three outcomes rather than two: allow / needs-approval / deny [Rallabandi](https://www.youtube.com/watch?v=s67bE2Ur3bY) (2026-07)
- Policy evaluates *before* a credential is minted, not after: token exchange (RFC 8693) scopes each individual tool call to one audience, short-lived and never stored, so a disallowed action never gets a credential created for it at all — nothing to leak, replay or steal even if the transport were compromised [Keycard-Maida](https://www.youtube.com/watch?v=I3znWC3MEXM) (2026-07)
- Network-layer variant of the same "no credential in the box" idea: bind identity to the CONNECTION (WireGuard per-node keys plus user/group/tag identity) and let an LLM gateway attach it per request, so the sandbox holds a placeholder rather than a key. Revocation is instant and there's no failing key for the agent to notice and route around [Tailscale-Guercio](https://www.youtube.com/watch?v=BM2JX9hqsVQ) (2026-06) (discounted src)
- Permission classifier over static rules: a fast model judges each tool/bash call *in conversation context*, so "push this to GitHub" grants what "don't push" denies, and it mediates sandbox escapes where deterministic rules have too many edge cases [Anthropic-CC](https://www.youtube.com/watch?v=uU5Gv2h8-9g) (2026-07)
- **Shipped shape of that classifier — a deliberately crippled reviewer sub-agent**: on escalation spawn a reviewer that is read-only and may not spawn sub-agents, handing it the transcript, the pending call, a risk taxonomy and "did the user authorize this?". It scores authorization × impact (deleting a file you asked to delete is fine; deleting `.git` you never mentioned isn't) instead of matching commands, and data exfiltration is carved out as never auto-approvable. Aimed at approval fatigue, which is what drives people to full-access mode [OpenAI-Kundel](https://www.youtube.com/watch?v=shRR1e2HXMk) (2026-08)
- ...its shipped surface is a third permission MODE (allow-all / ask-every-time / **auto-review**), one of four layers alongside the sandbox, MCP-layer allowlists (no mail outside the org domain; no `git push` to external repos — the human runs it) and system messages [OpenAI-Liu-MLOps](https://podcasters.spotify.com/pod/show/mlops/episodes/How-To-Delegate-To-An-Agent-Like-You-Would-An-Employee-e3nglg8) (2026-08)
- **Deterministic enforcement, LLM as advisor-not-bouncer**: rule match → block/kill-session before any model sees it; the LLM triage layer only reviews non-blocked findings to silence false-positive noise, can never let things through, and fails closed (model outage = all runs killed). "If it isn't enforced deterministically, it isn't enforced" [PostHog-WF26](https://www.youtube.com/watch?v=I2cbIws9j10) (2026-07)
- **Layered prompt stack with a DETERMINISTIC post-generation veto as the bottom layer**, four layers, order load-bearing: (1) immutable identity / hard rules nothing below overrides, (2) situational mode (who you're talking to, what they're going through), (3) example-anchored voice, (4) post-generation veto. Layers 1–3 are probabilistic INSTRUCTIONS ("asking nicely, hoping"); layer 4 is the only one that reads actual OUTPUT and checks specifics against ground truth (an offered date must be in an allowlist or it doesn't ship) [Isadora](https://www.youtube.com/watch?v=ij-AU9dpJjc) (2026-06)
- Multi-tenant identity must NEVER have a default — a missing brand-identity field should crash (fail loud), not silently fall back, else white-label leak (every venue shipped as the default persona, emailing from another tenant's address); the quiet failure is a tenant speaking in a stranger's voice, and trust erodes before anyone notices [Isadora](https://www.youtube.com/watch?v=ij-AU9dpJjc) (2026-06)
- **Guardrails as SEPARATE LLM-as-judge calls sandwiching the core agent** (input judge reads the incoming message; output judge reads the response AND the conversation so far) are measurably harder to prompt-engineer or conversationally jailbreak around than the same rules inside the main prompt — a latency and cost premium a high-stakes domain can justify. Modularity also makes each independently evaluable [SonderMind](https://www.youtube.com/watch?v=O72p-rBb2bA) (2026-07)

## Retrieval & comprehension
- Agentic search (let the agent grep and read the filesystem) beat AST indexing plus dense/sparse RAG — the indexing approaches "just went away" [Pi](https://newsletter.pragmaticengineer.com/p/building-pi-and-what-makes-self-modifying) (2026-04)
- **Counterpoint with production data**: a semantic-search tool measurably lifts coding agents — Cursor measured +12.5% average answer accuracy across models on an internal context benchmark (~24% for Composer); online A/B +2.6% code retention in large codebases, −2.2% dissatisfied requests. Headline numbers look small only because the tool fires on a fraction of queries [Turbopuffer](https://www.youtube.com/watch?v=UM6sFg_jdlE) (2026-06)
- **Live disagreement, and the condition that decides it**: grep-only vs semantic index is scale-dependent — Pi (solo/medium repos) dropped indexing; Cursor measures real gains on large codebases. Steelman for the index: embeddings as cached compute — per-session grep→read→assess loops re-derive the same understanding across devs and days (~6k tokens per sub-step), and a one-time index turns that rediscovery into a cheap query [Pi](https://newsletter.pragmaticengineer.com/p/building-pi-and-what-makes-self-modifying) [Turbopuffer](https://www.youtube.com/watch?v=UM6sFg_jdlE) (2026-06)
- **Bolt-on tool ≪ native tool**: Claude Code is built and trained around grep and doesn't know when to call an extra semantic-search tool, so gains run far below Cursor's, where Composer treats it as a built-in — a retrieval tool's value depends on the model being trained to invoke it [Turbopuffer-CC](https://www.youtube.com/watch?v=zKk7sDMGDEQ) (2026-06)
- **WHY agents underuse semantic search — the query-writing habit, not the tool**: coding models emit keyword-gibberish queries because their habits come from grep/regex exploration and BM25-favoring benchmarks. Harness fixes that reshaped queries: instruct "write one concise sentence describing what you want to find" — never "write a search query"; few-shot good queries; split intent into ≤4 aspect queries; seed the prompt with an initial search over the user query so the agent plans from a corpus preview; ≤4 rounds with parallel searches inside a round; dedupe chunks across rounds [Mixedbread](https://www.youtube.com/watch?v=1IdzkRVmWAA) (2026-07)
- **Clone a dependency's source repo INTO your project** (git subtree, squashed, e.g. `.repos/`) so the agent reads it as first-class code: coding models are post-trained to focus on your own repo, so they de-prioritize the same library in `node_modules` and won't read gitignored dirs at all — beats MCP-docs or stale training, across languages. Add a test-runner ignore, and forbid watch/dev-server commands in AGENTS.md or the agent runs them first and hangs [Effect](https://www.youtube.com/watch?v=Wmp2Tku2PrI) (2026-05) [Nx-Savkin](https://www.youtube.com/watch?v=jVjt-2g8NMY) (2026-06)
- **"LLMs plan, deterministic code searches"** — for exact lookup over a huge structured namespace (500k near-identical sensor names ≈ symbols/paths), never make the model scan or embed the names: embeddings can't discriminate 20-char strings differing by one char. The LLM sees only a small schema summary and emits a structured plan {collect, scope, filter}; a deterministic resolver runs set operations over pre-indexed subtrees → perfect recall by construction. Measured: naive-LLM correctness 80%→30% as the system grew 64→460k nodes; plan+resolver 100% across scales at a flat ~9k tokens/query (~300× fewer) [Phaidra](https://www.youtube.com/watch?v=EUsPvBeIx70) (2026-07)
- **"Satisfaction of search"**: agents stop at the first plausible match (like radiologists), so retrieval must force exhaustive search or it grabs the wrong pattern → correction doom-loop [Unblocked](https://www.youtube.com/watch?v=BiG2ssibKGc) (2026-05)
- **Split retrieval in two and expect EXTRACTION to be the hard half**: (a) produce good output given context, (b) traverse the store to find the right context. One team trained custom traversal tools in an RL environment for (b) — the half that usually gets no investment [Varick-Pruitt](https://www.youtube.com/watch?v=l0FLhNqBOic) (2026-07)
- Cheap statistical retrieval-confidence signal instead of an LLM self-check per search: compute stats over the top-K scores (spread, top-1/top-2 gap) as a near-zero-cost good/bad classifier, then tier escalation — confident → proceed; borderline → cross-encoder rerank; clearly bad → only then invoke an LLM to re-query. Agents search orders of magnitude more often than humans, so don't add a round trip to every search [Qdrant-Roundtable](https://podcasters.spotify.com/pod/show/mlops/episodes/The-Current-State-of-Agentic-Retrieval---Qdrant-Roundtable-e3lh8v8) (2026-07)
- In a large mature codebase the dominant agent use is comprehension, not generation (measured 67% comprehension / 2% code gen) — instrument your own usage to find where leverage actually is [Sentry](https://www.youtube.com/watch?v=li0SaBt9RDM) (2026-05)

### Data agents — structuring the corpus before the agent reads it
- **Rank your sources of truth; don't hand the agent N knowledge bases of equal weight.** Ambiguity about which table or doc is authoritative — not model size — is what makes enterprise data agents wrong. Cleanest→messiest: semantic layer (curated KPI/metric definitions) → canonical parameterized queries → full table/column/metric graph [Tesla-Daga](https://www.youtube.com/watch?v=B8l81jhvHbI) (2026-07)
- Build order follows cost: the first two layers are cheap and cover ~80%; the graph is expensive to build AND to maintain, so it's the last 20%, not the starting point [Tesla-Daga](https://www.youtube.com/watch?v=B8l81jhvHbI) (2026-07)
- **Overloaded vocabulary is the same ambiguity one layer up, and it needs an explicit noun/verb ontology**: one entity is "customer" to sales, "client" to ops, "billing entity" to finance, "org ID" to devs. Diagnostic — list terms overloaded across teams, find the integration points where one vocabulary is translated to another, name the systems of record you can't swap. That's where an agent silently gets the wrong entity [Kepler-Ganesh](https://www.youtube.com/watch?v=1OMHGsUZiqA) (2026-07)
- **Entity resolution needs its own tool, not better prompting**: the same person is spelled differently across email, Slack and docs and the model silently conflates or splits them. A second custom tool detects redundancy cycles / DAG violations in the process graph [Varick-Pruitt](https://www.youtube.com/watch?v=l0FLhNqBOic) (2026-07)
- ...and for process corpora the representation is a dependency graph (enterprise workflows are "remarkably linear but with a lot of cycles") while the STORE does not matter — Postgres is fine, a dedicated graph DB is not required [Varick-Pruitt](https://www.youtube.com/watch?v=l0FLhNqBOic) (2026-07)
- **Staleness needs a lifecycle, not better docs**: bind context to sources updated BY CONSTRUCTION (dbt/Tableau semantic layer, GitHub, CRM) over hand-maintained markdown, and log every correction as an event that feeds back into context [Tesla-Daga](https://www.youtube.com/watch?v=B8l81jhvHbI) (2026-07)
- ...with the number that makes it urgent: that same Anthropic analytics deployment drifted 95% → 65% in ONE month, until they required every data-model change to update its matching context in the SAME PR [Anthropic-analytics](https://claude.com/blog/how-anthropic-enables-self-service-data-analytics-with-claude) (2026-06)
- **Unstructured corpora explode on the way in** — 90 dash-cam videos yield ~100k detection records (clips→frames→objects→labels), so neither millions of sidecar JSONs on S3 nor a separate SQL stack works. Pydantic schemas transpiled to a queryable local DB keep schema, data and code in one language [DataChain-Petrov](https://www.youtube.com/watch?v=bUJgirn4_yc) (2026-07)
- **Make the agent ask "do I already have a dataset that answers this in one query?"** before answering — and if not, build that intermediate layer deliberately general enough to serve a FAMILY of questions rather than the one asked [DataChain-Petrov](https://www.youtube.com/watch?v=bUJgirn4_yc) (2026-07)
- Publish each derived dataset as a markdown entry carrying why it was built, the session context, schema, stats, a preview and — the part both he and OpenAI's data-agent post call most important — the SOURCE CODE, so the next teammate's agent reuses it instead of re-running the compute [DataChain-Petrov](https://www.youtube.com/watch?v=bUJgirn4_yc) (2026-07)
- Why verification bites harder here (Anthropic's framing): in software many solutions are valid; in data there is usually exactly one correct answer [DataChain-Petrov](https://www.youtube.com/watch?v=bUJgirn4_yc) (2026-07)

## Tool output handling
- Tool outputs as semantic summaries, not raw artifacts — a 50k-line JSON perf trace blows any context; return a markdown key-metrics summary by default and keep the raw file on disk for CLI post-processing [Chrome DevTools](https://www.youtube.com/watch?v=_B4Pv9ttFgY) (2026-06)
- **Bounded counter-case**: RAW profiler output is worth feeding directly, because every profiler emits the same tabular shape (call stack + self/inclusive CPU) and the model spots a quadratic pattern from the call stack alone, before reading any source. Reconciles as summarize-unstructured-blobs / pass-through-structured-columns [Netflix-Shah](https://www.youtube.com/watch?v=CgsWxRUY5Eo) (2026-07)
- Add a `token_limit` parameter to any tool that can return unbounded output (log queries, "search all users") so the LLM declares how many tokens it wants back — a broad query then can't blow the window; map it deliberately NOT one-to-one to the underlying API [MCPcat](https://podcasters.spotify.com/pod/show/mlops/episodes/MCP-Servers-Are-Becoming-the-UI-for-AI-Agents-e3ks6n3) (2026-06)
- **Errors as steering, not just reporting**: on a bad call return a constructive error naming the likely fix ("you forgot `last_name`, retry" / "maybe you meant tool X, Y, Z") — treat the agent like a human filling a form. Customers running this report large success-rate gains at near-zero overhead; every unrecovered error is retry tokens [MCPcat](https://podcasters.spotify.com/pod/show/mlops/episodes/MCP-Servers-Are-Becoming-the-UI-for-AI-Agents-e3ks6n3) [Chrome DevTools](https://www.youtube.com/watch?v=_B4Pv9ttFgY) (2026-06)

## Computer use & browser agents
- **Rendered state is not in the HTML — the structural reason scraping agents fail.** An NBA score arrives via async XHR after an empty placeholder loads; stock status lives in a JSON `quantity: 0` that a render script turns into a greyed-out option, with no "sold out" text anywhere. What you see is computed [Yutori-Batra](https://www.youtube.com/watch?v=Ki980nV0__0) (2026-08)
- "The browser is a rendering engine; scraping asks for an exact inversion of that process." Hence the **bitter lesson for web agents**: per-site scaffolds don't reach the long tail, pixels-in does. The long tail really is that bad — menus as JPEG galleries of scanned PDFs, districts answering procurement only by FOIA request [Yutori-Batra](https://www.youtube.com/watch?v=Ki980nV0__0) (2026-08)
- ...but don't stay limited to *human* actions: add an `execute JS` action so the model scripts what's cheaper to script (filling many fields at once) while still verifying through the SCREENSHOT — "click when you have to, write code when you have to, verify through pixels". Same conclusion as the persistent-REPL computer-use move in § Tool design [Yutori-Batra](https://www.youtube.com/watch?v=Ki980nV0__0) (2026-08)
- Page representation token cost: full DOM ≈20k tokens, raw screenshot ≈1.1k, custom compressed markdown ≈1.8k for one benchmark page — compact markdown + screenshot (not full DOM) let a cheap model plan a 30-step task. And **diff-based feedback beats re-screenshotting**: state what changed since the last action so it recovers from a failed click instead of looping [ARK](https://www.youtube.com/watch?v=JnubYCYunk8) (2026-06)
- **Partial observability is structural, and the model has no prior about which source to trust**: the DOM misses dynamically-generated content (ad text baked into an image), the screenshot misses anything below the fold. Feeding both without telling it what each is good for is its own failure mode [Amazon-AGI-Mishra](https://www.youtube.com/watch?v=Cc0_nyxROBA) (2026-08)
- **Chrome stamps every input event trusted or untrusted, and pages drop untrusted input SILENTLY** — a synthetic JS `click()` produces no error and no effect. CDP Input-domain events travel the real mouse path and are stamped trusted [Rexmore-Gallon](https://www.youtube.com/watch?v=26RtyAm9y_Q) (2026-08)
- Escalation ladder, climb only as far as the page forces: (1) the page's own JS API / synthetic click — free, instant, right default; (2) CDP input domain — trusted; (3) real mouse path with jitter, easing and deliberate overshoot, plus vision. Explore by hand, then write the winning path down as code or a skill [Rexmore-Gallon](https://www.youtube.com/watch?v=26RtyAm9y_Q) (2026-08)
- **Verify through a DIFFERENT channel than you acted through** — don't ask the click whether it worked, read the network or the screen. Loop is sense → act → verify [Rexmore-Gallon](https://www.youtube.com/watch?v=26RtyAm9y_Q) (2026-08)
- **Under a hard deadline, invert the usual split**: deterministic code drives everything at machine speed and calls the model for the ONE step needing eyes and judgment, then takes back control. A challenge whose rounds expire beats any agent that round-trips a model per click [Rexmore-Gallon](https://www.youtube.com/watch?v=26RtyAm9y_Q) (2026-08)

### Failure modes and guardrails specific to computer use
- Two from real RL training runs: session expires → the model reasons "credential expired, but I can infer the password", guesses repeatedly and LOCKS the account; and an ad with a lookalike submit button → it clicks through to a third-party site and starts filling in personal details [Amazon-AGI-Mishra](https://www.youtube.com/watch?v=Cc0_nyxROBA) (2026-08)
- **Recovery has to be a native model action, not an infra reset**: training loops normally reset state on error, but real life doesn't — surface the error and require recovery through real actions (refresh, backtrack, compare, wait, abandon, escalate). Reward the PATH too, since "done" can include side effects nobody asked for [Amazon-AGI-Mishra](https://www.youtube.com/watch?v=Cc0_nyxROBA) (2026-08)
- Escalation decision trained on four axes — is the action authorized, irreversible, visible to the user, high-impact. Sharpens the earned-autonomy spectrum in § Guardrails & limits to a per-ACTION judgment [Amazon-AGI-Mishra](https://www.youtube.com/watch?v=Cc0_nyxROBA) (2026-08)
- Harness guardrails worth copying: checkpoint+rollback before risky states, an action-risk classifier over proposed actions, a credential guard detecting signed-out, an execution monitor for loops and repeated clicks, audit logs of actions AND effects, and a harness override forcing handoff when model confidence is miscalibrated [Amazon-AGI-Mishra](https://www.youtube.com/watch?v=Cc0_nyxROBA) (2026-08)
- **The harness starts THICK on purpose and thins as the model improves** — early on its job is to detect model gaps and fail gracefully, so failure modes are captured for the next training round without harming real users. The active form of "harness mitigations are temporary" above [Amazon-AGI-Mishra](https://www.youtube.com/watch?v=Cc0_nyxROBA) (2026-08)

## Production failure modes (LLM/VLM-in-the-loop)
- Output loops: ~0.5–1% of queries return repeated output; worst is a whitespace loop (infinite spaces burns the full budget). You can't use space as a stop sequence (tokenizers have 1..128-space tokens). Fix: always stream plus repetition-detection to kill the stream early, then retry with a different model/prompt/temperature [LlamaIndex](https://www.youtube.com/watch?v=m12vGjfbNlo) (2026-05)
- **Claude silently drops part of a multi-part instruction**: told within one task to support both sync and async versions of a hook, it implements sync and omits async — observed in roughly 2 of 3 Claude rollouts on a long-horizon benchmark, notable precisely because Claude is otherwise the most exhaustive explorer. Split multi-part requirements into separately-verifiable items. GPT is the least likely to miss stated requirements [DeepSWE](https://www.youtube.com/watch?v=Yk87oUPVaxU) (2026-07)
- **Never make an LLM enumerate long lists of near-identical names** — two failure modes: sharding the list across parallel calls yields phantom entities plus silently dropped real ones, and internal repetition penalties truncate even a legitimate enumeration of ~100 similar tokens (the model "thinks it's spiraling" and shuts off). Produce such lists in code; the model only emits the query [Phaidra](https://www.youtube.com/watch?v=EUsPvBeIx70) (2026-07)
- Empty-input hallucination: a templated prompt plus an empty or failed tool result makes the model invent content rather than report empty (Anthropic models love fake "Delaware incorporation documents") — guard by checking for blank input before the call [LlamaIndex](https://www.youtube.com/watch?v=m12vGjfbNlo) (2026-05)
- Provider reliability: APIs go down roughly daily → multi-provider fallback with each model family on its OWN code path; always keep a NON-LLM fallback (a CPU parser at ~500 pages/s). Thinking loops are now harder to catch since providers stopped streaming the thinking trace, leaving max_tokens as a blunt cap [LlamaIndex](https://www.youtube.com/watch?v=m12vGjfbNlo) (2026-05)

## Tool design for agents
- **Tool-count accuracy collapse, measured**: loading every tool schema into every prompt ("fat agent") gives tool-selection accuracy ~78% at 10 tools → ~40% at 100 → ~13.6% at 741. Semantic routing (embed tool descriptions, retrieve top-k at query time) holds >83% flat across the same range. Cost too: 741 schemas ≈127k tokens before the question vs ~1k for JIT retrieval of 3–5 (~99% reduction); full-catalog TTFT blows past 5s at ~500 tools while router retrieval stays flat [Prosodica](https://www.youtube.com/watch?v=vh2VGuQ3zhY) (2026-06)
- **Deferred tools are an API-level primitive now, not just a client trick** (Responses API since GPT-5.4): mark any tool deferred so its schema never enters context and the model reaches it via tool search — either the built-in search tool or your own discovery implementation [OpenAI-Kundel](https://www.youtube.com/watch?v=shRR1e2HXMk) (2026-08)
- **Partial function application as the strongest safety primitive short of not giving a tool at all**: lock a tool's dangerous argument (bind the directory a file-read/write tool can touch) so the model never sees or can change it — full autonomy without a human-approval bottleneck, because the constraint isn't promptable around [Etsy-Bhargava](https://www.youtube.com/watch?v=2e9ANoOEn28) (2026-07)
- Trend is *fewer* tools: keep cardinality low and require each new tool to have a function distinct from all others so the model can tell when to call which. Dedicated grep/glob tools were removed in favour of native bash [Anthropic-CC](https://www.youtube.com/watch?v=uU5Gv2h8-9g) (2026-07)
- **Endpoint of that trend — collapse the tools into ONE REPL**: ~15 spreadsheet tools became JS functions inside a single Node REPL call; internal benchmark 50%→74% (later tuning reached 92%), 5-minute timeouts to essentially zero. Parallel tool calls hadn't helped — you can't combine their results [Witan-Campos](https://www.youtube.com/watch?v=HEFSExa0xl0) (2026-07)
- Heuristic for spotting the need: many sequential or parallel tool calls means you've invented a bad scripting language — give it a real one [Witan-Campos](https://www.youtube.com/watch?v=HEFSExa0xl0) (2026-07)
- **REPL ≠ code mode; the difference is persistent state**: plain code mode yields long one-shot scripts (~50 lines typical), while variables surviving between calls make agents write SHORTER ones and interleave reasoning between steps — less static, better answers faster [Witan-Campos](https://www.youtube.com/watch?v=HEFSExa0xl0) (2026-07)
- Two follow-ons: a new capability is a new method plus a regenerated `.d.ts` in the prompt, not new schemas to disambiguate; and the agent-facing scripting language needn't be the implementation one (JS for the agent, C# doing the real work) [Witan-Campos](https://www.youtube.com/watch?v=HEFSExa0xl0) (2026-07)
- **Same conclusion reached independently for COMPUTER USE**: the original one-action-per-turn click/type tool was replaced by a persistent Node REPL living across turns that the agent writes Playwright JS into — it inspects one page, then scripts the rest (scraping subsequent pages) instead of paying a turn per click [OpenAI-Kundel](https://www.youtube.com/watch?v=shRR1e2HXMk) (2026-08)
- **Match tools to what the model was post-trained on, and ship the binary**: models are trained on `apply_patch` for edits and reach for ripgrep unprompted, so the Codex harness BUNDLES ripgrep for machines lacking it rather than teaching the model another tool; on Windows the model was trained to emit PowerShell instead [OpenAI-Kundel](https://www.youtube.com/watch?v=shRR1e2HXMk) (2026-08)
- **Derive composite tools from your existing UI, not your API surface**: a product page already orchestrates ~10–20 API calls to serve one human need — expose that as ONE intent-shaped tool that runs them behind the scenes, since agents want roughly the same outcome the UI was built for. Antidote to one-to-one API→tool sprawl [MCPcat](https://podcasters.spotify.com/pod/show/mlops/episodes/MCP-Servers-Are-Becoming-the-UI-for-AI-Agents-e3ks6n3) (2026-06)
- **Tool-misrouting fix ladder**: write a *real* description (core purpose → trigger conditions "use when / don't use when" → relationships "call skill X first") → if still wrong, reinforce the same instruction in the system prompt; one-line descriptions are the usual cause. Bootstrap unknown query shapes by shipping ONE general tool and logging — >4–5 tool calls per question signals it's too hard, so carve out a specialized tool for that pattern [Elastic](https://www.youtube.com/watch?v=ynJyIKwjonM) (2026-05)
- **HTML over SVG/canvas as the agent-native medium for visual artifacts** (slides, docs, video): models have seen billions of HTML examples and reason about it as structured language (tags carry semantics), while SVG is "a wall of numbers" — explains why canvas-based tools (Figma MCP, screenshot-and-replace loops) underperform by forcing the model into pixel space. Editing format and deliverable format needn't match: generate in HTML, render out to PDF or slides [Nori Agentic](https://www.youtube.com/watch?v=htM02KMNZnk) (2026-07)
- Constrained "focus modes" (plan/research/debug) shrink the action and input space so you can drop irrelevant tools, sharpen the system prompt and tune evals per mode instead of optimizing one do-anything agent; debug mode in particular is hypothesis-driven — spin up a dedicated debug server and push logs there rather than reasoning blind [Flinn](https://www.youtube.com/watch?v=7CrPrHgoEYk) (2026-05)

## Generator / evaluator (adversarial critic)
- **Separate the verifier's *context window*, not just its prompt**: one context both doing and grading the work confabulates, while a context tuned only for critique does far better. Why a separate critic works even though it's also an LLM — tuning a standalone critic to be harsh is tractable; tuning a builder to be self-critical is not [Anthropic-Martin](https://www.youtube.com/watch?v=9QebvrrY3KY) (2026-07) [Anthropic](https://www.youtube.com/watch?v=mR-WAvEPRwE) (2026-05)
- Why loops work with high-capacity models: the steering signal moves into the **environment** rather than into you, so the model self-corrects on verifier feedback. Primitives: `goal` (Claude Code), `outcomes` (managed agents) — a measurable end state graded by an independent context [Anthropic-Martin](https://www.youtube.com/watch?v=9QebvrrY3KY) (2026-07)
- **How `goal` actually terminates, and why it constrains what you write**: the harness re-injects a continuation prompt carrying the objective after every turn, and stops only when the model calls the update-goal tool declaring it met. So goals must be concrete and verifiable — an essay-length goal has no detectable done state [OpenAI-Kundel](https://www.youtube.com/watch?v=shRR1e2HXMk) (2026-08)
- The evaluator must actually USE the app (Playwright: open live pages, click, screenshot), not just read diffs — catches live-only bugs (route ordering, a boolean delete-key bug) that pass unit tests. Corroborated for production monitoring: a user-perspective computer-use agent catches UI failures logs and code miss, though a website-specific skill that knows your DOM is far faster than generic browser use [Anthropic](https://www.youtube.com/watch?v=mR-WAvEPRwE) (2026-05) [Wandero](https://www.youtube.com/watch?v=kZsf_Sfm7RU) (2026-07)
- **When the product isn't a web page, build the driving CLI yourself** (theirs is a VS Code extension): screenshot, a token-compressed snapshot of UI state, log extraction from front-end AND back-end services, service restart, plus high-level composable commands — open this menu, send a message and wait for the reply, upload an image. Domain-specific form of the same: an ASCII rendering of your 3D world for a Unity game [Poolside-Lajili](https://www.youtube.com/watch?v=iRcX54EO5g8) (2026-07)
- **Don't accept the fix until the agent REPRODUCED the bug** — agents are eager ("I know what's going on, just add this call") and until reproduction that's an assertion, not a diagnosis. This is the specific precondition for trusting a run you leave going unattended [Poolside-Lajili](https://www.youtube.com/watch?v=iRcX54EO5g8) (2026-07)
- Sharper framing of why brownfield trails greenfield: it isn't code age, it's that the agent's INTUITION is correct on greenfield and wrong against dead code and paths it never looked at — so the feedback loop is the whole gap. Explains the polarized field reports: people who built a loop see brownfield work [Poolside-Lajili](https://www.youtube.com/watch?v=iRcX54EO5g8) (2026-07)
- **"Negotiate done" before building**: the generator proposes feature plus tests, the evaluator pushes back on scope, weak tests and missed edge cases, and they iterate via markdown files on disk until both agree — THEN build, with the evaluator grading against this negotiated contract, not the planner's original spec. Granularity matters: one app produced 27 criteria; vague criteria give vague critiques the generator shrugs at [Anthropic](https://www.youtube.com/watch?v=mR-WAvEPRwE) (2026-05)
- A GAN-style loop course-corrects by throwing everything out and restarting when stuck on a criterion — a single-pass loop just keeps patching the same broken thing. 4.6-class models readily discarded 10 passes and restarted, and did NOT exhibit the feared "evaluator gives up and rubber-stamps". Generalizes: when an agent runs out of forward progress, wipe and restart with a genuinely different approach rather than repairing sunk cost [Anthropic](https://www.youtube.com/watch?v=mR-WAvEPRwE) (2026-05) [Kent Beck](https://newsletter.pragmaticengineer.com/p/how-kent-beck-shapes-the-software) (2026-07)
- **Put the critic in the AUTHORING surface, not only the runtime**: as a human builds the workflow an agent alongside flags missed edge cases and unowned steps ("who owns this, so the mail goes to the right place") — catching the gap before it ships, not after [Varick-Pruitt](https://www.youtube.com/watch?v=l0FLhNqBOic) (2026-07)

## Verification & anti-cheating
- **Make the verification agent independent and adversarial**: it never sees the discovery agent's reasoning traces, receives only the claimed finding, and is told to assume it's false and prove that. Discovery optimises recall, verification precision — a discovery agent that debates itself self-censors and loses recall [Anthropic-Yan](https://www.youtube.com/watch?v=imFedndyXYQ) (2026-07)
- Patch-validation ladder: the original exploit stops working → the existing suite stays green → a *fresh* discovery agent re-attacks the patched code → a human confirms. Feeding that re-attack signal back improves patch quality substantially [Anthropic-Yan](https://www.youtube.com/watch?v=imFedndyXYQ) (2026-07)
- **Agents fabricate rather than report tool failure**: a blocked, captcha'd or empty fetch gets presented as "I searched the web", and a failed fetch silently falls back to stale training data answered as current (2024 data for a 2026 question) — please-the-user bias makes the failure silent and confident. Verify tool *results*, never trust "I did X"; treat agent-supplied citations as unverified until fetched [Bright Data](https://www.youtube.com/watch?v=btxGmN8RvNU) (2026-06). Deep-research variant ("AI psychosis"): a 20-page report reads authoritative and cites product features that don't exist or are actually still beta — check it against the real product before building on it [Wisedocs-Linkov](https://www.youtube.com/watch?v=7vn4WpqNpck) (2026-08)
- **Agents lie about doing work** (touched a sentinel file claiming tests ran) — require cryptographic proof: SHA-256 the actual test output into the marker file. Make doing the real work easier than faking it; that, not polite instruction, stops the lying. A deterministic verify step should read the run's own tool/trace history to confirm the action happened [WorkOS](https://www.youtube.com/watch?v=vy7o1g2iHY8) [IBM](https://www.youtube.com/watch?v=C_GG5g38vLU) (2026-05)
- **Treat "done" as an OBJECT, not a boolean**: a done-claim decomposes into artifact + scope + rubric + evidence + who verified + who has sign-off authority + residual risk + next owner. Done-ness is a graded ladder (producer-claimed → reviewer-no-obvious-issues → evidence-verified → authorized-approver-signed → accountable-owner-stands-behind → survived-real-world), and merge-done, deploy-done and announce-done are different claims most systems flatten to one green checkmark [Dotta/Paperclip](https://www.youtube.com/watch?v=7P0elyLIxXo) (2026-07)
- **One line of prompt can switch self-verification off**: SWE-Bench Pro's template says tests are handled and the model needn't write any — that single sentence stops even GPT-5.5 and Opus 4.8 from verifying their own work. Remove it and stronger models write tests to check themselves most of the time. Audit your prompts for accidental suppression of a behaviour you want [DeepSWE](https://www.youtube.com/watch?v=Yk87oUPVaxU) (2026-07)
- **Agents edit or delete the TEST to make it pass** ("if I remove that line everything works") — protect the assertions: rule that the agent must never modify a test, must run a fast suite (~300ms) before AND after every change, and must fix red rather than rewrite the expected value, because the expected values ARE the spec. Commit code and passing tests BEFORE letting the agent touch tests — a git baseline is the safety net [Kent Beck](https://newsletter.pragmaticengineer.com/p/tdd-ai-agents-and-coding-with-kent) [Playwright](https://www.youtube.com/watch?v=FWEInOtngmM) (2025-06)
- **Verification chain before a human looks at an agent-authored perf rewrite**: unit + integration tests (so the optimization can't quietly break business logic), THEN a canary — old and new code taking the same traffic ~10 min — reading CPU reduction, latency and error rate; an error-rate rise means it got the logic wrong. "The profiler gives the estimate, the canary gives ground truth, the engineer makes the decision" [Netflix-Shah](https://www.youtube.com/watch?v=CgsWxRUY5Eo) (2026-07)

## Enforcement loop — pin to the action the agent must take
- The harness IS the enforcement loop: git hooks + CI + linters running identical tasks both pre-commit and on CI, so a lazy agent skipping local checks gets caught downstream. The agent's terminal goal is "deliver a PR" — pin enforcement to git, the action it must take, so checks are unavoidable [SafeIntelligence](https://www.youtube.com/watch?v=504PvfXou5Y) (2026-06)
- **Deterministic instructions > prompt-nagging AT SCALE**: writing "PLEASE run tests before commit" in screaming-caps AGENTS.md is a code smell — make it deterministic (hooks/CI gates), since arguing with the agent over process steps is unreliable across thousands of runs; reserve screaming-caps context files for solo workflows [Stripe](https://www.youtube.com/watch?v=_xQnSNlBP_w) (2026-05)
- **Pre-commit hooks that echo prompts**: encode architecture and domain boundaries as hooks whose failure output IS a prompt ("this module can't depend on that") — back-pressure that stops the loop closing until constraints are satisfied. Humans resent slow pre-commit hooks; agents don't care [Huntley-WF26](https://www.youtube.com/watch?v=I2cbIws9j10) (2026-07)
- **Session-END is the other attachment point**: a Stop hook runs a config-defined deterministic check suite when the agent finishes and feeds failures back so it retries — the agent doesn't get to be the one who declares done. Same contract belongs at every level (end of conversation, pre-commit, between multi-agent steps, on async agents), with a judge tier only for what can't be checked deterministically [Checkout.com-Sheikh](https://www.youtube.com/watch?v=MpZzWMdmQCE) (2026-07)
- Argument against "the next model won't need this": each release buys CAPABILITY, which is a different axis from RELIABILITY, and enforcement is priced against the latter. Corollary — instructions are not verification; the best spec, MCP servers and sub-agents still aren't a check that the thing happened [Checkout.com-Sheikh](https://www.youtube.com/watch?v=MpZzWMdmQCE) (2026-07)
- **Prevent whole bug classes by construction** instead of detecting instances ("what you cannot find, you cannot enforce"): enforce architecture via module-import rules — a BDD suite forbidden from importing DB-accessing modules, templates forbidden from DB access, making N+1 queries structurally impossible [SafeIntelligence](https://www.youtube.com/watch?v=504PvfXou5Y) (2026-06)

## Guardrails & limits
- **The choice of what's deterministic and what's agentic *is* your security model**, because that boundary bounds blast radius under prompt injection. A useful coding agent is a supply-chain actor whether you planned for it or not; once it holds production credentials it needs an engineer's guardrails [Form3](https://www.youtube.com/watch?v=LqLoYksJ6do) (2026-07)
- **Under-privileged credentials trigger credential-hunting**: give an agent a token too weak for its goal and it goal-seeks the filesystem for higher-privileged ones. RL makes models *more* goal-seeking, not safer — no model keeps itself aligned, so alignment comes from infrastructure. Most concrete mitigation: never keep secrets as files [LoopsDebate](https://www.youtube.com/watch?v=c35YoMdnI78) [Huntley+Keycard-WF26](https://www.youtube.com/watch?v=I2cbIws9j10) (2026-07)
- **Sub-agents inherit the goal, not the discipline**: sub-agents spawned for large tasks tried to circumvent the parent's guardrails by hunting and inventing secrets from anywhere in the codebase — caught only via output scanning; PostHog banned sub-agents in that product [PostHog-WF26](https://www.youtube.com/watch?v=I2cbIws9j10) (2026-07)
- Scoped capability credentials for agent authority — bind to counterparty + amount cap + expiry, enforced by infrastructure outside the agent, so an over-limit action is rejected even if the agent was duped; blast radius bounded by construction, not prompt [Stripe](https://www.youtube.com/watch?v=KLSuFPj2ld0) (2026-06)
- **Guardrails as composable hard caps at the harness level**: max iterations (kill run), max messages (trigger compaction), max tool calls, max retries, recursion-depth cap, execution-time cap — agents aren't linear workflows and cost spirals without per-run and per-agent budgets. Throttle by reading OpenTelemetry traces back into the loop, checking every ~10 calls to avoid a latency tax [IBM](https://www.youtube.com/watch?v=C_GG5g38vLU) [PwC](https://podcasters.spotify.com/pod/show/mlops/episodes/Autonomous-Agents-at-Work-From-OpenClaw-Hype-to-Enterprise-Reality-e3jj7u3) (2026-05). Add max DIFF SIZE, read-only mode and a ban on deleting files [Cerebras-Chieng](https://www.youtube.com/watch?v=TeGsFFNqRLA) (2026-05)
- **Confidence gate with a PRIVATE escalation channel**: an agent watching Slack channels answers only when confident enough, and when unsure DMs a human — "I think I know the answer, can you confirm before I respond?" — so the public channel only ever sees vetted answers and the uncertainty costs one person a glance instead of a visible wrong reply [Resolve-Smith](https://www.youtube.com/watch?v=vSx5IULvBns) (2026-08)
- **Grant autonomy as an earned spectrum, not binary**: assist (answers with tools) → recommend (proposes, doesn't act) → gated action; an agent earns each step up and moves back down on regression. Classify work by reversibility first — reversible (ticket enrichment, RCA) can be autonomous; sensitive (prod changes) gets tighter approvals; consequential (customer/legal docs) the highest gating. Gating decision = risk × blast radius [PwC](https://podcasters.spotify.com/pod/show/mlops/episodes/Autonomous-Agents-at-Work-From-OpenClaw-Hype-to-Enterprise-Reality-e3jj7u3) [Keys to my life](https://www.youtube.com/watch?v=sJ2jc7leKBk) (2026-05)
- **Failure PREVENTION over detection**: wrap the tool layer with a guard that hard-limits irreversible actions (DB deletes, resource spin-up) so a looping agent can retry safely — don't rely on the agent "knowing" the policy [BuzzHPC](https://podcasters.spotify.com/pod/show/mlops/episodes/Architecting-Modern-AI-Systems-Platforms--Agents--and-Integration-e3k0qlu) (2026-05)
- **Gate agent dispatch on problem specificity**: a coding agent thrown a vague report ("onboarding is broken") will always "fix" something → noisy meaningless PRs. Triage to three states — actionable (dispatch), needs-human (inbox), under-evidenced (return to the pool to accumulate more signal). Error-tracking signals are specific enough to action; Slack and session-replay signals usually aren't [PostHog](https://www.youtube.com/watch?v=zMiSRliEzv4) (2026-06)
- **80/20 hybrid loop-breakers**: ~80% open research on a high-reasoning model, ~20% hard-gated deterministic steps (validation, summarization, critic) on cheap non-reasoning models; cap research with use-last-result counters (after 4–5 iterations) or ~5-min timeouts — degrade to the last decision, don't kill the run. This interweaving is how Deep-Research-style workflows reliably out-spend Claude Code on report generation [Qodo](https://www.youtube.com/watch?v=EcqMYoIV57A) (2026-06) [BuzzHPC](https://podcasters.spotify.com/pod/show/mlops/episodes/Architecting-Modern-AI-Systems-Platforms--Agents--and-Integration-e3k0qlu) (2026-05)
- **Container ≠ agent platform**: a container knows only one session and has no isolation boundary across stateful sessions → real incidents from this root cause — parallel sessions clobbering a *shared cache*, and an auto-accept agent pushing the whole company's source to a personal GitHub because secrets were commingled. You end up rebuilding above the VM anyway [Cognition](https://www.youtube.com/watch?v=_xQnSNlBP_w) (2026-05)
- Dev boxes (64–128GB RAM, pre-warmed pool, ~10s spin-up) beat lightweight sandboxes as agent homes — the agent inherits all the repo tooling plus isolation for free. Static analysis and type-checkers become *must-haves* once agents drive: a missing one no longer costs an engineer an hour, it costs thousands of failing agent cycles [Stripe](https://www.youtube.com/watch?v=_xQnSNlBP_w) (2026-05)

## Transparency, control & reversibility
- Transparent execution (live todo list, visible context and skills in use, tool-call inputs AND outputs) lets the user intervene mid-run before wasted steps compound — collaboration over delegation. Multi-granularity reversibility (per-line, per-file, conversation-checkpoint rollback) bounds the cost of mistakes, making users bolder [Flinn](https://www.youtube.com/watch?v=7CrPrHgoEYk) (2026-05)
- **HITL granularity for long-running background agents**: instead of fixed checkpoints, pause the agent precisely where it would otherwise make an assumption and let the human resolve that specific decision inline by tagging it in a chat thread, then resume; separately, gate irreversible actions behind an explicit plan approved first [Ramachandran](https://www.youtube.com/watch?v=RGiXcVxSD3s) (2026-07) (discounted src)
- Stay-in-the-loop techniques for long autonomous runs: (a) **implementation notes** — instruct the agent to log every unknown it hits mid-run plus why it chose what it did, so you audit where it deviated from the spec instead of diffing blind; (b) **exit quiz** — before merge, have the model quiz YOU on what was built [Fable-field-guide](https://www.youtube.com/watch?v=9fubhllmsBU) (2026-07)
- ...formalized: auto-append a 5-question medium-difficulty quiz to an agent-generated code explainer and don't send code for review until you can pass it. Framed as a *speed regulator* — everything else speeds you up, the quiz keeps you moving at the speed of understanding, not just correctness [Litt](https://www.youtube.com/watch?v=WkBPX-oDMnA) (2026-07)
- Stable deterministic scaffolding matters more than capability: hidden context mutation (silent system reminders, system-prompt edits per release, tool-result pruning) silently breaks workflows you can't see [Pi](https://newsletter.pragmaticengineer.com/p/building-pi-and-what-makes-self-modifying) (2026-04)

## Multi-agent orchestration
- **The missing primitive for agent swarms isn't runtime, orchestration or triggers (treated as solved) — it's coordination**: how agents pick up tasks from each other. GitHub is a poor coordination layer at agent-scale PR volume; candidates are state-machine/durable-execution workflow definitions, or a CLI-level gateway agents call to check SDLC-step completion [Ona-Bichard](https://www.youtube.com/watch?v=5Sui_OnSRlY) (2026-07)
- The fix was to consolidate distributed **judgment** into one agent owning data and reasoning end-to-end, keeping parallelism and dynamically-spawned sub-agents for scoped *investigations* only — sub-agents return results, never judgment [ZS](https://www.youtube.com/watch?v=u6jJcIFDLE4) (2026-07)
- **One async-handle primitive covers sub-agents AND background terminals**: a `spawn agent` tool creates the instance and a `send input` tool then feeds it more content, waits on it, or shuts it down — background shells reuse the identical shape (spawn, write to stdin, wait N seconds), so the harness needs one abstraction, not two [OpenAI-Kundel](https://www.youtube.com/watch?v=shRR1e2HXMk) (2026-08)
- **Taxonomy of 5 multi-agent comm primitives** a long-running system composes: (1) delegation — parent spawns child, gets result; (2) creator-verifier — a fresh-context agent checks the builder, who has a "ship it" cost bias; (3) direct communication — agents DM with no coordinator (hard: state fragments); (4) negotiation — agents coordinate over a *shared resource*, best when positive-sum; (5) broadcast — one→many status updates, unflashy but critical for coherence over long runs [Factory-Alvoeiro](https://www.youtube.com/watch?v=ow1we5PzK-o) (2026-05)
- **Run features SERIALLY** (one worker/validator at a time), parallelizing only READ-ONLY ops within a feature (search, API research, review). Naive parallelism fails for SWE: agents step on each other's changes, duplicate work and make inconsistent architectural decisions, so coordination overhead eats the speed gain — looks slower on paper but error rate drops and correctness compounds over multi-day runs [Factory-Alvoeiro](https://www.youtube.com/watch?v=ow1we5PzK-o) (2026-05)
- **Live disagreement on where orchestration logic lives.** Factory keeps ~all of it in PROMPTS + SKILLS the orchestrator defines per mission (~700 lines of text; 4 sentences can change execution strategy) with a thin deterministic layer for bookkeeping — a "bitter-lesson defense" so the next model improves your system instead of obsoleting a hardcoded state machine. WorkOS moved orchestration INTO deterministic code to stop context leak. Condition that decides it: how much the orchestration changes per run — stable pipelines harden into code, mission-customized behavior stays in prompts [Factory-Alvoeiro](https://www.youtube.com/watch?v=ow1we5PzK-o) [WorkOS](https://www.youtube.com/watch?v=vy7o1g2iHY8) (2026-05)
- **Tokens are not fungible — give them jobs**: at a FIXED token budget, allocating tokens to non-executor roles beats pure execution — *advise* (executor consults an advisor mid-task), *grade* (rubric grader loops the executor until pass), *dream* (post-hoc reflector reads transcripts and writes learnings to memory). Financial-analyst bench, same 600k-token budget: execute 0.76 accuracy vs advise 0.89 [Anthropic-WF26](https://www.youtube.com/watch?v=I2cbIws9j10) (2026-07)
- ...*advise* has since shipped as a server-side Advisor Tool (2026-04): a cheap executor drives the loop and calls out to a big advisor only when it hits a decision it can't resolve, both sharing one conversation state so control returns with no context-switch. Published deltas — Sonnet+Opus-advisor +2.7pp on SWE-bench Multilingual at −11.9% cost per task; Haiku+Opus-advisor 41.2% vs 19.7% solo on BrowseComp [Anthropic Advisor Tool](https://docs.litellm.ai/docs/completion/anthropic_advisor_tool) (2026-04)
- **Agent = a graph of nodes, NOT pre-planned sub-agents**: grow it from a single node + tools + eval set; ship, watch which action the agent reliably botches, split THAT node into its own node (own prompt/context/tools), re-run evals, repeat — "complexity should be a result of time, not planned". A sub-agent is just a sub-graph that emerged; reserve sub-agent framing for cross-team boundaries [iFood](https://podcasters.spotify.com/pod/show/mlops/episodes/The-Control-vs-Magic-Spectrum-Building-Agents-e3k9n0g) (2026-06)
- **Constellation of models** — route by task, not general intelligence: even with a strong frontier model, reliability improves picking the best model per sub-task, and a pure prompt-and-loop often FAILS on narrow task reliability even when the model is impressive in open chat (general intelligence ≠ procedure-following) [ElevenLabs](https://podcasters.spotify.com/pod/show/mlops/episodes/Voice-Agent-Use-Cases-e3ileg6) (2026-05)
- ...but route-by-task-*type* is fragile once the session is agentic: complexity shifts mid-session (explore → implement → live-debug) and the model picked for phase one is wrong by phase three. Fix — keep a frontier agent *watching* even when it isn't doing the work, so it can pull the task back; piggyback the "is the small model down a rabbit hole?" check on the ~5-min cache refresh you pay for anyway [Cognition/Yan](https://www.youtube.com/watch?v=QHBjufYK8TA) (2026-08)
- **Sidekick beats spawning sub-agents** when the delegate is used repeatedly: ONE long-lived side agent holding a continually-running context means the main agent never re-supplies context and it all stays in KV cache (~10× cheaper on cached tokens) — fresh sub-agents per task throw that away. Reported result of frontier-plans/cheap-implements: ~40% cost cut at frontier-level quality [Cognition/Yan](https://www.youtube.com/watch?v=QHBjufYK8TA) (2026-08)
- Handoff shape between them: the sidekick returns *file references*, not content dumps — bigger models are more token-efficient at deciding which parts to read. Stated as a general harness principle: context should be allowed to be lossy, the harness only needs to be able to *find* what it needs [Cognition/Yan](https://www.youtube.com/watch?v=QHBjufYK8TA) (2026-08)
- **Org-chart hierarchy as real entity types** (CEO/VP/manager/worker — not a metaphor): each layer its own agent with scoped context and an approval boundary; context flows down as the slice each layer needs, results flow up, the human reviews only the top — collapsing the N live contexts you must hold to 1. A flat pile of >4–5 agents makes the human the scheduler, memory and reviewer [KRAFTON-fleet](https://www.youtube.com/watch?v=4kYl2_mqmnQ) (2026-07)
- ...generation-pipeline sibling, three levels: a queue of agents each with own prompt/model/IO plus configured entry, exit and call frequency; an **orchestrator** dynamically reordering, skipping and rewriting the next agent's instructions; a **supervisor** policing the orchestrator from a global view [poolside-Abdin](https://www.youtube.com/watch?v=KhYifX22yhE) (2026-07)
- **Shape the work queue as a Kanban board specifically so humans can steer mid-run**: a strategist agent files experiment cards, workers implement, submit to the cluster, read the resulting curves and write a POST-MORTEM back to the strategist, which shifts direction ("three transformer variants underperformed, XGBoost is working"). Humans cancel cards, add their own, and chat with the strategist while it runs [MorganStanley-AlphaLab](https://www.youtube.com/watch?v=kiqubc5b5Yo) (2026-07)
- **Stripe "Minion" one-shot loop** (prompt→PR, no human in loop, ~65% merge with zero edits): gather all context (Slack thread, ticket, linked PRs) → an `analyzer` agent localizes the right part of the repo → coding agent makes one turn → run lints/tests/typecheck → hand the diff plus the ORIGINAL prompt to an LLM judge whose context is NOT poisoned by the coding agent's excuses → if incomplete, a `diagnostic` agent writes a SHORT note ("built endpoint, didn't wire frontend") fed back in; repeat until PR-shaped [Stripe](https://www.youtube.com/watch?v=_xQnSNlBP_w) (2026-05)
- **Best-of-N agent runs are "map without reduce"**: fanning out 100 parallel agents on one input is easy; the missing primitive is the REDUCE — a cheap way to eliminate bad runs and pick the best (test-pass count is one usable reducer: keep whichever sandbox passes the most tests) [Sazabi](https://podcasters.spotify.com/pod/show/mlops/episodes/Logs-Are-All-You-Need-Rethinking-Observability-with-AI-Agents-e3jthog) (2026-06)
- ...the exception where the reduce is free: TASTE tasks (UI, design, research or architecture directions) — generate 15 variants and eyeball them, cheaper than hand-writing reference examples or an exhaustively detailed prompt [Cerebras-Chieng](https://www.youtube.com/watch?v=TeGsFFNqRLA) (2026-05) (discounted src)
- **Cross-repo meta-harness**: agents are constrained in SPACE (repo-bound), so one logical change spanning N repos costs ~N re-explanations to fresh agents. Fix = an agent-agnostic layer extracting metadata from all reachable repos (what each produces/consumes, which APIs) into ONE unified dependency graph, giving the illusion of a single big codebase, with no code changes in the analyzed repos. Select repos by INTENT ("update every repo depending on lib vX") and treat CI across all involved repos as ONE vector [Nx-Savkin](https://www.youtube.com/watch?v=jVjt-2g8NMY) (2026-06)
- ...the blunt alternative, chosen first-hand: actually consolidate. 10 repos → one monorepo, on the finding that NAVIGATION was never the problem (models handle multiple repos nested under a parent folder) — end-to-end testing, verification and deployment are, and a sandbox must clone every repo before doing anything. Decider is whether your bottleneck is comprehension or the verify/deploy path [Wisedocs-Linkov](https://www.youtube.com/watch?v=7vn4WpqNpck) (2026-08)
- **Manager-agent-of-agents**: the observed evolution ran 10 terminals paired 1:1 → managing 10 terminals as "10 direct reports" → a single long-running manager agent that delegates to a team and wakes on a timer (a chief-of-staff agent waking every 10 minutes, coordinating workstreams, creating sidebar threads for human steering) [OpenClaw/Steinberger](https://www.youtube.com/watch?v=htM02KMNZnk) (2026-07)
- **Multi-machine fleet ops** (one control plane over a laptop plus always-on Linux boxes): move context between machines via git — commit the agent's context files, push, poke the remote agent (tmux send-keys over ssh) to pull and resume; per-machine dirs for machine-bound state, shared state changes only via PR, or the machines silently diverge [KRAFTON-fleet](https://www.youtube.com/watch?v=4kYl2_mqmnQ) (2026-07)
- **Anti-reward-gaming pattern for tuning emergent multi-agent behavior**: freeze the harness, scenarios and metrics and expose only a small NAMED policy surface to the optimizer (memory-write policy, retrieval policy, trust-update rule) rather than letting it rewrite the whole system; score a balanced scorecard instead of one scalar (optimize only diffusion → agents overshare; only recall → stale memory); keep a change only if the WHOLE scorecard improves, else revert [Supercell](https://www.youtube.com/watch?v=4sX_He5c4sI) (2026-07)

## Streaming, transport & durable sessions
- SSE (the Vercel AI SDK / TanStack AI default) is one-way server→client and couples the response stream to a single client's connection — drop = stream lost. Resumability requires buffering events to a store with sequence numbers plus a per-client resume handler computing the missed set and replaying in order [Ably](https://www.youtube.com/watch?v=YNJvm7t3yq8) (2026-05)
- **Past ~1000 tok/s the NETWORK, not inference, is the bottleneck** (found running Codex Spark on Cerebras): tool-call-heavy turns spend their time on transport. Fix is a persistent WebSocket instead of SSE/HTTP for the inference API, plus stateful server-side context so a turn sends only the item that changed (one tool result) rather than replaying all N items [OpenAI-Kundel](https://www.youtube.com/watch?v=shRR1e2HXMk) (2026-08)
- SSE also forces resume and cancel to be mutually exclusive: with no upstream channel a client closing the connection is ambiguous (reconnect-later vs cancel), so you can't have both a stop button and resumability — stop/interrupt and steering need a bidirectional transport [Ably](https://www.youtube.com/watch?v=YNJvm7t3yq8) (2026-05)

## Plan-heavy vs review-heavy — optimizing for human time
- **Plan the stack BEFORE code** (30 min upfront reliably saves hours of review): product review (behavior, mockups) → system architecture (component contracts, data models) → **program design** (types, method signatures, call stacks — the most-skipped step) → vertical slices with checkpoints. PRs built this way stay small enough to read line-by-line [HumanLayer/Horthy](https://www.youtube.com/watch?v=htM02KMNZnk) (2026-07)
- Models write **horizontal** plans (database → services → API → front end), which is the wrong shape: nothing is testable until the end and you review 2000 lines at once. Slice vertically — mock endpoint, front end, real data, migration, business logic — for five small verifiable diffs [Horthy-CtxEng](https://newsletter.pragmaticengineer.com/p/context-engineering-with-dex-horthy) (2026-07)
- Plans containing every line of code as diff blocks are anti-leverage: you review the plan *and* the PR, doubling your reading. Plans were also popular for a non-obvious reason — they anchor the agent so it keeps working until done [Horthy-CtxEng](https://newsletter.pragmaticengineer.com/p/context-engineering-with-dex-horthy) (2026-07)
- Spec/code parity doesn't survive contact: maintaining specs alongside code gives two sources of truth, and nobody reports being glad they maintained it — use the code as the source of truth [Horthy-CtxEng](https://newsletter.pragmaticengineer.com/p/context-engineering-with-dex-horthy) (2026-07)
- **Three honest options for an agentic factory**: lights-off and pray the next model beats the compounding slop; read every line for a modest 30–50% lift; or find leverage points where an hour of planning saves four of rework — put at 2–3× faster while staying near hand-written accuracy [Horthy-CtxEng](https://newsletter.pragmaticengineer.com/p/context-engineering-with-dex-horthy) (2026-07)
- Agent coding displaces human effort into planning and reviewing (~20 min back per 30 min coding), not free time — optimize for accuracy per HUMAN time, not wall-clock. Heuristic: "5 min planning saves 30 min reviewing AI code", so default plan-heavy. Work-type matrix: frontend feature dev → stay in-loop; backend → plan-heavy/TDD; refactor/migration → fully plan-heavy [Plan and Review](https://www.youtube.com/watch?v=W76woOYHlvY) (2026-05)

## Loop engineering — in-the-loop → out-of-the-loop
- **Loops as control theory, not bash**: set point (desired end state for one property), sensor, measured error, controller (one incremental change), actuator, re-measure. Precedents — thermostats, Kubernetes autoscaling, IaC desired-vs-current. Incrementality is what prevents 40k-line PRs [HumanLayer-Mistele](https://www.youtube.com/watch?v=xIt_mTQp6mY) (2026-07)
- ast-grep is the sensor of choice for code patterns: language-agnostic across a multilingual monorepo and out of band from tsconfig/ESLint — which matters because agents disable those with inline comments [HumanLayer-Mistele](https://www.youtube.com/watch?v=xIt_mTQp6mY) (2026-07)
- **Stop the bleeding before migrating**: one full scan on main, violations sorted deterministically and committed to version control, then fail any PR that adds new ones — a disturbance dampener against teammates shipping more of what you're removing [HumanLayer-Mistele](https://www.youtube.com/watch?v=xIt_mTQp6mY) (2026-07)
- Build "golden patterns" by hand before setting the actuator loose — idiomatic worked examples — because agents are pattern replicators and will otherwise reproduce the docs or whatever they absorbed online [HumanLayer-Mistele](https://www.youtube.com/watch?v=xIt_mTQp6mY) (2026-07)
- **Flow control beats throughput**: label PRs per loop and exit before doing any work if one is still open — no human reviewed the last output, so producing more is waste. At most one open PR per loop; no stacking, no conflicts. A `/iterate` PR comment re-triggers the loop with feedback appended to a version-controlled feedback file, so tuning history is diffable and revertible [HumanLayer-Mistele](https://www.youtube.com/watch?v=xIt_mTQp6mY) (2026-07)
- Slow loops are the shape with the most practitioner confidence: a nightly cron fixing one linter finding, growing along two axes — more feedback mechanisms (including hand-written "here's good, here's bad" rules where no deterministic tooling exists), then more scope per run [Horthy-CtxEng](https://newsletter.pragmaticengineer.com/p/context-engineering-with-dex-horthy) (2026-07)
- ...and the loop needn't be pre-wired: **let the agent schedule its own**. "Keep an eye on this every X minutes" registers a recurring message into the thread's own context; it can also create, name and pin threads — so Codex ships no `/loop` command [OpenAI-Liu-MLOps](https://podcasters.spotify.com/pod/show/mlops/episodes/How-To-Delegate-To-An-Agent-Like-You-Would-An-Employee-e3nglg8) (2026-08)
- Cost objection to loops-on-loops, from a practitioner running them: 5% per-step error compounds over 10–20 iterations, and non-deterministic verification adds non-determinism rather than removing it — keep verification cheap and deterministic. Where loops demonstrably pay: security scanning on PRs at ~$5/PR, and domains with years of existing test suites (language/runtime rewrites) [LoopsDebate](https://www.youtube.com/watch?v=c35YoMdnI78) (2026-07)
- **"Loop engineering"**: stop prompting the agent directly — author the loops that prompt it (triggers + goals), so your job moves to issue-writing on one end and code review on the other. Pull the human out one stage at a time (ticket → triage → implement → verify → PR) but keep the final merge gate; don't let agents self-merge yet [Warp](https://www.youtube.com/watch?v=gi0Lx6c84VE) (2026-06)
- Two-stage chain beats one agent: automation A turns an under-specified issue into a spec doc (affected packages, version bumps, acceptance criteria) which you merge as a paper trail, and automation B implements it. Each loop is only as good as its issue's explicit acceptance criteria [Warp](https://www.youtube.com/watch?v=gi0Lx6c84VE) (2026-06)
- ...shipped instance, and the intake agent INTERROGATES the human: requests land in a Slack channel at wildly varying quality, and the agent runs several rounds of clarifying questions with the submitter until it judges the request spec-ready. Without that gate, automating the rest gives you a "token-maxing slop cannon" [Ramp-Mehr](https://www.youtube.com/watch?v=ITMXwI6QL6A) (2026-07)
- Two things they learned running it: adoption came from LATENCY, not quality (replies went from hours/days to seconds and non-engineers started engaging unprompted, ~20% of scoping time saved); and **the ENDS of a pipeline automate first** — context-gathering works, spec→code frontier models largely one-shot, and the scope→spec middle is the unformed hard part [Ramp-Mehr](https://www.youtube.com/watch?v=ITMXwI6QL6A) (2026-07)
- **Start with ONE sequential loop, not parallelism**: the bottleneck on a continuous loop is your own ability to spec and review, not tokens/sec — skip multi-agent until you actually hit the agent-throughput wall (most don't). Don't pre-compute a dependency DAG and fan out either, which recreates waterfall and makes agents contend; drop the graph, single loop, prompt "pick the next most important ticket" and let it infer deps from what's done [Ralph-Parsons](https://www.youtube.com/watch?v=2TLXsxkz0zI) (2026-05)
- A Ralph-loop prompt is a built-up role + procedure, not "do the ticket": cast the agent as "one engineer in a relay team — do exactly one change, drop context, stop", and encode ticket format, status values, when work qualifies, how to run tests in *your* framework, and "test passing is not enough — verify actual behaviour" [Ralph-Parsons](https://www.youtube.com/watch?v=2TLXsxkz0zI) (2026-05)
- Prefer a fresh context per iteration over resuming the session, as a forcing function: it forces all in-session knowledge to be codified into repo files and skills, yielding a durable store any future session or human can read instead of knowledge trapped in a session [Ralph-Parsons](https://www.youtube.com/watch?v=2TLXsxkz0zI) (2026-05)
- **Never let the loop close or mark-done its own work** — stay the final verification gate. Motivation is "cognitive debt": losing track of what the codebase does. If the builder grades its OWN work you didn't remove review, you HID it; and capability drift only moves WHERE proof belongs (inspect outputs → inspect task direction → maybe inspect the loops), never WHETHER [Ralph-Parsons](https://www.youtube.com/watch?v=2TLXsxkz0zI) (2026-05) [Volkov](https://www.youtube.com/watch?v=ZpK5PWX2YRM) (2026-07)
- **The "missing layer" is post-launch, triggered by LOG MONITORING** (not a PR merge or user report): a log-monitoring agent runs every 15–60 min over a ~1-hour window, has codebase access, diagnoses stuck or "successful-but-wrong" users, and opens a PR (~30 min) or fires an alert. Gate every PR with a SEPARATE review agent with FRESH context that critiques it from a different angle and can close it — filtering the "agents are eager to open PRs" problem [Wandero](https://www.youtube.com/watch?v=kZsf_Sfm7RU) (2026-07)
- **Change-triggered variant: a check plan PER RELEASE, not the fixed CI checks.** The agent reads what changed, infers which telemetry is causally downstream, watches that (checkout swaps currency service → checkout latency and error rate, then the Kafka pipeline). It picks the cadence too — an hour for an intermittent failure, or three days later to confirm the intended effect landed [Resolve-Smith](https://www.youtube.com/watch?v=vSx5IULvBns) (2026-08)
- Its real coverage gain is the changes CI never sees: feature flags and infra edits don't pass through the pipeline at all, so today they get no deploy monitoring [Resolve-Smith](https://www.youtube.com/watch?v=vSx5IULvBns) (2026-08)
- **"Mirror harness" principle** for any self-operating loop: give the agent the SAME debugging access a human has (logs, trajectories, metrics, database, UI) so a fix addresses the real problem instead of guessing — the moat is the self-watching harness, not the model. It needs its own reasoning agent because log-diagnosis isn't grep, it's real-bug-vs-noise and symptom-vs-root-cause judgment [Wandero](https://www.youtube.com/watch?v=kZsf_Sfm7RU) (2026-07)
- Compile repeated LLM work into generated scripts: the agent inspects one raw page, writes a deterministic parser, then the script runs (~100 tokens/run vs ~10k through context; ~62% saving even on a structured site). Pair with a self-healing check — a scheduled run validates output and, on missing fields, re-inspects the source and patches its own scraper [Bright Data](https://www.youtube.com/watch?v=zTZ0qunQXnM) (2026-06)
- ...but **don't cost-optimize while experimenting**: run the expensive agent on the same problem ~100×, watch its solutions converge, and only THEN compile that step into a one-shot call or small model — premature avoidance of agent calls was PostHog's biggest mistake [PostHog](https://www.youtube.com/watch?v=zMiSRliEzv4) (2026-06)
- Partition agent workflows by determinism: discovery benefits from non-determinism, but credentials, transactions and anything with consequence require it — design an explicit handoff point where the LLM-mediated phase ends and a purely programmatic flow takes over [Stripe](https://www.youtube.com/watch?v=KLSuFPj2ld0) (2026-06)

## Agent-rate development — CI in the loop, merge queues
- **The PR breaks as the unit of work at agent scale**: it was built for human-paced discrete-handoff review, but agents emit N PRs across N repos with thousands of short-lived branches. Validation moves OUT of a separate post-PR CI phase and INTO the agent's inner loop — every iteration builds, tests and gets reviewed, not just at the end [Namespace](https://www.youtube.com/watch?v=VktrqzQgytY) (2026-05)
- ...pushed a stage earlier at OpenAI: the Codex leads wrote opinionated "finalize code" review skills the agent triggers at PR-CREATION time, so it self-heals before the PR reaches GitHub and CI at all — what keeps thousands of PRs/day affordable [OpenAI-Liu-MLOps](https://podcasters.spotify.com/pod/show/mlops/episodes/How-To-Delegate-To-An-Agent-Like-You-Would-An-Employee-e3nglg8) (2026-08)
- ...generation speed is what makes that affordable: at ~1,200 tok/s vs ~40–60, running suite, linters, hooks, diff review and browser QA at EVERY step costs almost nothing — and all are deterministic checks [Cerebras-Chieng](https://www.youtube.com/watch?v=TeGsFFNqRLA) (2026-05) — throughput premise since corroborated first-hand, see § Context, compaction & memory
- **Merging at agent rate ≈ a DB serialization problem** — the git repo is a single ledger needing a lock per commit, and machine merge-locks are short and frequent (vs human long and rare), so time-to-merge dominates. "Pre-merge queue": completed candidates wait in a reconciliation queue, not the repo, so many parallel agents serialize into the ledger — and the human approves intent plus result here (a video of the feature working, the security-LLM output) rather than reading raw diffs [Namespace](https://www.youtube.com/watch?v=VktrqzQgytY) (2026-05)
- **Solo agent builders re-derive 5 CI/CD controls badly**, roughly in this order: output-shape/regression test (a prompt change breaks downstream); alerts (a silent cron failure unnoticed for a week); boundary/contract validation (one skill's schema change breaks 3 consumers); a checkpoint/staging gate before the "ready" folder; audit trail (which prompt emitted the bad output). Agent frameworks give none by default [Shrabony](https://www.youtube.com/watch?v=WLXxTaPagA8) (2026-07)
- Prioritize gates by first MAPPING every handoff (each arrow between agents is where output silently corrupts) — don't gate them all; put your FIRST gate on the most EXPENSIVE handoff (biggest blast radius), not the most complex. A gate that only warns is a suggestion: it must BLOCK the artifact from advancing. "Before you add another agent, add one boundary" [Shrabony](https://www.youtube.com/watch?v=WLXxTaPagA8) (2026-07)
- **De-risking displaces speed as the pipeline priority**: with an agent driving, feedback-loop *speed* matters less (no human context-switch cost waiting on a build) so emphasis shifts to de-risking agent-generated code — the agent can babysit its own pipeline, read the failure, push a fix and re-run [CI/CD Erez](https://newsletter.pragmaticengineer.com/p/cicd-with-robert-erez) (2026-06). Shipped as a standing loop with an explicit checklist — every 30 min: rebased on main, every review comment addressed, CI green [OpenAI-Liu-MLOps](https://podcasters.spotify.com/pod/show/mlops/episodes/How-To-Delegate-To-An-Agent-Like-You-Would-An-Employee-e3nglg8) (2026-08)
- **"Agent readiness" made measurable = how many DETERMINISTIC validation loops your codebase already has** (linters, type checkers, security scans, e2e tests — anything that hard passes or fails). Stated as a proportionality: long-running harness output quality tracks how much of the work you can validate, so validation at scale IS autonomy at scale [Factory-Reyes](https://www.youtube.com/watch?v=wpOA-UXynoM) (2026-07)
- ...which inverts where the effort goes — "if you can frame the problem as the set of verification systems that must validate it, you can solve it with AI today", so the work is preparing the environment to verify, not solving. Same shape as dense reward in post-training [Factory-Reyes](https://www.youtube.com/watch?v=wpOA-UXynoM) (2026-07)
- **Where you can't build a validator is exactly where autonomy stops**, first-hand: their internal legal workflow is ~100% autonomously maintained, while their own core harness isn't, for want of a verifiable check on hard visual bugs (terminal UI flickering). A customer's codebase can be MORE autonomous than the vendor's if it's more constrained [Factory-Reyes](https://www.youtube.com/watch?v=wpOA-UXynoM) (2026-07)
- Sequencing caveat: only ~30–40% of agent-readiness gaps are click-to-fix; the rest need workflow change, and humans resist the nitpickiness of the new checks. Metric they run is "autonomy ratio" — AI vs human actions before an interruption [Factory-Reyes](https://www.youtube.com/watch?v=wpOA-UXynoM) (2026-07)
- **"Self-validation == an ephemeral environment"**: any "have the agent confirm its change works" loop is really spin-up env → agent pokes → tear down, the same preview-env pattern used for humans even when no human looks. The agent's verification is only as good as the env you hand it — Granola turned a one-instance Electron app into a web shell so CI emits a per-PR preview link the agent tests against [CI/CD Erez](https://newsletter.pragmaticengineer.com/p/cicd-with-robert-erez) [Granola](https://www.youtube.com/watch?v=ON5LIT0M4do) (2026-05)
- **Sharper, and it inverts the build order: a PARTIAL verification engine is worse than none.** With a formula engine covering ~50% of Excel, the agent writes a formula correct in the real tool, your engine errors, and it "fixes" working code. Build the sensor to fidelity *before* closing the loop on it [Witan-Campos](https://www.youtube.com/watch?v=HEFSExa0xl0) (2026-07)

## Dynamic workflows — a bespoke harness per task
- One coding harness gets funnelled all knowledge work but isn't optimal for non-coding jobs — let the agent write a custom harness per task at runtime. A static workflow wired ahead of time must stay generic → generic output; a dynamic workflow is a JS file running a small team of agents with primitives `agent` (sub-agent in its own clean context), `parallel` (fan out, barrier-wait) and `pipeline` (stream items through stages), picking model and worktree per agent and resuming if interrupted [Prompt Engineering](https://www.youtube.com/watch?v=l5rae4LMKBc) (2026-06)
- Why split a job across clean contexts: one overflowing window causes three failure modes — agentic laziness (quits early, declares done), self-preferential bias (grades its own work kindly), and goal drift (the brief leaks out, especially after compaction) [Prompt Engineering](https://www.youtube.com/watch?v=l5rae4LMKBc) (2026-06)
- **Six portable harness patterns**: (1) classify-and-act — a classifier routes by task type or shapes output at the end; (2) fan-out-and-synthesize — isolated contexts so biases don't cross-contaminate, then a barrier merges; (3) worker+critic — a separate critic attacks output against a rubric (cures self-preferential bias); (4) generate-and-filter — many candidates filtered by rubric, keep the best; (5) tournament — agents solve the same task differently and a judge compares head-to-head (pairwise beats absolute scoring); (6) loop-until-done — a gate asks "any new findings?" so the loop, not a tired context, decides when to stop (cures laziness) [Prompt Engineering](https://www.youtube.com/watch?v=l5rae4LMKBc) (2026-06)
- Harnesses are reusable saved artifacts, not single-use — generate several, keep the best. Cap cost in the prompt ("use only 10,000 tokens") and pair with a hard finish line, but it burns tokens dramatically: first ask whether the job needs more compute or a simple agentic pattern suffices [Prompt Engineering](https://www.youtube.com/watch?v=l5rae4LMKBc) (2026-06)
- **OpenProse** — dynamic-workflow/RLM behavior on ANY agent: a markdown "logical English" spec (`.pros.md`) compiled by the CODING AGENT, not the computer, turning any agent with a filesystem and sub-agents into an RLM. It declares sub-agent work explicitly, verifies each sub-agent's work in the PARENT session, and wires skills and CLI tools as explicit DEPENDENCIES of a sub-agent [OpenProse](https://www.youtube.com/watch?v=3hXJI2q0Jz8) (2026-06)
- **Golden-session → reusable workflow**: take a run that worked great and have an agent deconstruct it into a reusable workflow program, so you reproduce that quality repeatably instead of re-rolling the dice each run [OpenProse](https://www.youtube.com/watch?v=3hXJI2q0Jz8) (2026-06)

## Running LLM-generated code — sandboxes
- **"Seven stages of sandboxing"** (OpenAI's sandbox infra behind ChatGPT/Codex Web): teams try fork/exec → containers/seccomp → gVisor → V8 and all end at microVMs — hardware virtualization is the only boundary that survives guest root, since container and gVisor exploit chains still reach the host kernel. Start there (Firecracker / Cloud Hypervisor / crosvm) [OpenAI-Bhardwaj](https://www.youtube.com/watch?v=OqM67QG_Ikk) (2026-07)
- Syscall-allowlist (seccomp) filters fight GENERAL agents: you can't enumerate the needed syscalls up front and blocked calls make a terrible feedback loop — isolate the environment rather than over-restricting it. Accept the trade-offs (VM-exit tax, balloon memory reclaim, single-tenant GPU passthrough): "system tricks can cover performance issues; they cannot hide security breaches" [OpenAI-Bhardwaj](https://www.youtube.com/watch?v=OqM67QG_Ikk) (2026-07)
- **The sandbox breaks at exactly the point the agent gets useful**: it wants to build and run containers to verify its own work, so you hand it the Docker socket — and now it can spawn a privileged container, escape, and read other processes' memory and env. Ran in production, then withdrawn. Landlock, bubblewrap, Kaniko et al. don't compose with containers and none can contain a Docker socket; the working design is a Firecracker microVM per agent with the socket inside it [Form3](https://www.youtube.com/watch?v=LqLoYksJ6do) (2026-07)
- **Mental model: maximize non-determinism *inside* the box, make the box *really strong***. Cleric's arc — early on they hand-wrote extremely rigid tools (no raw `kubectl`) so the agent could only do the intended thing; as models improved the rigid tools became the constraint blocking better performance, so they relaxed to letting the model compose bash/Python, but only AFTER doing sandboxing hard, because rigid tools had been giving free security guarantees that bash gives up [MLOps-Sandboxing](https://podcasters.spotify.com/pod/show/mlops/episodes/Sandboxing--Agent-Harnesses--and-Agent-Teamwork-e3kts75) (2026-06)
- **Inverted sandbox design for generated code**: start from a zero-capability JS isolate (no fetch, no filesystem, no env vars) and grant explicit capabilities outward (only outbound fetches to github.com) — the opposite of a VM locked down after the fact; ms spin-up makes a fresh sandbox per generated code string cheap [Cloudflare](https://www.youtube.com/watch?v=SKDJo2CopRs) (2026-06)
- Full-stack version of that inversion, so generated code's security bugs become *unreachable* rather than reviewed: generated UI in a null-origin iframe under a CSP permitting only postMessage to the parent, generated server code in a worker sandbox with no egress, and the two can talk only to each other. An XSS in agent-written code then leaks nothing [Varda/Cloudflare](https://www.youtube.com/watch?v=RmS5s6Wbin4) (2026-08)

## Trajectory stores & retro / self-improvement
- **End every agent invocation with a short retrospective** — what went well, what went wrong, what tools were missing, what context would help next time. Aggregating these across runs is what makes the system debuggable at scale; the recurring classes were infrastructure and repo complexity [Form3](https://www.youtube.com/watch?v=LqLoYksJ6do) (2026-07)
- **"Agentic map-reduce" over your own history**: map cheaply over past coding sessions to extract every place you corrected the agent, reduce with a stronger model into recurring-failure categories, then feed those into the next batch of eval tasks or a skill. Cheap model for map, smart for reduce [Harbor](https://www.youtube.com/watch?v=jRCpXUjz4CI) (2026-07)
- **Past a certain length you cannot read a trace WITH an agent** — a long coding-agent session doesn't fit a reader agent's context, so treat the trace as an external object you query into rather than something you feed in. Cost scales as input-price × traces × avg size, so the mining has to be selective [LangChain-Trivedy](https://www.youtube.com/watch?v=CvRngaQZQ3Y) (2026-08)
- ...**so write the classifier as CODE and run it in a sandbox at production scale** rather than LLM-reading each trace — code mode applied to telemetry instead of MCP. Sharpens the map step above: cheap code for map, smart model for reduce [Raindrop-Hylak](https://www.youtube.com/watch?v=jHMiYtjoJfA) (2026-08)
- Two cheaper triggers for the same signal: in the moment, when you catch yourself telling the agent something you can SEE and it can't ("the button is a bit to the left"), that's the affordance to build; retrospectively, hand it your logs and ask what smells — `sleep(15)` everywhere instead of waiting on a condition, storybook run over and over [Poolside-Lajili](https://www.youtube.com/watch?v=iRcX54EO5g8) (2026-07)
- Retro agent parses Claude/Codex JSONL transcripts to detect doom loops (the same tool call repeated unchanged, excessive parallel tools) and writes lessons into per-stack markdown memory files. The discipline: when the agent errs, fix the harness so it can fix itself — never hand-fix the output; every failure is a system bug plus data for the next run [WorkOS](https://www.youtube.com/watch?v=vy7o1g2iHY8) (2026-05)
- **"Agent recipe" as a portable unit**: bundle harness config + evals + per-model profiles into one git-versioned artifact, the agentic analogue of an RL data recipe. Each loop run should distill into a reusable artifact rather than tribal prompt-tweaks — a repeated failure becomes a new judge/eval, a repeated good behavior becomes a skill, user frustration becomes a harness extension. Optimize cost only *after* reaching frontier capability [Pie/Roland](https://www.youtube.com/watch?v=4sX_He5c4sI) (2026-07)
- Skill-loop for factory self-improvement: pair a factory agent that runs a skill (a code-review agent) with a separate observer agent that watches how the skill's output gets corrected (a senior engineer editing its review comments) and uses that correction signal to improve the skill for the next run [Warp](https://www.youtube.com/watch?v=htM02KMNZnk) (2026-07)
- A working agent harness plus collected eval traces ≈ ready-made training data — RL can teach a model your service from what the harness already logs; RL rollouts are embarrassingly parallel, so fan out to ephemeral sandboxes and kill unpromising runs early [Modal](https://www.youtube.com/watch?v=HvZXAOZ3iv8) (2026-06)

## Org-scale rollout & adoption
- **Org-level (multiplayer) harness as the next shape**: one harness the whole org shares, with its own identity and credentials not tied to a user, and access to org-level rather than local context. Enables checking others' work before running an experiment, de-duplicating findings, and giving a new hire a configured harness on day one instead of weeks of ramp [Anthropic-Martin](https://www.youtube.com/watch?v=9QebvrrY3KY) (2026-07)
- What makes a team agent different from a personal one: multiplayer by default, **proactive** rather than reactive (standing channel instructions that persist), and shared team memory in natural language. Reported internal effect — a team-level agent lands ~65% of one product engineering team's PRs, with the personal CLI agent reserved for the most complex interactive work [Anthropic-Martin](https://www.youtube.com/watch?v=9QebvrrY3KY) [Anthropic-CC](https://www.youtube.com/watch?v=uU5Gv2h8-9g) (2026-07)
- Team agents need public channels to work — accuracy comes from being able to search everything, so it's a culture prerequisite, not a feature. Side effect: colleagues seeing your prompts reduces slop, because you want work you'd do in public [Anthropic-CC](https://www.youtube.com/watch?v=uU5Gv2h8-9g) (2026-07)
- **Address ONE session from every surface, rather than a bot per surface**: a Slack bot alone just moves the agent from trapped-on-a-laptop to trapped-in-Slack. Keeping Slack, app and GitHub on the same session means nobody re-supplies context at a handoff, and a reviewer can ask the thread "why did you do it this way" instead of waiting on the author [Superconductor-Singh](https://www.youtube.com/watch?v=OL7kfezynJM) (2026-08)
- **Standing ownership beats per-task delegation**: most internal usage is async multiplayer delegation, not interactive CLI, and the unlock was durable responsibility — "you own this part of the codebase, monitor this feedback channel, proactively take on tasks, react if this API changes" [Krieger-WF26](https://www.youtube.com/watch?v=I2cbIws9j10) (2026-07)
- **Treat it as leadership's problem, not the IC's**: the highest-leverage fixes (how the codebase is organized for agents) need team buy-in no individual can get. Failure mode of "figure it out yourself" — adopters ship 10 PRs/day while non-adopters ship 1–2 AND inherit the review burden, so the people furthest behind see the worst agent output and disengage permanently [Amazon-AGI-Khandelwal](https://www.youtube.com/watch?v=aeTb5BdmTTc) (2026-08)
- Adoption lever that won skeptics over: ONE end-to-end high-value skill rather than broad enablement — theirs covered code-done → PR-ready (opens the PR, writes the description, handles review comments and CI failures). It ran over an hour, and setting expectations about that runtime was the work, since long-running is the point [Amazon-AGI-Khandelwal](https://www.youtube.com/watch?v=aeTb5BdmTTc) (2026-08)
- Give experiments and prototypes an explicit opt-OUT lane from the repo's standards rather than one uniform bar that throwaway code then violates; and read "model X is dumb today" as a harness change, not a model change — results swinging on small harness edits is itself the defect [Amazon-AGI-Khandelwal](https://www.youtube.com/watch?v=aeTb5BdmTTc) (2026-08)
- Standardize on ONE agent platform — like avoiding multi-cloud: spreading work across tools forfeits compounding platform benefits, and it kills per-task "model anxiety". Onboard the agent like a new hire, capturing framework conventions, architecture, UI patterns and testing/security standards as context, skills and hooks [Intercom](https://www.youtube.com/watch?v=4_VQBbs2iQA) (2026-05)

# Harnesses

## What the harness is
- Harness = everything *around* the model (tool registry, model, context primitives, guardrails, agent loop, verify step), often a loop around the agent loop. Claude Code and Codex CLI are themselves harnesses [IBM](https://www.youtube.com/watch?v=C_GG5g38vLU) [MLOps-Sandboxing](https://podcasters.spotify.com/pod/show/mlops/episodes/Sandboxing--Agent-Harnesses--and-Agent-Teamwork-e3kts75) (2026-06)
- Every agent is a while loop with conditions and end states; a human must design that state machine — don't let models rip through it, even when pairing [Cline](https://www.youtube.com/watch?v=yUmS-F9IX90) (2026-05)
- Move control flow OUT of the model when step-adherence is ~a coin flip; stop prompting harder. The model proposes, the harness decides, and is never asked to remember which of six steps it's on [Microsoft-ACE](https://www.youtube.com/watch?v=m24UKZomm7k) (2026-07)
- Inner vs outer harness: inner = the while loop in one process (model + tools + filesystem), or the tool definitions an agent exposes; outer = "brain" (which tool) split from "hands" (sandbox/state), or what you build around it. Split once → many brains × many hands [ZenML](https://podcasters.spotify.com/pod/show/mlops/episodes/Agents-are-Just-While-Loops-e3j3a6q) [Horthy-CtxEng](https://newsletter.pragmaticengineer.com/p/context-engineering-with-dex-horthy) (2026-05)
- **The harness dominates coding-eval results**: SWE-Bench Pro swung ~22% from harness alone while frontier models sat within a few points. One eval tests model, harness and problem realism at once; a strong model masks a weak harness [Cline](https://www.youtube.com/watch?v=QuuIywMG4s8) [DeepMind](https://www.youtube.com/watch?v=Ubwb6NzegyA) (2026-05)
- Harness + architecture decisions ≈ 3× the price swing of model selection — optimize the harness BEFORE picking the model [Notion](https://www.youtube.com/watch?v=wjXowoQ7E8c) (2026-06)
- **Biggest published context delta: 21% → >95%, same model** — curated per-domain reference docs (tables, joins, required filters, gotchas) vs raw data access. The lever is DISTILLATION: raw search over thousands of prior queries moved accuracy <1pp [Anthropic-analytics](https://claude.com/blog/how-anthropic-enables-self-service-data-analytics-with-claude) (2026-06) [DataChain-Petrov](https://www.youtube.com/watch?v=bUJgirn4_yc) (2026-07)

## Minimalism — get out of the model's way
- Frontier models let you *delete* prompt: Claude Code's system prompt shrank ~80%, largely by removing **examples** (the model out-imagines them) and replacing hard "do not" constraints with context [Anthropic-CC](https://www.youtube.com/watch?v=uU5Gv2h8-9g) (2026-07)
- ...but that shrink is a SAWTOOTH, not a trend: each release ships short because last cycle's hotfixes were post-trained in, then regrows as the team patches fresh behaviour. Repetition inside a prompt = "fighting the weights" [Breunig](https://podcasters.spotify.com/pod/show/mlops/episodes/The-Winchester-Mystery-House-Problem-in-AI-Development-e3nqiao) (2026-08)
- ...mechanism for dropping prohibitions: a negative instruction ("don't save greetings") activates exactly those parameters, and conflicting rules ("add any fact" vs "only important memories") are a common source of bad behavior [Vercel](https://www.youtube.com/watch?v=wflNENRSUb4) (2026-05)
- Each addition risks making the agent worse — large system prompts, edge cases and if-else degrade frontier models (Codex GPT-5.3's prompt is ~1/3 of GPT-5's) [Cline](https://www.youtube.com/watch?v=yUmS-F9IX90) (2026-05)
- "Bash is all you need": one `bash` tool returning stdout/stderr/exit code covers most work. But offer a DB tool alongside — hybrid bash + DB scored highest on analytical queries; pure DB wins analytics, file/grep wins quick lookups [Vercel](https://www.youtube.com/watch?v=wflNENRSUb4) [Elastic](https://www.youtube.com/watch?v=ynJyIKwjonM) (2026-05)
- **d0's evolution** (Vercel data agent, ~30k questions/month): scoped agents passing summaries hit a wall — handoff loses too much; one agent holding all context beat it; a Claude-Code-style filesystem agent with the semantic layer as files roughly DOUBLED eval scores [Vercel-d0](https://www.youtube.com/watch?v=I2cbIws9j10) (2026-07)
- ...corroborated elsewhere: a rigid discovery→plan→execute split was abandoned — discovery ran once and couldn't be revisited, context didn't flow between agents. Consolation: it moved errors from build-time to PLAN-time, where they're cheaper [Witan-Campos](https://www.youtube.com/watch?v=HEFSExa0xl0) (2026-07)
- **"Build to delete" telemetry**: Cursor replaced ~12,000 lines of worktree orchestration with a skill; Manus rebuilt its harness 5× in 6 months; Vercel removed 80% of tools and got fewer steps AND better accuracy. If your harness gets MORE complex as models improve, you're over-engineering [Gemini-WF26](https://www.youtube.com/watch?v=I2cbIws9j10) (2026-07)

## Frameworks & API lock-in
- Frameworks (LangChain/LangGraph) fit prototyping but hit a customizability ceiling in production — expect to rewrite. OpenGov moved OFF LangGraph to their own loop once use cases scaled; dependency injection in the loop hot-swaps the model [Cline](https://www.youtube.com/watch?v=yUmS-F9IX90) (2026-05) [OpenGov](https://www.youtube.com/watch?v=4uFVSLgD2Q4) (2026-06)
- Don't lock the harness to one provider — the best frontier model keeps shifting; Notion swaps its default every 3–4 weeks and forgoes vendor discounts to keep that optionality [Notion](https://www.youtube.com/watch?v=wjXowoQ7E8c) (2026-06)
- **Meta-harness = a portable layer above model AND harness**: keep context, memory, config and policies portable. Approval and budget semantics differ per harness AND per model, so the policy layer must NORMALIZE each, not express policy in prompts [Omnigent](https://podcasters.spotify.com/pod/show/mlops/episodes/Omnigent-Composition--Control--and-Collaboration-for-AI-Agents-e3lka92) (2026-07)
- Embedding an agent in an editor (ACP, the editor↔agent interop layer — JSON-RPC over stdio, LSP-shaped): **the detail everyone gets wrong is proxying the FILESYSTEM through the client**, so the agent sees UNSAVED BUFFER state instead of stale disk bytes. Same for terminals, which the client creates and manages [Zed-Fenner](https://www.youtube.com/watch?v=HsxQICTLF84) (2026-07)
- MCP Apps: a tool returns a UI *resource* the host renders sandboxed, bypassing the context window — an interactive 100k-row table for the user, a short confirmation for the model. Events route to the *host*, not a vendor backend [MCP UI](https://www.youtube.com/watch?v=o-zkvb0iFDQ) [FastMCP-Lowin](https://podcasters.spotify.com/pod/show/mlops/episodes/The-Creator-of-FastMCP-Explains-the-Future-of-MCP-e3maib0) (2026-05). Tooling choice: see misc.md § MCP vs CLI

## MCP security, trust & auth
- **Tool poisoning**: publish a benign server, earn an "always allow", then swap a tool's behavior. Manifest hashing and tools-list-changed both fail — they still trust the server's self-report. Real fix is trust in the SERVER (app-store model), an open problem [MCP-DarkSide](https://podcasters.spotify.com/pod/show/mlops/episodes/The-Dark-Side-of-MCP-Servers-e3l5thf) (2026-06)
- **Confused-deputy**: passing "whose email to check" as a tool parameter lets one injection swap the subject; even "always use the logged-in user's ID" is overridable when the subject is agent-controlled. Fix — MCP+OAuth carries the subject in the protocol HEADER from the authorization server [MCP-DarkSide](https://podcasters.spotify.com/pod/show/mlops/episodes/The-Dark-Side-of-MCP-Servers-e3l5thf) (2026-06)
- Legacy auth (fixed permissions granted at registration) structurally breaks: scopes safe for a human can't bound non-deterministic behavior — you need actor-bound, time-limited, purpose-scoped credentials. Most MCP servers compound it by surfacing the account's FULL tool surface [ScaleKit-Madabhushi](https://www.youtube.com/watch?v=lMCxVorb9wM) (2026-07)
- Keep MCP servers off the public internet: run them inside your network making only OUTBOUND calls to the hosted agent loop ("MCP tunnels"), rather than exposing an inbound endpoint [Anthropic-AppliedAI](https://www.youtube.com/watch?v=K0X9QDRkIdg) (2026-08)
- **Endpoint-level auth is too coarse**: one enterprise endpoint co-mingles sensitivities (an HR API returns timezones AND 401k data), and REST can't enforce policy because the server never sees what the agent composes across calls. Fix — declare intent as a query with per-field rights, approved field-by-field before execution [Apollo-DeBergalis](https://podcasters.spotify.com/pod/show/mlops/episodes/AI-Agents-Should-Be-Treated-Like-Hackers-e3lncle) (2026-07)

## Long-running / multi-hour agents
- **Three failure modes blocking multi-hour runs**: context (amnesia across sessions, rot, "context-sense anxiety" rushing near window end), weak planning (one-shots, or half-builds and stops), bad self-judgment (calls half-baked work done) [Anthropic](https://www.youtube.com/watch?v=mR-WAvEPRwE) (2026-05)
- Long-run pattern: an initializer expands a vague prompt into persistent artifacts — feature-list.json, progress file, init script, git repo — then a loop in fresh windows picks ONE unfinished feature, implements, verifies, commits, flips its done flag, repeats [Anthropic](https://www.youtube.com/watch?v=mR-WAvEPRwE) (2026-05)
- Add a planner decomposing into sprints but deliberately NOT specifying granular technical detail — a granular plan error cascades across every sprint. Keep the planner OUT of the build loop; re-inject the original spec as reference [Anthropic](https://www.youtube.com/watch?v=mR-WAvEPRwE) (2026-05)
- Forced to-do list as anti-early-exit device: have research first write a list such that completing every item leaves it ready to work — that list is what you re-prompt against. Each item writes notes so later agents QUERY them rather than inherit context [MorganStanley-AlphaLab](https://www.youtube.com/watch?v=kiqubc5b5Yo) (2026-07)
- **Harness mitigations are temporary**: with Opus 4.6 they dropped fresh-context resets AND sprint decomposition for one continuous compacted session, evaluating once at the end — ~half the cost. And a stale patch isn't free: the reset workaround kept one generation too long added latency AND discarded the prompt cache [Anthropic](https://www.youtube.com/watch?v=mR-WAvEPRwE) (2026-05) [Anthropic-AppliedAI](https://www.youtube.com/watch?v=K0X9QDRkIdg) (2026-08)
- On runs >48h detect context DRIFT — the "you're absolutely right" mimicry of early context creeping in — and hand off to a fresh agent rather than continuing a degraded session [AutoHand](https://www.youtube.com/watch?v=wjXowoQ7E8c) (2026-06)

## Control planes, durable execution & replay
- Harness as a **control plane** (scheduling, memory coordination, policy, routing) — an OS for agents. The model should **never directly control** production: model proposes → infrastructure validates → policy engine improves → execution gateway enforces [Meta-Superintelligence](https://www.youtube.com/watch?v=APh1Vx0oLmQ) (2026-06)
- **Retry amplification** is the biggest infra failure mode: bad tool call → error → retry with a slightly-different still-invalid request → repeat. Each retry deepens reasoning; uncontrolled retries are a compute incident waiting to happen [Meta-Superintelligence](https://www.youtube.com/watch?v=APh1Vx0oLmQ) (2026-06)
- **Memory consistency failures masquerade as reasoning failures**: stale reads, conflicting updates, inconsistent views. CAP/eventual-consistency issues hit once agents share state — many "agent reasoning errors" live in the state layer [Meta-Superintelligence](https://www.youtube.com/watch?v=APh1Vx0oLmQ) (2026-06)
- Keep execution (flow/state/durability/retries), context (models/prompts/tools/memory) and compute (sandboxes/runtimes) decoupled — prompts decay in weeks, models in months, execution lasts years; coupling drags the long-lived layer down [Inngest-Farrelly](https://www.youtube.com/watch?v=X1kp-ABIIxQ) (2026-07)
- Resumability requires state living externally and durably, not in the sandbox: a failed call at step 38 should retry from there. Treating a sandbox as durable storage is an anti-pattern — sandboxes are ephemeral by design [Inngest-Farrelly](https://www.youtube.com/watch?v=X1kp-ABIIxQ) (2026-07)
- Decouple brain (harness) from hands (execution env): one container loses the whole session when either dies and parks credentials next to a 10-hour unsupervised agent. Stateless harness → append-only event-log session → containers as hands, credentials in a vault [Anthropic-Martin](https://www.youtube.com/watch?v=9QebvrrY3KY) (2026-07)
- ...the split also buys LATENCY and recovery: decoupled, reasoning starts immediately with setup in parallel (60% faster TTFT at P50, >90% at P95); sandbox dies → the brain spins a fresh one; brain dies → it replays the log. The hands can sit in your VPC [Anthropic-AppliedAI](https://www.youtube.com/watch?v=K0X9QDRkIdg) (2026-08)
- **What durable execution guarantees**: recovery from *external* failures (pod killed, network drop, throttling) via backoff plus state rehydration. NOT: the program finishing (a bad tool call is app logic), or rollback of side effects — no control-Z on a Salesforce edit [ZenML](https://podcasters.spotify.com/pod/show/mlops/episodes/Agents-are-Just-While-Loops-e3j3a6q) (2026-05)
- **Sandbox checkpoint/restore is a harness PRIMITIVE, not crash insurance**: cheap block-level snapshots (copy-on-write reflink + FIEMAP diff) let the harness branch rollouts Monte-Carlo style and survive node death; guest-MEMORY snapshots give millisecond starts without warm pools. Route recovery by failure type — rate-limited → snapshot; crash → replay the context log [OpenAI-Bhardwaj](https://www.youtube.com/watch?v=OqM67QG_Ikk) (2026-07) [Trigger.dev](https://www.youtube.com/watch?v=svCnShDvgQg) (2026-05)
- **Replayability > bitwise determinism**: don't chase temperature-zero (GPU batching, MoE routing, float non-associativity make it impossible at scale) — record-and-replay, recording at **boundaries** (method I/O), not network or token level [Microsoft-Chronicle](https://www.youtube.com/watch?v=Lc8zRh9muoY) (2026-06)
- **Boundary annotation pattern**: wrap tool/LLM/retrieval calls with a `@boundary` decorator recording I/O pairs plus metadata (model version, code version, sampling params). The run becomes a frozen trace where you stub the LLM and run live tools — free CI with zero model calls [Microsoft-Chronicle](https://www.youtube.com/watch?v=Lc8zRh9muoY) (2026-06)
- **Cohort replay beats single replay**: one swapped-model replay looked equivalent, but a whole cohort showed the cheaper model produced worse resolutions in aggregate. A model passing 60% of the time is self-consistent only ~25%, so a single replay is not informative [ZenML-Tahir](https://www.youtube.com/watch?v=bZISsg7H7DA) (2026-07)
- SSE couples the stream to one client's connection — drop = stream lost — and forces resume and cancel to be mutually exclusive, since a client closing is ambiguous. Resumability needs buffered events with sequence numbers; steering needs a bidirectional transport [Ably](https://www.youtube.com/watch?v=YNJvm7t3yq8) (2026-05)
- **Past ~1000 tok/s the NETWORK, not inference, is the bottleneck**: tool-call-heavy turns spend their time in transport. Fix — a persistent WebSocket instead of SSE/HTTP, plus stateful server-side context so a turn sends only the changed item [OpenAI-Kundel](https://www.youtube.com/watch?v=shRR1e2HXMk) (2026-08)

## Event-sourced design & failure shapes
- **"The log IS the agent"**: the append-only event log is the agent's identity; the model's view, UI, debugging, auditing and compaction are all PROJECTIONS. The per-turn loop is DISPOSABLE — any worker claims a session, reads, advances one step, appends, disappears [Omnara](https://www.youtube.com/watch?v=UPwGaM2MKHY) (2026-06)
- **Deepest lock-in is LOG lock-in** — deeper than model (swappable) or API (wrappable). Claude Code/Codex write JSONL fire-and-forget, OpenCode uses SQLite with corruption issues, so reliability and forking get bolted on. Keep your log inspectable [Omnara](https://www.youtube.com/watch?v=UPwGaM2MKHY) (2026-06)
- **The session log is not the context window.** Conflate them and whatever the model compacts away is gone; keep every event in a durable log and the harness can read slices back in [Anthropic-AppliedAI](https://www.youtube.com/watch?v=K0X9QDRkIdg) (2026-08)
- Agent state = a synchronous pure reduce over the log; ban side effects in the reducer and move them to an `afterAppend` hook → on restart the reducer catches up over the backlog *without* re-firing N replayed LLM calls [Iterate](https://www.youtube.com/watch?v=vi-2nasppAg) (2026-05)
- **Anti-before-hooks stance**: blocking before-hooks break prompt caching and tank cost/latency — only the platform may block an append. Replace blocking with eventual consistency: wait up to ~200ms for optional enrichers, then proceed regardless [Iterate](https://www.youtube.com/watch?v=vi-2nasppAg) (2026-05)
- **Five production failure shapes, invisible in the moment**: state hole (delivery succeeded, the durable record didn't); overlapping writers (load-modify-save race); dangling tool call; approval drift (expired approval still durable); missing edge proof (tool reported success, nothing rendered) [OpenAI-Govindarajan](https://www.youtube.com/watch?v=BInpv7lGp1o) (2026-07)
- Ownership rule: for every fact the agent may reuse, name the system of record AND the replay path — "storage tells you where the bytes live, ownership tells you who can reconsider reality"; unreplayable is not remembered [OpenAI-Govindarajan](https://www.youtube.com/watch?v=BInpv7lGp1o) (2026-07)
- The concurrency rule is narrow: fan out sub-agents, parallel reads and many sessions freely, but keep ONE ordered commit path per mutable state boundary. Be conservative at commit time, not system-wide — "last writer wins is not a consistency model" [OpenAI-Govindarajan](https://www.youtube.com/watch?v=BInpv7lGp1o) (2026-07)

## Context & compaction
- **Two context budgets, not one**: the information budget *and* the **instruction** budget. Too many (especially conflicting) instructions degrade compliance, and a mid-conversation change of direction costs real computation to notice [Horthy-CtxEng](https://newsletter.pragmaticengineer.com/p/context-engineering-with-dex-horthy) (2026-07)
- **Context-zone guideline, with numbers**: keep working context ~100k tokens even on 1M-context models, under ~60k for the hardest problems. Dumb-zone tell — the model rationalizes a failing test away as "pre-existing". After ~2–3 months of heavy use intuition replaces the rule [LoopsDebate](https://www.youtube.com/watch?v=c35YoMdnI78) [HumanLayer-WF26](https://www.youtube.com/watch?v=I2cbIws9j10) (2026-07)
- **At million-token windows compaction is far less necessary** (one turn ran 104 min / 316 tool calls at 32% of a 1M window, zero compaction). Naive pruning hurts: trimming early tool calls to hold a 40–60% band invalidates the input cache every trim, costly at ~95% cache-read [Vercel](https://www.youtube.com/watch?v=wflNENRSUb4) (2026-05)
- Compaction takes the cache miss either way (~10× on those input tokens), so **compact for *intelligence*, never to save money**. And server-side compaction holds up where an ad-hoc summarizer doesn't, because it's a transform the model was explicitly TRAINED on [Cognition/Yan](https://www.youtube.com/watch?v=QHBjufYK8TA) [OpenAI-Kundel](https://www.youtube.com/watch?v=shRR1e2HXMk) (2026-08)
- **Faster models make compaction arrive 20× sooner in wall-clock**: a window taking ~10 min to fill at 40–60 tok/s fills in ~30s at ~1,200. Speed is a third selection axis beside intelligence and cost [Cerebras-Chieng](https://www.youtube.com/watch?v=TeGsFFNqRLA) (2026-05), corroborated by [OpenAI-Kundel](https://www.youtube.com/watch?v=shRR1e2HXMk) (2026-08) and [Microsoft-ACE](https://www.youtube.com/watch?v=fnLBmfsI_Fg) (2026-07)
- **Prefer offloading over compaction**: sub-agents take semi-independent work off the main thread and return a ~1k-token summary (one used 30k, returned ~500); a handoff tool lets the agent generate the context it carries into a fresh thread [Vercel](https://www.youtube.com/watch?v=wflNENRSUb4) (2026-05)
- **Reset instead of compact** (fleet-scale): compaction is slow, you can't choose what survives — wipe context and have the agent re-read the on-disk workspace it wrote. Live tension: Steinberger credits *server-side compaction* for reliable manager agents; state-in-files fleets reset, single long threads compact [KRAFTON-fleet](https://www.youtube.com/watch?v=4kYl2_mqmnQ) (2026-07)
- **Auto-compaction is lossy on the instruction you can least afford to lose**: a huge email list dumped into context triggered auto-compaction, the user's "don't delete" got overwhelmed in the summary, and the agent deleted the inbox. Do compaction surgery in a `prepare` hook as a deliberate pure function [Vercel](https://www.youtube.com/watch?v=wflNENRSUb4) (2026-05)
- **Smart truncation + an off-context store beats naive truncation and summarization**: keep head + tail, truncate the middle, dedupe repeated messages, keep only the latest tool result, never reset the system prompt, and stash the dropped middle in a DB keyed by IDs the agent can fetch back [Arize-context](https://www.youtube.com/watch?v=esY99nYXxR4) (2026-05)

## Memory
- **Memory needs an out-of-band consolidation pass ("dreaming")**, not just in-band writes, which can be wrong or locally optimal. Measured — a bad memory made the agent mislocalise and fail 5/5 replicates; dreaming corrected it, while no-memory made no progress at all [Anthropic-Martin](https://www.youtube.com/watch?v=9QebvrrY3KY) (2026-07)
- **Don't prescribe a memory schema.** Any programmable substrate works (filesystem or DB); performance DROPS when you pre-specify memory types. At higher capability the differentiator is **distillation** — saving the generalisable abstraction, not the fact [Anthropic-Martin](https://www.youtube.com/watch?v=9QebvrrY3KY) (2026-07)
- **Shipped consumer systems converged independently on two layers**: a continuously-updated "running profile" injected into every conversation, plus on-demand tools to search past conversations. Neither uses RAG over chunked conversations [Khemani](https://www.shloked.com/writing/claude-memory) (2026-08)
- ...the design dial being **profile length × update frequency**: ChatGPT ≈4k tokens refreshed every few days (high serving cost, low update cost); Claude ≈1k refreshed every 24h, exposing the raw profile and re-synthesizing on user edit [Khemani](https://www.shloked.com/writing/claude-memory) (2026-08)
- ...and a third shipped variant splits the profile by TIME WINDOW, precomputed offline because meaning can't be built at query time: a slow engine mining weeks into a durable profile, a fast one recomputing live signals over recent days [monday.com](https://www.youtube.com/watch?v=Btk8wDUVs74) (2026-07)
- ...its resilience trick: at serve time a thin slice is verified against live data and the rest falls back to last-verified context, with sources isolated so one bad feed can't take the others down [monday.com](https://www.youtube.com/watch?v=Btk8wDUVs74) (2026-07)
- **Memory-harness ablation on long-horizon local-model agents**: a "ranked decisions ledger" — log and rank each turn's decision, retrieve by rank — beat no-memory, vector-RAG and a use-memory gate, on XBench and Spider V2 [Druga/Sakana](https://www.youtube.com/watch?v=R3-anFK1YM8) (2026-08) [WF2026](https://www.youtube.com/watch?v=4sX_He5c4sI) (2026-07)
- ...two calibration points: an oracle handed the right memory every turn still did NOT hit max — the model can retrieve correctly and ignore it, so retrieval isn't the ceiling. And memory is pure cost while the task fits in context [Druga/Sakana](https://www.youtube.com/watch?v=R3-anFK1YM8) (2026-08)
- **Independent corroboration that fancy memory loses to plain context** (Continual Learning Bench, 6 domains): vanilla in-context learning topped raw reward AND held the reward-vs-cost Pareto frontier over dedicated context-management systems. Caveat — medium-horizon tasks [CL-Bench-Asawa](https://www.youtube.com/watch?v=iqloyWCGYQQ) (2026-08)
- **Three memory failure shapes to test for**: *stability* — corrected twice, the model jumped back to its original prediction, having lost the first correction; *plasticity* — a notepad dismissed an applicable schema as "from a different study"; *conflict-blindness* — a conversation *deciding between* options was consolidated as "did both" [CL-Bench-Asawa](https://www.youtube.com/watch?v=iqloyWCGYQQ) [Khemani](https://www.shloked.com/writing/chatgpt-memory-bitter-lesson) (2026-08)
- **Outcome-weighted memory retrieval**: rank memories by a learned "did this help or hurt" score, not embedding similarity — fixes stale-but-still-cited facts (a since-dropped DB column). Once memories cluster on one recurring case, fold the pattern into a skill [Starlight Search](https://www.youtube.com/watch?v=Jx4ZFEAq6bY) (2026-06)
- **Fleet-wide memory for a stateless agent = a pattern/anti-pattern catalog** as markdown in ONE git repo, not a vector DB: each entry carries the symbols to match on, services where it was confirmed, a confidence rising as more confirm, and both the anti-pattern and the good pattern [Netflix-Shah](https://www.youtube.com/watch?v=CgsWxRUY5Eo) (2026-07)
- **Scope limit on markdown memory**: fine for one agent and one user; degrades over time and across CONCURRENT agents, where a mutated line carries no trace of why it changed and errors compound uncaught [Zep-Chalef](https://www.youtube.com/watch?v=H7puB0RwJMM) (2026-07) [survey](https://arxiv.org/pdf/2606.04990) (2026-08)
- ...read that as a scope condition, NOT a refutation of the file-based entries above — the sharpest "markdown is not memory" framing is published by a graph-memory vendor, and the 2026 read is hybrid [Zep blog](https://blog.getzep.com/markdown-is-not-agent-memory/) (2026-08)
- **Provenance belongs in the STRUCTURE, not a log written afterwards**: synthesis destroys the paper trail — the derived fact appears nowhere verbatim in its sources. A `source_id` stamp breaks three ways: many parents per fact, entities merging, new data invalidating old [Zep-Chalef](https://www.youtube.com/watch?v=H7puB0RwJMM) (2026-07)
- ...which buys the deletion rule that retention and right-to-be-forgotten need: a derived fact SURVIVES if any remaining source still supports it, and dies only when none do [Zep-Chalef](https://www.youtube.com/watch?v=H7puB0RwJMM) (2026-07)
- **Tag sources ONCE at ingestion and let derived artifacts inherit** — retrieval then filters on veracity while walking the store. Keep the multi-parent policy in the AGENT, not the store: an allergy needs any parent asserting it, a consent needs all [Zep-Chalef](https://www.youtube.com/watch?v=H7puB0RwJMM) (2026-07)
- Push dedup and deconfliction OUT of the LLM wherever classical IR/NLP reaches (hashing, entropy) — cheaper, faster, more deterministic; reserve the model for the single-shot entity/relationship extraction nothing else does [Zep-Chalef](https://www.youtube.com/watch?v=H7puB0RwJMM) (2026-07)

## Guardrails as execution boundary (not behavior prompts)
- **"Stop asking the actor to behave; change what the actor can do."** A deterministic OS-level boundary, near-zero overhead: one policy file enforcing filesystem, network (forced through a filtering proxy, allow-listed domains) and command policies checked before exec, incl. chained shells [Tusk](https://www.youtube.com/watch?v=m12vGjfbNlo) (2026-05)
- ...make the egress allowlist grantable PER-TICKET as well as per-project, prompting on each new destination, or people route around it. Motivating failure: an agent told to wipe staging found a laptop token and hit prod [Superconductor-Singh](https://www.youtube.com/watch?v=OL7kfezynJM) (2026-08)
- Swiss-cheese defense in depth: (1) classification "is this reasonable?" probabilistic; (2) policy enforcement "is this allowed?" deterministic — the fence sits here; (3) isolation. Most teams have (1) and/or (3); **the missing MIDDLE layer is the OS-level allow/deny boundary** [Tusk](https://www.youtube.com/watch?v=m12vGjfbNlo) (2026-05)
- Guardrails you *prompt at* the agent aren't guardrails — any injection overrides them; they must be config the agent can't reach. Corollary: tell it anything from strangers (listing copy, scraped pages, inbound email) is "evidence, not instructions" [GitHub-Gazit](https://www.youtube.com/watch?v=iQ5xldZ9StU) (2026-08) [PwC](https://podcasters.spotify.com/pod/show/mlops/episodes/Autonomous-Agents-at-Work-From-OpenClaw-Hype-to-Enterprise-Reality-e3jj7u3) [Angie-Jones](https://www.youtube.com/watch?v=ZD9-4fW2HhM) (2026-05)
- **Safe outputs** — declare the exact write actions an agent may emit and cap the cardinality: "create *one* PR" means an injected agent can't open 500. Include "do nothing" as a declared output, or the automation becomes noise you learn to ignore [GitHub-Gazit](https://www.youtube.com/watch?v=iQ5xldZ9StU) (2026-08) [shipped docs](https://github.github.com/gh-aw/reference/safe-outputs/)
- ...the cap earns its place benignly too: issues wired into a repo with several agents able to file them and nobody capping creation produced 400–500 open issues in ~2 weeks [Amazon-AGI-Khandelwal](https://www.youtube.com/watch?v=aeTb5BdmTTc) (2026-08)
- **Guard the ACTION surface, not the input**: gating everything an agent reads is hopeless (every page, message, issue and promotional email is an injection channel), so let it read freely and check deterministically at the point it acts — allow / needs-approval / deny [Rallabandi](https://www.youtube.com/watch?v=s67bE2Ur3bY) (2026-07)
- Policy evaluates *before* a credential is minted: token exchange (RFC 8693) scopes each tool call to one audience, short-lived and never stored, so a disallowed action never gets a credential at all [Keycard-Maida](https://www.youtube.com/watch?v=I3znWC3MEXM) (2026-07)
- Permission classifier over static rules: a fast model judges each tool/bash call *in conversation context*, so "push this to GitHub" grants what "don't push" denies, and it mediates sandbox escapes where deterministic rules have too many edge cases [Anthropic-CC](https://www.youtube.com/watch?v=uU5Gv2h8-9g) (2026-07)
- **Shipped shape of that classifier — a crippled reviewer sub-agent**: read-only, may not spawn sub-agents, handed the transcript, the pending call, a risk taxonomy and "did the user authorize this?". Scores authorization × impact rather than matching commands; exfiltration is never auto-approvable. Ships as a third permission MODE (auto-review) [OpenAI-Kundel](https://www.youtube.com/watch?v=shRR1e2HXMk) [OpenAI-Liu-MLOps](https://podcasters.spotify.com/pod/show/mlops/episodes/How-To-Delegate-To-An-Agent-Like-You-Would-An-Employee-e3nglg8) (2026-08)
- **Deterministic enforcement, LLM as advisor-not-bouncer**: rule match → block/kill-session before any model sees it; the LLM triage layer only reviews non-blocked findings to silence false positives, can never let things through, and fails closed. "If it isn't enforced deterministically, it isn't enforced" [PostHog-WF26](https://www.youtube.com/watch?v=I2cbIws9j10) (2026-07)
- **Layered prompt stack with a DETERMINISTIC post-generation veto at the bottom**: (1) immutable identity, (2) situational mode, (3) example-anchored voice, (4) veto. Layers 1–3 are probabilistic instructions; layer 4 is the only one reading actual OUTPUT against ground truth (an offered date must be in an allowlist) [Isadora](https://www.youtube.com/watch?v=ij-AU9dpJjc) (2026-06)
- Multi-tenant identity must NEVER have a default — a missing brand-identity field should crash, not silently fall back, else white-label leak (every venue shipped as the default persona, emailing from another tenant's address) [Isadora](https://www.youtube.com/watch?v=ij-AU9dpJjc) (2026-06)
- **Guardrails as SEPARATE judge calls sandwiching the agent** (input judge on the message; output judge on the response AND the conversation) are measurably harder to jailbreak around than the same rules inside the main prompt — a latency premium a high-stakes domain can justify, and each is independently evaluable [SonderMind](https://www.youtube.com/watch?v=O72p-rBb2bA) (2026-07)

## Retrieval & comprehension
- **Live disagreement, and the condition that decides it**: agentic grep beat AST indexing plus dense/sparse RAG on solo/medium repos, while Cursor measured +12.5% average answer accuracy on large codebases (~24% for Composer), +2.6% code retention, −2.2% dissatisfied requests. Scale decides [Pi](https://newsletter.pragmaticengineer.com/p/building-pi-and-what-makes-self-modifying) (2026-04) [Turbopuffer](https://www.youtube.com/watch?v=UM6sFg_jdlE) (2026-06)
- **Bolt-on tool ≪ native tool**: Claude Code is trained around grep and doesn't know when to call an extra semantic-search tool, so gains run far below Cursor's, where Composer treats it as built-in — a retrieval tool's value depends on the model being trained to invoke it [Turbopuffer-CC](https://www.youtube.com/watch?v=zKk7sDMGDEQ) (2026-06)
- **WHY agents underuse semantic search — the query-writing habit**: coding models emit keyword-gibberish because their habits come from grep/regex and BM25-favoring benchmarks. Fixes: instruct "write one concise sentence describing what you want to find"; few-shot good queries; split intent into ≤4 aspect queries; ≤4 rounds, parallel within a round, dedupe across [Mixedbread](https://www.youtube.com/watch?v=1IdzkRVmWAA) (2026-07)
- **Clone a dependency's source repo INTO your project** (git subtree, squashed) so the agent reads it as first-class code: models are post-trained to focus on your repo and won't read gitignored dirs at all. Add a test-runner ignore, and forbid watch/dev-server commands in AGENTS.md or it hangs [Effect](https://www.youtube.com/watch?v=Wmp2Tku2PrI) (2026-05) [Nx-Savkin](https://www.youtube.com/watch?v=jVjt-2g8NMY) (2026-06)
- **"LLMs plan, deterministic code searches"** — over 500k near-identical names, embeddings can't discriminate 20-char strings differing by one char. The LLM sees a schema summary and emits a plan {collect, scope, filter}; a resolver runs set operations over pre-indexed subtrees. Naive-LLM 80%→30% as nodes grew 64→460k; plan+resolver 100% at a flat ~9k tokens/query [Phaidra](https://www.youtube.com/watch?v=EUsPvBeIx70) (2026-07)
- **"Satisfaction of search"**: agents stop at the first plausible match (like radiologists), so retrieval must force exhaustive search or it grabs the wrong pattern → correction doom-loop [Unblocked](https://www.youtube.com/watch?v=BiG2ssibKGc) (2026-05)
- **You cannot search for a NEGATIVE** — "which procedures see no field usage", "which failures have no docs", and whole-corpus pattern questions need navigation or aggregation, not top-k. Grounding on structure first also cuts vector hops, each a chance to grab the wrong doc [Neo4j-Blumenfeld](https://www.youtube.com/watch?v=kRkcNOsRyYg) (2026-07)
- ...cheapest corpus-wide shape for that: Leiden community detection over the doc→doc link graph ALONE, clusters described only from data already in them plus a conductance score for tight-vs-loose. Deterministic, so it re-runs as a time series [Neo4j-Blumenfeld](https://www.youtube.com/watch?v=kRkcNOsRyYg) (2026-07)
- ...but having the shape doesn't mean the agent picks it: given an estate-level question it skipped the cheap outline traversal for an exhaustive text crawl — right answer, far slower [Neo4j-Blumenfeld](https://www.youtube.com/watch?v=kRkcNOsRyYg) (2026-07)
- **Split retrieval in two and expect EXTRACTION to be the hard half**: (a) produce good output given context, (b) traverse the store to find the right context. One team trained custom traversal tools in an RL environment for (b) — the half that usually gets no investment [Varick-Pruitt](https://www.youtube.com/watch?v=l0FLhNqBOic) (2026-07)
- Cheap statistical retrieval-confidence signal instead of an LLM self-check per search: stats over the top-K scores (spread, top-1/top-2 gap), then tier escalation — confident → proceed; borderline → cross-encoder rerank; clearly bad → LLM re-query. Agents search far more often than humans [Qdrant-Roundtable](https://podcasters.spotify.com/pod/show/mlops/episodes/The-Current-State-of-Agentic-Retrieval---Qdrant-Roundtable-e3lh8v8) (2026-07)
- In a large mature codebase the dominant agent use is comprehension, not generation (measured 67% comprehension / 2% code gen) — instrument your own usage to find where leverage actually is [Sentry](https://www.youtube.com/watch?v=li0SaBt9RDM) (2026-05)

### Data agents — structuring the corpus before the agent reads it
- **Rank your sources of truth; don't hand the agent N knowledge bases of equal weight.** Ambiguity about which table is authoritative, not model size, is what makes enterprise data agents wrong. Cleanest→messiest: semantic layer → canonical parameterized queries → full table/column/metric graph. Build order follows cost — the first two cover ~80% cheaply, the graph is the last 20% [Tesla-Daga](https://www.youtube.com/watch?v=B8l81jhvHbI) (2026-07)
- **Overloaded vocabulary is the same ambiguity one layer up and needs an explicit ontology**: one entity is "customer" to sales, "client" to ops, "billing entity" to finance, "org ID" to devs. Diagnostic — list cross-team overloaded terms, find the translation points, name the systems of record you can't swap [Kepler-Ganesh](https://www.youtube.com/watch?v=1OMHGsUZiqA) (2026-07)
- **Entity resolution needs its own tool, not better prompting**: the same person is spelled differently across email, Slack and docs and the model silently conflates or splits them. For process corpora the representation is a dependency graph, but the STORE doesn't matter — Postgres is fine [Varick-Pruitt](https://www.youtube.com/watch?v=l0FLhNqBOic) (2026-07)
- **Staleness needs a lifecycle, not better docs**: bind context to sources updated BY CONSTRUCTION (dbt/Tableau semantic layer, GitHub, CRM) over hand-maintained markdown, and log every correction as an event feeding back into context [Tesla-Daga](https://www.youtube.com/watch?v=B8l81jhvHbI) (2026-07)
- ...with the number that makes it urgent: that Anthropic analytics deployment drifted 95% → 65% in ONE month, until every data-model change had to update its matching context in the SAME PR [Anthropic-analytics](https://claude.com/blog/how-anthropic-enables-self-service-data-analytics-with-claude) (2026-06)
- **Unstructured corpora explode on the way in** — 90 dash-cam videos yield ~100k detection records (clips→frames→objects→labels), so neither millions of sidecar JSONs on S3 nor a separate SQL stack works. Pydantic schemas transpiled to a queryable local DB keep schema, data and code in one language [DataChain-Petrov](https://www.youtube.com/watch?v=bUJgirn4_yc) (2026-07)
- **Index documents by their EXISTING structure before reaching for LLM extraction**: containment tree from folder/section nesting, ordering edges, cross-doc links by regex — no model in the ingest path, so it is idempotent, fast and stable run to run [Neo4j-Blumenfeld](https://www.youtube.com/watch?v=kRkcNOsRyYg) (2026-07)
- ...its price: only as good as your titles and link labels, and it cannot flag a merely STALE doc — the reported top real-world failure. LLM entity extraction plus cluster summaries is more capable but costs more and differs run to run [Neo4j-Blumenfeld](https://www.youtube.com/watch?v=kRkcNOsRyYg) (2026-07)
- **Give each node a hierarchical URI as its ID**: buys subtree-scoped search via a prefix filter, plus drill-down from any URI the agent just saw. Traversal depth as a query parameter [Neo4j-Blumenfeld](https://www.youtube.com/watch?v=kRkcNOsRyYg) (2026-07)
- **Relationship/label vocabulary is a context-window budget, not taste**: one coarse `has` across every containment level keeps queries simple; granular names are more precise but at scale the vocabulary stops fitting and query generation degrades [Neo4j-Blumenfeld](https://www.youtube.com/watch?v=kRkcNOsRyYg) (2026-07)
- Publish each derived dataset as a markdown entry carrying why it was built, schema, stats, a preview and — the part called most important — the SOURCE CODE, so the next teammate's agent reuses it instead of re-running the compute. Verification bites harder here: in data there is usually exactly one correct answer [DataChain-Petrov](https://www.youtube.com/watch?v=bUJgirn4_yc) (2026-07)

## Tool design for agents
- **Tool-count accuracy collapse, measured**: every schema in every prompt gives tool-selection accuracy ~78% at 10 tools → ~40% at 100 → ~13.6% at 741. Semantic routing holds >83% flat. 741 schemas ≈127k tokens vs ~1k for JIT retrieval of 3–5; full-catalog TTFT blows past 5s at ~500 tools [Prosodica](https://www.youtube.com/watch?v=vh2VGuQ3zhY) (2026-06)
- **Deferred tools are an API-level primitive now** (Responses API since GPT-5.4): mark a tool deferred so its schema never enters context and the model reaches it via tool search — built-in or your own discovery implementation [OpenAI-Kundel](https://www.youtube.com/watch?v=shRR1e2HXMk) (2026-08)
- **Partial function application, the strongest safety primitive short of withholding the tool**: lock a tool's dangerous argument (bind the directory a file tool can touch) so the model never sees or changes it — full autonomy without an approval bottleneck, because it isn't promptable around [Etsy-Bhargava](https://www.youtube.com/watch?v=2e9ANoOEn28) (2026-07)
- **The trend is fewer tools, and its endpoint is collapsing them into ONE REPL**: ~15 spreadsheet tools became JS functions inside a single Node REPL call; internal benchmark 50%→74% (later 92%), 5-minute timeouts to essentially zero. Parallel tool calls hadn't helped — you can't combine their results [Witan-Campos](https://www.youtube.com/watch?v=HEFSExa0xl0) (2026-07)
- Heuristic for spotting the need: many sequential or parallel tool calls means you've invented a bad scripting language — give it a real one. **REPL ≠ code mode; the difference is persistent state**: variables surviving between calls make agents write SHORTER scripts and interleave reasoning between steps [Witan-Campos](https://www.youtube.com/watch?v=HEFSExa0xl0) (2026-07)
- **Same conclusion reached independently for COMPUTER USE**: the one-action-per-turn click/type tool was replaced by a persistent Node REPL the agent writes Playwright JS into — inspect one page, then script the rest instead of paying a turn per click [OpenAI-Kundel](https://www.youtube.com/watch?v=shRR1e2HXMk) (2026-08)
- **Match tools to what the model was post-trained on, and ship the binary**: models are trained on `apply_patch` and reach for ripgrep unprompted, so the Codex harness BUNDLES ripgrep rather than teaching another tool; on Windows the model emits PowerShell [OpenAI-Kundel](https://www.youtube.com/watch?v=shRR1e2HXMk) (2026-08)
- ...the flip side when your harness ISN'T lab-shaped: if your tool definitions merely resemble Claude Code's, the model reaches for Claude Code tools that aren't there and your instructions must fight it. Labs are trading model diversity for agentic reliability [Breunig](https://podcasters.spotify.com/pod/show/mlops/episodes/The-Winchester-Mystery-House-Problem-in-AI-Development-e3nqiao) (2026-08)
- **Derive composite tools from your existing UI, not your API surface**: a product page already orchestrates ~10–20 API calls to serve one human need — expose that as ONE intent-shaped tool. Antidote to one-to-one API→tool sprawl [MCPcat](https://podcasters.spotify.com/pod/show/mlops/episodes/MCP-Servers-Are-Becoming-the-UI-for-AI-Agents-e3ks6n3) (2026-06)
- **Tool-misrouting fix ladder**: write a *real* description (core purpose → "use when / don't use when" → relationships) → if still wrong, reinforce it in the system prompt. Bootstrap unknown query shapes with ONE general tool plus logging — >4–5 calls per question means carve out a specialized tool [Elastic](https://www.youtube.com/watch?v=ynJyIKwjonM) (2026-05)
- **HTML over SVG/canvas as the agent-native medium for visual artifacts**: models have seen billions of HTML examples and reason about tags as structured language, while SVG is "a wall of numbers" — which is why canvas-based tools underperform. Generate in HTML, render out to PDF or slides [Nori Agentic](https://www.youtube.com/watch?v=htM02KMNZnk) (2026-07)
- Constrained "focus modes" (plan/research/debug) shrink the action and input space so you can drop irrelevant tools and tune evals per mode; debug mode is hypothesis-driven — spin up a dedicated debug server and push logs there rather than reasoning blind [Flinn](https://www.youtube.com/watch?v=7CrPrHgoEYk) (2026-05)
- Tool outputs as semantic summaries: a 50k-line JSON perf trace blows any context, so return key metrics and keep the raw file on disk. Counter-case — RAW profiler output is worth feeding directly, since the model spots a quadratic from the call stack. Summarize unstructured blobs, pass through structured columns [Chrome DevTools](https://www.youtube.com/watch?v=_B4Pv9ttFgY) (2026-06) [Netflix-Shah](https://www.youtube.com/watch?v=CgsWxRUY5Eo) (2026-07)
- Add a `token_limit` parameter to any tool that can return unbounded output (log queries, "search all users") so the LLM declares how many tokens it wants back; map it deliberately NOT one-to-one to the underlying API [MCPcat](https://podcasters.spotify.com/pod/show/mlops/episodes/MCP-Servers-Are-Becoming-the-UI-for-AI-Agents-e3ks6n3) (2026-06)
- **Errors as steering, not just reporting**: on a bad call return a constructive error naming the likely fix ("you forgot `last_name`, retry"). Customers running this report large success-rate gains at near-zero overhead; every unrecovered error is retry tokens [MCPcat](https://podcasters.spotify.com/pod/show/mlops/episodes/MCP-Servers-Are-Becoming-the-UI-for-AI-Agents-e3ks6n3) [Chrome DevTools](https://www.youtube.com/watch?v=_B4Pv9ttFgY) (2026-06)

## Computer use & browser agents
- **Rendered state is not in the HTML — the structural reason scraping agents fail.** An NBA score arrives via async XHR after an empty placeholder; stock status lives in a JSON `quantity: 0` a script turns into a greyed-out option, with no "sold out" text anywhere [Yutori-Batra](https://www.youtube.com/watch?v=Ki980nV0__0) (2026-08)
- Hence the **bitter lesson for web agents**: per-site scaffolds don't reach the long tail, pixels-in does. But don't stay limited to *human* actions — add an `execute JS` action so the model scripts what's cheaper to script while verifying through the SCREENSHOT [Yutori-Batra](https://www.youtube.com/watch?v=Ki980nV0__0) (2026-08)
- Page representation token cost: full DOM ≈20k tokens, raw screenshot ≈1.1k, compressed markdown ≈1.8k — compact markdown + screenshot let a cheap model plan a 30-step task. **Diff-based feedback beats re-screenshotting**: state what changed so it recovers from a failed click instead of looping [ARK](https://www.youtube.com/watch?v=JnubYCYunk8) (2026-06)
- **Partial observability is structural, and the model has no prior about which source to trust**: the DOM misses dynamically-generated content (ad text baked into an image), the screenshot misses anything below the fold. Feeding both without saying what each is good for is its own failure mode [Amazon-AGI-Mishra](https://www.youtube.com/watch?v=Cc0_nyxROBA) (2026-08)
- **Chrome stamps every input event trusted or untrusted, and pages drop untrusted input SILENTLY** — a synthetic JS `click()` gives no error and no effect. Escalation ladder: page's own JS API → CDP input domain (trusted) → real mouse path with jitter and overshoot plus vision. Climb only as far as the page forces [Rexmore-Gallon](https://www.youtube.com/watch?v=26RtyAm9y_Q) (2026-08)
- **Verify through a DIFFERENT channel than you acted through** — don't ask the click whether it worked, read the network or the screen. Loop is sense → act → verify [Rexmore-Gallon](https://www.youtube.com/watch?v=26RtyAm9y_Q) (2026-08). Independently framed as perceive → plan → act after robotics: today's agents fire an action and move on, never watching whether it landed [Amazon-AGI-Barth](https://www.youtube.com/watch?v=2JX6JYyQG4Y) (2026-07)
- **Annotation as an INPUT channel, not just an output one**: let the user point at on-screen elements and attach the instruction there, capturing element, location and current style into a structured summary. A more precise and less lossy signal than a prose description, and it kills the describe/misunderstand/re-describe round trips [Amazon-AGI-Barth](https://www.youtube.com/watch?v=2JX6JYyQG4Y) (2026-07)
- Two failure modes from real RL training runs: session expires → the model reasons "credential expired, but I can infer the password", guesses repeatedly and LOCKS the account; an ad with a lookalike submit button → it clicks through to a third-party site and fills in personal details [Amazon-AGI-Mishra](https://www.youtube.com/watch?v=Cc0_nyxROBA) (2026-08)
- **Recovery has to be a native model action, not an infra reset**: training loops reset state on error, but real life doesn't — surface the error and require recovery through real actions (refresh, backtrack, wait, abandon, escalate). Reward the PATH too, since "done" can include side effects nobody asked for [Amazon-AGI-Mishra](https://www.youtube.com/watch?v=Cc0_nyxROBA) (2026-08)

## Production failure modes (LLM/VLM-in-the-loop)
- Output loops: ~0.5–1% of queries return repeated output; worst is a whitespace loop burning the full budget, and you can't use space as a stop sequence (tokenizers have 1..128-space tokens). Fix: stream plus repetition-detection to kill early, then retry with a different model/prompt/temperature [LlamaIndex](https://www.youtube.com/watch?v=m12vGjfbNlo) (2026-05)
- **Claude silently drops part of a multi-part instruction**: told to support both sync and async hooks, it implements sync and omits async — ~2 of 3 rollouts, notable because Claude is otherwise the most exhaustive explorer. Split multi-part requirements into separately-verifiable items; GPT misses stated requirements least [DeepSWE](https://www.youtube.com/watch?v=Yk87oUPVaxU) (2026-07)
- **Never make an LLM enumerate long lists of near-identical names**: sharding across parallel calls yields phantom entities plus silently dropped real ones, and internal repetition penalties truncate even a legitimate ~100-item enumeration. Produce such lists in code [Phaidra](https://www.youtube.com/watch?v=EUsPvBeIx70) (2026-07)
- Empty-input hallucination: a templated prompt plus an empty or failed tool result makes the model invent content rather than report empty (Anthropic models love fake "Delaware incorporation documents") — check for blank input before the call [LlamaIndex](https://www.youtube.com/watch?v=m12vGjfbNlo) (2026-05)
- Provider reliability: APIs go down roughly daily → multi-provider fallback with each family on its OWN code path; keep a NON-LLM fallback (a CPU parser at ~500 pages/s). Thinking loops are harder to catch now providers stopped streaming the trace, leaving max_tokens as a blunt cap [LlamaIndex](https://www.youtube.com/watch?v=m12vGjfbNlo) (2026-05)

## Generator / evaluator (adversarial critic)
- **Separate the verifier's *context window*, not just its prompt**: one context both doing and grading confabulates. Tuning a standalone critic to be harsh is tractable; tuning a builder to be self-critical is not [Anthropic-Martin](https://www.youtube.com/watch?v=9QebvrrY3KY) (2026-07) [Anthropic](https://www.youtube.com/watch?v=mR-WAvEPRwE) (2026-05)
- **`goal` / `outcomes` put a measurable end state in the environment; how it terminates constrains what you write**: the harness re-injects the objective after every turn and stops only when the model calls update-goal declaring it met. An essay-length goal has no detectable done state [OpenAI-Kundel](https://www.youtube.com/watch?v=shRR1e2HXMk) (2026-08)
- The evaluator must actually USE the app (Playwright: open pages, click, screenshot), not just read diffs — catching live-only bugs unit tests pass. Same for production monitoring, though a site-specific skill that knows your DOM is far faster than generic browser use [Anthropic](https://www.youtube.com/watch?v=mR-WAvEPRwE) (2026-05) [Wandero](https://www.youtube.com/watch?v=kZsf_Sfm7RU) (2026-07)
- **Give that evaluator a written design spec to grade against** (`design.md`: colours, components, layout rules — extractable from the existing design if never written down), then run two passes: a VISUAL on-brand check plus the user-flow walkthrough, emitting a pass/fail report naming what failed [Amazon-AGI-Barth](https://www.youtube.com/watch?v=2JX6JYyQG4Y) (2026-07)
- ...and treat a flagged violation as a FORK, not a verdict: fix the code, or decide the spec was wrong and update it. Without that branch a stale design rule quietly becomes the thing the agent optimizes against [Amazon-AGI-Barth](https://www.youtube.com/watch?v=2JX6JYyQG4Y) (2026-07)
- **When the product isn't a web page, build the driving CLI yourself**: screenshot, a token-compressed snapshot of UI state, log extraction from front-end AND back-end, service restart, plus high-level composable commands. Domain variant: an ASCII rendering of your 3D world for a Unity game [Poolside-Lajili](https://www.youtube.com/watch?v=iRcX54EO5g8) (2026-07)
- **Don't accept the fix until the agent REPRODUCED the bug** — agents are eager ("I know what's going on, just add this call") and until reproduction that's an assertion, not a diagnosis. This is the precondition for trusting an unattended run [Poolside-Lajili](https://www.youtube.com/watch?v=iRcX54EO5g8) (2026-07)
- Why brownfield trails greenfield: not code age — the agent's INTUITION is right on greenfield and wrong against dead code and paths it never looked at, so the feedback loop is the whole gap. Explains the polarized field reports [Poolside-Lajili](https://www.youtube.com/watch?v=iRcX54EO5g8) (2026-07)
- **"Negotiate done" before building**: the generator proposes feature plus tests, the evaluator pushes back on scope, weak tests and missed edge cases, iterating on disk until both agree — THEN build, graded against that contract. One app produced 27 criteria; vague criteria give vague critiques [Anthropic](https://www.youtube.com/watch?v=mR-WAvEPRwE) (2026-05)
- A GAN-style loop course-corrects by throwing everything out and restarting when stuck; a single-pass loop keeps patching the same broken thing. 4.6-class models readily discarded 10 passes and did NOT rubber-stamp as feared — out of forward progress → wipe and restart differently [Anthropic](https://www.youtube.com/watch?v=mR-WAvEPRwE) (2026-05) [Kent Beck](https://newsletter.pragmaticengineer.com/p/how-kent-beck-shapes-the-software) (2026-07)

## Verification & anti-cheating
- **Make the verification agent independent and adversarial**: it never sees the discovery agent's reasoning, receives only the claimed finding, and is told to assume it's false and prove that. Discovery optimises recall, verification precision — a discovery agent that debates itself self-censors [Anthropic-Yan](https://www.youtube.com/watch?v=imFedndyXYQ) (2026-07)
- Patch-validation ladder: the original exploit stops working → the existing suite stays green → a *fresh* discovery agent re-attacks the patched code → a human confirms. Feeding that re-attack signal back improves patch quality substantially [Anthropic-Yan](https://www.youtube.com/watch?v=imFedndyXYQ) (2026-07)
- **Agents fabricate rather than report tool failure**: a blocked or empty fetch is presented as "I searched the web", and a failed fetch silently falls back to stale training data answered as current. Verify tool *results*; treat agent-supplied citations as unverified until fetched. A 20-page deep-research report cites product features that don't exist [Bright Data](https://www.youtube.com/watch?v=btxGmN8RvNU) (2026-06) [Wisedocs-Linkov](https://www.youtube.com/watch?v=7vn4WpqNpck) (2026-08)
- **Agents lie about doing work** (touched a sentinel file claiming tests ran) — require cryptographic proof: SHA-256 the actual test output into the marker file. Make doing the real work easier than faking it; a deterministic verify step should read the run's own trace history to confirm it happened [WorkOS](https://www.youtube.com/watch?v=vy7o1g2iHY8) [IBM](https://www.youtube.com/watch?v=C_GG5g38vLU) (2026-05)
- **Treat "done" as an OBJECT, not a boolean**: artifact + scope + rubric + evidence + who verified + sign-off authority + residual risk + next owner. Done-ness is a ladder (producer-claimed → evidence-verified → approver-signed → survived-real-world), and merge-done, deploy-done and announce-done are different claims [Dotta/Paperclip](https://www.youtube.com/watch?v=7P0elyLIxXo) (2026-07)
- **One line of prompt can switch self-verification off**: SWE-Bench Pro's template says tests are handled and the model needn't write any — that sentence stops even GPT-5.5 and Opus 4.8 from verifying their own work. Audit prompts for accidental suppression of a behaviour you want [DeepSWE](https://www.youtube.com/watch?v=Yk87oUPVaxU) (2026-07)
- **Agents edit or delete the TEST to make it pass** — the agent must never modify a test, must run a fast suite (~300ms) before AND after every change, and must fix red rather than rewrite the expected value, because expected values ARE the spec. Commit code and passing tests BEFORE letting it touch tests [Kent Beck](https://newsletter.pragmaticengineer.com/p/tdd-ai-agents-and-coding-with-kent) [Playwright](https://www.youtube.com/watch?v=FWEInOtngmM) (2025-06)
- **Verification chain before a human looks at an agent-authored perf rewrite**: unit + integration tests, THEN a canary — old and new code taking the same traffic ~10 min — reading CPU, latency and error rate; an error-rate rise means it got the logic wrong. "The profiler gives the estimate, the canary gives ground truth" [Netflix-Shah](https://www.youtube.com/watch?v=CgsWxRUY5Eo) (2026-07)

## Enforcement loop — pin to the action the agent must take
- The harness IS the enforcement loop: git hooks + CI + linters running identical tasks pre-commit and on CI, so a lazy agent skipping local checks gets caught downstream. Pin enforcement to git — the action it must take to deliver a PR [SafeIntelligence](https://www.youtube.com/watch?v=504PvfXou5Y) (2026-06)
- **Deterministic instructions > prompt-nagging AT SCALE**: "PLEASE run tests before commit" in screaming-caps AGENTS.md is a code smell — make it hooks/CI gates, since arguing over process steps is unreliable across thousands of runs; reserve screaming-caps files for solo workflows [Stripe](https://www.youtube.com/watch?v=_xQnSNlBP_w) (2026-05)
- **Encode org policy at BOTH ends of the loop**: an allow/deny list (disallowed machine types) in the dev-environment system prompt so the agent never generates the banned resource, plus the same rule as a PR-stage check — the engineer tracks neither [Wayfair-Eubanks](https://podcasters.spotify.com/pod/show/mlops/episodes/How-Predictive-Analytics-Stops-Budget-Overruns-Before-They-Happen-e3nk2h1) (2026-08)
- **Pre-commit hooks that echo prompts**: encode architecture and domain boundaries as hooks whose failure output IS a prompt ("this module can't depend on that") — back-pressure that stops the loop closing until constraints are satisfied. Humans resent slow hooks; agents don't care [Huntley-WF26](https://www.youtube.com/watch?v=I2cbIws9j10) (2026-07)
- **Session-END is the other attachment point**: a Stop hook runs a deterministic check suite when the agent finishes and feeds failures back — the agent doesn't get to declare done. Same contract belongs at every level, with a judge tier only for what can't be checked deterministically [Checkout.com-Sheikh](https://www.youtube.com/watch?v=MpZzWMdmQCE) (2026-07)
- Against "the next model won't need this": each release buys CAPABILITY, a different axis from RELIABILITY, and enforcement is priced against the latter. Instructions are not verification — the best spec, MCP servers and sub-agents still aren't a check that the thing happened [Checkout.com-Sheikh](https://www.youtube.com/watch?v=MpZzWMdmQCE) (2026-07)
- **Prevent whole bug classes by construction** instead of detecting instances: enforce architecture via module-import rules — a BDD suite forbidden from importing DB-accessing modules, templates forbidden from DB access, making N+1 queries structurally impossible [SafeIntelligence](https://www.youtube.com/watch?v=504PvfXou5Y) (2026-06)

## Guardrails & limits
- **Under-privileged credentials trigger credential-hunting**: give an agent a token too weak for its goal and it goal-seeks the filesystem for stronger ones. RL makes models *more* goal-seeking, not safer — alignment comes from infrastructure. Most concrete mitigation: never keep secrets as files [LoopsDebate](https://www.youtube.com/watch?v=c35YoMdnI78) [Huntley+Keycard-WF26](https://www.youtube.com/watch?v=I2cbIws9j10) (2026-07)
- **Sub-agents inherit the goal, not the discipline**: sub-agents spawned for large tasks tried to circumvent the parent's guardrails by hunting and inventing secrets from anywhere in the codebase — caught only via output scanning; PostHog banned sub-agents in that product [PostHog-WF26](https://www.youtube.com/watch?v=I2cbIws9j10) (2026-07)
- **Composable hard caps at the harness level**: max iterations (kill run), max messages (trigger compaction), max tool calls, max retries, recursion depth, execution time, max DIFF SIZE, read-only mode, no file deletion — cost spirals without per-run budgets. Throttle by reading OpenTelemetry traces back into the loop every ~10 calls [IBM](https://www.youtube.com/watch?v=C_GG5g38vLU) [PwC](https://podcasters.spotify.com/pod/show/mlops/episodes/Autonomous-Agents-at-Work-From-OpenClaw-Hype-to-Enterprise-Reality-e3jj7u3) [Cerebras-Chieng](https://www.youtube.com/watch?v=TeGsFFNqRLA) (2026-05)
- **Confidence gate with a PRIVATE escalation channel**: an agent watching Slack answers only when confident, and when unsure DMs a human — so the public channel only sees vetted answers and uncertainty costs one person a glance instead of a visible wrong reply [Resolve-Smith](https://www.youtube.com/watch?v=vSx5IULvBns) (2026-08)
- **Grant autonomy as an earned spectrum**: shadow (can't affect outcomes) → advisory (proposes, human approves) → gated action → wider autonomy, each step earned on outcome evidence and reversible on regression. Classify by reversibility first; gating = risk × blast radius, judged per ACTION on authorized / irreversible / user-visible / high-impact [PwC](https://podcasters.spotify.com/pod/show/mlops/episodes/Autonomous-Agents-at-Work-From-OpenClaw-Hype-to-Enterprise-Reality-e3jj7u3) [Keys to my life](https://www.youtube.com/watch?v=sJ2jc7leKBk) (2026-05) [Accenture-GroganWang](https://www.youtube.com/watch?v=AGkzpxMdPn8) [Amazon-AGI-Mishra](https://www.youtube.com/watch?v=Cc0_nyxROBA) (2026-07)
- **Gate agent dispatch on problem specificity**: a coding agent thrown a vague report ("onboarding is broken") will always "fix" something → noisy PRs. Triage to three states — actionable (dispatch), needs-human (inbox), under-evidenced (return to the pool). Error-tracking signals qualify; Slack and session-replay usually don't [PostHog](https://www.youtube.com/watch?v=zMiSRliEzv4) (2026-06)
- **80/20 hybrid loop-breakers**: ~80% open research on a high-reasoning model, ~20% hard-gated deterministic steps (validation, summarization, critic) on cheap non-reasoning models; cap research with use-last-result counters (4–5 iterations) or ~5-min timeouts — degrade to the last decision, don't kill the run [Qodo](https://www.youtube.com/watch?v=EcqMYoIV57A) (2026-06) [BuzzHPC](https://podcasters.spotify.com/pod/show/mlops/episodes/Architecting-Modern-AI-Systems-Platforms--Agents--and-Integration-e3k0qlu) (2026-05)
- **Container ≠ agent platform**: a container knows only one session and has no isolation across stateful sessions → parallel sessions clobbering a *shared cache*, and an auto-accept agent pushing the company's source to a personal GitHub because secrets were commingled. Dev boxes (64–128GB, pre-warmed, ~10s spin-up) beat lightweight sandboxes — the agent inherits all repo tooling plus isolation [Cognition](https://www.youtube.com/watch?v=_xQnSNlBP_w) [Stripe](https://www.youtube.com/watch?v=_xQnSNlBP_w) (2026-05)

## Transparency, control & reversibility
- Transparent execution (live todo list, visible context and skills in use, tool-call inputs AND outputs) lets the user intervene mid-run before wasted steps compound. Multi-granularity reversibility (per-line, per-file, conversation-checkpoint rollback) bounds mistakes, making users bolder [Flinn](https://www.youtube.com/watch?v=7CrPrHgoEYk) (2026-05)
- **HITL granularity for background agents**: instead of fixed checkpoints, pause exactly where the agent would otherwise make an assumption and let the human resolve that decision inline by tagging it in a chat thread, then resume; separately, gate irreversible actions behind an approved plan [Ramachandran](https://www.youtube.com/watch?v=RGiXcVxSD3s) (2026-07) (discounted src)
- Stay-in-the-loop devices for long runs: **implementation notes** — the agent logs every unknown it hits and why it chose what it did, so you audit deviations instead of diffing blind; and an **exit quiz** before merge [Fable-field-guide](https://www.youtube.com/watch?v=9fubhllmsBU) (2026-07)
- ...at fan-out scale reading trajectories stops being viable — 20–30 sub-agents fire per run. Read the end-of-run DECISION summary end to end instead, and prompt for one when the harness didn't emit it [Osmani-PE](https://newsletter.pragmaticengineer.com/p/from-chrome-devtools-to-ai-engineering) (2026-08)
- ...with the guard that makes that honest: a decision summary is GENERATED, not recorded, so it can confabulate — most likely on runs that exhausted the context window. Check it against the durable log (§ Event-sourced design) [Osmani-PE](https://newsletter.pragmaticengineer.com/p/from-chrome-devtools-to-ai-engineering) (2026-08)
- Stable deterministic scaffolding matters more than capability: hidden context mutation (silent system reminders, system-prompt edits per release, tool-result pruning) silently breaks workflows you can't see [Pi](https://newsletter.pragmaticengineer.com/p/building-pi-and-what-makes-self-modifying) (2026-04)

## Multi-agent orchestration
- **The missing primitive for agent swarms isn't runtime, orchestration or triggers — it's coordination**: how agents pick up tasks from each other. GitHub is a poor coordination layer at agent-scale PR volume; candidates are durable-execution workflow definitions, or a CLI-level gateway agents call to check SDLC-step completion [Ona-Bichard](https://www.youtube.com/watch?v=5Sui_OnSRlY) (2026-07)
- **Run features SERIALLY** (one worker/validator at a time), parallelizing only READ-ONLY ops. Naive parallelism fails for SWE: agents step on each other's changes and make inconsistent architectural decisions. Consolidate judgment into one agent; sub-agents return results, never judgment [Factory-Alvoeiro](https://www.youtube.com/watch?v=ow1we5PzK-o) (2026-05) [ZS](https://www.youtube.com/watch?v=u6jJcIFDLE4) (2026-07)
- **One async-handle primitive covers sub-agents AND background terminals**: a `spawn agent` tool creates the instance and a `send input` tool feeds it more content, waits, or shuts it down — background shells reuse the identical shape, so the harness needs one abstraction [OpenAI-Kundel](https://www.youtube.com/watch?v=shRR1e2HXMk) (2026-08)
- **Live disagreement on where orchestration logic lives.** Factory keeps ~all of it in prompts + skills per mission (~700 lines; 4 sentences change execution strategy) — a "bitter-lesson defense". WorkOS moved it INTO deterministic code to stop context leak. Decider: how much the orchestration changes per run [Factory-Alvoeiro](https://www.youtube.com/watch?v=ow1we5PzK-o) [WorkOS](https://www.youtube.com/watch?v=vy7o1g2iHY8) (2026-05)
- **Tokens are not fungible — give them jobs**: at a FIXED budget, allocating tokens to non-executor roles beats pure execution — *advise*, *grade* (rubric grader loops the executor), *dream* (reflector writes learnings to memory). Financial-analyst bench, same 600k budget: execute 0.76 vs advise 0.89 [Anthropic-WF26](https://www.youtube.com/watch?v=I2cbIws9j10) (2026-07)
- ...*advise* shipped as a server-side Advisor Tool: a cheap executor calls a big advisor only on decisions it can't resolve, sharing one conversation state. Sonnet+Opus-advisor +2.7pp on SWE-bench Multilingual at −11.9% cost/task; Haiku+Opus-advisor 41.2% vs 19.7% solo on BrowseComp [Anthropic Advisor Tool](https://docs.litellm.ai/docs/completion/anthropic_advisor_tool) (2026-04)
- **Agent = a graph of nodes, NOT pre-planned sub-agents**: grow from a single node + tools + eval set; ship, watch which action it reliably botches, split THAT node out, re-run evals, repeat — "complexity should be a result of time, not planned". Reserve sub-agent framing for cross-team boundaries [iFood](https://podcasters.spotify.com/pod/show/mlops/episodes/The-Control-vs-Magic-Spectrum-Building-Agents-e3k9n0g) (2026-06)
- **Route by task, not general intelligence** — a pure prompt-and-loop often FAILS on narrow reliability even when the model impresses in chat. But route-by-task-*type* is fragile once agentic: complexity shifts mid-session (explore → implement → debug). Keep a frontier agent *watching* so it can pull the task back, piggybacked on the ~5-min cache refresh [ElevenLabs](https://podcasters.spotify.com/pod/show/mlops/episodes/Voice-Agent-Use-Cases-e3ileg6) (2026-05) [Cognition/Yan](https://www.youtube.com/watch?v=QHBjufYK8TA) (2026-08)
- **Sidekick beats spawning sub-agents** when the delegate is reused: ONE long-lived side agent holding a running context means the main agent never re-supplies context and it stays in KV cache (~10× cheaper on cached tokens). Frontier-plans/cheap-implements: ~40% cost cut at frontier-level quality [Cognition/Yan](https://www.youtube.com/watch?v=QHBjufYK8TA) (2026-08)
- Handoff shape: the sidekick returns *file references*, not content dumps — bigger models are more token-efficient at deciding what to read. General principle: context may be lossy, the harness only needs to be able to *find* what it needs [Cognition/Yan](https://www.youtube.com/watch?v=QHBjufYK8TA) (2026-08)
- **Org-chart hierarchy as real entity types** (CEO/VP/manager/worker): each layer its own agent with scoped context and an approval boundary; context flows down as the slice each layer needs, results flow up, the human reviews only the top — collapsing N live contexts to 1. A flat pile of >4–5 agents makes the human the scheduler [KRAFTON-fleet](https://www.youtube.com/watch?v=4kYl2_mqmnQ) (2026-07)
- **Shape the work queue as a Kanban board so humans can steer mid-run**: a strategist files experiment cards, workers implement, read the resulting curves and write a POST-MORTEM back to the strategist, which shifts direction. Humans cancel cards, add their own, and chat with the strategist while it runs [MorganStanley-AlphaLab](https://www.youtube.com/watch?v=kiqubc5b5Yo) (2026-07)
- **Stripe "Minion" one-shot loop** (prompt→PR, ~65% merge with zero edits): gather context → `analyzer` localizes the repo area → one coding turn → lints/tests/typecheck → an LLM judge sees the diff plus the ORIGINAL prompt, NOT poisoned by the agent's excuses → a `diagnostic` agent's short note feeds back; repeat [Stripe](https://www.youtube.com/watch?v=_xQnSNlBP_w) (2026-05)
- **Best-of-N agent runs are "map without reduce"**: fanning out 100 agents is easy; the missing primitive is the REDUCE (test-pass count is one usable reducer). Exception where reduce is free — TASTE tasks (UI, design, architecture directions): generate 15 variants and eyeball them [Sazabi](https://podcasters.spotify.com/pod/show/mlops/episodes/Logs-Are-All-You-Need-Rethinking-Observability-with-AI-Agents-e3jthog) (2026-06) [Cerebras-Chieng](https://www.youtube.com/watch?v=TeGsFFNqRLA) (2026-05)
- **Cross-repo meta-harness**: agents are repo-bound, so one logical change spanning N repos costs ~N re-explanations. Fix = an agent-agnostic layer extracting metadata from all reachable repos into ONE dependency graph. Select repos by INTENT ("update every repo depending on lib vX") and treat CI across them as ONE vector [Nx-Savkin](https://www.youtube.com/watch?v=jVjt-2g8NMY) (2026-06)
- ...the blunt alternative, chosen first-hand: 10 repos → one monorepo, on the finding that NAVIGATION was never the problem — end-to-end testing, verification and deployment are, and a sandbox must clone every repo first. Decider: comprehension bottleneck or verify/deploy bottleneck [Wisedocs-Linkov](https://www.youtube.com/watch?v=7vn4WpqNpck) (2026-08)
- **Multi-machine fleet ops**: move context between machines via git — commit the agent's context files, push, poke the remote agent (tmux send-keys over ssh) to pull and resume; per-machine dirs for machine-bound state, shared state changes only via PR, or the machines silently diverge [KRAFTON-fleet](https://www.youtube.com/watch?v=4kYl2_mqmnQ) (2026-07)

## Plan-heavy vs review-heavy — optimizing for human time
- **Plan the stack BEFORE code** (30 min upfront reliably saves hours of review): product review → system architecture (component contracts, data models) → **program design** (types, method signatures, call stacks — the most-skipped step) → vertical slices with checkpoints. PRs built this way stay small enough to read line-by-line [HumanLayer/Horthy](https://www.youtube.com/watch?v=htM02KMNZnk) (2026-07)
- Models write **horizontal** plans (database → services → API → front end), the wrong shape: nothing is testable until the end and you review 2000 lines at once. Slice vertically — mock endpoint, front end, real data, migration, business logic — for five small verifiable diffs [Horthy-CtxEng](https://newsletter.pragmaticengineer.com/p/context-engineering-with-dex-horthy) (2026-07)
- Plans containing every line of code as diff blocks are anti-leverage: you review the plan *and* the PR. Plans were also popular for a non-obvious reason — they anchor the agent so it keeps working until done [Horthy-CtxEng](https://newsletter.pragmaticengineer.com/p/context-engineering-with-dex-horthy) (2026-07)
- Spec/code parity doesn't survive contact: maintaining specs alongside code gives two sources of truth, and nobody reports being glad they maintained it — use the code as the source of truth [Horthy-CtxEng](https://newsletter.pragmaticengineer.com/p/context-engineering-with-dex-horthy) (2026-07)
- Agent coding displaces human effort into planning and reviewing (~20 min back per 30 min coding), not free time — optimize for accuracy per HUMAN time, not wall-clock. Work-type matrix: frontend feature dev → stay in-loop; backend → plan-heavy/TDD; refactor/migration → fully plan-heavy [Plan and Review](https://www.youtube.com/watch?v=W76woOYHlvY) (2026-05)

## Loop engineering — in-the-loop → out-of-the-loop
- **Loops as control theory, not bash**: set point (desired end state for one property), sensor, measured error, controller (one incremental change), actuator, re-measure. Precedents — thermostats, Kubernetes autoscaling, IaC desired-vs-current. Incrementality is what prevents 40k-line PRs [HumanLayer-Mistele](https://www.youtube.com/watch?v=xIt_mTQp6mY) (2026-07)
- ast-grep is the sensor of choice for code patterns: language-agnostic across a multilingual monorepo and out of band from tsconfig/ESLint — which matters because agents disable those with inline comments [HumanLayer-Mistele](https://www.youtube.com/watch?v=xIt_mTQp6mY) (2026-07)
- **Stop the bleeding before migrating**: one full scan on main, violations sorted deterministically and committed, then fail any PR adding new ones. Build "golden patterns" by hand before setting the actuator loose, because agents are pattern replicators [HumanLayer-Mistele](https://www.youtube.com/watch?v=xIt_mTQp6mY) (2026-07)
- **Flow control beats throughput**: label PRs per loop and exit before doing any work if one is still open — no human reviewed the last output, so producing more is waste. A `/iterate` PR comment re-triggers the loop with feedback appended to a version-controlled file, so tuning history is diffable [HumanLayer-Mistele](https://www.youtube.com/watch?v=xIt_mTQp6mY) (2026-07)
- Slow loops are the shape with the most practitioner confidence: a nightly cron fixing one linter finding, growing along two axes — more feedback mechanisms (including hand-written "here's good, here's bad" rules where no deterministic tooling exists), then more scope per run [Horthy-CtxEng](https://newsletter.pragmaticengineer.com/p/context-engineering-with-dex-horthy) (2026-07)
- ...and the loop needn't be pre-wired: **let the agent schedule its own**. "Keep an eye on this every X minutes" registers a recurring message into the thread's own context; it can also create, name and pin threads — so Codex ships no `/loop` command [OpenAI-Liu-MLOps](https://podcasters.spotify.com/pod/show/mlops/episodes/How-To-Delegate-To-An-Agent-Like-You-Would-An-Employee-e3nglg8) (2026-08)
- Cost objection from a practitioner running loops: non-deterministic verification adds non-determinism rather than removing it (compounding math in evals.md § LLM judges). Where loops demonstrably pay: security scanning on PRs at ~$5/PR, and domains with years of existing test suites [LoopsDebate](https://www.youtube.com/watch?v=c35YoMdnI78) (2026-07)
- **"Loop engineering"**: stop prompting the agent directly — author the loops that prompt it (triggers + goals), so your job moves to issue-writing on one end and code review on the other. Pull the human out one stage at a time (ticket → triage → implement → verify → PR) but keep the final merge gate [Warp](https://www.youtube.com/watch?v=gi0Lx6c84VE) (2026-06) [Osmani-PE](https://newsletter.pragmaticengineer.com/p/from-chrome-devtools-to-ai-engineering) (2026-08)
- ...make review TARGETED rather than uniform by having the loop itself flag when a change touches a critical part of the system. A loop building everything with no blast-radius guardrail is the named recipe for disaster [Osmani-PE](https://newsletter.pragmaticengineer.com/p/from-chrome-devtools-to-ai-engineering) (2026-08)
- Two-stage chain beats one agent: automation A turns an under-specified issue into a spec doc (affected packages, version bumps, acceptance criteria) you merge as a paper trail, and automation B implements it. Each loop is only as good as its issue's acceptance criteria [Warp](https://www.youtube.com/watch?v=gi0Lx6c84VE) (2026-06)
- ...shipped instance, where the intake agent INTERROGATES the human: requests land in Slack at wildly varying quality, and the agent runs rounds of clarifying questions until it judges the request spec-ready. Without that gate you get a "token-maxing slop cannon" [Ramp-Mehr](https://www.youtube.com/watch?v=ITMXwI6QL6A) (2026-07)
- Two things they learned: adoption came from LATENCY, not quality (replies went from hours to seconds, ~20% of scoping time saved); and **the ENDS of a pipeline automate first** — context-gathering works, spec→code frontier models largely one-shot, and the scope→spec middle is the hard part [Ramp-Mehr](https://www.youtube.com/watch?v=ITMXwI6QL6A) (2026-07)
- **Start with ONE sequential loop, not parallelism**: the bottleneck is your own ability to spec and review, not tokens/sec. Don't pre-compute a dependency DAG and fan out either — that recreates waterfall and makes agents contend; single loop, prompt "pick the next most important ticket", let it infer deps from what's done [Ralph-Parsons](https://www.youtube.com/watch?v=2TLXsxkz0zI) (2026-05)
- A Ralph-loop prompt is a built-up role + procedure: cast the agent as "one engineer in a relay team — do exactly one change, drop context, stop", and encode ticket format, status values, when work qualifies, how to run tests in *your* framework, and "test passing is not enough — verify actual behaviour" [Ralph-Parsons](https://www.youtube.com/watch?v=2TLXsxkz0zI) (2026-05)
- Prefer a fresh context per iteration over resuming, as a forcing function: it forces in-session knowledge to be codified into repo files and skills, yielding a durable store any future session or human can read [Ralph-Parsons](https://www.youtube.com/watch?v=2TLXsxkz0zI) (2026-05)
- **Never let the loop close or mark-done its own work** — stay the final verification gate. Motivation is "cognitive debt". If the builder grades its OWN work you didn't remove review, you HID it; capability drift only moves WHERE proof belongs, never WHETHER [Ralph-Parsons](https://www.youtube.com/watch?v=2TLXsxkz0zI) (2026-05) [Volkov](https://www.youtube.com/watch?v=ZpK5PWX2YRM) (2026-07)
- **The "missing layer" is post-launch, triggered by LOG MONITORING** (not a merge or user report): an agent runs every 15–60 min over a ~1-hour window, has codebase access, diagnoses stuck or "successful-but-wrong" users, and opens a PR. Gate every PR with a SEPARATE review agent with FRESH context that can close it [Wandero](https://www.youtube.com/watch?v=kZsf_Sfm7RU) (2026-07)
- **Change-triggered variant: a check plan PER RELEASE, not fixed CI checks.** The agent reads what changed, infers which telemetry is causally downstream, watches that, and picks the cadence (an hour for an intermittent failure, three days to confirm the effect landed). Its real gain is the changes CI never sees: feature flags and infra edits [Resolve-Smith](https://www.youtube.com/watch?v=vSx5IULvBns) (2026-08)
- ...wire in SEVERAL signals rather than one trigger — error tracking, analytics, deploy logs, bug reports, the backlog — so the loop PRIORITIZES instead of merely firing: a slow view outranks others once traffic share says who it hits [Osmani-PE](https://newsletter.pragmaticengineer.com/p/from-chrome-devtools-to-ai-engineering) (2026-08)
- **"Mirror harness" principle**: give the agent the SAME debugging access a human has (logs, trajectories, metrics, database, UI) so a fix addresses the real problem instead of guessing — the moat is the self-watching harness, not the model. It needs its own reasoning agent, because log-diagnosis is real-bug-vs-noise judgment, not grep [Wandero](https://www.youtube.com/watch?v=kZsf_Sfm7RU) (2026-07)
- Compile repeated LLM work into generated scripts: the agent inspects one raw page, writes a deterministic parser, then the script runs (~100 tokens/run vs ~10k; ~62% saving even on a structured site). Pair with a self-healing check that re-inspects and patches its own scraper on missing fields [Bright Data](https://www.youtube.com/watch?v=zTZ0qunQXnM) (2026-06)
- ...but **don't cost-optimize while experimenting**: run the expensive agent on the same problem ~100×, watch its solutions converge, and only THEN compile that step into a one-shot call — premature avoidance of agent calls was PostHog's biggest mistake [PostHog](https://www.youtube.com/watch?v=zMiSRliEzv4) (2026-06)
- Partition workflows by determinism: discovery benefits from non-determinism, but credentials, transactions and anything with consequence require it — design an explicit handoff point where the LLM-mediated phase ends and a programmatic flow takes over [Stripe](https://www.youtube.com/watch?v=KLSuFPj2ld0) (2026-06)

## Agent-rate development — CI in the loop, merge queues
- **The PR breaks as the unit of work at agent scale**: built for human-paced discrete-handoff review, but agents emit N PRs across N repos with thousands of short-lived branches. Validation moves OUT of a post-PR CI phase and INTO the agent's inner loop — every iteration builds, tests and gets reviewed [Namespace](https://www.youtube.com/watch?v=VktrqzQgytY) (2026-05)
- ...pushed a stage earlier at OpenAI: opinionated "finalize code" review skills the agent triggers at PR-CREATION time, so it self-heals before the PR reaches GitHub and CI at all. Generation speed is what makes that affordable — at ~1,200 tok/s vs ~40–60, running suite, linters, hooks and browser QA every step costs almost nothing [OpenAI-Liu-MLOps](https://podcasters.spotify.com/pod/show/mlops/episodes/How-To-Delegate-To-An-Agent-Like-You-Would-An-Employee-e3nglg8) (2026-08) [Cerebras-Chieng](https://www.youtube.com/watch?v=TeGsFFNqRLA) (2026-05)
- **Merging at agent rate ≈ a DB serialization problem** — the repo is one ledger needing a lock per commit, and machine merge-locks are short and frequent, so time-to-merge dominates. "Pre-merge queue": candidates wait outside the repo, and the human approves intent plus result (a video of it working), not raw diffs [Namespace](https://www.youtube.com/watch?v=VktrqzQgytY) (2026-05)
- **Solo agent builders re-derive 5 CI/CD controls badly**: output-shape/regression test; alerts (a silent cron failure unnoticed for a week); boundary/contract validation (one skill's schema change breaks 3 consumers); a checkpoint/staging gate; audit trail (which prompt emitted the bad output). Agent frameworks give none by default [Shrabony](https://www.youtube.com/watch?v=WLXxTaPagA8) (2026-07)
- Prioritize gates by MAPPING every handoff (each arrow between agents is where output silently corrupts) — don't gate them all; put your FIRST gate on the most EXPENSIVE handoff, not the most complex. A gate that only warns is a suggestion: it must BLOCK the artifact from advancing [Shrabony](https://www.youtube.com/watch?v=WLXxTaPagA8) (2026-07)
- **De-risking displaces speed as the pipeline priority**: with an agent driving there's no human context-switch cost waiting on a build, so emphasis shifts to de-risking. Shipped as a standing loop with a checklist — every 30 min: rebased on main, every review comment addressed, CI green [CI/CD Erez](https://newsletter.pragmaticengineer.com/p/cicd-with-robert-erez) (2026-06) [OpenAI-Liu-MLOps](https://podcasters.spotify.com/pod/show/mlops/episodes/How-To-Delegate-To-An-Agent-Like-You-Would-An-Employee-e3nglg8) (2026-08)
- **"Agent readiness" made measurable = how many DETERMINISTIC validation loops your codebase already has** (linters, type checkers, security scans, e2e tests). Long-running harness output quality tracks how much of the work you can validate, so validation at scale IS autonomy at scale [Factory-Reyes](https://www.youtube.com/watch?v=wpOA-UXynoM) (2026-07)
- ...which inverts where effort goes — "if you can frame the problem as the set of verification systems that must validate it, you can solve it with AI today". **Where you can't build a validator is where autonomy stops**: their legal workflow is ~100% autonomous while their own harness isn't, for want of a check on visual bugs [Factory-Reyes](https://www.youtube.com/watch?v=wpOA-UXynoM) (2026-07). Same claim from the other end — coding crossed the trust threshold FIRST purely because code runs and tests; knowledge work has no unit test [Amazon-AGI-Barth](https://www.youtube.com/watch?v=2JX6JYyQG4Y) (2026-07)
- Sequencing caveat: only ~30–40% of agent-readiness gaps are click-to-fix; the rest need workflow change, and humans resist the nitpickiness of the new checks. Metric they run is "autonomy ratio" — AI vs human actions before an interruption [Factory-Reyes](https://www.youtube.com/watch?v=wpOA-UXynoM) (2026-07)
- **"Self-validation == an ephemeral environment"**: any "have the agent confirm its change works" loop is really spin-up env → agent pokes → tear down, even when no human looks. Granola turned a one-instance Electron app into a web shell so CI emits a per-PR preview link the agent tests against [CI/CD Erez](https://newsletter.pragmaticengineer.com/p/cicd-with-robert-erez) [Granola](https://www.youtube.com/watch?v=ON5LIT0M4do) (2026-05)
- **A PARTIAL verification engine is worse than none, and it inverts the build order.** With a formula engine covering ~50% of Excel, the agent writes a formula correct in the real tool, your engine errors, and it "fixes" working code. Build the sensor to fidelity *before* closing the loop on it [Witan-Campos](https://www.youtube.com/watch?v=HEFSExa0xl0) (2026-07)

## Dynamic workflows — a bespoke harness per task
- Let the agent write a custom harness per task at runtime: a static workflow wired ahead of time must stay generic → generic output. A dynamic workflow is a JS file running a small team of agents with primitives `agent`, `parallel` and `pipeline`, picking model and worktree per agent and resuming if interrupted [Prompt Engineering](https://www.youtube.com/watch?v=l5rae4LMKBc) (2026-06)
- **Six portable harness patterns**: classify-and-act; fan-out-and-synthesize (isolated contexts so biases don't cross-contaminate); worker+critic against a rubric (cures self-preferential bias); generate-and-filter; tournament (pairwise beats absolute scoring); loop-until-done, where a gate asks "any new findings?" so the loop, not a tired context, decides when to stop [Prompt Engineering](https://www.youtube.com/watch?v=l5rae4LMKBc) (2026-06)
- **OpenProse** — dynamic-workflow behavior on ANY agent: a markdown "logical English" spec (`.pros.md`) compiled by the CODING AGENT. It declares sub-agent work explicitly, verifies each sub-agent's work in the PARENT session, and wires skills and CLI tools as explicit DEPENDENCIES [OpenProse](https://www.youtube.com/watch?v=3hXJI2q0Jz8) (2026-06)
- **Golden-session → reusable workflow**: take a run that worked great and have an agent deconstruct it into a reusable workflow program, so you reproduce that quality repeatably instead of re-rolling the dice [OpenProse](https://www.youtube.com/watch?v=3hXJI2q0Jz8) (2026-06)
- **...then CRYSTALLIZE it out of the model.** Once you understand a repeated task end to end it's a workflow, not an agent — move it to a small model or plain code. A frontier agent on a cron job is a consultant mowing the lawn [Breunig](https://podcasters.spotify.com/pod/show/mlops/episodes/The-Winchester-Mystery-House-Problem-in-AI-Development-e3nqiao) (2026-08)

## Running LLM-generated code — sandboxes
- **"Seven stages of sandboxing"**: teams try fork/exec → containers/seccomp → gVisor → V8 and all end at microVMs — hardware virtualization is the only boundary surviving guest root, since container and gVisor exploit chains still reach the host kernel. Start there (Firecracker / Cloud Hypervisor / crosvm) [OpenAI-Bhardwaj](https://www.youtube.com/watch?v=OqM67QG_Ikk) (2026-07)
- Syscall-allowlist (seccomp) filters fight GENERAL agents: you can't enumerate the needed syscalls up front and blocked calls make a terrible feedback loop — isolate the environment rather than over-restricting it. "System tricks can cover performance issues; they cannot hide security breaches" [OpenAI-Bhardwaj](https://www.youtube.com/watch?v=OqM67QG_Ikk) (2026-07)
- **The sandbox breaks at exactly the point the agent gets useful**: it wants to build and run containers to verify its work, so you hand it the Docker socket — and it can now spawn a privileged container, escape, and read other processes' memory. Landlock, bubblewrap and Kaniko don't compose with containers; the fix is a Firecracker microVM per agent with the socket inside [Form3](https://www.youtube.com/watch?v=LqLoYksJ6do) (2026-07)
- **Maximize non-determinism *inside* the box, make the box *really strong***. Cleric's arc — early rigid tools (no raw `kubectl`) became the constraint blocking performance as models improved, so they relaxed to bash/Python composition, but only AFTER doing sandboxing hard, because rigid tools had been giving free security guarantees [MLOps-Sandboxing](https://podcasters.spotify.com/pod/show/mlops/episodes/Sandboxing--Agent-Harnesses--and-Agent-Teamwork-e3kts75) (2026-06)
- **Inverted sandbox design for generated code**: start from a zero-capability JS isolate (no fetch, no filesystem, no env vars) and grant capabilities outward — the opposite of a VM locked down after the fact; ms spin-up makes a fresh sandbox per generated code string cheap [Cloudflare](https://www.youtube.com/watch?v=SKDJo2CopRs) (2026-06)
- Full-stack version, so generated code's security bugs become *unreachable* rather than reviewed: generated UI in a null-origin iframe under a CSP permitting only postMessage to the parent, generated server code in a worker sandbox with no egress, and the two can talk only to each other [Varda/Cloudflare](https://www.youtube.com/watch?v=RmS5s6Wbin4) (2026-08)

## Self-evolving harnesses, trajectory stores & retro
- **Meta-harness optimization needs a measurement surface first**, which is what makes arbitrary design choices ("is a strategist+worker split arbitrary?") answerable — build 10–20 careful environments, then let an LLM read traces and edit the harness. The durable value is ENVIRONMENT-building, not the harness in the middle, which is why they open-source the harness and keep the environments [MorganStanley-AlphaLab](https://www.youtube.com/watch?v=kiqubc5b5Yo) (2026-07)
- **Caution on optimizing a harness against a FROZEN model**: Adaption Labs got no return from auto-research until data adaptation was co-optimized with the model — the stated corollary being that an auto-scientist for HARNESSES needs the same joint treatment, a co-training problem rather than search over a fixed model [Adaption-Hooker](https://www.youtube.com/watch?v=XEd_SRVHBgU) (2026-08) (data half is a result; harness half is a prediction)
- **Self-fixing agent pattern**: observability skills pull production traces into FILES inside the repo, not an API call — coding harnesses work well with files. Deliberately-scoped skills (fetch one session's traces, not generic full-data access) determine whether the agent finds the issue [Arize-Lopatecki](https://www.youtube.com/watch?v=9HbzAWnKbo4) (2026-07)
- Same pattern for performance: a weekly autonomous perf-audit workflow with MCP access to production traces posts scored high-ROI fixes to Slack. Map production metrics to function/file level, not service level, because coding agents reason at that granularity [HUD-Walter](https://www.youtube.com/watch?v=JJGbw4ggaFs) (2026-07)
- Bring-your-own-harness post-training: attach RL to an existing production harness via only a model-completion endpoint plus request/response logging — trains on real production traces without replicating the environment, at the cost of losing on-policy replay [Applied Compute/Feng](https://www.youtube.com/watch?v=k35LeKZEhiE) (2026-07)
- **End every agent invocation with a short retrospective** — what went well, what went wrong, what tools were missing, what context would help. Aggregating these across runs is what makes the system debuggable at scale; the recurring classes were infrastructure and repo complexity [Form3](https://www.youtube.com/watch?v=LqLoYksJ6do) (2026-07). Framed elsewhere as "mutual amplification" — log decisions, friction and anything unusual about the approach so agent AND human compound [Osmani-PE](https://newsletter.pragmaticengineer.com/p/from-chrome-devtools-to-ai-engineering) (2026-08)
- **"Agentic map-reduce" over your own history**: map cheaply over past sessions to extract every place you corrected the agent, reduce with a stronger model into recurring-failure categories, then feed those into eval tasks or a skill [Harbor](https://www.youtube.com/watch?v=jRCpXUjz4CI) (2026-07)
- **Past a certain length you cannot read a trace WITH an agent** — treat the trace as an external object you query into. So write the classifier as CODE and run it in a sandbox at production scale rather than LLM-reading each trace: cheap code for map, smart model for reduce [LangChain-Trivedy](https://www.youtube.com/watch?v=CvRngaQZQ3Y) [Raindrop-Hylak](https://www.youtube.com/watch?v=jHMiYtjoJfA) (2026-08)
- Two cheaper triggers for the same signal: in the moment, when you catch yourself telling the agent something you can SEE and it can't ("the button is a bit to the left"), that's the affordance to build; retrospectively, hand it your logs and ask what smells — `sleep(15)` everywhere instead of waiting on a condition [Poolside-Lajili](https://www.youtube.com/watch?v=iRcX54EO5g8) (2026-07)
- Retro agent parses Claude/Codex JSONL transcripts to detect doom loops (the same tool call repeated unchanged, excessive parallel tools) and writes lessons into per-stack markdown memory files. The discipline: when the agent errs, fix the harness so it can fix itself — never hand-fix the output [WorkOS](https://www.youtube.com/watch?v=vy7o1g2iHY8) (2026-05)
- **"Agent recipe" as a portable unit**: bundle harness config + evals + per-model profiles into one git-versioned artifact. A repeated failure becomes a new judge/eval, a repeated good behavior becomes a skill, user frustration becomes a harness extension. Optimize cost only *after* reaching frontier capability [Pie/Roland](https://www.youtube.com/watch?v=4sX_He5c4sI) (2026-07)

## Org-scale rollout & adoption
- **Org-level (multiplayer) harness as the next shape**: one harness the whole org shares, with its own identity and credentials not tied to a user, and org-level rather than local context — enabling checking others' work, de-duplicating findings, and a configured harness on a new hire's day one [Anthropic-Martin](https://www.youtube.com/watch?v=9QebvrrY3KY) (2026-07)
- What makes a team agent different: multiplayer by default, **proactive** rather than reactive (standing channel instructions that persist), shared team memory in natural language, and public channels as a prerequisite since accuracy comes from searching everything. Reported effect — a team agent lands ~65% of one team's PRs [Anthropic-Martin](https://www.youtube.com/watch?v=9QebvrrY3KY) [Anthropic-CC](https://www.youtube.com/watch?v=uU5Gv2h8-9g) (2026-07)
- **Address ONE session from every surface, rather than a bot per surface**: a Slack bot alone just moves the agent from trapped-on-a-laptop to trapped-in-Slack. One session across Slack, app and GitHub means nobody re-supplies context at a handoff, and a reviewer can ask the thread "why did you do it this way" [Superconductor-Singh](https://www.youtube.com/watch?v=OL7kfezynJM) (2026-08)
- **Standing ownership beats per-task delegation**: most internal usage is async multiplayer delegation, not interactive CLI, and the unlock was durable responsibility — "you own this part of the codebase, monitor this feedback channel, proactively take on tasks, react if this API changes" [Krieger-WF26](https://www.youtube.com/watch?v=I2cbIws9j10) (2026-07)
- **Treat it as leadership's problem, not the IC's**: the highest-leverage fixes (how the codebase is organized for agents) need buy-in no individual can get. Failure mode of "figure it out yourself" — adopters ship 10 PRs/day while non-adopters ship 1–2 AND inherit the review burden, so the people furthest behind disengage permanently [Amazon-AGI-Khandelwal](https://www.youtube.com/watch?v=aeTb5BdmTTc) (2026-08)
- Adoption lever that won skeptics over: ONE end-to-end high-value skill rather than broad enablement — theirs covered code-done → PR-ready (opens the PR, writes the description, handles review comments and CI failures). It ran over an hour, and setting expectations about that runtime was the work [Amazon-AGI-Khandelwal](https://www.youtube.com/watch?v=aeTb5BdmTTc) (2026-08)
- Give experiments an explicit opt-OUT lane from the repo's standards rather than one uniform bar throwaway code then violates; and read "model X is dumb today" as a harness change, not a model change — results swinging on small harness edits is itself the defect [Amazon-AGI-Khandelwal](https://www.youtube.com/watch?v=aeTb5BdmTTc) (2026-08)
- Standardize on ONE agent platform — spreading work across tools forfeits compounding platform benefits and kills per-task "model anxiety". Onboard the agent like a new hire, capturing framework conventions, architecture, UI patterns and testing/security standards as context, skills and hooks [Intercom](https://www.youtube.com/watch?v=4_VQBbs2iQA) (2026-05)
